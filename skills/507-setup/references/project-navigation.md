# 项目地图与导航维护

根或分层 README、spec/doc 导航、目录职责或迁移引用需要维护时采用。地图维护只写指定地图与必须同步的上下级；规则、设计、词义、规格、进度、路线图、日志和代码正文各自沿当前任务权限维护，不能因为导航缺文件就顺手建立正文。

从实际 AGENTS、根 README、旧入口及上下级地图进入，按问题读取现行正文和实现。地图的职责与入口来自当前代码、配置或已确认文档，不能凭目录名推断职责。已确认目标、尚未实现、已运行与真实可用分开；新项目无源码时可写已有文档入口并说明工程缺口。

根 README 指向项目定位与真实入口；spec 导航指向当前行为与验收，doc 导航指向长期依据、说明、规划与历史。共用设计和词义摘要回链唯一正文。已完成但仍有效的规格或说明不因完成被归档，只有被取代、放弃或纯追溯材料进入历史。

存在当前快照时根地图链接 PROGRESS，完整历史索引归 doc；地图不复制进度或工单字段。不为单文件机械造 README，过时地图只校准失真部分。

迁移先验证目标正文及消费者，再切换地图并退出旧现行入口；必要迁移指引列真实消费者与退出条件。非地图正文旧引用须由对应获授权维护者同步，尚未同步具体报告，不能用局部导航完成称全项目迁移完成。

完成前检查相对链接、锚点、围栏、真实阅读路径、地图与依据一致性及差异范围；确认无范围外正文或代码写入。交付处理／未处理范围、依据、冲突与验证；缺依据保留未知，返回查证而不补造入口。

持续任务新增了必要记录且本次允许维护入口时，接入现有导航并回链唯一正文；只有局部导航权限时，不以记录需要为由改写正式规格、规则或建立进度系统。实际记录方法见[工作记录](shared/work-records.md)，阅读入口不能替代正文和当前版本证据。
