# 项目规则与自动检查

作为主要技能，承接检查项目规则是否有可持续执行的保障、寻找机器可检查的缺口，以及按授权建立检查的目标。用户只要求盘点时交可追溯的发现和建议；要求实施时继续完成可行的检查、接入与验证。普通故障修复、单次代码审查和局部文档导航不因此扩大为全项目盘点。

共有依赖从[共有资源合同](../../lib/README.md)开始：首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同，参数取当前实际读取的 SKILL.md 路径；其余引用按合同解析。

## 找到有效规则和现有保障

先核项目范围、工作树、现行入口、用户决定和写入授权。按项目实际存在的文件读取适用的 `AGENTS.md`、`CLAUDE.md`、项目规范、规格及维护文档，沿引用寻找其他有效规则；子目录指令按其作用范围核对。区分现行要求、历史记录、上游样本、建议与尚待决定的内容，不把搜索命中或历史计划自动当成现行规则。来源冲突或条件不清时保留未知，不擅自决定新规则。

从实际运行入口检查已有 lint（静态检查）、测试、构建、持续集成（CI）及其配置，核对应规则、作用范围、触发时机、失败处理和例外；配置存在不等于实际运行或能阻止交付。盘点的每个候选保留规则原文位置、适用对象、条件与例外，以及现有保障和缺口。先复用已有工具或扩充已有检查，已有保障足够时不重复建设。

## 选择并落实

将每项要求拆为可观察的条件与结果，优先覆盖有实际风险和可可靠判断的部分：

| 适用情况 | 选择与边界 |
| --- | --- |
| 文件、链接、结构或代码依赖有确定规则 | 静态检查；说明扫描范围、排除和定位方式 |
| 行为、状态、顺序或失败恢复可由输入输出验证 | 自动测试；从实际入口覆盖正常、违规及必要边界 |
| 交付前必须运行现有检查 | 接入构建或 CI；核对真实触发、失败退出和是否具备阻止合并的权限 |
| 意图、内容质量、授权或真实接受依赖上下文 | 保留人工判断；机器可辅助发现线索，不能宣称已完整判断 |

一条规则可同时需要多种保障；说清机器能覆盖的片段和剩余人工责任。不要把宽泛关键词匹配、文件存在或测试全绿当成业务语义、用户接受或完整合规已成立。新检查的依赖、运行成本、误报、漏报、例外及失败提示要能维护；发现现有违规时分别说明历史问题、拟议处置和新的保护，不通过删规则、放宽断言、隐藏错误或无依据的排除求通过。

实施前确认当前请求允许改代码、测试和配置；只读盘点不写入。规则修订、提交、推送、发布和改变远端仓库设置各按具体授权执行。允许实施时，在当前范围完成检查、相关依赖与维护说明，并将检查接到实际使用的入口；远端门禁需要实际配置和相应权限，不能仅凭本地命令声称远端已保护。需要工程实现时可采用 `507-do`；工作依据和导航由 `507-setup` 维护，技能体系变化由 `skill-design` 处理，独立只读验收由未参与实施的执行者采用 `507-review`。

## 验证与交付

用真实规则和原故障复验，另准备能区分正确与错误的正反例、例外和相邻合法情况；确认违规确实失败且失败原因正确，合法输入通过，诊断定位准确。检查新增门禁的真实调用链和非零退出，不用直接调用内部函数替代入口验证。涉及 CI 时核对当前候选版本、触发事件、任务结果和日志；尚未推送或未配置分支保护时分别说明。无法安全重现真实数据时使用明确标注的隔离样本，不将合成样本冒充真实业务结果。

交付来源、范围、现有覆盖、选择理由、实际改动、运行证据及残余人工判断。只读请求止于盘点；已授权实施在检查、相关文档和独立审查完成后返回原目标。来源不明、规则冲突、工具不可用或检查失败时保留可用基线和失败证据，说明受影响范围，继续处理无依赖部分。宿主发现、自然选用、检查执行、CI 和用户接受分别成立。
