# 执行计划

作为次要能力，承接已成立的目标与方向，产出可被执行者和协调者直接消费的安排。主要技能可按需采用，用户也可直接请求；不替代 what 的目标定义、how 的方案构造、spec 的行为与验收依据或 coordinate 的实际分派，不成为必经入口。

## 输入与范围

读取当前请求、有效决定、指定方案与版本、范围/排除、已有计划、验收与执行条件。已有充分计划只校核变化后返回执行，不重写。仅需几个顺序动作时直接说明，不为计划建立独立文件或技能链。缺失事实自行查；目标或方案缺口只暂停依赖部分，指出具体缺口并交回原职责，不把假设补成定案。

只要求计划时交付计划及必要本地记录，不改业务产物、不创建执行会话、不派工、不发消息、不提交或发布。已有实施授权时计划是内部工作，形成后返回原任务继续；计划中的拟议动作不构成额外授权。

## 组织可执行安排

1. 沿原目标划分可观察的完整结果，不按代码层或零散动作拆成无独立价值的任务。复用已有规格和方案，计划引用它们，不复制第二份要求。
2. 标出真实先后依赖、可独立部分与必要输入，区分当前事实、设计选择和待验证假设；未知有最小查证动作，依赖不成立只阻塞相关步骤。
3. 每个重要步骤给开始条件、结果、验证点及失败时的保全/恢复办法。验收源来自原目标与有效规则，不因实施便利改合格标准。
4. 标明现有执行/整合责任与接续位置；未分配保持未分配，不编造负责人。独立验收须安排未参与实施者，实际委托由协调职责在授权内完成。
5. 核步骤能连回最终结果、范围与明确排除，更新现有计划及受影响关系。按[工作记录](references/shared/work-records.md)主动保存实质计划进展；明确不写文件时在会话交付，不新建竞争总账。

## 按需依据

| 条件 | 方法及用途 |
| --- | --- |
| 版本、输入或已有结果不明 | [事实与证据](references/shared/evidence.md)：核真实基准 |
| 目标或责任有实质取舍 | [决定归属](references/shared/decision-ownership.md)：保持已确认要求 |
| 缺口阻塞步骤 | [问题依赖](references/shared/question-frontier.md)：先处理真实前提 |
| 选择验证点和恢复条件 | [可观察验收](references/shared/validation.md)：使错误结果可被拒绝 |
| 新决定影响旧计划或计划已完成 | [权威与返回](references/shared/authority-and-return.md)：同步关系并继续父目标 |
| 真实中断或转交 | [续办方法](references/shared/continuation.md)：保全版本、写权和下一动作 |

## 完成与返回

完成于授权范围内的步骤、依赖、验证、恢复与接续已足够执行，真实阻塞及未分配责任可辨。交付当前计划、来源和未覆盖；仅计划请求止于此，不以排程证明实施、验收或发布已经发生。父目标仍有授权工作则立即应用计划继续，不让用户选择下一技能。

关键前提变化时保留有效步骤与历史理由，只修受影响关系；不可确认的条件保持未决并继续独立部分。没有兄弟技能时按同一合同完成计划并回交所需结果，不要求安装。
