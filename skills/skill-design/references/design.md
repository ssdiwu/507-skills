# 从任务与方法设计能力

用于体系规划、职责重组、拆合、退役，新建或改进技能时识别提升空间，以及执行质量问题的诊断。单一能力的问题只核相关方法与消费者，不展开全库；已有方向时跳过四维选择，仍处理实际质量缺口。不改含义的文字修订直接完成。

先确定要完成哪些真实任务、输入由谁提供、哪些动作被授权、结果如何被消费和验证。把旧入口拆成动作、条件、原则、领域知识、工具和偶然历史，不把每个旧名称当必须保留的模块。

| 放置方式 | 成立条件 |
| --- | --- |
| 主要技能 | 面向用户的稳定目标入口，负责特有判断与整体结果；用户主要触发，Agent 也可按需采用 |
| 次要技能 | Agent 按需采用的完整工作能力，有独立输入、操作授权、产物、完成与返回；不把内部选择交给用户 |
| 包内专用方法 | 只服务一种能力或模式，调用者已拥有目标和权限 |
| 共有方法或原则 | 多个真实消费者需要相同判断依据、输入关系或约束；每个消费者有明确采用条件 |
| 工具或脚本 | 确定性重复动作能可靠执行，错误与副作用可观测，已有工具不足 |
| 项目权威 | 只在具体项目持续成立的要求、词义、设计与运行事实 |
| 不进入新体系 | 没有本轮消费者、依赖未经验证、与目标无关或只是重复提醒 |

## 按需识别和选择优化方向

需要判断技能怎样更有用时，从当前目标、实际瓶颈或尚未尝试的机会选择角度。速度、高度、深度、广度没有固定先后，也不是成熟度等级；可以只用一个或组合使用，不逐项打分、不要求四项齐全或每次向用户提问。简单文字修订和已有充分方案不追加四维筛选；探索新机会也不必先证明旧做法失败。

| 方向 | 识别的问题 | 落到技能设计与验证 |
| --- | --- | --- |
| 速度（Speed） | 同样的工作能否更快完成，时间主要花在什么地方？ | 保持结果、质量和必要约束，减少重复获取、人工接续与返工，复用已有工具；同条件观察完整任务耗时，不能靠省略必要验证声称提速。 |
| 高度（Altitude） | 当前任务要促成什么后续结果；这项任务是否只是实现目的的一种手段？ | 从交付物追到它支持的理解、决定或持续结果，比较更直接的工作方式，必要时提出替代机制。用结果证据检验机制，例如历史回测或限定并行试用；不能只改成更宏大的目标句。 |
| 深度（Depth） | 同一任务中，顶尖专业人士还会怎样处理底层材料、方法和问题？ | 接触相称的原始材料，采用具体领域工具与方法，检验假设、发现盲点；需要提出新知识或预测时检查独立材料或未见数据。把可运行的外部反馈接入执行，避免只换专业词汇。 |
| 广度（Range） | 哪些平时未采用的领域能提供有用的方法，改善或创造当前结果？ | 用使用者要完成的动作重述载体，再寻找能补足证据、表达、检验或制作的方法。说清每个领域贡献的实际动作和产物；从有收益假设的尝试取得反馈，不以角色扮演或代理人数证明价值。 |

选定方向后，把预期改善落到相关技能的输入、动作、工具、结果与可反驳的观察，沿已有验证方法做相称切片；不新建固定四维表单或总控。高度更适合已有最终结果诉求的工作；作品本身、作者主张或明确载体就是目的时，保留其要求。改变用户目标、成本风险或引入持续代办仍由用户决定，探索建议不自动授予实施权限。

执行前核对所需数据、可用工具、运行环境和反馈能否实际取得。工具与数据可得不等于获准安装、付费或访问；缺口只限制相关执行与结论。模型或工具能力变化、旧判断仅来自未试过的经验时，可用有边界的小试验重新判断可行性，保留失败和退出条件，不以坚持或自信代替证据。

## 用结果、材料、方法和反馈核对所选方向

当新增或修订的是质量提升能力，或同类任务反复出现“步骤完成但结果不够用”时，先核是否存在尚未发生的专业动作，再决定改定义、补工具还是修执行。对照已有合同核四件事：用户结果怎样被消费；最接近事实的可得材料是什么；实际会使用哪种领域方法和工具；什么外部观察能推翻结果。已有内容足够直接复用，不给每个技能重复增加四栏、固定问卷或通用总控。

原始材料按当前结论需要选择，并非数据越多越好。领域方法要落实为可执行动作，例如复现故障、核对原件、检验样本外数据、对同版渲染做阅读路径检查；“扮演专家”、更多专业词或增加角色人数不构成方法升级。工具、环境或数据缺失时记录具体影响，继续可完成范围；能力建议不取得安装、付费、访问其他资料或长期监控的权限。

维持或提高深度时，优先补一项有区分力的观察；跨领域尝试核具体方法能带来的贡献与代价。大胆指标先作待验证目标，核现状、限制和代价，不能把反复要求模型相信可行当作证据。明确载体、作者主张和有效排除项保留。

结果反馈应回到持有该结果的技能及其共有源。先沿真实任务核对方法是否需要、是否读到、动作是否发生、反馈是否影响下一步，再区分规则缺失、读取条件遗漏、已读未执行、材料或工具不足、判断失误和目标不匹配。读取遗漏修直接消费者的采用条件；动作做过仍出错则查方法和反馈的区分力；已有规则没有执行时不继续堆同义规则。共有实现改在 lib，项目专有判断留在项目，定义和工具都不能靠自评分证明有效。

比较不同组合对完整任务的影响：无用路由、重复读取、授权重复询问、状态协调、依赖和恢复成本。可以合并、拆分、替换或取消旧身份；采用的是方法与必要保障，不是旧目录的外形。

主要入口用简短动作词或短语表达核心意图，详细职责和模式放在描述与正文；既有名字只在本次获授权的范围迁移，名称简化不省略完成与恢复要求。

选择条件先写清要交付的独立结果，并让相邻职责的跳过条件在入口描述中可见。读代码、理解机制、写代码或检查来源是许多能力的内部动作，不会自动形成新的主要目标或交接；确有独立结果且当前消费者需要时再委托。消费者引用共有方法时说明当前要核对的字段、主张或动作，不能只挂一个原则名字期待它自行生效。

合并时检查职责、触发关系、操作授权与完成结果能否清楚表达；拆分时检查是否产生无独立工作的空壳。共有抽取必须减少重复维护或调用者负担；不要因文件短、数量整齐或名称相似制造额外层。

规划产物说明首批能力、明确不进入的内容、共有消费者、失败恢复和验证切片。没有必要预造未来能力的SKILL文件；后续出现真实任务时再组合方法与工具形成入口。

已有且经过验证的决定默认有效，重组先核原理由及适用条件。改变、合并或退出须有前提变化或反证，并说明原保护怎样继续成立；没有证据不为整理结构重开已确认决定。本库 what/why/how 沿 5W2H 命名视角，不为命名整齐造七个入口或固定流程。
