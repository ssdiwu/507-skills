# 技能规划、编写与演进

从用户要完成的任务出发，构建能被准确选择、独立使用并可靠返回的能力。支持规划、新建、改写、拆合与退役；不以入口数量决定保留或退出；已验证决定默认延续，前提变化或反证才复审，也不以入口更少作为收益证明。

## 技能架构与触发关系

主要／次要是职责分工与默认触发关系，不是能力等级、操作特权或运行环境权限。用户主要通过主要技能表达目标；Agent 根据当前需要采用主要或次要技能，选择由 Agent 完成，不让用户点选内部技能链，也不因切换技能重复确认已有请求。

| 层次 | 明确职责与使用方式 |
| --- | --- |
| 主要技能 | 面向用户的稳定任务入口，保留特有判断与整体交付责任；也可被 Agent 按需采用，内部结果返回原任务 |
| 次要技能 | 供 Agent 复用的完整工作能力，有明确输入、结果和返回；不因作为内部能力而丢失自身完整说明 |
| 共有资源库 | 提供条件方法、执行脚本、工具说明、设计参考和索引，无独立 Skill 入口，不自行启动任务 |

主要技能使用简短、易记、可直接表达意图的动作词或短语命名；名称表达核心动作，完整职责、适用范围、内部模式与完成标准写在描述和正文中。展示名称保持简洁，不把内部能力清单拼成名称；命名不扩大职责或操作授权，也不要求为了整齐批量改动其他既有名称。

触发指选择、读取并采用技能，不默认新建 Agent、会话或执行服务，也不要求固定主→次→资源三级串行。任务和材料充分时直接执行所需方法，成熟稿的局部修改不重走采访、主线选择或规划。主要入口持续承担原目标，不能把内部结果完成当作整件任务完成。

讨论分工用“职责边界”，讨论使用方式用“触发关系”。“操作授权”指当前用户请求允许的实际动作，“运行环境权限”指工具或宿主的技术访问限制；它们独立于技能层次。共有资源库集中维护方法与做法，素材库和灵感库提供输入与来源，不混称为技能或可运行组件。

## 输入、操作授权与交付

承接目标、指定版本、用户修订、现有能力和授权范围。只要求规划时交付清楚的设计与取舍；要求创建或重构时持续完成源文件、资源、直接消费者、导航与必要验证。普通命名、结构和可逆实现选择由 Agent 自行决定。

技能本身保留职责、触发条件、必要输入、操作授权、产物、完成、失败与返回。方法可以共享，关键许可与停止条件不能只藏在参考中。安装、消息发送、付费生成、提交和发布仍按具体授权处理，技能编写不增加这些权限。

## 从任务重组能力

先列真实任务和可观察结果，再拆其中的判断、动作、条件与工具需求。逐项决定它应成为独立技能、包内专用方法、共有方法、项目规则、工具，还是无需保留的重复做法。

涉及体系规划、拆合或职责重建时，读[能力设计](references/design.md)。旧技能是可拆解来源；可以只采纳片段、改变组合或退出身份。不得把未实现的工作全部塞进隐藏技能，也不强迫普通任务经过总控。

| 当前缺口 | 按需方法及用途 |
| --- | --- |
| 基线或来源仍不确定 | [事实与证据](references/shared/evidence.md)：核对版本、消费者和证据范围 |
| 范围、权限或判断归属不清 | [决定归属](references/shared/decision-ownership.md)：区分用户取舍与 Agent 实现责任 |
| 规划中仍有会改变结构的信息缺口 | [问题依赖](references/shared/question-frontier.md)：只处理当前必要问题 |
| 需要比较保留、合并、拆分或重建 | [候选与反证](references/shared/alternatives.md)：检查真实替代方案与代价 |
| 需要制定或判断验证 | [可观察验收](references/shared/validation.md)：绑定实际结果与边界 |
| 新旧结论冲突、持久化或内部工作完成 | [权威与返回](references/shared/authority-and-return.md)：维护唯一归宿并继续原目标 |
| 方案关系不易看清 | [清晰表达](references/shared/clear-expression.md)：选择最小可用图表与阅读路径 |

这些方法可直接采用，不必先调用另一个技能，也不要求全部读取。确有尚未明确的用户目标或实质取舍时可委托 `507-what`，获得结论后继续；没有该技能时依相同边界直接澄清，不能形成安装依赖。

## 写成可用交付

明确职责后按[编写与交付](references/delivery.md)完成所需包和元数据。主入口只保存独有的使用与完成合同；共有源记录实际消费者及读取条件，必要资源进入独立包，专用知识留在所属能力。

`description`（用途说明）的首句先说核心动作与对象，让开头就能看出解决什么任务；适用条件、细分模式和排除随后说明。核对宿主实际返回的目录，分别记录说明缺失、缩短和正文未读取，不以文件或界面完整代替模型已收到，也不为单次截断设固定字数。

新增脚本须解决已确认的确定性重复动作，写清输入、依赖、错误和副作用；先复用可用工具。工具执行可靠步骤，Agent 仍负责目标、判断和语义，不能用通用路由器替代这些工作。

依据[验证与演进](references/replay.md)验证选择、执行、资源闭包、返回及必要负例。未通过的候选保留回退点，不覆盖可用基线；改名、移动或退出旧入口须同步本次获授权的消费者。安装与宿主发现按实际回执报告。

## 完成与返回

- **完成**：约定的规划或可用技能包已交付，职责、输入输出、权限与结束一致；必要资源和消费者已同步，已验证与未覆盖范围清楚。
- **返回**：原请求仍有已授权工作时，带着当前产物、证据与剩余项继续；只需技能规划或编写时可结束。不自动追加业务实现或发布。
- **恢复**：来源不明、目标冲突或验证失败时保留可用基线，说明阻塞和最小下一动作，继续不受阻部分。

本次出现融合外部方法、核一手出处与适用条件时，读[外部取证与证据交接](references/shared/external-research.md)并在本职责原权限与完成边界内采用。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。

库级清单与旧能力去向需对账时，读[当前库投影合同](references/shared/library-view.md)，运行[投影组件](scripts/library_view.py)；用真实维护清单生成当前状态，历史规划与待实现／待验证分开。组件不安装或自动路由。

旧名需要查当前职责或维护其消费者时，按[旧引用与当前职责](references/shared/skill-entry-resolution.md)查询包内声明；入口／旧处置变化后从真实维护源重新生成声明索引并校核。技能归属、宿主存在与原任务权限分别判断，不恢复旧活动身份或自动改业务项目。

按[工作记录](references/shared/work-records.md)主动保存范围、现有决定及理由、候选与验证边界。已验证决定默认延续；前提变化或反证才复审，不以数量、字数或外部流行结构为改动理由。每项实质变更说明原依据、新证据、保全条件和回归方式；当前产物通过、首次采用、反馈后修正和可扩大使用分别判断。
