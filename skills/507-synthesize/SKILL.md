# 归纳研判

当一组材料可能指向不同的处理动作时，形成能供原任务采用的判断。可以独立交付一次研判，也可为已有工作提供中间结果。

共有依赖从[共有资源合同](../../lib/README.md)开始。首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同，参数取当前实际读取的 `SKILL.md` 路径。后续引用按合同解析，已完整读取且未变化的合同直接复用。

## 输入与权限

承接当前要决定的问题、已确认的目标和约束、获准读取的记录及其来源标记。沿用已核对的材料身份、独立性和支持范围。身份或范围有实质缺口时，可用 `507-material` 核对涉及的原件，或直接核对获准读取的依据。主要目的是解释现象或机制时，由 `507-why` 持有解释结果。相邻技能按需采用。

一次性研判在会话交付。持续任务按原授权在已有接续位置保存必要判断、出处和待查项，明确只读时在会话返回。实际修改、更新工单状态、分派或对外承诺沿原任务授权处理。

## 形成判断与处理顺序

1. 明确现在要决定什么，以及谁将使用结果。先区分反馈原话、报告者及适用环境、独立核实的现象、已确认要求、原因假设和未知。对会改变决定的来源、版本或支持范围补做窄范围核对。将同源转述合并计证，保留不同对象或条件下的反例。需要核关键主张时读[事实与证据](../../lib/methods/evidence.md)。
2. 选取可能产生不同动作的分组依据，例如已确认要求与实测偏差、受影响场景、绕行条件或依赖的协商决定。存在有意义的替代分组时，用同一批关键材料比较两种分法会改变哪些动作、顺序或决策归属。结合反例检查组界，将跨组项或证据不足项标明，避免强行归入。同一类问题可以拆成不同处理路径，处理方式相同的主题可以归并。只有一种分法有实际差异时，直接说明理由。需要检验竞争解释或分组时读[候选与反证](../../lib/methods/alternatives.md)。
3. 给出各组判断、推荐动作与次序，逐组关联可定位的材料、关键反例和成立条件。可据有效要求和已证实的偏差列出修复候选，原因仍未知时列出区分假设所需的观察。尚需确定目标行为或交付责任的事项交由相应负责人协商。按当前决策需要的影响范围、紧迫性、绕行成本、证据和依赖安排先后。同源重复只算一个来源，证据不足但后果严重的事项可优先调查。说明哪些可以推进，哪些有前置条件，并标明建议与已确认决定的归属。
4. 对足以改变分组、判断或优先级的未知，给出最小待查证据、取得方式和结果会改变的动作。已授权且现在就能取得的决定性证据先查。仍无法区分时交付成立部分及有条件的建议。保存、前后结论冲突或返回原任务需要对账时，读[权威与返回](../../lib/methods/authority-and-return.md)。

## 完成与返回

- **完成信号**　分组能够解释具体处置差异，关键判断可回到原始记录或已核实的观察，优先级有理由，待查证据指向具体的下一项决定。核对条目与汇总对材料身份、复现事实、根因假设及决定状态的表述一致。
- **产物**　交付当前问题、采用的分组及其处置差异、按优先级排列的判断和建议动作、可回查依据及待查证据。同一动作所需信息放在一起，条目少时用短段或清单。
- **候选出口**　将结果交回原任务，说明哪些安排可以推进、哪些要先调查或协商。原任务据已有授权继续修复、验证、制定方案或准备沟通。仅请求研判时交付后结束。
- **回退条件**　材料身份不清、基线有冲突或证据无法区分时，保留已成立的窄结论，将受影响的判断退回待查或有条件建议。若新证据改变处理方式，重算受影响组和顺序。
