# 任务拆解与情境协调

作为次要技能，承接已有目标下的协作工作，对所接范围的组合结果负责，完成后返回原目标；执行者对指定结果负责。工程、创作、研究或工作入口都可按需采用，不要求先经过507-work。拆分以可独立完成的工作为单位；一件简单工作可直接完成，不要求工单、任务网页、PR（拉取请求）或固定流程。

共有依赖从[共有资源合同](../../lib/README.md)开始：首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同，参数取当前实际读取的 SKILL.md 路径；其余引用统一按合同解析，已完整读取且未变化的合同直接复用。 持有多阶段原任务时，局部动作完成后按[阶段返回](../../lib/README.md#阶段返回)核对指定交接并继续。

## 先确定本次结果与情境

承接已有目标、指定版本、稿件／资料、过程记录、执行位置、授权和验收。已有计划充分时直接使用；只要求计划则交付必要工作及依赖，不自动启动 Agent、通知他人或修改业务产物。明确授权推进协作时接收、组合并验证结果，不能派发后把父目标当完成。

接续旧安排或新报告改变条件时，按[权威与返回](../../lib/methods/evidence-and-decisions/authority-and-return.md)分别承接已有授权与当前依赖。依赖未满足只阻塞依赖它的执行，授权内可独立完成的准备继续；不把旧条件当现状，也不把待执行写成无授权。决定这些判断的原资料截断时补读相关部分。

交接点名旧技能且当前去向不清时，读[旧引用与当前职责](../../lib/methods/collaboration/skill-entry-resolution.md)，用包内索引查必要职责并保留原目标、许可及返回位置。多个消费者是候选，不要求全部调用；历史交接不授予写入或消息权限，未授权的项目／自动化引用只交回差距。

有实际独立产物、明确读写范围与可检查结果才拆分。安排分工、依赖推进或持续协调前，读[按情境拆解与协调](../../lib/methods/collaboration/task-coordination.md)，据实际收益选择局部协作、任务图或持续协调，并应用其中的任务信息、跨领域所有权与接收方法；不把每个动作变成任务。一个执行者顺序完成更合适时直接继续。任务图只表示依赖；页面标为 ready（依赖允许继续）不会授予写入、派发或领取权限。

## 工作、依赖与所有权

按已读协调方法，把本次委托的目标、必要输入、读写范围、预期产物、适用方法及必要读取入口和接收依据交清；已有过程记录中能引用的信息不重复建表。

同一工作树仅一人写入；同仓库并行改代码时使用独立工作树／checkout（检出副本），核对基准及已有改动。写作可在不同稿件或隔离候选中并行，由一个明确整合者维护主稿；共享材料、生成产物及外部平台也需明确写者。串行任务不强制隔离目录、工作树或远端 PR。

采用宿主允许的协作工具与当前权限。对其他用户会话、邮件或协作平台发送消息仍需具体授权。缺少协作工具时可按同边界顺序执行，不承诺后台常驻、自动通知或自动取得外部任务。

## 接收、刷新依赖与组合验证

收到结果按交付用途核对实际产物、所读版本、必要方法的落实、证据覆盖和未覆盖，不仅听取完成自报或技能读取记录。依赖已被满足且当前授权覆盖的工作可继续；部分失败只阻塞受影响项，保留有效产物及失败依据。依赖、目标或代价改变时可以合并工作、重拆或退回单人直接完成，不为维持任务图保留空任务。

唯一整合者消费通过必要检查的候选，保留各方合理改动。工程集成回到目标完整行为；写作组合核作者主线、声音、来源与当前主稿；研究和一般工作核原问题与实际结果。子任务各自通过不代替组合结果成立；作者主张和实质目标取舍返回相应负责人。独立审查由另一执行者完成，再修改后核受影响范围。

## 用既有记录生成临时任务网页

需要共同查看任务、依赖、进度或阻塞时，用[任务视图脚本](../../lib/components/tools/projections/task_view.py)按[使用说明](../../lib/components/tools/projections/task-view.md)校验已有记录。新建页面按[任务页方法](../../lib/methods/design/task-page.md)围绕分工、等待条件和交回物组织。沿用原记录维护状态，已有生成页从原入口重生成。

视图生成失败保留上一版并指出它依据的旧记录；不把旧页面当当前状态。无需网页时直接用现有记录、文字或关系图，不为工具创建额外流程。

## 条件性方法

| 条件 | 读取与用途 |
| --- | --- |
| 跨位置、版本或执行者报告的身份不清 | [事实与来源](../../lib/methods/evidence-and-decisions/evidence.md)：核对原版、实际产物和覆盖 |
| 子任务权限、责任或实质取舍有歧义 | [决定归属](../../lib/methods/evidence-and-decisions/decision-ownership.md)：确定当前允许动作 |
| 多种拆分／隔离方案真实有代价差异 | [候选与反证](../../lib/methods/evidence-and-decisions/alternatives.md)：比较协作收益与组合成本 |
| 定义接收信号或验证组合结果 | [可观察验收](../../lib/methods/evidence-and-decisions/validation.md)：验证父目标而非仅子步骤 |
| 子任务完成、部分失败或真实转交 | [权威与返回](../../lib/methods/evidence-and-decisions/authority-and-return.md)：继续父目标并保留未完成依赖 |
| 对象、依赖或状态关系难以读清 | [清晰表达](../../lib/methods/writing/clear-expression.md)：解释真实关系，图失败退回文字／表格 |

## 完成与返回

计划请求以可继续的工作、依赖及执行边界结束；实施协调以原范围内的组合结果、整体检查及必要独立审查状态完成。交付已达成、剩余、阻塞、实际位置与证据。任务没有依赖阻塞不表示它已派发、完成或被接受；提交、平台写入、发布及人的接受各自按具体授权成立。

关键变化按已读协调方法回到已有过程记录，不建立另一个长期事实源。没有清楚写入所有权、隔离或接收条件时暂停受影响并行写入，可改串行继续。原目标尚有授权工作时带结果返回并继续。

本次出现工作关系需要固定任务视图之外的理解载体时，读[对象关系、比较与观察](../../lib/methods/design/visual-understanding.md)并在本职责原权限与完成边界内采用。

只有真实中断、上下文压缩、跨会话接手或转交时，先读[真实中断、交接与续办](../../lib/methods/collaboration/continuation.md)，对准最近有效的人类请求与本轮派发，再核实际版本、写权和剩余；普通返回或完成跳过该方法。

## 三组分工与验收安排

技能层次、会话位置和 A/B/C 验收职责分别判断。主要技能可被执行会话采用，主会话也可采用次要能力；不是一项技能一个 Agent。需要独立计划结果时采用 507-plan；spec 支持验收定义，本能力负责实际分工与接收，不能用计划或规格代替验收。

采用既定三层协作时，主会话保持目标并可直接核查执行与产物，任务和返工统一交协调会话安排，不越层追加指令；协调会话维护依赖、写权、公共记录和独立检查；执行会话可承担制作、调查或独立验收。既有规则能解决的问题自行处理，向用户知情汇报不等于请求介入。

A 可复用主会话或协调会话；B 按任务采用 do、create、adapt、skill-design、spec 等现有能力，不新增通用执行包装；C 由未参与受审范围实施的执行者采用 507-review 和相称领域方法。B 自查不代替 C，C 参与修复后另安排独立者复核；产物版本改变时复核相关内容。缺少独立执行条件则保持待验收，不以同一执行者换技能或换模型冒称独立。简单任务不强制三层会话或固定人数。

持续协调按[工作记录](../../lib/methods/collaboration/work-records.md)主动保存分工、依赖、写权、接收及未完成整合，公共正文由指定整合者单一写入。
