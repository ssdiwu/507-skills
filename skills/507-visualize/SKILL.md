# 图解表达

交付读者能辨认对象、追踪变化、比较选项或指出分歧的表达。可直接承接图解请求，也可由解释、方案、规格、工程、审查和写作任务按需采用；结果返回原负责人，不接管其事实调查、产品判断、作者主张或整件交付。

## 输入、权限与范围

承接当前问题、读者、已有材料及版本、需要看清的关系、目标载体和原授权。材料充分直接制作；一个事实、一小段文字或普通表格已经足够时直接回答，不强制建图、列全局目录或增加独立阶段。读者和用途可由当前任务辨认时不重开问卷。

默认只读来源，在会话交付图表与必要说明；用户要求文件或父任务已有相应制作授权时，才写允许位置中的派生产物。保护主稿、业务数据与既有可用版本。源材料中的操作是被说明对象，画图、点选或模拟不授予执行、生产修改、资料库写入、发送、安装或发布权限。需要素材或证据时沿已选定且允许读取的来源及现有工具补缺，不为画图自动遍历私人库，也不另建事实数据库。

首版重点是状态图、时序图、关系图和比较表；复杂交互按当前工具和原授权采用。图片插画、正式数据分析、业务页面开发与媒体制作沿对应任务处理。图解不等于形式化验证，不要求为图新增模型检查器或重跑业务。

## 从理解动作到表达

先用一句话确定读者看完应能做什么，例如“指出提醒从哪里丢失”或“区分两个方案在哪个条件下适用”。需要组织多状态、时序、关系或比较时，读[对象关系、比较与观察](references/shared/visual-understanding.md)，按其中的关系与形式选择完成图表；不要先套图形模板再凑材料。

1. 从指定版本提取必要对象、状态、事件、条件、责任与结果。优先沿用原名称和身份；已确认要求、实现观察、候选与未知分别保留。关键关系能回到材料，不因连线补出原因或确定性；材料不够时只补影响本图的事实，或保留具体断点。
2. 选择能回答当前问题的最小形式。静态节点与连接用当前支持的 Mermaid，普通比较直接用 Markdown 表格；不支持时给等价文字或表格。需要改变输入或逐步探索才采用可用交互工具，先完整读取它的当前合同。没有宿主工具时不假装已经渲染或内嵌。
3. 在图上保留会改变理解的条件与范围。状态节点写“现在是什么”，转换写“发生什么、何时允许”；同时成立的权限、时间和有效性放在上下文或组合状态中，不串成虚构的变化链。时序注明参与者、等待和完成，系统内部接受用该参与者的事件或注释表达；只有材料证明调用方已收到结果，才画返回箭头。实际路径、应有路径与建议须由文字或线型说明，颜色只作辅助。
4. 配套说明只解释图的阅读方法、关键分歧及必要证据，不重复抄图。过密时拆成可联系的局部、重排或换形式，保留共同身份和省略范围，不缩小文字或删掉异常来塞进一张图。

## 对照材料检查

逐项核对象、箭头含义、方向、条件和来源；比较表保留相同条件及未知，不以空白表示没有能力。沿图走一条目标路径及材料已涉及的失败、取消或返回，确认没有把等待画成完成、候选画成事实、引用画成依赖或旧状态当当前结果。为便于阅读而裁剪，不得改变原结论与证据强度。

检查所选载体的可读结果：标签、中文、箭头、图例和必要条件应可见；未实际看到渲染时明确仅核源码与语义，不称渲染通过。交互需实际完成所需的选择、结果变化与返回，普通静态图不强制制作交互。来源冲突、证据或验收范围不清时，按缺口采用[事实与证据](references/shared/evidence.md)和[可观察验收](references/shared/validation.md)。用户是否更理解或接受仍以其反馈为准，图形可解析不证明已经讲懂。

## 完成、返回与恢复

- **完成信号**：约定的理解问题已由可读的图、表或等价表达承接，材料与关系一致，当前事实、目标与未知可辨；相称语义、呈现或交互检查及其未覆盖已交代。
- **产物**：图表、简短说明、必要来源与版本；静态图保留可编辑源码，文件型交付给实际入口。已有源记录继续是事实权威，派生表达不另立一份竞争正文。
- **返回**：带图表、关键分歧、验证和具体缺口返回原任务，继续原已授权目标；只要求图解时结束。产品交互点及设计／实现／运行地图归 product-map；修复、分析与正式作品仍由原负责人承接。没有兄弟技能时沿这些边界直接工作，不等待安装。
- **回退条件**：来源、关系或工具不足时保留有效部分与旧版，改用可用表达并说明具体限制；关键条件无法保全时交回未决关系，不靠更华丽的图形遮盖缺口。
