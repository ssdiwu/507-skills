# 项目初识与代表路径

用于用户刚接触一个项目、还不知道该问什么，需要先建立整体认识的情境。只服务 why 的整体理解职责；取证、关系表达和必要观察复用现有共有方法，不新增总控或强制调查链。具体术语、明确故障或已成立实施任务不展开本情境。

## 自主调查，先建立可辨认的全貌

先确认当前对象与版本，从实际工作位置、项目规则、介绍和资料导航找到现行依据，再追实现与已有验证。用户已给路径或当前项目明确时直接开始；材料不存在与用户意图不清是不同缺口。请求了解项目默认只读，不因“新项目”安装依赖、初始化、执行来源脚本、修改业务文档或调用外部写入。

下列维度是观察方向，不是必填问卷或固定章节。按项目类型、读者背景和已有材料选择重点；关键维度没有依据时说明未知及其影响，不能用猜测补齐。

| 认识方向 | 需要核对的对象与关系 |
| --- | --- |
| 定位与用途 | 为谁解决什么问题、核心场景与已有价值依据；介绍中的愿景与当前事实分开 |
| 角色与关键对象 | 谁使用、接入、维护或协作，关键业务对象与词义是什么，哪些状态影响行动 |
| 功能或工作路径 | 从真实入口做什么、经过哪些条件到什么结果，失败、返回或接续在哪里 |
| 内部职责与依赖 | 谁持有状态、数据或工作结果，主要部分怎样协作，外部系统和公开接口在哪里 |
| 当前实际情况 | 现行要求、已实现内容、历史运行、当前实测、未完成和未观察分别有何证据 |
| 关键选择与约束 | 现有条件、成本或限制，以及有原记录支持的设计理由；不从现行代码猜历史动机 |
| 后续入口 | 继续理解、参与或核实应从哪里进入；给阅读入口和必要补证，不自动列重构执行计划 |

软件产品可从角色与操作进入；库或后端围绕调用者、接口、输入输出、持久化与失败展开；活动、研究和创作项目围绕参与者、材料、协作过程及成果展开。不要把所有项目转换为页面目录或界面地图。

## 用代表路径校准概览

选择能说明核心价值和主要职责的一条或少量代表路径，从实际入口追到结果与必要返回。已有充分证据可直接采用；某个关键关系不明才扩读相连资料或实现，不为完整感扫描全库。先建立全貌再深入是阅读组织方式，不要求每次全量重复。

沿选定路径依相连依据调查，不用全库搜索结果或中间处理器代替接线：

1. 找到用户或调用者实际发起动作的位置，读调用的输入和当前上下文。类型定义、控件名称及引用搜索只定位候选；尚未读调用正文时不能称入口已核。
2. 读接收动作的处理与结果分支，分别辨认成功、条件阻断和会影响理解的失败。一个处理器服务多个动作时，先比较各分支；共享字段校验不证明后续权限、额度、保存或返回相同。先返回的分支不会自动经过后面的检查。
3. 继续读结果的直接调用者和最后消费者：谁更新状态、显示结果、保存或导出，成功、取消或关键失败后原现场保留还是退出。只读处理器前段、看到回调名或测试名时，按缺口继续读取调用正文与结果处理，不用目录职责猜结果。
4. 将实际读到的入口、条件、结果与返回连成一段可理解的具体路径；关系复杂可用表格或图，保留每项条件适用的动作。只有逐分支都有依据时才写共同规则；没读到的连接明确断点，不能靠“通常”补全。

声明、接线和运行仍分开。遇到持久化或外部服务，明确哪一段只读了实现、哪一段有历史观察；正确讲出代码路径不表示当前产品已经运行通过。上述读取止于代表路径足以解释，不展开所有功能的完整审计。

项目规模大时先交付足以定位和继续探索的概览及这条代表路径，明确省略范围。资料不足则交付有依据的部分认识和路径断点；不把深入每个模块或审查所有功能作为结束门槛。

## 组织成读者可用的认识

从具体用途和场景开始，说明必要对象，再连接操作或工作路径与内部职责；陌生术语及时解释，用户无需先掌握实现细节。并列比较可用表格，关系复杂可用示意；只有点选、筛选或实际观察能帮助理解时才制作交互载体，沿原授权和已有组件处理。

需要功能交互地图时，委托或采用可用的 product-map，仅处理指定功能范围；其结果不替代项目定位、数据职责或历史理由。需要保存说明时沿实际授权写交付位置，不擅自创建竞争的项目权威、进度或规格。

交付时区分依据支持的认识、关键未知和未读范围。历史证据注明版本和条件；当前源码与旧证据不一致时保留差异，不把旧通过迁到新版本。没有实际运行就明确本轮未运行；未见完成记录不等于功能未完成。

完成于本次理解目标已有必要全貌、代表关系可追溯、边界与后续入口清楚。无读者反馈，只能说说明已交付和依据已核对，不能声称对方已经理解。后续请求可沿同一项目认识继续深入；出现真实修改目标时带有效结论回到对应工作，不能因调查发现自动扩权。
