# 工程实现、修复与验证

作为主要工程入口，承接用户的实现、修复、局部修改、测试和产品界面组件请求，负责约定范围的结果、验证及返回。用户主要通过本入口表达目标，Agent 也可按需采用；内部方法选择由 Agent 完成。已有需求、方案、指定版本与操作授权直接沿用，规格、规划、工单和协作只补当前真实缺口，不重新走完整准备流程。

共有依赖从[共有资源合同](../../lib/README.md)开始：首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同，参数取当前实际读取的 SKILL.md 路径；其余引用统一按合同解析，已完整读取且未变化的合同直接复用。 持有多阶段原任务时，局部动作完成后按[阶段返回](../../lib/README.md#阶段返回)核对指定交接并继续。

## 当前请求与操作范围

核对原任务、有效要求、用户改动、基准和项目必要检查，记录自己可写的范围。先读取实际入口与存量能力，优先复用已有接口、框架和依赖。

实现依赖尚未澄清或需要修订的领域概念、边界或关系时，可采用 `507-domain-model` 形成必要依据，再沿原实现目标继续。有效词义与要求已充分时直接实施，不因代码涉及业务名词重开建模；仅有命名建议不授权改变已有数据或公开契约。

先核已读取计划或项目记录是否规定结果回写：有明确记录要求时，即使单阶段小修复，也将实际结果和必要验证状态写回该记录或其指定位置并读回，聊天中的“结果记录”不替代实际写入。分阶段、跨轮或有人接手的工作，另定位当前阶段和下一步，在阶段结束前保存实际完成、原动作复验与未覆盖、下一阶段状态。需求未变化只表示不必改行为规格，不能据此省略进度和证据；不把实现细节强塞进 PRODUCT 等要求正文。记录归处不清时按[工作记录](../../lib/methods/collaboration/work-records.md)选择最小既有位置，明确不写文件的限制优先。

多轮确认或完整交付含相连模块时，按[权威与返回](../../lib/methods/evidence-and-decisions/authority-and-return.md)确定本次有效目标，再依[可观察验收](../../lib/methods/evidence-and-decisions/validation.md)对账实际产物。完整目标不得自行缩为独立演示；沿用户主路径核共同状态、跨模块操作和返回，局部按钮可用不能代替整体完成。只要求局部修改时保持该范围。

目标要求完整首次使用时，按[工程证据](../../lib/methods/engineering/engineering-evidence.md)核实际起点和夹具代做的前提；预置状态不证明用户已完成同一配置、绑定或确认。已验后段保持其范围，未覆盖的目标动作仍待闭合；只要求SDK或已准备中段时沿原范围执行，不强制增加首次使用全流程。

| 请求范围 | 可修改与停止位置 |
| --- | --- |
| 新增功能或改变已确认行为 | 直接实现已有需求与方案，修改范围内代码、必要行为测试及直接相关说明，完成约定用户路径 |
| 恢复既定行为、修 bug 或合并冲突 | 进入下节修复模式；保留失败信号、根因、最小修复及原动作复验，不借修复改变目标 |
| 指定位置的局部修改 | 沿指定版本直接处理，修改范围保持局部；属于故障仍走完整修复步骤，属于新行为或行为不变调整分别采用对应做法 |
| 明确保持公开行为的内部简化 | 首次修改前读[行为不变修改证据门](../../lib/methods/engineering/behavior-preserving-change.md)，建立相称的改前基线和可重复验证信号。再逐项修改并复验、有据关闭或转回需求变化 |
| 补测、修测试或维护测试环境 | 仅相应测试资产及必要测试环境；生产故障只定位并返回修复需求 |
| 只跑测试或只读诊断 | 运行约定检查并分类报告；不修改生产代码、测试断言或持久配置，失败不自动转为修复；必要运行产物沿原测试约定处理 |
| 只查产品界面组件 | 只交真实库、组件位置、适用性和未知；不修改组件、调用处、依赖或库配置，不自动转为接入或抽取 |
| 明确 TDD（测试驱动开发）并实施行为 | 测试及最小生产实现，逐个完整行为保留红绿证据 |
| 只先写测试，禁止实现 | 完成有效失败测试后停止，不进入生产实现 |

已有规格足够时直接实施；项目要求规格先行且行为变化时，先在同一授权内补受影响的现行条目，不机械新建 PRD。只有用户目标、成本或风险发生实质改变时才返回该取舍。局部范围内的故障也须保留修复步骤；必要检查可以覆盖相邻路径，修改范围仍保持原约定。只跑测试发现的故障只报告，不因本入口兼具实现能力取得修改权。

## 修复模式：复现、根因与原动作复验

当前目标是恢复既定行为或处理合并冲突时，修改前读[修复方法](references/debugging.md)，保留原输入、版本、准备条件和观察位置。主文的四项要求始终适用于修复，详细方法只在该模式采用：

1. 先取得可信失败信号。复用已有失败测试、请求、命令或原操作证据；没有确定信号时补观测并缩小范围。原故障版本不可得时说明限制，不破坏当前可用版来制造失败。
2. 定位最早偏离的输入、状态、转换或时序，分清生产故障、规格变化、过时测试及依赖／环境问题。环境或测试准备失败不冒充目标行为失败。
3. 按有证据的根因做最小修复，保护无关行为与存量数据；不删断言、放宽预期、伪造返回或静默失败来求通过。
4. 修复后用同一输入、关键准备条件、原动作和观察复验，再检查实际受影响路径。涉及共享状态或生命周期时，核已有及之后新建消费者；保留首次失败与后续修复的区别。

新增功能不需要先制造旧故障，普通实施不强制测试先行。只要求诊断时止于证据和原因；发现实质需求变化或额外操作需求时处理具体取舍，仍有效的原目标与授权继续承接。

## 完成原目标路径

开发或修改前端页面前，先锁定单屏唯一主焦点和可见区块上限。写明用户在此屏首先要看见或完成什么，哪些次要操作可以收进详情。同一页面由一人整合布局，按目标窗口尺寸打开成品，核对最醒目的内容和实际区块数。

项目需要反复复验同一路径时，先找已有脚本或操作说明，在授权范围内补足新会话从启动、确认就绪、执行用户动作到观察结果和副作用的最短步骤。用这套步骤实际复验。不能仅凭成功提示、文件存在或构建通过宣称用户路径已经验证。受阻时说明观察到哪一步。一次性小改沿实际入口做相称检查即可。

以调用者可观察的垂直切片推进，选择已有公开 API（接口）、CLI（命令行）或页面验证入口。明确写入所有者、接口和失败恢复，只在状态／异步变化影响结果时展开相连路径；不增加第二条权威写入路径或临时双轨来凑结果。

改动触及状态写入、数据或权限、模块依赖、异步顺序时，沿本次调用路径找出以后仍须成立的具体条件。不同来源或不同结果写入同一状态时，修改前对照实际返回构造处、保存模型与读方，列出受影响的字段及各来源的更新权。区分未返回、明确清空与迟到。部分失败只提供诊断时，保留上次有效结果中的业务字段，同时更新失败状态。核对界面之外的消费者，例如依赖归档标志、版本号或权限标记的后续操作。

在授权范围内，选能覆盖该风险的最小持久约束。优先复用项目已有的写入入口、状态类型或公开接口来限制错误用法。模块依赖和非法状态等可准确表达的规则，可接入已有静态检查。依赖事件顺序、持久化或运行环境的条件，从实际入口验证。针对部分失败的合并，用一个包含应保留字段的完整状态作为起点，经失败响应再到成功恢复，断言合并结果中的字段及正常更新，能够抓住界面恢复但底层数据丢失的情况。复用现有检查入口，已有保护足够时直接沿用，普通局部调整按原范围检查。

测试资产、测试先行、失败分类或复测判定需要展开时，读[测试方法](references/testing.md)，完成授权内必要取证并按有效要求给出具体判定。不默认将普通实施改成 TDD；不写仅镜像内部实现的无效测试。验证覆盖原目标的实际输入、操作、输出及必要边界；自动测试不足的视觉、语义或真实外部能力保持未覆盖状态。

按项目要求运行必要检查，通过后只有新变化、失败或具体疑点才扩大。有关架构检查区分新增问题、已有违规、例外与未覆盖，不刷新基线制造通过。同步实际受影响的规格与入口，维护持续任务的阶段记录，保护无关改动；没有规格变化不免除后者。

需要可复验的命令日志或前后源码指纹时，先核命令、运行位置、复制/探针/缓存、日志和清理的副作用都在当前可写范围及数据归属内。包内 check_run 会写回执和日志，并执行给定命令；示例不授权临时目录或清理已有数据。参数形状如下，不能原样执行：

```sh
python3 <共有库>/components/tools/checks/check_run.py --argv-json '<已核实命令的参数数组>' --cwd '<允许执行的位置>' --log-dir '<获准写入范围内尚不存在的新目录>' --timeout 60 --source '<执行位置内的源文件>'
```

argv（参数数组）不通过 shell 拼接。日志目录须本次唯一且尚不存在；已存在时保全它并另选允许的新位置，不先删目录来重跑。退出 0 只表示该命令成功，1 表示命令失败，2 表示输入或运行准备错误；业务判定仍依据断言与日志。组件不自动运行全套检查，超时与未运行如实保留。

## 按需采用

| 条件 | 读取与用途 |
| --- | --- |
| 指定版本、未提交改动或旧报告影响基准 | [事实与来源](../../lib/methods/evidence-and-decisions/evidence.md)：确认实际原版与执行覆盖 |
| 需要区分例行工程选择与实质目标取舍 | [决定归属](../../lib/methods/evidence-and-decisions/decision-ownership.md)：在现有授权内收口 |
| 关键断言、原动作或运行状态证据 | [工程证据](../../lib/methods/engineering/engineering-evidence.md)：核验红绿、最终消费者和源码指纹 |
| 验证计划、代表性错误或扩大测试范围 | [可观察验收](../../lib/methods/evidence-and-decisions/validation.md)：选择相称检查并保留边界 |
| 规格修订、内部工作已完成或父目标仍未完成 | [权威与返回](../../lib/methods/evidence-and-decisions/authority-and-return.md)：保全条件并继续原目标 |
| 用户点名呈现参考，或视觉／交互方向有会改变做法的缺口 | [视觉方向与真实反馈](../../lib/methods/design/visual-direction.md)：按需查已授权来源、优先复用并把选择落实到产品；已有设计与普通局部修改直接继续 |

存在可独立结果且并行收益成立时才采用 coordinate；串行可直接完成。行为、数据、权限或公开契约变化完成后由另一执行者独立 review；实施者自查不替代独立审查。提交、推送、PR（拉取请求）写入与发布按具体授权另立结果。

制作或修改产品界面时，按[组件查找、复用与抽取](references/component-reuse.md)核对项目已有组件。有合适实现时直接复用。新界面按当前内容、参考、交互和项目技术选择实现。已有离线 React 场景可沿[共有导出器](../../lib/components/visual/scripts/render-artifact.mjs)维护。只要求查找时交回位置、适用性和未知。仅在目标项目有多个真实或已确认的使用位置时抽取组件，并迁移范围内的调用。产品操作、状态、反馈及完整路径按本职责验证。

工程交付还需介绍页中的界面展示图或模拟操作短动画时，可采用 `507-ui-demo` 并将场景接回当前页面。真实表单、交互及业务结果仍由本任务实现和验证，不用展示组件替代；普通功能开发不因出现界面或动画而转入演示制作，技能不可用时沿当前工程工具继续。

结果包含多个状态或异步交叠、读者难以看清故障位置时，可采用 `507-visual-explain` 把已取得的事件顺序、异常与应有行为图解后返回本任务。图只表达证据，不代替原动作复验或授权新修复；简短结果直接说明。

## 完成与返回

有代码改动时，提交前逐段读回本次 Diff（代码差异），删除缺乏可达输入的防御性死分支、用户未请求且没有调用价值的包装、只复述代码的注释。保留有实际失败输入、兼容契约或数据保护依据的处理。整理后复验受影响路径，不处理他人的无关改动。

本次验证发现可复用的运行步骤时，按[工程证据](../../lib/methods/engineering/engineering-evidence.md#项目验活步骤)在项目现有运行说明或测试入口记录前提、动作、成功信号与恢复办法。报告性能数字时核同条件基线、冷热缓存、波动和理论上界。

范围内行为已实现并回到原目标完整路径，必要检查与独立审查状态准确，直接相关说明已同步。既有计划/记录明确要求保存结果，或任务具有阶段/持续接续需要时，还须在实际计划/过程记录保存并读回：当前产物位置/版本、本阶段完成、原动作复验及未覆盖、未完成或下一步；没有规格变化不能跳过这项完成条件，明确不写文件则在会话交付。无明确记录要求且没有接续需要的微小任务可只交会话结果，不另建日志。交付实际文件、证据、未覆盖和剩余项。只查组件时以可定位的发现、适用性和未知完成；只要求测试时以该范围完成，均不宣称生产实现或用户接受。

检查失败时保留原信号和可用基线，定位失败类型后按本次范围处理：已授权实现或修复时继续修相关部分；仅测试维护时只处理已授权的测试资产和测试环境；只跑测试或只读诊断时报告结果，不自动转为修改。不删断言、放宽预期、静默失败或替换基线来伪造通过。需要新增操作授权或实质产品取舍的部分停在具体缺口，独立部分继续。

中断续办、换会话、上下文压缩或转交时，按原授权读[续办方法](../../lib/methods/collaboration/continuation.md)。普通结束跳过。

本次出现实现产品操作、异步状态与失败恢复时，读[操作、状态与实际呈现](../../lib/methods/engineering/interaction.md)并在本职责原权限与完成边界内采用。

B 可补自查；最终验收依据有误时提交原目标与错误证据，经相应职责修正及独立复核，不能自行放宽要求求绿。修复当前缺陷与防复发措施有效分别判断，内部步骤通过后继续原目标。
