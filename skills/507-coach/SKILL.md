# 判断陪练

每轮选一个用户想练的判断，例如「现有证据足以支持多强的承诺」。优先使用用户给的材料和已有回答。目标清楚但缺少材料时，可以给一个短的虚构情境，标明哪些信息是题设。陪练默认在对话中进行，题中的决定和修改只用于练习。

共有依赖从[共有资源合同](../../lib/README.md)开始。首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同。参数取当前实际读取的 `SKILL.md` 路径。 持有多阶段原任务时，局部动作完成后按[阶段返回](../../lib/README.md#阶段返回)核对指定交接并继续。

## 一轮怎么练

1. **先让用户作判断。** 给出角色、要做的决定，以及足以比较选项的事实。问「你会怎么选？哪条事实最影响你的决定？」然后等待回答，作答后再用示范、提示和评判依据。用户已有判断和理由，直接从反馈开始。只有结论时只问依据。用户要求直接解答或改写时，按其指定范围交付，练习停在当前进度。改稿时若用户要理由，说明具体修改怎样帮助目标读者理解或决定。
2. **沿着用户的理由反馈。** 先复述用户实际给出的选择和理由，随后指出哪条证据支持哪部分。补充理由或新判断时，明确说明是陪练反馈。挑出一个会影响决定的假设，给出能检验它的反例或待观察事实。如果另一种选择也说得通，讲清它成立的条件。让用户有机会保留或修正原判断并解释原因。用户卡住时，只提示一个值得比较的事实，记清哪一步用了提示。
3. **换条件，再让用户决定。** 保留所练的判断，换一个用户没答过的案例，让关键证据、决定用途或出错代价发生足以影响选择的变化。只给新题和所需事实，等用户独立给出选择和理由，再看理由是否抓住了改变的条件。结论可以相同。若已经给过解法或关键提示，把这次记为在帮助下作答；要观察独立运用，另换新题。

## 范例：方案里的哪句话值得留

以下为虚构练习，按轮次逐段取用。用户有自己的题目时沿用原题。

- **给用户的首题**　负责人要决定是否试行新的工单分流流程。提案写着「预计每单可省两分钟。目前只计时了白班的 12 单。本组已尽力考虑各种情况。」你会怎样写给负责人？哪些信息影响了你的写法？
- **作答后才用的反馈示例**　如果用户为了简短删掉后两句，先说明他在取舍篇幅。再给反馈：「白班样本限定了估计的适用范围。如果夜班也想用它安排人手，还缺哪条依据？『已尽力考虑』这句可以删，因为它没有提供决策依据。」若用户主张把样本细节移到附件，检查正文是否仍能让负责人看出试行范围，再评价这个选择。
- **独立出示的迁移题**　另一支团队已按事先约定的标准验证全部班次，负责人也批准上线。现在给值班员写操作卡，已知断网时自动分流会停止，工单须由值班员手动分派。你会在卡片上写什么？为什么？等用户作答后，核对他依据的是值班员要采取的动作，还是照搬上题保留样本说明的做法。

## 什么时候收束

用用户的实际回答说明「这次独立识别了什么，哪一点经过提示才识别」。只有收到新题的独立判断和理由，才评价本次迁移表现。若用户暂停、只听了解法或尚未答新题，就停在相应位置，保留已观察到的结果。有原任务时，按用户已授权的目标接回。

AI 可以模拟提问、反馈和可能的回答。展示或测试这类对话时标为「AI 模拟」；只有用户本人的作答才计入本次练习结果。一次新题上的表现只支持对这道题的判断。
