# 清理存量代码与规则

承接明确范围的清理目标，减少无用路径、重复规则和维护负担，保全已有功能与数据。先交可核对的清单，再按本次已有授权实施。用户主要通过本入口表达清理目标，Agent 也可按需采用；普通功能实现、已定位故障与指定小修沿原工程任务处理。

## 锁定范围与当前权限

先核仓库、指定模块／文件、版本、用户改动、排除项及可运行的检查。对象不明时只补最小范围问题，不从“清理一下”推定全仓调查。

读取适用的 `AGENTS.md`／`CLAUDE.md`、项目入口和目标目录说明，再在指定路径内列文件、统计行数、查符号与调用。读取根规范不增加全仓读取权；检索也必须带指定路径，不能先遍历全仓再筛结果。范围外的调用、配置、生成源、嵌套项目或其他工作树只记录相关缺口，不自动跟读；需要它们才能判断时，给最小扩展范围及用途，相关项保持待核。依赖、生成副本与历史证据沿其维护源和职责处理。

| 原请求 | 本轮动作与停止位置 |
| --- | --- |
| 先看看、先列清单、只读或未明确要求实施 | 只读调查，交清单、依据、规格缺口与必要方案；不改项目文件 |
| 已明确授权清理实施，且没有只读限制 | 先展示具体清单，依据充分后连续实施，不为内部步骤重复索取许可 |
| 已有确认清单、规格或拆分方案，并要求继续实施 | 核当前版本与有效授权，直接沿原结论处理变化，不重走整轮调查 |
| 只要求清理规则文件 | 只处理指定规则与获准读取的依据，不顺带改源码或重做项目初始化 |

本模式保持已有功能，不增加功能、顺带修复产品缺陷、升级依赖或改变公开行为。提交、推送、安装与发布沿具体授权。发现必须改变行为的项时交回明确需求，其余独立清理继续。

## 先有范围内的行为规格

进入重构前，核本次范围是否已有完整、现行且可验的功能依据：入口／公开调用、角色与前提、成功和失败结果、状态与数据、权限、兼容、时序和恢复条件，以及能拒绝错误结果的验收。现有规格充分时直接沿用，不重复成文；完整性按本次模块及实际消费者判断，不扩成全项目重写。

规格缺失、过时或与实现冲突时，整理具体缺口、有效要求、当前实现依据与受阻清理项，按原授权采用 `507-spec` 的职责补齐唯一现行正文。只读请求只报告缺口，不写规格；实施授权包含必要规格维护时继续补齐，未包含时交回所需范围。技能不可用时按相同职责直接整理，不产生安装依赖。

源码和运行观察帮助核对现状；已确认要求决定应保留什么。实现缺陷不改写成新要求，未实现功能不因“代码不存在”被删出规格。关键行为仍有歧义时停止相关重构，保全原有效要求并继续明确部分。规格完成后回到原清理项，不把文档完成当重构完成。

## 先列有证据的清理项

清单逐项给位置／符号或规则、现状、消费者与规格依据、建议动作、真实收益、风险／未知、验证办法及是否可实施。没有可靠删除依据的项标为待核，收益不足的项有据关闭；没有候选时如实结束，不为凑数量改代码。

| 类型 | 必要判断 |
| --- | --- |
| 死代码或旧路径 | 核指定范围内调用、配置、注册、反射／动态加载、测试和兼容用途，以及公开／外部契约；搜不到文本调用只能证明本次检索未命中。无法排除外部消费者时保留待核 |
| 重复逻辑 | 比较输入输出、错误、状态所有权、生命周期和变化原因。优先复用现有同责实现；抽取须减少重复规则或调用者负担，不能只凭相似代码、减行数或搬文件成立 |
| 失效或重复规则 | 按下节逐条对照当前对象、有效要求和承接机制；区分过时约束、实现不合规、仍有效的防错规则与未知 |

## 超过800行先出拆分方案

统计指定范围内人工维护源文件的实际物理行数；任一单文件超过800行，本轮止于清单和拆分方案，不修改代码、测试、配置或规则文件。没有明确纳入的依赖、生成物和历史样本不充当拆分对象。

方案说明现有职责与消费者、建议边界、保留的公开入口及行为、状态／副作用所有者、迁移顺序、逐步验证和回退点。按职责与变化原因拆分，行数只触发先做方案，不按固定长度切文件。已有明确采用该方案并要求实施的后续授权时沿用，不让同一阈值永久阻断已批准的拆分。

## 把规则当作有依据的约束维护

规则清理逐条处理本次指定的 `AGENTS.md`／`CLAUDE.md`，对照允许读取范围内的实现、有效规格、入口和机制。清单记录保留、合并、删除或待核及其理由；实施时只删已证实对象退役、被可靠机制承接或纯重复的旧约束，必要引用同步退出。

每条保留规则在原位补一句“原因：……”：说清适用时防止哪种具体误判或损失，并以当前有效要求、可核实项目事实或具体风险支持。不编造历史事故，不只写“提高质量”。合并后保全条件、例外和约束强度。

代码没有对应实现不足以证明规则过时。授权、数据保护、安全、无障碍和单一写入等约束可能约束操作过程；有效功能要求也可能尚未实现。前者核现行风险及承接机制，后者记录实现差距；都不能靠删除条款制造一致。证据超出允许读取范围或原意未明时保留待核，不猜原因后删除。

## 实施、验证与返回

仅在已有实施授权、行为规格足够且未停在大文件方案阶段时，读[行为不变修改](references/shared/behavior-preserving-change.md)，逐项建立原行为基线、修改并复验，或带依据关闭。复用项目已有检查和原入口，核成功、失败、数据／兼容及受影响消费者；不通过删断言、改预期或刷新基线掩盖问题。验证失败保留信号和上一可用状态，停止受阻项，继续独立部分。

行为、数据、权限、公开接口或正式要求变化须由另一执行者独立审查；规则退役或修改有效约束也按其影响判断。实施者自查不替代独立结果，纯文字和格式且不改含义时可相称自查。只读查找清理机会不冒充对已完成变更的独立审查。

完成清单请求时交本次范围、逐项证据、待核与必要方案。完成实施请求时逐项对账实际修改、关闭或未完成，交规格差异、行为对照、必要检查、独立审查及未覆盖；清单、规格完成、代码验证和人的接受分别判断。父任务仍有已授权工作时携结果返回继续，不因内部规格或某个清理项完成提前结束。

真实中断、上下文压缩或转交时，读[真实中断、交接与续办](references/shared/continuation.md)，核实际版本、写权、有效尝试与剩余项；普通结束无需展开。

实施清理时按[工作记录](references/shared/work-records.md)维护清单处置、原理由和验证；只读清单请求仍不写项目文件。实质删除前核原决定保护什么、前提或证据怎样变化、真实消费者和替代机制是否成立；没有反证继续保留已验证决定。表达归并与行为要求变更分别审查，不因新模型、更短或更整齐而退役。
