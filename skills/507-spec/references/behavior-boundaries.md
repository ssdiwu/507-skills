# 按真实差异选择行为场景

跨入口、身份、状态、失败或恢复差异会改变结果时采用。按公开契约找真正有关的维度，不枚举所有组合；没有读到或没有测试不能作为排除依据。

优先主路径和会改变用户结果的分歧，关注共用组件各入口的默认值、校验、正式提交及保存／读回。复杂场景可以用表格记录：准备条件、用户动作或公开调用、预期结果、须保持的边界、验证接缝与证据要求。具体测试文件和运行记录留工程交接。

| 证据状态 | 处理 |
| --- | --- |
| 已接受的行为 | 写入当前要求与验收 |
| 产品行为尚未定义 | 先查事实；只有实质取舍需要用户决定，解决前不将它定稿 |
| 有依据排除 | 写明不可达、等价或拒绝进入的条件 |
| 本次不涉及 | 明确范围，不承诺测试覆盖 |
| 疑似故障 | 保留现象和来源，调查实现；不能改需求迁就缺陷 |

同一验收须能被另一执行者判定。若目前只有计划或自动检查覆盖局部事实，写明所缺环境、实际操作或人的检查，不写成已接受。
