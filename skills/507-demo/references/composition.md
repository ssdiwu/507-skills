# 画面与信息

需要确定构图、裁切、密度与文字时采用。使用者应先认出这是哪类产品，再看见关键对象、动作与结果；布局由展示位置和产品内容决定。

## 先做结果静帧

记录目标尺寸、容器底色、焦点对象与观众需要读出的内容。用最终展示尺寸制作开场和结果，比较真实页面中的观感；不靠放大预览判断小卡片是否清楚。先修构图，再层次，再运动，最后局部装饰。

从配套范例开始，静态卡用 `runtime/examples/static-card/`，表单反馈用 `runtime/examples/form-error/`，无光标状态变化用 `runtime/examples/payout-flow/`；中文适配样例为 `runtime/examples/review-card/` 和 `runtime/examples/review-flow/`。范例是可修改起点，不能替代当前产品设计。需要更细的上游案例时按当前问题查 [Framing](../runtime/references/framing.md) 与 [Craft](../runtime/references/craft.md)，其中营销展示的裁切、文字数量、间距和颜色偏好不成为所有产品的硬规则。

## 保留内容，减少干扰

- 真实文字优先放在被操作对象、其必要邻项和最终结果上。周边占位条可降低干扰；需要准确阅读的表格、工程信息和对比依据继续保留真实内容。
- 一张画面应有明确主次。窗口、细节卡、设备和注释的关系要能说明焦点；避免同权卡片铺满所有区域。
- 裁切可用于暗示更大界面，但不能切断观众需要识别的控件、单位、状态或弹出内容。整窗展示、边缘延伸与留白按具体用途选择。
- 已有产品的颜色、图标和原生外框优先。通用范例不提供当前产品的品牌真实性；没有许可的图标和图片不随意带入交付。
- 宽版和窄版分别排版。信息过密时调整组合、裁切与动作，不能仅缩小字体或隐藏决定含义的内容。

## 中文与可读性

以目标字体检查汉字、数字、中英混排和标点；不要直接沿用按拉丁大写字母高度裁切的文字设置。长标签保留可理解语义，金额与单位连在一起。检查行高、按钮内边距、最密状态和动画后的文字位置，不能由英文范例通过推出中文通过。

对并排或多格展示，先确定整组的视觉主次、共同底色和阅读顺序，再制作单格；不是每格都需要动画或光标。同页多个场景还要核 CSS 命名、目标测量和播放控制是否互相影响。
