# 动作与状态

已有静态画面成立且需要展示变化时采用。动画应帮助观众看懂发生了什么，动作数量与时长按当前展示位置决定，不套固定秒数或节拍数量。

## 一次动作及其结果

写清开场、触发、变化、结果和必要的循环复位。光标应触达当前舞台中的真实命名目标；点击反馈与场景变化分别编排，不能由光标按下推断业务已执行。拖拽保留拾取位置、周围对象让位与落点；新增行带动邻行，数值变化与它表示的事件同步。

切换文字、浮层或尺寸时保留空间关系，避免容器缩放连同文字一起拉伸、内容突然替换或动画结束跳一下。循环结束可回到开场，或用明确事件解释复位；一次播放则允许结果停留。减少动态效果使用 `poster` 保留完整结果，不选择变化中途的帧。

上游的 API 与案例在 [Kit](../runtime/references/kit.md)，更细的编排参考见 [Motion](../runtime/references/motion.md) 和 [Choreography](../runtime/references/choreography.md)。只读所用组件与当前问题；其中数值是示例起点，实际验收继续服从当前内容。

## 播放与宿主

正常网页内 Stage 使用浏览器时间；配套预览将虚拟时钟放在隔离 iframe 中，外部播放按钮继续使用正常时间。不要把 `installVirtualClock()` 放到真实宿主页面顶层：它替换页面计时与动画 API，可能影响页面其他内容。

网页演示直接使用 Stage 的 `loop`、`once` 或 `hover`，按需求检查离屏、恢复、重播与窄版切换。需要暂停或逐帧时复用配套隔离播放器；多个独立播放器各有 iframe 与自己的时钟。`runtime/examples/dual/` 同页挂载两个原生时钟场景，用于检查样式与目标测量的共存。

完整视频由已有媒体工具负责镜头、声音、字幕和成片。Stageshow 的逐步推进时钟没有现成的 HyperFrames 时间定位适配；未经验证不直接组合两个时钟。可以采用同一构图方法，或先制作并检查可用片段再进入成片流程，目标视频仍须实际导出、播放与核验。
