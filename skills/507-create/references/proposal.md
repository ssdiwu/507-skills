# 面向人的正式方案

目标是让特定读者能够理解、批准或执行活动、培训、合作与项目安排时使用。具体软件行为和验收规格不在此方法中。

先复用已确认读者、目标、范围、约束和成功标准。已有资料中的人数、费用、角色、频率、日期和责任不能从参考方案类推；Agent 自行安排章节和表达，用户拥有真实业务承诺与会实质改变目标、成本或风险的决定。

只要求讨论稿时在同一文档区分已确认内容、建议和待决事项，不把章节完整或状态名当成已批准的执行依据。明确缺项影响某环节时保留未知，不能为了方案看起来周全补出负责人、预算、日程或验收。

围绕读者下一次真实决定组织正文。先写明建议及其适用条件，再选出足以支撑建议、也能让读者看出取舍的理由。做对标时，选择会影响读者决定的比较维度，逐项把同条件证据连到读者能获得的价值。需要先介绍矛盾或敏感背景时，先点明要解决的问题，再给建议。已确认的主张直接组织论据。

明确希望谁批准、参与、执行或知悉什么。需要行动时写清已知的前提、责任、资源和完成结果；仍待确定的责任或期限放到讨论事项。只需知悉时讲清影响及是否需要行动。出资、交付、参与和招募角色按实际职责写。

正式与易读并存。删掉没有事实作用的宣传词、制作过程和自我辩护，保留执行所需的约数、条件、否定、例外与边界。表格用于角色、步骤、资源或并列比较，章节数随方案规模决定，不套一套“完整”目录。

交付前按首次阅读顺序复述建议、理由和所需行动，核对关键理由的依据。逐项核对获授权执行环节的规则、数值、条件、责任和产出，确认各方能提供、拟承担和已承诺的事项与依据一致。资料足够时直接完成可通读方案。方案获批、开始执行和实际成功分别核实。
