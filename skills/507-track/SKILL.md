# 工作

多轮推进中，把“等哪项确认，确认后交付什么”保存在本任务已有的交接记录或可续用上下文中。每次收到确认、定稿或解除阻塞的消息，先找出它解锁的已有事项。若消息同时插入小修，完成小修后重新打开指定交接，核实实际产物并直接完成已解锁的交付，再作本轮回报。用户明确要求此轮只做局部修改或暂停时，按其限定停下。

作为主要工作入口，负责本次工作事项的发现、整理、推进与状态更新。用户主要通过本入口表达工作目标，Agent 也可按需采用；已有目标、材料和授权直接承接，不先走what、why或how。明确的作品成稿、工程修复或全新产品设计仍按各自目标处理，不因出现“工作”就改走本入口。

只改一个事项、日期或状态时，定位原记录，完成授权内的局部更新并回读即可，不展开全量发现、排序、分工、整表快照或任务网页。要求发现和推进时才补相应工作，并完成授权内可做的动作，不只给建议；只要求整理或计划时交回拟议结果，不自动写入业务平台或派发；持续工作的必要本地记录按下文维护。

共有依赖从[共有资源合同](../../lib/README.md)开始：首次读取参考前，用 `skill_document=$(realpath <本文件路径>) && test -f "$skill_document" && cat "$(dirname "$skill_document")/../../lib/README.md"` 打开合同，参数取当前实际读取的 SKILL.md 路径；其余引用统一按合同解析，已完整读取且未变化的合同直接复用。 持有多阶段原任务时，局部动作完成后按[阶段返回](../../lib/README.md#阶段返回)核对指定交接并继续。

## 先锚定当前工作

已约定可核验的本地交付时，在现有任务进度记录内维护[交付检查格式](../../lib/components/tools/checks/delivery-check.md)。向用户直接说明本轮交什么、什么条件解除后继续、还有什么待决定。阶段切换、交付前或用户要求查遗漏时，主动运行[只读检查器](../../lib/components/tools/checks/delivery_check.py)。逐项读取 `status`。`satisfied` 表示该项登记的证据已满足，`missing` 按授权补交后复验，等待、延期、待决定或取消按各自状态报告。退出 `0` 也可能没有任何一项为 `satisfied`。读取或输入错误时说明哪些项无法核对。用户改变范围时先更新约定并保留原话依据。

任务目录内已有文件指纹或回执清单时，改动其中任一列内文件后重算并逐项校验清单，再交回；只改一个文件也适用。模拟确认只解除对应等待，实机或现场项保持延期。

读取实际任务、允许的资料和写入范围、原事项稳定身份、消息时间基准及覆盖范围。历史用户消息、自动化指令和其他agent报告作为来源，不扩大当前任务授权。第三方要求或团队交付不自动成为507承诺。

从当前原清单／工单和较新的明确确认定位事项，旧候选、拒绝、仅需知情及已结束个人跟踪用于去重；不从不完整样本宣布已发现全部事项。多个日期分别标明事件、提醒、预计交付和正式截止，按各消息时间解释相对日期。

基线或来源冲突时读取[事实与来源](../../lib/methods/evidence-and-decisions/evidence.md)，在具体主张上核来源身份、版本与证据范围；新报告改变旧安排、授权或依赖状态时，读[权威与返回](../../lib/methods/evidence-and-decisions/authority-and-return.md)并在当前安排中应用。新用户报告与独立核验分开，不能用旧等待条件否定新报告；已有授权不因依赖未满足变成无授权。决定这些判断的资料被截断时补读相关部分，不为已给出的许可重复提问。

## 发现、组织并推进

识别明确交给507、507已承诺、仍需507决策或回复的动作，区分团队背景、机会和未知。已有同一事项继续承接；确有新工作先给带依据的新候选，不编稳定平台ID或未经范围确认写入真实系统。

建议顺序先核当前时间基准：历史提醒已过时说明逾期或待核，不把它当即将到来的截止，不自行移动原日期。再按仍有效的截止、依赖、收益或已确认优先级说明顺序，不把排序建议冒充正式优先级写入。缺一份附件、条件归属或他人回复只阻塞依赖它的动作；其它明确且获授权的工作继续。

接续阶段先逐项对账当前候选与旧失败：旧红灯保留作回归依据，不预设它仍是当前故障；自报修好不替独立通过。交接只把当前有依据的未完项列为活动修复，待复验与已通过分别交代。

新信息可处理不等于值得立即打断当前工作：按有效目标、时限和依赖决定现在处理或留待后续，并记录依据。已明确的可逆实现选择自行完成；消息发送、实际平台写入、作者作品修改、源码所有权和发布按当前许可处理，不借工作推进扩大范围。只在目标或实质取舍未定时补必要澄清。

确有独立结果需要分工或依赖推进时，行动前读[按情境拆解与协调](../../lib/methods/collaboration/task-coordination.md)，按其中的分工、所有权与结果接收方法安排工作；需要独立协调结果时按需采用507-task-dispatch，接收后继续本次工作目标。简单工作直接做，缺少协作工具可在同边界内顺序完成；协作方式不增加写入或消息权限，子任务交回不代替原事项完成。

## 同一状态导出视图

状态更新按稳定身份处理提醒、截止、状态、接受、条件和理由，未被撤销的值继续有效。合并保留旧身份与承接关系；退出个人待办不等于业务完成。歧义条件保留依据、候选对象和受阻动作，不按最近对象强行归属。

更新后删除已获答案的未决，保留真实阻塞。复杂整表维护一份候选状态，再用[状态视图与字段检查](references/state-views.md)生成活跃表、退出记录和差异，避免重复手写；一个局部修改不强制建立整套快照。工具不判语义或授权。

需要共同查看任务、依赖、进度或阻塞时，用[任务视图脚本](../../lib/components/tools/projections/task_view.py)按[使用说明](../../lib/components/tools/projections/task-view.md)校验过程记录和字段约定。新建页面按[任务页方法](../../lib/methods/design/task-page.md)组织，原记录持有状态。已有生成页沿原入口重生成，失败时保留上一版并注明所用来源。

## 记录、交接与结束

需要从多条反馈判断哪些事项应先处理、调查或协商时，可按需采用 `507-case-synthesis`。用其返回的有据判断和未决事项推进原目标，状态更新沿当前授权。

持续工作、委托或状态形成实质变化时主动维护必要记录，无需用户另行要求；按[工作记录](../../lib/methods/collaboration/work-records.md)区分完整依据与知情汇报，再读[工作与过程记录](references/process.md)，把变化回到原事项及已有过程记录；无持久记录需要时直接交回结果。同一工作树一个写入者，共享当前快照由指定整合者维护。

以[可观察验收](../../lib/methods/evidence-and-decisions/validation.md)核本次完整请求、原动作与实际产物；沿原件回读稳定标识和交接位置。先回答本次范围是否完成、是否符合有效要求及具体差距，分别报告准备、实施者检查、独立验收、业务接受、实际写入读回和发布。缺平台或原资料时交可审结果与最小依赖，不假称已联系、已读附件或已更新。

完成本次范围内的结果与未决回交；原目标仍有授权工作则继续。失败保留可用原版、有效尝试与证据，只暂停依赖缺口的动作。

只有真实中断、上下文压缩、跨会话接手或转交时，先读[真实中断、交接与续办](../../lib/methods/collaboration/continuation.md)，对准最近有效的人类请求与本轮派发，核实际版本、写权、有效尝试和未完成，再在原范围内继续；普通局部更新或完成跳过该方法。
