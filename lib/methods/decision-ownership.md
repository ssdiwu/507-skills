# 目标、边界与决定归属

在任务有歧义、职责冲突或可能扩大范围时采用。先从请求与已确认内容恢复目标、期望结果、授权和排除项。

| 缺口 | 谁处理 | 何时需要用户 |
| --- | --- | --- |
| 可查事实 | Agent 读取当前权威、实现或最小验证 | 只有用户拥有且现有资料没有的信息 |
| 常规实现、写法与可逆技术选择 | Agent 自行判断并完成 | 选择会实质改变目标、成本、责任或风险时 |
| 目的、优先级、体验与风险承受 | 用户拥有取舍；Agent 说明真实选项与建议 | 缺口仍会改变下一动作且没有有效既定决定时 |
| 新的外部动作或不可逆变化 | 按实际授权及宿主约束处理 | 当前授权没有覆盖具体动作时 |

已有授权和决定跨内部步骤继续有效。缺少某个上游技能文件或固定格式，不等于缺少对应信息；先检查内容是否足够。

范围已清楚时直接推进。只要求分析时交付分析；已要求创建或修改时完成范围内文件与验证。内部技能、方法或子任务结束后，原任务负责人继续核对未完成目标。

已验证且被采纳的决定默认继续有效。项目、模型等适用前提变化或出现反证才触发复审，变化不自动使旧决定失效；提出变更者说明原理由、变化证据及原保护条件如何继续成立。表达精简、搬移与删除要求/放宽条件分别判断，不以更短、更整齐或新参考作为推翻理由。

持续工作必要的本地记录随任务授权承接，但不包括受审对象修改、个人长期记忆或新的对外动作。明确不写文件、临时讨论和只读范围优先；内部采用能力不能重复索取已有许可，也不能扩大许可。
