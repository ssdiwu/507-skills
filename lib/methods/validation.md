# 可观察验收与相称验证

在定义“做到什么算完成”、检查产物或评估方法改变时采用。先指定用户要得到的结果，以及一个能拒绝代表性错误的观察动作。

区分要求、机制与结果证据。文件存在、结构通过、静态推演、独立执行、真实环境验收和发布分别成立；不能用前者替代后者。

以本次最终请求及有效确认对照实际产物，核对主路径、组合关系和明确排除。完整目标不能被自行缩成几个独立演示；局部目标也不扩大成整项目。检查经过本次应连接的入口、状态、最终读者和返回动作，能够拒绝一个与目标相近但错误的结果。可以直接利用现有规格或过程记录，不要求新表、额外日志或固定技能链。

在执行验证前核整条检查动作的副作用与位置许可，包括准备副本、探针、日志、缓存和清理；原件未变不能证明全部动作合规。示例和工具可用不授予写入/删除权，许可不足采用不落盘检查或保留未运行。

按变化风险选择正例、相邻反例、权限边界或续办例。比较候选时保持任务、输入和工具条件相同；成本和效果需要真实记录，不能从篇幅、入口数或规则数推算。

既有内容或状态的修改，逐项对照输入、作用对象、实际字段/句子和未决项：明确变更是否落对位置，未撤销信息是否保留，歧义是否仍未决，正文与字段是否一致。日期解释合理不证明旧字段已被明确取代；条件文字存在不证明对象归属正确；多来源引用不证明它们是同一实验。检查者要指出支撑关系或具体缺口，不能用可解释的猜测放行。

选择一个实际错误结果反问：若条件落错对象、旧精确值被推算替换或来源身份被混接，当前检查会拒绝吗？结构可解析、表格齐全、没发生禁止动作和执行者自称采用规则，都不能替代这个观察。只核对当前变化，不把相称验收扩成全库检查。

并发、重试和异步失败回到原动作的时序与分支：门控实际等待位置，观察期间另一写入，再检查最终状态；重试分别检查结果未知、对账命中与未命中；数据/API通过不能替代受影响页面渲染。已有测试只有注释声称覆盖时，核对触发动作与断言；不为复验强行给已修代码制造原故障。

已有有效验证仍对应当前版本和环境时复用。新变化、失败或具体疑点才补验；每次失败记录假设、动作、结果与新信息，同类无信息尝试不反复重做。

涉及用户偏好时，Agent 只能验证表达与条件是否一致，不能替用户宣称满意。检查足够后明确本次范围完成与否、是否满足有效要求、具体不符合及未验证项，返回原任务；没有验过的部分保留未知，不用已完成数量代替目标验收。

## A/B/C 与独立结果

A 将原目标、通用规则和约束表达为输入、预期输出与验收场景，可复用主会话或协调会话，不要求另建 Agent。B 采用对应任务技能实施并自查，可写自查测试，但不能自行删改最终验收依据求通过；发现验收错误提交证据，经相应职责修正和独立复核。目标或验收含义改变仍按用户决定边界处理。

C 必须未参与当前受审范围实施；Agent 以 review 为核心，按领域采用方法与工具。C 同时核产物和 A 的场景是否忠实覆盖原目标，现有测试全绿不代表遗漏要求通过。可核验并利用 B 的证据，不必全部重复；只转述自报不成立。非代码产物按内容、来源、载体检查，不能强套工程测试。

切换技能、模型或角色名不形成独立性；共有资源不是执行者。C 不修受审内容，若参与修复则由另一 C 核验该修改范围。独立结论绑定受审版本，后续差异须相关复核；条件不足保持待验收。作者/用户接受另立结果。

当前产物最终通过、首次表现、反馈后修正与方法适合推广分别报告。同类错误反复时暂停相关扩容并查因；检查同时失效时收紧受影响范围，凭新证据恢复，不取消独立检查。
