# 当前权威、冲突与返回

新结论与已有决定冲突、需要持久化，或一个内部动作已经结束时采用。

事实冲突由 Agent 核实；Agent 误读了已确认决定时自行纠正。用户明确的新指令按适用优先级承接；若是否取代旧决定仍有实质歧义，说明旧项、新项、影响和最小待决问题。

当前用户报告、已核运行事实与历史执行报告分别说明支持范围。当前报告改变了旧等待条件时，在当前安排中采用该报告，并保留尚待实证的部分；不能因还没独立核验就继续把旧报告当现状。已有授权与执行依赖分别承接：依赖未满足不撤销授权，也不授予新权限；授权内不依赖该条件的准备继续，实际执行停在相应依赖门。

接续多个阶段时按同一对象和当前候选逐项核对：历史失败保留作回归依据，不因仍在旧记录中就重新登记为当前待修；历史自报修好也不自动成为当前独立通过。需要复验的项目保持待验证，仅当前候选实际仍失败或现行要求明确未实现的项进入活动修复。

修改既有内容或状态时，在当前消费者里对账，不另建总控或状态台账：

1. 用实际原版定位对象，先逐项提取原请求中的新信息，包括条件与原因。每项都须有去向：已应用到字段/正文、明确保留，或进入未决；“未涉及项沿用旧值”不能用来跳过用户本次新增的信息。逐项核对“依据片段 → 作用对象 → 改变什么 → 目标字段”；身份说明、背景原因、提醒、事件、交付预期、截止与动作许可分别判断，不能因出现在同一句话就相互代替。
2. 依据无法唯一指向对象时，在现有未决项保留原条件、候选对象和它阻塞的动作，不把条件认领到任一对象的确定字段。明确指向时直接采用；独立且明确的修改继续，不为一个歧义冻结整个请求。
3. 默认复制未涉及的有效原值、条件与理由。新身份说明或口语与已有精确字段冲突、且未明确取代时，保留旧字段，把冲突放到未决项；明确修订该字段时才替换并记录依据。整体替换备注、段落或摘要也需把未撤销信息带到新正文，不能仅靠历史聊天补足。
4. 回看实际变更集、当前字段与正文：身份或提醒的更改不能悄悄变成截止或许可的更改，未决内容不能在标题/正文中又写成定案。用已有变更说明和未决位置交付即可，不要求为普通修改生成额外表格。

对账是当前消费者的判断，不负责平台权限、实际写入或调度，也不要求普通任务先进入what。

同一结论只有一个当前正文归宿。仅服务当前请求的共识留在会话；需要长期生效且已有写入授权时，回写它实际约束的规格、设计、词义或其他项目权威。历史原因保留追溯，不建立第二份总状态台账。

返回结果先回答本次范围是否完成、是否符合有效要求，以及具体不符合或未验证之处，再给必要产物、版本/证据和下一动作。符合要求不等于用户已接受；未知不当失败，也不当通过。能力完成不等于原目标完成：原任务仍有已授权可推进工作时继续；只需本次分析或澄清时可直接结束。工作回报与作品正文分别表达，不把过程说明塞进作者作品。

失败时保留上一可用版本和具体失败信号。恢复以相同目标及已确认范围为基准，重用有效信息，不重新启动完整问卷或全库扫描。

续办需要原版状态时，使用实际保存的稿件、数据或输出及其版本。摘要、执行者事后重建和“已经完成”的报告可提供线索，不能代替可用原版或实际结果；原版不可得时明确限制，不把猜测补成基线。
