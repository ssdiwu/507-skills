# 临时任务网页组件

`task_view.py`把明确选定的现有过程记录，投影为可筛选、可点击详情与依赖的离线任务网页。任务正文只在已有过程记录维护；契约规定读哪个字段、怎样显示和本次选择哪种情境，不另存人工维护的任务状态，不建立工作日志、派工器或自动领取队列。

```sh
python3 task_view.py --record process.json --contract task-view-contract.json --out-root task-view
```

只用 Python 标准库，无网络、安装或后台服务。记录和契约为只读输入，唯一写入范围是专用输出根。成功退出0（`RENDERED`或相同内容的`UNCHANGED`），错误退出2并报告原因；参数缺失由标准命令解析器返回2。生成与语义核对、作者接受、业务验收及发布分别成立。

## 先选来源与情境

契约中的`mode`必须由调用方明确选定，组件不替用户决定：

| mode | 适用显示 | 不会自动发生 |
| --- | --- | --- |
| simple | 普通工作按需拆分，列表和详情即可 | 不要求先建完整依赖图 |
| graph | 多项独立工作已有依赖，显示前置／后续关系 | 不自动领取ready任务、不派工 |
| continuing | 跨轮或长期工作，沿用原过程记录并显示关系 | 不建立第二套常驻状态或日志 |

三种情境共享同一只读投影，写作、研究、工程和日常工作都可以用。本次模式的理由放`modeNote`；有独立工作才拆，有协作收益才协调，网页也不成为每个任务的必需步骤。

JSON 示例（虚构字段）：

```json
{
  "title": "虚构作品协作",
  "mode": "graph",
  "modeNote": "本次同时核对作者材料和结构，只有成文依赖材料交回。",
  "source": {"format": "json", "tasksPath": ["work", "tasks"]},
  "fields": {"id": "key", "title": "name", "status": "report", "owner": "person", "dependsOn": "deps", "acceptance": "accepted", "notes": "memo", "evidence": "proof"},
  "columns": ["title", "status", "owner", "acceptance"],
  "statusMap": {"done": {"label": "报告已做完", "dependencySatisfied": true}}
}
```

记录可以是JSON数组，契约用`tasksPath: []`明确选中根数组；也可以是对象，`tasksPath`以字符串对象键或非负整数数组下标精确选择一个数组。不猜多个包装，不扫描整份文档找“可能是任务”的内容。

Markdown 使用`source: {"format":"markdown","heading":"## 本次工作"}`精确选一个标题（含`#`层级），并显式映射表头。该标题必须唯一，该节到下个同级／更高标题之间必须恰有一张标准竖线表。Markdown 每条来源带实际行号和表头行号；JSON 带精确数组路径。两者均显示原文件名／路径和原始字节SHA-256。

Markdown 依赖单元格只能用JSON字符串数组（例如`["A","B"]`），或`-`表示明确无依赖；空依赖不能猜成无依赖。支持`\|`表示单元格里的竖线，不支持复杂嵌套Markdown表、合并单元格或多行HTML表。未知格式、标题歧义、缺少映射列明确失败；先调整原记录的已确认表达或扩展适配器，不猜测。

## 字段与关系的语义

最少映射`id/title/status`（非空字符串）；可选`owner/dependsOn/result/evidence/notes/decision/acceptance`。字段映射须唯一，列名只选择映射后的字段。可选字段为文字或null，`evidence`也可为文字数组；依赖为唯一字符串ID数组。未提供、null、空文本、空数组分别显示；未映射内容仍在原过程记录，不因投影缺席而删除。

状态显示映射保留原值，未知状态原样呈现。`dependencySatisfied`只描述显示契约如何派生依赖提示：缺映射保守地显示尚未明确满足，未提供依赖显示“未判断可开工”，明确空数组显示“记录无依赖”。这种提示不构成授权、领取、自动阻塞或验收。报告状态和`acceptance`验收记录分别显示；报告done不能推断“已验收”。

重复身份、无效依赖、自依赖、循环、重复JSON键、非法字段／状态映射、竞争任务数组进入契约都会拒绝。输入文字在页面中保持文本，来源链接不作为可执行链接，组件不会联网拉取证据或自动确认内容。

## 更新机制与回退

更新只做两步：修改原过程记录中已授权的内容，再用相同契约和输出根重跑组件。输出根包含：

- `versions/<fingerprint>/index.html`、`projection.json`、`manifest.json`：不可变版本，绑定原记录、契约、渲染器脚本源码指纹及来源位置。
- `current.json`：生成登记，指向当前版本并登记全部已生成版本的manifest指纹；只含生成元数据，不维护独立任务正文。
- `index.html`：生成的稳定阅读入口，链接到当前不可变版本。

旧版本保留。每次更新先核对已登记历史版本与稳定入口；任何手改、软链或未登记文件都拒绝，不用新生成覆盖修正。相同来源与契约及渲染器返回`UNCHANGED`；重现某个非当前历史身份不会默默回退。输出根用独占锁阻止同时生成；中断留下的锁须先核对在途写入，不自动移除他人锁。

运行异常时保留已存在的当前入口与登记，新增半成品回收。进程被强杀或机器断电属于未验证的恢复范围，锁及登记不一致会如实失败，不能宣称跨断电事务。各版本由组件生成，不能直接编辑网页；布局、字段或功能不足时，修改唯一组件／契约，完成适用测试后生成新身份。

页面支持搜索、报告状态／承担者筛选、点击工作详情、前置／后续关系，键盘焦点、可滚动窄屏表和减少动效设置。测试校验字段、来源、更新与失败保全；桌面和390px实际使用仍需打开最终生成页面核对，不以静态源码或脚本测试替代。

```sh
python3 -m unittest discover -s tests -p test_task_view.py -v
```
