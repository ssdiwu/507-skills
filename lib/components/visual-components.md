# 共有 React 呈现组件

需要图解、产品界面演示、任务视图或产品地图时读取。所有视觉组件统一使用 React、TypeScript 和 CSS；服务端预渲染与浏览器交互使用同一组件。Python 仅承担数据校验、记录投影、比较、检查与文件管理，不再维护 HTML 界面或另一套交互脚本。

## 一份资源，直接引用

唯一组件与运行库为 `visual-runtime/`。组件、五类图解、任务视图、产品地图、窗口／光标、范例、播放器、运行与检查工具只在共有库存在一份。技能目录禁止 runtime、kit、执行脚本及共有文档副本；技能保留其任务判断、采用条件、交付标准和专用文字方法。角色与依赖见[逐技能关系](../skill-resource-map.md)。

集合采用 `skills/` 与 `lib/` 并列布局。Agent 根据实际读取的技能文件定位同一集合的 lib，而非当前业务工作目录；下文 `<共有库>` 代表已定位的 lib 绝对路径，由 Agent 自行解析，不让用户填路径。不要求作者仓库或其他技能代码，但必须有明确登记的共有库依赖；缺失时说明依赖并停止相关动作，不能临时往技能里复制实现。

查找未确定的组件或范例时，按[运行合同](visual-runtime.md)使用本地component-library脚本；已知适用的组件直接采用。搜索返回预览、状态和真实源码，inspect从当前类型读取接口，实际场景在导出前检查。不把文字标签当兼容性或视觉通过证据。

## 统一技术栈与入口

呈现：React 18.3.1、TypeScript 5.6.3、CSS；预览与构建：Vite；离线导出：共有 Node.js 入口使用 esbuild 将同一 React 组件预渲染并内嵌浏览器交互代码。最终 HTML 可离线打开，不依赖 CDN。工具首次运行前在共有运行库安装一次锁定依赖；依赖目录不复制到技能。

```sh
cd <共有库>/components/visual-runtime
npm ci --ignore-scripts
npm run typecheck
node scripts/render-artifact.mjs --example --out-dir <新的输出目录>
node scripts/render-artifact.mjs --input artifact.json --out-dir <另一个新目录>
```

输入与目标关系成立后直接选组件，不因有库而增加无必要图例，也不把全部关系压成段落后只改样式。普通网页正文也由同一 React 呈现入口承载。详细字段与运行见[运行合同](visual-runtime.md)。

| 读者需要看清 | React 组件／块 | 必须保留 |
| --- | --- | --- |
| 日期与阶段先后 | timeline | 事件、日期、暂定／目标身份，不从日期推完成 |
| 连续过程 | steps | 真实顺序和条件；复杂分支或时序用对应图解工具，不能删分支硬套直线 |
| 同条件数值差异 | comparison | 同单位、数值或区间；未知不画长度，零值保留数字 |
| 文档或界面区域 | layout | 各区真实文字，明确示意，窄屏重新排列 |
| 任务与等待时间 | queue | 单通道示意假设、各任务表格数、每份耗时与正在处理任务剩余时间；非生产队列 |
| 工作记录与依赖 | TaskView | 搜索、状态、承担者筛选，依赖导航，缺失／空值与报告／验收分别保留 |
| 产品交互与证据 | ProductMap | 共享对象、关系、三维证据、路径、筛选与选择返回；节点证据不能自动合成路径通过 |
| 产品窗口与编排动作 | 共有 kit 与场景 | 产品身份、来源许可、光标目标、状态与实物检查；模拟不取得业务操作权限 |

## 五类图解输入

顶层为 `mode: site/cards/deck`、title、可选 subtitle、非空 pages、可选 sources。每页有 title，可选 body、bullets、sourceIds、notes、有序 blocks。正文在图前、补充列表在图后，需要交错时按认知任务拆页。每块有 type、title，可选 caption、sourceIds。

- timeline：非空 items，每项 label，可选 date、detail、status。
- steps：非空 items，每项 label、可选 detail。
- comparison：unit、可选共同 max、非空 items；每项 label、value、可选 note。value 为非负数、[下界,上界] 或 null。区间有序，max 不能裁掉已知值。
- layout：非空 items 与可选 aside；每项 label、可选 detail。全部标为版面示意，不是产品截图。
- queue：显式 model: serial；taskForms 为前方各等待任务的表格数（0–8 个示意任务，每任务1–100份）；minutesPerForm 为正数或区间，remainingMinutes 为非负数或区间。估算为当前处理剩余＋前方表格总数×每份耗时。 队列按当前处理通道、前方各任务、我的任务排列，每任务表格数在对应对象内调整；窄容器转为紧凑列表。切换非等待状态隐藏队列示意，但保留会话内输入。控件上限不是产品容量。

可选 `language` 为 `en` 或 `zh-CN`，默认 `zh-CN`；可选 `translations` 以另一语言为键，值为完整的 mode/title/subtitle/pages/sources 内容对象。两种内容使用相同模式、对应页数及各页图解类型、顺序和 id；翻译对象不再嵌套语言字段。图解可设唯一 id，双语 queue 必须设相同的唯一 id，且两种语言的数值条件完全一致；不对齐时拒绝输出，避免切换把输入带到另一对象。提供翻译时由同一 React 阅读组件显示切换按钮，正文、导航、来源和图解控件同步切换；默认语言由同一组件预渲染。翻译内容的事实、数字和条件一致性仍须核对。切换保留现有排队输入和状态；文件本身不保存会话状态。

sources 每项有唯一 id、label、可选 HTTP/HTTPS URL；sourceIds 须已登记。不可信文字交由 React 转义，数值有限，未知字段与图解类型拒绝。输入限制8 MiB，错误返回 ERROR JSON／退出2；只写新输出目录，既有输出拒绝覆盖，不联网提交、不改业务数据。生成成功不表示语义、审美、用户接受或发布通过。

## 共有样式边界

基础字体、颜色、焦点和输入控件只定义一份；普通阅读、任务记录和产品地图的布局分别限定在自己的 React 根节点内，不能依赖样式加载顺序覆盖全局标题、表格或卡片。共享的是基础表达和组件，不把所有载体强制成同一种密度或嵌套卡片结构。修改后同时核实际消费者，不只看当前业务示例。

## 实际检查

沿时间／步骤复述、在同条件下比较、辨认区域，或改变输入解释结果。来源、单位、未知与模型假设在图旁可读；检查中文长标签、窄屏、键盘、减少动效、失败与返回。统一 React 不代替事实调查或作者判断。会话内 Mermaid 作为表达语言仍可使用，不构成技能私有实现或第二套组件运行库。

## 真实界面基础控件

产品界面的表单、对话框、页签、菜单、渐进展开、空状态和错误反馈直接引用 [ui/](visual-runtime/ui/README.md)。先用现有产品组件；缺少时才用共有基础控件并沿项目主题适配。仅展示光标或动画的 `kit/controls` 与 `kit/parts` 仍承担编排演示，不提供真实表单校验或键盘交互保证。三类消费者（内容图解、数据视图、产品界面）共用一个 React 运行库，具体内容与业务行为由调用方拥有。

## 阅读分组与顺序

页面需要“说明 → 案例列表 → 测试依据”等交错顺序时，用 `sections` 有序数组，每组按需提供 `body`、`blocks`、`bullets`，组内仍按正文、图解、列表显示。例如先放一组引导与案例列表，再放一组依据，避免“以下两种情况”与实际案例被长段落隔开。该字段与页面原有 `body/blocks/bullets` 互斥，防止重复或隐藏内容；旧输入继续使用原顺序。双语页的分组数量和每组图解身份须对应，数字、条件与队列参数仍按原严格合同校验。不得为了适配模板删掉原文条件。
