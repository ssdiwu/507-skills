# 视频制作（507-video）

把成熟内容、已确认创作包和授权素材制作为**经用户审片、技术验证通过的本地视频母版**。当前首选执行引擎是 Remotion；已有项目使用别的可验证视频工具时，保留项目现状，不为统一工具重建。

先读 [制作合同](references/production-contract.md)。当成片以网站、桌面端或移动端产品的真实页面与功能状态为主要证据时，再读[产品宣传片 profile](references/product-promo-profile.md)；它是 `507-video` 的条件制作合同，不是新 skill。进入 Remotion 制作、审片、迭代或渲染时，再按需读 [Remotion 制作与验收](references/remotion-production.md)。

## 不覆盖什么

- 不研究外部事实、不决定选题、不写长文；分别进入 `507-research`、`507-mine` / `507-fuse`、`507-forge`。
- 不把未收口内容直接排成视频；视频旁白或口播未成熟时进入 `507-stage`。
- 不使用克隆声音档案生成配音；成熟旁白需要本地 TTS 时进入 `507-narrate`。
- 不分析参考视频或借鉴其手法；分别进入 `507-breakdown`、`507-remix`。
- 不导出或维护剪映 / CapCut 等可编辑剪辑工程；这是独立下游候选，不属于本次本地母版合同。
- 不登录平台、不上传、不发布，也不把平台文案当成视频完成条件。
- 不维护 Remotion fork、Studio 汉化或通用视频引擎抽象层。

## 输入门

开工前至少确认：

1. 视频目标、受众、平台、时长、画幅和核心主张；
2. 成熟内容来源：已确认 brief、`507-stage` 视频旁白内容包、`507-remix` 创作包或已有视频项目；需要 TTS 时另有 `507-narrate` 配音包；
3. 素材路径、用途、来源/授权，以及隐私和公开边界；
4. 时间基准：真人配音、TTS、现有录像、音乐节拍或人工时间线；
5. 事实主张与画面证据的边界。

目标产品本身尚未看懂时先进入 `507-explore`；只有一个会改变制作方案的具体视觉未知值得低成本观察时才进入 `507-prototype`。缺少用户拥有的产品取舍时进入 `507-grill`；缺事实证据进入 `507-research`；缺内容、旁白或参考片创作包时进入对应上游后返回。不要用视觉效果掩盖输入未收口。

## 制作流程

### 1. 读取或建立项目状态

- 已有项目必须原位恢复：先读 README、制作合同、分镜、风格、素材清单、最近审片记录和现有渲染；不另起重复项目。
- 新项目按制作合同建立最小文件；项目已有等价文件时沿用，不机械改名。
- 启用条件 profile 时，把新增字段落进现有 brief、style、storyboard、素材清单和审片记录；不另建重复状态源。
- 记录当前可恢复阶段、已确认版本、未完成项和上次失败证据。

### 2. 核验素材与风险

- 实际读取媒体元数据并抽样查看，不只相信文件名或用户描述。
- 每个素材登记角色、来源、授权、时长/尺寸、隐私处理和使用状态；未登记素材不进入 composition（合成）。
- 付费生成必须先给成本和用途，取得明确授权后才执行；缺素材时允许可读的降级方案，不静默消费。

### 3. 锁定时间基准

- 使用真实媒体或真实生成结果确定时间，不用文字长度猜最终时间线。
- 真人配音为基准时保留自然音调；加速、降噪或切段后重新测量时长。
- 使用 `507-narrate` 配音包时核验 manifest 状态、section ID、相对音频路径、真实时长、参数和哈希；不从旁白字数重建时间。
- 脚本、配音、字幕、分镜和 composition 必须指向同一版时间基准；任何上游变化都使下游时间确认失效。

### 4. 制作并自检

- 按分镜实现画面、字幕、转场、配音、音乐和必要动效；每个节拍同时服务叙事目标与可见证据。
- 先做结构、运行时和时间线检查，再生成关键帧/联系表做真实视觉检查；代码可运行不等于画面成立。
- 产品宣传片还要逐项核对必须展示功能、真实页面状态、功能到镜头映射和所选 `motion grammar（镜头语法）`；最终渲染确认前按条件 profile 完成独立关键帧终检。
- 隐私遮挡、事实限定、素材授权和字幕可读性是制作内容，不是发布前附加项。

### 5. Studio 审片门

- 启动 Remotion Studio，给出可访问入口、审片版本和重点检查项，等待用户实际反馈。
- 用户提出任何可见或可听调整，都留在审片循环；修改后必须重新让 Studio 热更新或重启，并取得新一轮确认。
- 只有用户在当前版本上明确表示“可以渲染/导出最终版”，且同一条消息没有新修改要求，才进入正式渲染。

### 6. 最小重跑与正式渲染

- 只重跑受变更影响的最小链路：视觉改动不重做配音；音乐改动不重渲染画面；脚本/配音改动必须重建时间线、字幕、预览和下游产物。
- 正式渲染前再次记录输入版本、composition、规格和审片确认。
- 不覆盖上一版可恢复母版；用版本或时间标识保留可比较产物。

### 7. 验收与交付

- 核验文件可播放、时长、画幅、分辨率、帧率、编码、音轨、音画漂移、字幕、安全区、黑帧/空白段和素材缺失。
- 抽查开头、场景边界、高潮、结尾和所有高风险画面；自动检查不能替代观看或联系表。
- 写交付回执：母版路径、文件哈希、规格、时间基准、来源/授权摘要、验证结果、已知限制和可恢复中间产物。

## 硬门

- 没有当前版本的 Studio 明确确认，不渲染最终母版。
- 启用条件 profile 却没有完成其独立终检，或终检问题尚未回到 Studio 取得当前版本确认，不渲染最终母版。
- 任何影响观众所见/所听的修改都会使旧确认失效。
- 不把预览、成功构建或一次渲染称为已验收成片。
- 不使用未经授权素材，不泄露账号、路径、密钥、会话内容或个人信息。
- 不用成片暗示素材未证明的功能、效果或对比结论。
- 用户接受最终母版前，不删除干净画面、混音前文件或其他低成本恢复所需产物。

## 完成与接力

- **完成信号**：当前版本已在 Studio 经用户确认；本地母版通过技术与视觉验收；交付回执能复验输入、规格、来源和结果。
- **产物**：本地母版视频、项目源文件、素材清单、审片记录、必要中间产物与交付回执；启用条件 profile 时还包括嵌入现有项目文档的产品简报、功能到镜头映射、采集记录和独立终检报告。
- **候选出口**：需要内容改动时返回 `507-stage` / `507-forge`；成熟旁白需要重新生成本地 TTS 时进入 `507-narrate`；需要参考手法调整时返回 `507-remix`；视频本身继续修改时留在本 skill；需要平台文案时进入书面适配；只有用户明确授权后才进入外部发布流程。
- **回退条件**：制作合同未收口、素材授权不清、Studio 未确认、渲染能力缺失或验收失败时保留可恢复项目和证据，不宣称完成。
