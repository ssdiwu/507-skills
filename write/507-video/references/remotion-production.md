# Remotion 制作与验收

仅在项目使用 Remotion、进入 Studio、修改 composition 或准备渲染时读取。先遵循项目当前 Remotion 版本与[官方 Agent Skills](https://www.remotion.dev/docs/ai/skills)；不把旧快照写成永久 API 事实。

## 官方 skill 按需路由

`507-video` 管制作合同、审片门和成品验收；Remotion API 与实现细节交给当前官方 skill。只加载眼前需要的能力：

| 当前动作 | 官方 skill |
| --- | --- |
| 不确定具体规则或需要全局基线 | `remotion-best-practices` |
| 新建项目或 composition | `remotion-create` |
| 写布局、动画、媒体、音频、字体和 timing | `remotion-markup` |
| 字幕与 captions | `remotion-captions` |
| Studio 元素可编辑/可选择 | `remotion-interactivity` |
| 渲染视频或 still | `remotion-render` |
| 查询当前 API、props 或包文档 | `remotion-docs` |
| 升级 Remotion 与官方 skills | `remotion-upgrade` |

宿主没有这些官方 skills 时，优先查当前官方文档并说明缺失；不要用 `507-video` 内的旧示例猜 API。安装/升级属于独立环境变更，只有用户要求或任务确实被缺失能力阻塞时才执行。

## 制作前

1. 读取 `package.json`、入口、composition 注册和项目 README，确认真实版本与启动命令。
2. 复用已有项目、组件和依赖；不要为了新视频复制整套工程或覆盖已有 composition。
3. 每个视频使用独立 composition ID 和源文件；共用基础组件只在第三次真实重复后抽取。
4. 媒体只从项目认可的素材目录和 manifest 读取；不得引用临时绝对路径。
5. 先验证素材可解码、字体存在、中文字符正常，再进入排版。

## 时间线

- 用真实时间基准计算 durationInFrames，不从字数猜最终时长。
- 音频主导时，从实际音频/SRT 生成或校准节拍；素材主导时，从真实片段入出点计算。
- 转场重叠会改变总帧数；使用当前 Remotion 版本支持的方式补偿，并验证最终 composition 时长仍与主基准一致。
- 配音变速时优先保留音调；变速后重新测量，不沿用旧时长。
- 字幕、进度条、场景开始帧和动画节拍必须来自同一版时间数据。

## 画面与声音

- 每屏只承担一个主要叙事任务；复杂信息拆屏，不用缩小字号硬塞。
- 连续场景更换构图家族和信息密度，避免整支视频都是同一种卡片阵列。
- 色板、字体、圆角、阴影和动效语言在开工时锁定；不要逐场景引入新视觉系统。
- 画面上的数字、产品能力和比较结论必须能回指合同中的证据边界。
- 人声优先可懂；BGM/SFX 不能遮盖关键词，混音后重新听关键段落。
- 字幕需检查断句、时间、遮挡、安全区和中文标点；自动生成结果不是验收结果。

## Studio 审片

启动 Studio 前：

1. 确认端口没有被无关服务占用；不得用宽范围杀进程命令清理其他项目。
2. 运行 composition 列举/构建或项目现有静态检查。
3. 生成覆盖开头、各场景中点、转场、高潮和结尾的关键帧或联系表。
4. 记录审片版本、主时间基准和已知限制。

向用户交付审片入口时同时说明：

- 当前看的是哪个 composition/版本；
- 应重点检查哪些内容；
- 预期时长与画幅；
- 哪些仍是占位或已知降级。

用户提出修改后，按影响范围最小重跑：

| 改动 | 必须重跑 | 可以复用 |
| --- | --- | --- |
| 旁白/脚本 | 音频或录像基准、字幕、时间线、Studio 审片、渲染、验收 | 已授权素材与不受影响的视觉组件 |
| 画面/动效 | Studio 审片、渲染、视觉验收 | 未改变的音频与字幕时间 |
| BGM/SFX | 混音、听感检查、成品验收 | 干净画面渲染 |
| 字幕文字/样式 | 字幕输出、Studio/成品遮挡检查 | 画面与主音频（时间未变时） |
| 输出编码 | 正式渲染、技术验收 | composition 与审片确认（观感未变时） |

只要观众所见或所听改变，就需要当前版本的新确认；旧确认不跨版本继承。

## 渲染门

只有同时满足以下条件才正式渲染：

- Studio 可播放且结构/运行检查通过；
- 联系表或关键帧已经实际查看；
- 时间基准与 composition duration 一致；
- 当前版本不存在用户未处理的调整要求；
- 用户明确要求渲染当前版本。

渲染命令以项目 `package.json` 和当前 Remotion CLI 为准，不在共享 skill 固定可能过时的参数。先渲染低成本预览；用户确认后再按合同输出正式规格。

## 成品验收

技术检查至少包括：

- 容器和文件可播放；
- 视频/音频流存在，编码符合合同；
- 宽高、画幅、帧率和 duration 符合合同；
- 母版与时间基准漂移在项目容差内；未定义时先报告实测差值，不擅定标准；
- 无意外黑帧、空白尾段、冻结画面、缺失素材、字体替换或字幕乱码；
- 音量、削波、人声清晰度和 BGM 遮盖已经抽听；
- 开头、转场、高潮、结尾以及隐私高风险画面已经观看。

优先使用 `ffprobe` / `ffmpeg` 与项目现有验证器；缺失时可用平台原生媒体元数据建立基础证据，但必须说明未覆盖的检查。

## 交付回执

`DELIVERY.md` 至少记录：

```text
母版路径：
SHA-256：
Composition / 版本：
时长 / 分辨率 / 帧率 / 编码 / 音轨：
时间基准与实测漂移：
Studio 确认版本：
素材与授权摘要：
技术检查：
视觉/听感抽查：
已知限制：
保留的恢复产物：
```

母版、干净画面、混音前文件和项目源文件在用户接受前保留；清理必须是可恢复且目标明确的独立动作。
