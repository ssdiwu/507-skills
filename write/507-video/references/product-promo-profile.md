# 产品宣传片 profile

当视频以网站、桌面端或移动端产品的真实页面、功能状态和品牌视觉为主要证据时，在通用[视频制作合同](production-contract.md)上启用本 profile（条件制作合同）。它只扩展 `507-video` 的制作字段与验收门，不是用户可见的新 skill，也不复制模板 / 自主 / 共同创作的参与度决策树。

审片与版本记录遵循通用制作合同：Remotion 使用 Studio，其他已有引擎使用可核验的等价预览；独立终检与用户对当前版本的确认不因引擎不同而省略。

## 进入与边界

- 目标产品的定位、主要功能、可展示状态或数据风险尚未看懂时，先进入 `507-explore`，带回只读项目证据后再制作。
- 只有一个具体视觉未知必须通过低成本、可丢弃比较才能判断时才进入 `507-prototype`；为当前成片锁定视觉方向的 styleframe（静态风格帧）仍是本 profile 的制作产物。
- 用户拥有的核心主张、必须展示功能、品牌偏离和公开边界继续通过 `507-grill` 或已有上游内容合同确认；本 profile 不建立第二套决策树。
- 参考视频的事实取证归 `507-breakdown`，从参考片借结构或镜头手法归 `507-remix`；这里只读取并采用已确认创作包或项目自己的 `motion grammar（镜头语法）`参考。
- 剪映 / CapCut 等可编辑剪辑工程导出是独立下游候选，不属于本 profile。

在已有 brief、style lock、storyboard、素材清单和审片记录中补齐下列事实，不要求为每项另建文件：

| 字段 | 必须回答的问题 |
| --- | --- |
| `productTruthSource` | 哪个已检出目录、版本、构建或已验收页面是产品事实源？ |
| `mustShowFeatures` | 哪些功能必须被观众清楚看见；每项允许作出什么事实主张？ |
| `stateAndDataBoundary` | 每个功能用什么页面状态、账号 / fixture（固定样本）和公开 / 虚构 / 脱敏数据展示？ |
| `productVisualSource` | 字体、色彩、间距、圆角、材质和已有动效从哪里读取；哪些品牌规则不得偏离？ |
| `capturePlan` | 分镜需要哪些整页 / 整窗、元素切片、交互后状态和坐标信息；怎样安全重采？ |
| `featureShotMap` | 每个必须展示功能使用什么镜头任务和可选镜头语法；备选与失败风险是什么？ |
| `audioCondition` | 当前是配音、画面还是已选强节奏 BGM（背景音乐）主导；何时锁定并怎样回测？ |
| `independentReview` | 谁在什么版本上做独立关键帧终检；输入、发现和修复回路在哪里？ |

## 1. 从产品事实建立 profile

1. 只读检查产品入口、README、主要页面 / 窗口、可运行方式、当前版本和已有品牌规范；不得为了理解产品顺手修改业务项目。
2. 把核心主张拆成 `must-show（必须展示）`功能清单，并为每项记录真实页面状态、事实证据、素材风险和不能暗示的结论。
3. 客户、个人、内部、密钥、实时或其他敏感数据在采集前改用明确授权的公开演示数据、虚构 fixture 或脱敏冻结状态；空白骨架屏和未经核验的活数据都不是可用证据。

## 2. 产品设计令牌到 styleframe

先从目标产品现有设计系统、源码、可计算样式或品牌规范提取：

- 字体家族、字重、字号层级、行高与字距；
- 色板、渐变、表面、材质、圆角、描边与阴影；
- 栅格、间距、对齐、信息密度与安全区；
- 已有动效的速度、缓动、过冲、停留和减少动态效果边界。

把这些 token（设计令牌）与本片的光感、构图家族、信息密度和动效性格写进现有 style lock。若方向仍需低成本校准，先做 1～3 张目标画幅的静态 styleframe，使用少量安全预检素材检查字体、色板、材质和构图；它不替代最终采集，也不需要先写 Remotion 代码。

已有严格品牌规范、已经验收的 style lock 或明确创作包足以约束全片时可以跳过 styleframe，但要记录依据。宣传片视觉可以为叙事调整层次，不能给真实产品另罩一套无关的“宣传片皮肤”。

## 3. 功能到镜头映射

在完整分镜前先建立一对一可追踪映射：

| 功能 / 主张 | 观众要看懂什么 | 页面状态与证据 | 首选镜头任务 / 语法 | 备选与风险 | 素材缺口 |
| --- | --- | --- | --- | --- | --- |
| `<feature>` | `<new information>` | `<state / proof>` | `<grammar ref>` | `<fallback>` | `<capture>` |

`motion grammar（镜头语法）`是可选 reference（参考层），描述一个镜头可观察的运动结构，不是可直接触发的 skill。项目使用镜头卡、动效类别或参考样片时，每项至少记录：

- `purpose`：它为哪项功能承担什么叙事任务；
- `observableGrammar`：入场、主动作、停留、离场与关键时值应呈现什么；
- `requiredState`：需要什么真实页面状态、元素和坐标；
- `sourceAndBoundary`：参考来源、允许借的抽象手法与明确不复制的表达；
- `knownFailure`：可读性、遮罩、清晰度、动效同质化或实现风险；
- `adaptation`：为目标产品改了什么，哪些动作语法仍必须保留。

没有合适 reference 时可按产品需要原创镜头，并记录验证风险。功能映射不是分镜：它先保证必须展示功能没有漏拍，再由分镜安排顺序、时长、能量曲线、字幕、转场、声音和证据。

## 4. 分镜放行后采集真实页面

最终采集只在产品 profile、style lock、功能映射和分镜一致后开始；styleframe 使用的少量预检图不能自动升为成片素材。

- Web 产品优先从可复验的本地或安全演示环境采集；桌面端 / 移动端使用项目认可的窗口、模拟器或设备采集路径。
- 截图前等待字体、图片和确定性数据状态完成；记录页面 / 窗口、交互状态、语言、主题、视口 / 窗口尺寸、像素密度、产品版本和隐私处理。
- 只采分镜实际需要的素材。存在页面相机、元素飞入或遮罩运动时，按需同时保留高分辨率整页 / 整窗纹理、语义元素切片、空底板和同一坐标系的布局信息；普通正视演示不为形式齐全强制生成三件套。
- 表现“真实产品页面”时使用真实采集；抽象开场、品牌段或独立展示组件可以原创，但不得伪装成产品当前界面或暗示未实现功能。
- 每项素材继续进入通用 manifest（清单），记录稳定 ID、项目内相对路径、来源 / 授权、对应节拍、状态、隐私处理与文件哈希。采集脚本属于当前项目的可重跑实现，不从参考仓库复制固定脚本。

页面状态、产品版本、设计令牌或分镜变化使相关采集失效；按受影响页面 / 元素最小重采，不沿用过期截图。

## 5. 音频节拍条件

先区分音乐是否真的承担 `timingAuthority（时间基准）`：

- **已选强节奏 BGM 且镜头必须卡拍**：在分镜前分析并验收节拍 / 段落结构，镜头边界和关键冲击锚到稳定拍号；保留源音乐节拍数据与渲染输出偏移两个独立记录，成片后从实际输出音轨回测。
- **BGM 只作画面完成后的支持层**：画面或配音仍是主时间基准，不为“有音乐”强制重排全片；先把候选垫进预览试听，再锁定混音与必要转场。
- **后续决定改成音乐主导**：这是时间基准变化，字幕、分镜帧级时间线、SFX、preview（预览）和旧审片确认全部失效，必须回到时间线重建。

SFX（音效）在画面时间线锁定后再集中设计，优先相对镜头 / 动作锚点而不是散落的全局裸帧号。时间线变化后重对全部受影响音效；在渲染产物中检查动作命中、人声 / BGM 遮盖、削波、长尾越界与音画漂移，不能只相信编辑器预览。

## 6. 逐镜头自检与独立关键帧终检

制作中每个镜头至少检查入场、动作峰值和落定状态；转场、高潮、结尾、隐私与小字号页面另加高风险帧。静帧检查构图、清晰度、遮罩、真实落位和事实证据，整片预览检查接缝、节奏和声音。

先准备最新版低成本整片预览及下列审查输入，再执行一次独立终检。独立终检完成前，不请求当前版本“可以正式渲染”的审片确认：

1. reviewer（审查者）不参与本轮制作判断，只读接收最新版预览、逐镜头关键帧、产品 profile、style lock、功能映射、分镜、镜头语法记录、素材清单、音频条件和事实 / 隐私边界；不接收制作辩解或预期结论；审查者依据收到的实际画面与合同报告发现。
2. 宿主支持隔离任务 / Agent 时使用独立上下文；不支持时可先做明确分离的只读预审，但必须把 `independentReview` 标为未验证并停在最终渲染门前，不得把同一制作上下文的自检假称独立。
3. 按帧号或时间码报告：必须展示功能是否齐全、页面状态是否真实、产品视觉是否漂移、镜头语法是否成立、分镜是否一致、音画是否命中、文字 / 纹理是否清楚、隐私与素材来源是否合规。
4. 每条失败附可复核帧号 / 时间码和影响；无法获得输入时写“无法验证”，不用笼统“整体不错”代替证据。
5. 发现引起观众所见 / 所听变化的问题时，回到 style、分镜、采集、实现或音频的最小受影响环节；修复后重新终检并取得当前版本审片确认。

正式母版渲染后，按同一关键帧集合复查编码、字体、纹理、字幕与隐私没有因最终输出变化；这一步与通用成品技术验收共同进入交付回执。
