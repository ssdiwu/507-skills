# 社交视觉包验收

## 先看整组联系表

- 封面能否在一秒内看懂主题与阅读承诺。
- 文章模式是否像一篇被连续排版的文章，而不是文字覆盖完整的课件；摘要模式的每张正文图卡是否只表达一个观点。
- 文章模式的物理页是否只承担阅读长度，没有被补成逐页标题、摘要、金句和结论；摘要模式的页面结构是否随观点形状变化。
- 全篇是否使用同一视觉系统和主题，没有逐页随机换皮。
- 页面密度是否稳定；留白是否服务焦点，而不是漏排内容。
- 文章模式相邻页若仍有大面积可用空间，是否已经打平旧分页继续重排；只有不可拆图片、截图、列表或标题防孤行可以成为明显留白的理由。
- 原文小节标题是否保留在原位置附近并允许出现在页中；图片证据是否在论证位置近全宽显示。
- 后半段是否仍沿原文或中心判断推进。
- 文章模式是否没有未入选内容；摘要模式的未入选重要内容是否在 Copy Spec 中有明确去向。

## 再查关键静态页

至少检查封面、最密页、每张证据图/截图所在页、每个动态图片槽首帧和结尾：

- 文章模式封面为 1500×2000、正文为 1440×2400；摘要模式图卡为 1500×2000；公众号主封面为 2100×900；分享封面为 1080×1080。
- 没有文字或媒体裁切、遮挡、溢出、标题碰撞和页脚碰撞。
- 正文字号在手机缩略图上可读，没有为塞字过度缩小。
- 人脸、关键产品、界面文字和证据焦点没有被标题或裁切破坏。
- 普通图片裁切有明确主体位置；截图默认完整包含并保持文字可读。
- 截图没有账号、群名、项目名或其他隐私泄漏。
- 作者头像与署名资产只在声明适用的封面出现；文章正文不得自动重复。
- 文件页码从 01 连续到末页；文章模式正文只有来源范围，没有逐页观点与布局元数据；摘要模式页面任务、来源映射和页面结构与 manifest（清单）一致。

## 动态图片槽

- 静态首帧与 MOV 使用同一整卡构图，视频只替换目标图片槽。
- 起点、时长和裁切与用户选定片段一致，关键动作没有被截断。
- MOV 尺寸、编码和时长通过媒体检查。
- `.pvt`、配对 JPG、MOV 和媒体状态全部存在后，才称为 Live Photo 完成。
- 缺 `makelive` 或打包失败时，静态首帧与 MOV 只能作为调试产物。

## 公众号封面对

- `21:9` 与 `1:1` 是独立构图，不是机械裁切。
- 方形封面短标题仍保留核心对象与动作。
- 两张封面使用同一视觉系统、主题、作者识别资产和中心判断。
- 组合预览在缩略图尺度仍能辨认为同一组作品。

## 内容回归

- 文章模式逐段覆盖原文且顺序一致，标题、列表、图片和图注没有漏；摘要模式每页观点都能映射回 `copy-spec.md` 与来源。
- 逐字文案没有在 HTML、图片或视频阶段被改写。
- 文章模式没有新增视觉标签；摘要模式新增标签只帮助理解，不新增来源没有的观点或事实。
- 规格页数、manifest（清单）的 `pageCount`、实际 JPG 数量和联系表页数一致，输出目录没有超出末页的旧文件；若本次改变页数，`renderedPages` 必须是 1 到末页的完整序列。
- 单页合理但不推进原文阅读或整组中心判断时仍判失败。

自动检查负责尺寸、文件完整性、溢出、字号下限、碰撞和清单新鲜度；视觉系统辨识、主体安全与整组节奏最终仍需看联系表和关键页。
