# 小红书图文（rednote）

把一篇已经成立的书面作品编辑成可继续修改、可追溯分页、可直接导出的社交图文包。调用后默认打开本地动态工作台：左侧编辑平台稿，中间连续预览全部 3:4 页面，右侧调整三轴视觉和导出设置。

用户只说“小红书图文 / 图卡”时使用 **article（连续文章）**：文章是内容单位，物理页面只是最终 DOM 的阅读切片。只有用户明确要求“视觉摘要 / 一页一个观点 / 提炼 / 精华版”时才使用 **summary（视觉摘要）**。

## 运行条件

动态预览与静态导出需要 Python 3.10+、Pillow 和本机 Google Chrome / Chromium。动态媒体额外需要 ffmpeg/ffprobe；Live Photo 打包需要 macOS 与 makelive 0.6.2+。浏览器 runtime 与两套 SIL OFL 1.1 本地字体已随 Skill 打包，普通使用不需要 Node.js、额外安装字体或网络访问。

## 覆盖什么

- 成熟主稿 → `content.md` 平台稿 → 三轴视觉计划 → 真实 DOM 分页 → 动态预览与静态导出。
- 标题、段落、列表、引语、代码、表格、受控流程图、图片和截图按原文位置进入连续内容流；工作台可把本地图片上传到作品 `assets/` 并在光标处插入标准 Markdown 图片。
- 独立封面与至少一个可用封面视觉；工作台从本地上传封面图片，用户未提供素材时调用当前可用的图片生成能力后返回，再把产物上传进作品。
- 已选定短视频替换媒体槽并后处理为 Live Photo；独立构图的公众号 21:9 与 1:1 封面对。

## 不覆盖什么

- 选题、挖素材和长文成稿；分别返回 `507-mine`、`507-fuse`、`507-forge`。
- 从长视频自动选段或剪辑、公众号正文、账号登录、上传和发布。
- 在浏览器里联网生成图片、安装依赖或把用户内容上传到外部服务。
- 把普通文章擅自重组为流程图、课件或逐页观点。

## 一等输入与产物

默认输出到作品目录的 `小红书/`：

```text
小红书/
├── content.md                 # 小红书实际可见平台稿
├── assets/                    # 工作台上传的封面与正文图片
├── visual-plan.json           # 三轴视觉、封面、字体与页面装饰
├── paged-content.json         # runtime 生成的只读真实分页产物
├── rednote.html               # 当前导出状态的只读 HTML 快照
├── render-manifest.json
├── contact-sheet.jpg
├── pages/rednote_page_01.jpg ...
├── motion/                    # 按需
└── wechat/                    # 按需
```

`raw.md` 是长文主稿，不由网页自动回写。`content.md` 允许为图片阅读调整表述、符号和主动换行，但 article 模式必须保持全部可见内容、论证顺序和来源关系。

## 内容合同

若用户同时要求提升传播、增长或重写标题以增加吸引力，先返回 [`507-forge`](../507-forge/SKILL.md) 完成标题与正文兑现，再消费确定的 `content.md` 进入视觉制作；本 skill 复用该合同，不另建标题规则。仅制作图卡时保留已有标题与承诺。

### Article

- 第一个 H1 进入独立封面；其余 Markdown 块按顺序编译为语义组件。
- 普通 `---` 是水平线；`<!-- rednote:page-break -->` 是不显示的强制分页指令。
- Markdown 链接在图片中展示完整 URL；渲染器负责机械展开。
- 页面可以在段落、句子或转折中间续页；原文标题可位于页面中部。
- `excludedContent` 必须为空；帖子正文不能补回图片中漏掉的文字。

### Summary

- 先确定一句中心判断和入选观点；每页只承担一个观点。
- 封面 H1 后用强制分页指令分隔观点段；每段必须且只能有一个标题，并完整落在一页，超出时停止而不缩字。
- 观点、证据和未入选重要内容都映射回来源，未入选内容写明去向。
- 不设固定页数，不以缩字、编造标签或重复结论维持页数。

## 三轴视觉合同

1. **语义组件**说明内容是什么：封面、标题、段落、列表、引语、代码、表格、流程、关系图、图片、截图和动态媒体。
2. **设计语言**说明整组作品如何说话；一组只使用一个基础语言。
3. **视觉呈现**说明某个组件如何被看见，并由兼容矩阵限制。

`preset` 是面向使用者的一键成品组合：它同时固定基础设计语言、具体配色、各语义组件的视觉呈现与 treatment，所以可以有很多套，并允许多套 preset 共用一种设计语言。设计语言只规定层级、网格、轮廓、间距和色彩行为，不再暗中替换具体字体；字体与阅读密度是独立、可见的 typography 状态。当前六类设计语言收在工作台高级设置中；同一区域还可逐类调整封面、标题、正文、引语、列表、代码、表格、流程图和图片的视觉呈现，手动调整后进入自定义组合。`default / inverse / section-emphasis / dense` 是 treatment，不是第四轴。文章模式中的视觉呈现绑定语义组件，不绑定物理页。详细语言、呈现与字体规则见 [`references/styles.md`](references/styles.md)，schema 见 [`assets/visual-plan.schema.json`](assets/visual-plan.schema.json)。

## 字体与阅读密度合同

- runtime 原样内嵌 Adobe Source Han Sans CN Variable 2.005R（思源黑体）与 Source Han Serif CN Variable 2.003R（思源宋体）的官方 WOFF2，均为 SIL OFL 1.1；字体文件、许可证、SHA-256 和来源进入 [`third-party-notices.md`](third-party-notices.md)。
- 默认使用思源黑体；用户可以显式切换思源宋体。切换 preset 不改字体选择，缺失或哈希不符时 runtime 明确失败，不静默回退系统字体。
- 正文、引语和列表共同消费用户选择的正文字号与行距；标题和代码仍保留各自语义角色的字号规则。
- “字符占用宽度”通过 `letter-spacing` 参与真实 DOM 换行，范围为 94%～108%；不使用不会改变布局测量的 `transform: scaleX()` 拉伸字形。
- 不把许可证未知的自定义字体上传入口混入工作台；新增字体必须先核实商业使用、嵌入、再分发、修改与保留名称边界，再进入受控字体注册表。

## 启动动态工作台

不要直接双击 `runtime/index.html`；它是前端资源，没有浏览器文件写入权限。macOS 可以直接双击 Skill 根目录的 `open-rednote.command`，选择包含 `raw.md` 的作品目录，启动器会创建/复用 `小红书/` 并自动打开工作台。

主稿已存在时：

```bash
python3 <skill-dir>/scripts/serve_rednote.py \
  --project <作品目录>/小红书 \
  --source <作品目录>/raw.md
```

脚本只在 `content.md` 不存在时从 `--source` 初始化；已有网页改动绝不被主稿覆盖。浏览器编辑自动保存 `content.md` 与 `visual-plan.json`，并重新编译 `paged-content.json`。封面上传只更新 `visual-plan.json` 的封面素材，正文上传会把 `![替代文字](assets/文件名)` 插入 `content.md`；两者都将文件保存在当前作品 `assets/`。没有人工“保存”门槛，导出才是显式动作。

跳过人工预览、使用同一 runtime 直接导出：

```bash
python3 <skill-dir>/scripts/serve_rednote.py \
  --project <作品目录>/小红书 \
  --source <作品目录>/raw.md \
  --export jpg
```

## 分页不变量

- 封面、article 正文和 summary 图卡全部为 1500×2000。
- 分页只由最终 PageShell DOM 测量产生；禁止字符数估算、简化测量 DOM 和 HTML 字符串分页。
- 正文、标题和引语不缩字；列表优先按条目续页；代码按完整代码行续页；表格有限压缩后按行续页并重复表头。
- 图片、截图和流程图优先完整包含；低于可读阈值时失败，不裁切或隐藏。
- 预览一行显示一页、两页或多页只取决于工作台宽度，不改变真实分页。
- `paged-content.json` 记录输入哈希、页面可见文字、组件片段、来源范围、分页原因和溢出证据；它只能由 runtime 写入。

## 导出与可选载体

- PNG、JPG、PDF 和 HTML 使用动态预览同一个前端 bundle、三轴 Resolver、PageShell 和分页器。
- 只有当前内容、视觉计划和分页哈希一致且所有页面 `overflow=false` 时允许导出。
- 页数变化走全量导出并清除旧页；联系表、manifest 和实际文件页数必须一致。
- `render_rednote.py --spec` 只保留为旧 `rednote-project.json` 的迁移与现有动态媒体/公众号后处理入口，不再作为 article 的默认分页器；迁移完成后删除旧主路径。

## 交付硬门

1. `content.md`、`visual-plan.json`、`paged-content.json` 和 manifest 的哈希关系新鲜。
2. 每个可见 fragment 回链组件来源范围，续页 `visibleRange` 连续覆盖组件文字，完整 URL 存在，所有页面 `overflow=false`。
3. 页面、清单、实际图片和联系表均为同一页数，图片尺寸全部为 1500×2000。
4. 打开工作台检查桌面双列、窄屏单列、刷新恢复、样式切换重新分页和错误状态。
5. 切换两套本地字体与字符占用宽度，确认字体真实加载、分页重新编译、相同 typography 在不同 preset 中保持同一字体度量。
6. 打开联系表以及封面、最密页、表格/流程图/图片页和末页做视觉验收；规则见 [`references/visual-review.md`](references/visual-review.md)。
7. Live Photo 只有 JPG、MOV、`.pvt` 和媒体校验全部成立才完成；公众号封面对只有两张独立构图和组合预览全部成立才完成。

## 完成与接力

- **完成信号**：动态工作台与直出均消费当前文件状态；连续文章或视觉摘要合同成立；真实分页无裁切；请求的静态与可选载体产物通过自动和视觉验收。
- **产物**：平台稿、三轴视觉计划、真实分页产物、动态工作台状态、HTML、静态图片、联系表、manifest，以及按需生成的 Live Photo 和公众号封面对。
- **候选出口**：内容不成立时返回写作链；视觉方向未定时用真实内容候选收敛；成品完成后直接交付或进入另行授权的发布流程。
- **回退条件**：文件状态不新鲜、来源覆盖缺口、分页溢出、素材授权不清或可选载体不完整时保持未完成。

## 红线

- 不把视觉摘要当作文章模式默认值。
- 不让视觉计划改写内容语义。
- 不把预览候选、临时页数或旧 manifest 冒充成品。
- 不裁半行、半字、表格行、流程节点、人脸、关键 UI 或证据焦点。
- 不依赖远程 CDN，不把 RedNoteImage 的代码、模板或资产直接复制进本 Skill。
