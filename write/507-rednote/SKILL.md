# 小红书图文（rednote）

把一篇已经成立的书面作品编辑成社交图文包。用户只说“小红书图文 / 图卡”时，默认采用**全文模式**：保持原文措辞、论证顺序、图片与图注，只做连续分页和视觉层级；只有用户明确要求“视觉摘要 / 一页一个观点 / 提炼”时才进入**摘要模式**。两种模式都不能歪曲中心判断或关键证据。

## 覆盖什么

- 成熟主稿 → 全文载体合同 → 连续分页 3:4 静态图卡 → 全文覆盖校验、联系表与验收。
- 用户明确要求提炼时：成熟主稿或已确认逻辑文案 → 视觉摘要合同 → 一页一个观点的 3:4 静态图卡 → 联系表与验收。
- 用户已经选定的短视频 → 替换某页图片槽 → 整卡动态 MOV → Live Photo `.pvt` 包。
- 已确认标题与视觉资产 → 分别构图的公众号 `21:9` 主封面与 `1:1` 分享封面 → 组合预览。
- 根据反馈修改观点、布局或视觉系统后重新渲染；静态页可在全局配置不变时局部重渲染。

## 不覆盖什么

- 选题、挖素材和长文成稿，分别归 `507-mine`、`507-fuse`、`507-forge`。
- 从长视频自动选段、变速、剪辑，或二至四宫格多视频实况拼图。
- 单张海报、纯图片修图、公众号正文、账号登录、发布或运营。
- 在渲染阶段静默联网取图或安装缺失依赖。

## 输入与输出

输入优先级：已确认的 `copy-spec.md` > 已发布/待发布主稿 > 其他草稿。

默认输出到作品目录的 `小红书/`：

```text
小红书/
├── README.md
├── copy-spec.md
├── rednote-project.json
├── style-preview/style-gallery.jpg
├── rednote.html
├── render-manifest.json
├── contact-sheet.jpg
├── pages/rednote_page_01.jpg ...
├── motion/page_XX_live.mov
├── motion/page_XX_live.pvt
└── wechat/
    ├── wechat-main.jpg
    ├── wechat-share.jpg
    └── wechat-cover-pair.jpg
```

没有动态图片槽时不创建 `motion/`；没有公众号封面对时不创建 `wechat/`。

## 工作流程

### 1. 先锁定成品模式与内容合同

先根据用户用语选择模式，不把选择成本再抛给用户：

- 只说“小红书图文 / 图卡 / 编辑小红书” → **全文模式**。
- 明确说“视觉摘要 / 一页一个观点 / 提炼 / 精华版” → **摘要模式**。
- 同时要求全文与摘要 → 先分别建立两个明确出口，不能用摘要冒充全文。

全文模式先把以下内容写入 `copy-spec.md`：

1. 唯一主稿与完整性边界：哪些 Markdown 控制符可以移除，哪些标题、正文、列表、图片和图注必须逐项显示。
2. 按原文顺序形成的连续分页表；分页只切版面，不改写、概括、删减或重排原文。
3. 图片与截图在原文中的位置、显示方式与可读性要求。
4. 平台页数上限；原文超出单篇容量时，必须说明并拆成连续系列，不得偷偷删字或缩到不可读。
5. 全文覆盖验证方法；全文模式的 `excludedContent` 必须为空。

摘要模式才从来源提取：

1. 一句中心判断。
2. 入选观点 `P1`、`P2`……；每项只承担一个读者理解任务，并记录来源位置与关键证据。
3. 未入选的重要内容 `X1`、`X2`……及去向：帖子正文、配套文案、后续系列或明确不采用。
4. 主稿图片与截图清单，以及正文保留、改作封面或不采用的理由。
5. 帖子标题、封面标题、作者识别资产和目标载体。
6. 动态图片槽所用的用户选定短视频、起点、时长和裁切重点；没有合适片段时不替用户做叙事选择。

两种模板见 [`references/copy-spec.md`](references/copy-spec.md)。主稿未成立时返回 `507-forge`；摘要模式下观点之间不能共同支撑中心判断时返回 `507-fuse` 或 `507-grill`。

### 2. 按模式分页

全文模式：

- 原文顺序是硬约束；标题、小节、正文、列表、图片与图注全部进入图卡。
- 每页可以承载同一连续论证中的多个段落；`point` 用于记录本页阅读任务与来源片段，不授权改写原文。
- 优先在自然段、小节或图片边界分页；为避免孤行可以前后移动整段，不能把句子截断到两页。
- 通过字号层级、段落间距和强调块适配容量；不得用灰到难读、低于字号门槛或视觉拥挤的方式强塞。
- 平台容量装不下时拆成连续系列，并明确每篇覆盖范围。

摘要模式：

- 封面只建立主题与阅读承诺，不同时展开多个正文观点。
- 每个正文页必须有唯一 `point`、来源映射和显式页面结构。
- 例证、步骤、数据或对比可以支持本页观点，但不能形成第二条竞争主线。
- 不设固定页数。内容不足就减少页数，观点过多就压缩选择或拆成系列。
- 不为填满画布编造标签、数据、步骤、装饰信息或行动建议。
- 旧 `layoutMode` / `stylePreset` 规格不再接受；先按迁移提示改成显式观点页。

### 3. 选择视觉系统与页面结构

按 [`references/styles.md`](references/styles.md) 选择：

- `visualSystem` 决定整组排版语言，只能选一套；首批为编辑杂志与瑞士国际主义。
- `themePreset` 决定该视觉系统内的配色和材质。
- `layout` 由当前观点形状决定；封面、判断、证据、对比、步骤、清单、数据与结尾使用不同结构。

用户未指定时，先生成封面与一页正文的候选联系表。选样必须同时看封面和正文，不按上一份作品的惯性选风格。

### 4. 处理静态媒体

- 普通照片使用 `image`；必须显式设置裁切与主体位置。
- 应用、网页、终端和代码截图使用 `screenshot`；默认等比包含并保留可读文字。
- 图文叠加前先识别主体与安静区；标题不得遮挡人脸、关键产品、界面文字或证据焦点。
- 图片只接受本地路径或 `data:` URI，不接受远程 URL。

### 5. 处理动态图片槽

- `motion` 只接受用户已经选定、时长合规的短视频；每页最多一个。
- 脚本先用 `ffmpeg` 抽取指定时点的首帧，按静态图片槽完成排版与视觉检查。
- 浏览器测得图片槽的真实坐标后，脚本把短视频合成进整张静态卡片，生成同尺寸 MOV。
- Live Photo 打包使用外部 `makelive` CLI；脚本不安装依赖，也不修改源视频。
- 缺 `ffmpeg/ffprobe`、视频无有效画面、时长越界或缺 `makelive` 时必须失败。静态首帧或 MOV 可以作为调试产物保留，但不得称为 Live Photo 完成。

### 6. 生成公众号封面对

- `21:9` 主封面和 `1:1` 分享封面必须在规格中分别提供标题和构图，不能机械裁切。
- 两张封面共用视觉系统、主题、作者识别资产和中心判断。
- `1:1` 标题可以更短，但必须保留核心对象与动作。
- 同时生成组合预览检查两张图是否像同一组作品。

### 7. 创建机器规格

按 [`assets/rednote-project.schema.json`](assets/rednote-project.schema.json) 和 [`references/project-spec.md`](references/project-spec.md) 创建 `rednote-project.json`。每页的 `point`、`sourceMap` 和 `layout` 必填；顶层 `excludedContent` 必须存在。全文模式必须为空数组；摘要模式可记录未入选内容及去向。

### 8. 渲染

```bash
python3 <skill-dir>/scripts/render_rednote.py \
  --spec <作品目录>/小红书/rednote-project.json \
  --output-dir <作品目录>/小红书
```

有动态图片槽时可显式指定打包工具：

```bash
python3 <skill-dir>/scripts/render_rednote.py \
  --spec <...>/rednote-project.json \
  --output-dir <...>/小红书 \
  --makelive /path/to/makelive
```

静态页内容变化时可用 `--pages 3,5` 局部重渲染；视觉系统、主题、头像、页数、动态图片槽或公众号封面对变化时必须全量重渲染。运行条件见 [`scripts/README.md`](scripts/README.md)。

### 9. 交付硬门

每次修改规格、图片、视频、头像或全局视觉后，必须重渲染受影响输出。交付前独立核对：

1. `render-manifest.json` 的 `status` 为 `rendered`，规格 SHA-256 与当前 `rednote-project.json` 一致。
2. 全文模式逐项证明主稿标题、小节、正文、列表、图片与图注覆盖完整，顺序一致且 `excludedContent` 为空；摘要模式每张图卡记录唯一观点和来源映射，未入选的重要内容有去向。
3. 图卡、HTML、联系表和清单齐全；自动检查没有溢出、标题碰撞、页脚碰撞、不可读字号或错误媒体裁切。
4. 动态页只有在整卡 MOV、`.pvt` 包、媒体校验和静态首帧都存在时才算 Live Photo 完成。
5. 公众号模式只有在 `21:9`、`1:1` 和组合预览全部存在且尺寸正确时才算完成。
6. 打开联系表和关键页做视觉验收；规则见 [`references/visual-review.md`](references/visual-review.md)。

失败时回到 `copy-spec.md` 或 `rednote-project.json` 重渲染，不直接修 JPG、MOV 或 `.pvt`。

## 完成与接力

- **完成信号**：当前规格与清单新鲜度一致；全文模式覆盖原文且顺序一致，或摘要模式观点与来源映射完整；静态和请求的可选载体产物齐全，自动检查与视觉验收通过。
- **产物**：全文图文或视觉摘要规格、单文件 HTML、3:4 图卡、联系表、渲染清单，以及按需生成的 Live Photo 和公众号封面对。
- **候选出口**：中心判断不成立时返回 `507-forge`；观点竞争时返回 `507-fuse`/`507-grill`；缺必要静态素材时调用独立素材能力后返回；发布包完成后直接结束或交给另行授权的发布流程。
- **回退条件**：规格与产物不新鲜、来源映射缺失、可选载体不完整或视觉检查失败时，保持“未完成”并返回规格。

## 红线

- 不把“视觉摘要”当成歪曲或杜撰许可。
- 不在用户只要求“小红书图文”时擅自把全文改成视觉摘要。
- 不把帖子正文当作补回全文图卡删减的兜底；全文模式的原文必须实际显示在图卡中。
- 不在渲染阶段临时改观点或可见文案。
- 不把旧长文规格静默当作新观点页。
- 不自动安装依赖、联网取图或上传正文、图片、视频、头像和凭据。
- 不裁切人脸、关键 UI、产品细节或视频主体而不记录取舍。
- 不把静态首帧或普通 MOV 冒充 Live Photo。
- 不复制外部参考项目的代码、模板、文档正文或视觉资产。
