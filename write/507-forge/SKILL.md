# 锻造（forge）

把创意和创作材料共创成**可发布的书面成品**。默认不是逐段审批，而是先确定当前写作合同和作者模型，由 Agent 写出接近发布状态的完整版本，再用用户反馈校准剩余偏差。用户不承担替 Agent 补完结构、论证或声音的常规改稿工作。

## 一、职责与边界

**负责**：长文成文、已有草稿重组、同一创意的书面平台保真改编。

**不负责**：
- 无边界挖掘素材或重新发明选题（归 `507-mine` / `507-fuse`）；
- 讲稿、PPT、课程口播（归 `507-stage`）；
- 正式方案或计划（归 `507-frame`）；
- 封面、配图、HTML、分页视觉和最终渲染（交给设计或图片 skill）。

`shape / beats / edit` 只是 Agent 内部可取用的写法，不向用户暴露为模式。文章也没有全局“调性”开关：事实处可以克制，荒诞处可以毒舌，表达力度随内容变化，但作者立场与中心判断必须一致。

## 二、自动入口

1. 先读项目已有的 `AGENTS.md`、根 `README.md`、`doc/README.md`、术语表，以及创意区／作品区约定。
2. 查找当前创意卡和已有主稿；项目已有路径约定时直接使用，不再询问保存位置。
3. 已有经用户确认的创意卡，先检查其是否已有按核心争点整理的材料；齐全才把它作为当前依据。
4. 没有创意卡但中心判断和材料已明确，先自动建立或补齐创意区；若原始材料尚未碎片化进入 `507-mine`，若尚未比较竞争解释进入 `507-fuse`，再返回成文。
5. 外部事实缺口进入 `507-research`，写作碎片缺口进入 `507-mine`，竞争解释进入 `507-fuse`。存在真实竞争路径时，携带候选进入 `507-grill` 让用户决定中心判断，再返回 forge；材料只支持一条路径时，说明收敛理由后可继续。不让用户手动调度技能链。

不询问内部写作模式；需要用户选择中心判断、读者承诺或风险边界时统一进入 `507-grill`，不在 forge 内临时发明一套确认流程。

## 三、写作合同

动笔前确保创意区存在当前有效的：

- **中心判断**：全文最终要让什么判断成立；
- **读者入口与承诺**：读者正处在哪个具体困境、决策、误解或未解问题中，因此需要这个判断；若文中承诺提供可复制资源（提示词、模板等），写清它在哪里出现、读者能拿走什么；
- **论证链**：读者按什么顺序被带到这个判断；
- **核心争点材料**：每个关键推断的支持证据、反例、替代解释、适用边界/缺口与时间或制度语境；
- **证据与边界**：哪些事实承重，哪些只是作者判断；个案能证明什么、不能推出什么；哪些材料会动摇主张。
- **观点型立场（按需）**：本篇具体要纠正、反对或替换什么命题，作者提出什么解释、标准或行动主张；材料中没有真实分歧时省略，不为教程、资料整理、概念解释或事实报告强造敌对命题。

读者入口只负责建立相关性和阅读预期，**不承重事实**：不得为了代入感编造故事、堆情绪词，或让个案替代证据。

若核心争点材料缺失，写作合同未成立：按缺口分别进入 `507-research`、`507-mine` 或 `507-fuse`；需要用户选择候选路径时进入 `507-grill`，不得直接起草。只有材料经核对后只支持一条路径，才能带着收敛理由进入成文。

“锁定”指当前版本可追踪，不代表不能改：
- 用户明确给出新中心或新顺序时，简短复述变化后直接更新创意区并统一重写；
- 反馈看似局部但可能改变全文时，携带新的写作合同进入 `507-grill` 确认用户取舍，再返回统一重写；
- 禁止把改变主线的新判断局部塞进旧稿。

## 四、共创循环

1. 读取完整创意材料、已有主稿、同一作者已发布作品和既有明确纠正；先确定项目约定的唯一正文真相源，平台稿只能从它派生而不能成为并列主稿；确认写作合同中的核心争点材料完整后，先形成一篇可从头通读且已体现作者模型的版本，不逐段等待确认，也不等用户先改一轮才学习怎么写。
2. 用户反馈若只影响局部，精确修改；若改变中心、论证链或某个核心争点的解释，按写作合同规则处理受影响全文；新出现的外部事实缺口进入 research，材料缺口进入 mine，竞争解释进入 fuse，不局部硬塞。
3. 每次写入前重读目标主稿，保留已有手改，不另建同题平行稿。
4. 成文中新增的一手来源、二手参考、案例、反例、替代解释、事实边界和新判断，先回写创意区，再用于作品。
5. 创意区保存“为什么写、拿什么写”；作品区只保存具体成品及成品实际使用的附件。
6. 平台改编先继承原写作合同，可改变篇幅、分页和信息密度，不得借适配之名重写成另一篇；视觉实现另行路由。

### 作者模型与首稿责任

作者模型不是聊天口癖表，也不是等用户手改后再被动追认。动笔前要从同一作者的已发布作品、创意卡、历史明确纠正和当前一手叙述中，主动归纳并在首稿中落实五类稳定选择：**冲突从哪里起、判断下到多深、证据按什么顺序出现、责任主体如何落到“谁做了什么”、句子靠什么形成力度**。目标是首稿已经完成约九成的结构、论证、证据与声音，用户只需校准观点精度和少数个人细节。

对 507 的书面文章，当前已确认的作者模型是：

- 从真实场景里的具体问题起笔，按“原问题 → 摘出隐藏等号或默认前提 → 追问前提为何存在 → 推向行业争议”推进；先让读者看见被质疑的对象，不在对象出现前连续堆叠悬空问题。可以延后结论，不能延后冲突。
- 论证顺序服从冲突强度与文章中心，不服从材料的编号或出现顺序。开头列出“第一个／第二个”后，正文仍可明确“先说第二个”：编号标识讨论对象，“先／再”标识成文顺序；优先拆标题承载、最能带动全文的那个矛盾，再回收其余问题。
- 对已经形成判断的观点型作品，不以表面中立换取无争议。先让读者能够复述作者反对什么、相信什么，再处理反例与边界；边界用于校准适用范围，不能把判断稀释成“双方都有道理”。
- 对观点尖锐，对事实诚实；挑战命题、标准和结构，不替每个具体的人揣测动机。锋利来自把真正分歧说清楚，不来自情绪更重、措辞更狠或删掉必要边界。
- 主要证据优先来自“我实际怎样做”：用动作和责任分工写清定义、取舍、驱动、验证与交付，不用抽象能力清单代替亲历。
- 允许反问、短句、重复推进、括号补刀和带摩擦的口语；编辑时只修复无意的错字、病句与逻辑断裂，不把它们统一抛光成对称、圆润、像总结报告的句式。
- 标题和小节要推进争论；方法部分优先给有依赖关系的具体动作，只有真实目标受时间约束时才硬切成“几周计划”，不为显得完整虚构日程。
- 结尾先把中心判断完整落下；需要表明“不再迎合这类反驳”时，可以再留一句短促反讽作为态度余音，但不能靠它引出新论点，也不以空泛鼓励收束。

用户的新修改是更新作者模型的样本，不是后续工作必须等待的前置步骤。每次出现明确纠正，都要判断它改变的是单篇事实还是可迁移的写作选择；可迁移部分从下一次首稿开始直接执行。不要机械复制“我会认为”“理解一下”等协作口癖，也不要把偶然错字、无意重复或单篇节奏固化成作者风格。

### 解释推进与同案重跑

当文章需要修正读者已有解释时，不从正确答案直接宣告，也不把下面的分析顺序机械写成固定目录：

1. 选择一个足以承重的最小场景，让读者原有解释实际运行，而不是用一句“传统观点不行”提前宣布失败。
2. 找出旧解释无法说明的首个可观察缺口；缺口必须落在同一场景里的动作、结果、条件或边界，不能靠作者旁白制造。
3. 一次只补入一个解决当前缺口的必要区分，并回到同一场景重跑，让读者看见加入前后究竟发生了什么变化。
4. 将各区分接回一条完整关系，说明什么条件通过什么机制产生什么结果；概念只负责补缺口，不为显得深刻而堆叠。
5. 用距离较远的迁移场景或一个看似相同但不成立的反例校准边界。迁移与反例不必都写进正文，但主张至少要留下成立依据或失效条件。

这套推进只服务于存在旧解释、可观察缺口和必要新区分的文章。教程、事实报告、资料整理或读者尚无稳定旧解释时，直接选择更自然的论证顺序，不制造假缺口，也不反复回到案例拖慢正文。

### 真实链与图片证据

当文章来自作者亲历的尝试、协作或判断变化时，优先按真实因果组织：**未解处境或失败尝试 → 出现的工具/方法 → 可见的产物 → 他人或现实给出的具体反馈 → 作者据此作出的取舍**。工具不是开场的主角，而是对前一处困境的回应。

图片不是配图占位。每张图必须承担一个可说清的作用：证明此前确实卡住、展示产物是什么、或让读者看见反馈如何发生。图片放在它所证明的动作之后、由它引出的反馈之前；不要把“反馈图”放在“产物图”前面，也不要用正文替图片再讲一遍读者已经看见的东西。

多张截图若展示同一原型、流程或产物的不同状态，优先组合成一个证据单元，并用正文或图注说明这些状态共同证明了什么；没有时间顺序证据时只称“不同状态”，不包装成迭代过程。机制图负责解释、过程截图负责举证、结果图负责验收；无论版面是否空，都不补与论证无关的通用 AI 插画、氛围图或摆拍式场景图。

结尾只交付当前文章已经承诺的判断、材料或下一步。没有真实经历和材料承接的协作流程、产品边界或方法论总结，不因为“文章需要收束”而硬加；它们会把一篇已成立的实践文带离主线。

## 五、证据与经验接力

- **一手信息源是事实基石**：优先官方公告、原始论文、产品文档、当事人原文和真实产品证据。
- **二手聚合源是线索与写法参考**：用于发现背景、争议和表达方式；关键事实尽量回溯一手来源。
- **碎片承载既有判断，不自动等于事实成立**：涉及外部事实时仍要回溯原始来源。
- 论点缺外部事实时进入 `507-research`，缺可复用观点或经验时进入 `507-mine`，替代解释未比较时进入 `507-fuse`；新证据动摇写作合同时，暂停成文并经 `507-grill` 重选用户拥有的路径后返回。

发现可复用的写作失败时，先搜索项目 `doc/经验笔记.md`；文件不存在则按项目约定惰性创建。没有同类条目就按“现象 + 做法 + 证据”记录，已有条目只追加独立作品证据。跨至少三篇作品重复、且能解释共同机制时，再主动提出提升为主规则；单次事故不直接改本文件。

## 六、交付门

交付前先锁定不能漂移的内容：标题、引语、事实与判断的归属、人物或系统主体及其动作、数字及其修饰对象、日期与时间关系、专有名词、技术术语，以及因果、包含、先后和完成状态。表达审计只能在这些保护项不变的前提下进行。标题、引语和稳定术语还要保留作者已经采用的表层写法，不擅自翻译、展开缩写、增加括注或统一格式；Agent 协作层的术语解释约定不得自动进入书面成品。

再清理模板感和表演感：删除不承载独有事实、判断或必要过渡的空总结；把虚假主语、旁白式提示、成串连接词和表演性技术腔改回材料中已有的具体主体与动作；二元对比若只为制造洞见感，直接写成立的那一半。关键词该重复就重复，不用同义词轮换掩盖重复。不得为了更自然补充原文没有的事实、数字、经历或动机。

长文默认采用受限审计：不重排已经成立的论证，不合并承担节奏的实句，不把反问、有意重复、括号补刀、长短不一的呼吸和带摩擦的口语机械判成问题。只有删掉后信息点与过渡都不变的整句才可删除；否则只做句内降调。目标是去掉统一的模型腔，不是把作者声音抛光成另一种统一腔。

只有用户明确要求“去 AI 味”“自然一点”，或全文反复出现同类模板结构而上述审计只能识别现象、不能定位变体时，才完整读取 [中文高风险表达信号](./references/chinese-expression-risk-signals.md)；不要因为作品使用中文就默认加载。该表只提供候选信号，不改变本节的保护顺序：先判断语境、功能和作者手迹，再决定删除、降调或原样保留。不得按命中次数自动改写，也不得把词条中的替换箭头当成全局替换表。

随后完整通读，只检查六件事；未通过就修正文，不用清单宣言代替修复：

1. **写作合同一致**：正文仍在回答当前中心判断，论证链没有漂移，结尾没有另起主线。观点型作品还要让读者能够复述它反对的具体命题、作者自己的判断和提出的替代标准；缺少其中任何一项时补论证或收窄主张，不靠强化标题和语气伪造锋利。
2. **证据承重**：关键事实有一手来源或明确降格；作者判断没有伪装成事实或成熟概念的原创命名；每个核心争点的替代解释、反例和边界均已在创意区比较并被有意识地采用或舍弃；个案或情绪不能独自承载对群体、行业或制度的概括——要么补足横向证据，要么收窄为个案解释。观点的辨识度不能替代事实、亲历或实践证据。
3. **全文成立**：每一部分都在新增事实、因果或必要判断；删掉不影响全文的空心句直接删。
4. **读者入口兑现**：开头让读者看见这和自己的什么处境有关；若承诺提示词、模板等资源，正文在约定位置交付完整内容，而不是用空洞钩子吊着读者。相关性来自真实处境，不把情绪或个案伪装成证据。
5. **声音保真**：清理后的句子仍有具体主体、动作和作者判断；事实、关系与责任主体没有漂移，必要修辞和不均匀节奏没有被统一抹平，也没有用新的口号、金句或虚构细节填补删改后的空位。
6. **交付格式正确**：遵循目标平台与作品区约定。中文正文进入发布收口时，普通正文段落统一加两个全角空格 `　　`；标题、列表、引用、图片、表格和代码不加。

完成标准是 Agent 已独立完成结构、主要论证、证据和作者声音，经过少量校准后可发布的主稿；不得把“声音层需要用户自行手改”当作提前停工的理由，也不得把多轮大改默认成正常流程。

## 完成与接力

- **完成信号**：唯一主稿通过写作合同、证据承重、全文成立、读者承诺、声音保真和目标平台格式检查，已达到可发布状态。
- **产物**：作品区中的可发布书面主稿，以及同步更新的创意材料与实际附件索引。
- **候选出口**：外部证据、碎片、竞争解释或用户取舍不足时分别进入 `507-research`、`507-mine`、`507-fuse`、`507-grill` 后返回；需要现场讲述时进入 `507-stage`；需要小红书图片文章时进入 `507-rednote`；书面主稿即终点时直接结束。
- **回退条件**：中心判断、论证链或事实承重仍不成立时不进入平台适配，不用视觉包装掩盖内容缺口。
