# 框定（frame）

这个 skill 用来辅助用户起草结构化的方案、计划或文档。

## 这个 skill 覆盖什么

活动方案、培训方案、工作坊方案、合作提案、项目计划——任何"有明确结构、面向特定受众、用于推动决策或行动"的方案/计划/文档。

## 这个 skill 不覆盖什么

- 营销文案、公众号文章、博客
- 内部备忘录、工作日志
- 具体软件产品的行为、范围与验收规格（归 `507-prd`）
- 仍需用户确认的意图、边界或风险取舍（归 `507-grill`）
- 内容润色、代码审查
- 闲聊

## 输入合同与草稿状态

`507-frame` 根据已经确认的需求起草方案，不承担确认需求本身。动笔前先检查目标受众、目的、范围、关键约束和成功标准：

- 缺口能从资料或项目规则核实，或只涉及写法、章节与呈现时，Agent 自行处理并说明；专业判断不能补造业务事实、数字、责任或用户承诺；
- 缺口会改变用户意图、权责边界、体验、成本或风险时，携带当前草稿返回 `507-grill`，确认后再继续；
- 用户只要求先建立讨论载体时，可以写草稿，但必须显式区分**已确认共识**、**当前建议**和**待确认决策**，不得把它当正式执行依据。

确认完成后更新同一份文档，作为当前方案的唯一正文，不保留貌似正式、实际已过期的平行方案。

## 相关 skill

如果用户要写的是**现场分享稿、PPT 逐页稿、课程讲稿、企业培训演讲稿**，尤其是案例型分享风格，优先使用 `507-stage`。

`507-frame` 负责正式方案和结构化文档；`507-stage` 负责现场讲述和 PPT 内容风格。

## 一、调性：方案读起来应该像什么

读起来像"认真在做一件事"，不像"想推销你"，也不像"内部在讨论"。

- **独立方案**：不把"翻译自 XX""基于 XX 方法论""参考了 XX 文档"等制作说明当正文开场；事实依据、必须保留的来源和正式引用仍按其用途保留
- **正式但不营销**：不用"赋能""转型""价值闭环""强强联合"等空话
- **信息密度高**：每段话都有可读出的具体信息，不用"与此同时""考虑到""作为"等连接词凑字
- **结构清楚**：章节序号、表格、必要的清单——读者扫一眼就能抓到结构
- **不口语化、不内部对话**：不写"我们讨论后认为…""伙伴的反馈是…""经过几轮迭代…"

**反面例**（AI 风格的段落）：

> 在 AI 时代浪潮下，我们深入探讨 AI 如何赋能传统行业，致力于打造一站式、全链路的 AI 升级解决方案。我们的核心团队深耕多年，构建了从底层逻辑到应用层的完整闭环。

**正面例**（假设资料已经确认下列人数、时长与安排；这些信息不能从反面例推导）：

> 这次要做的是帮 B 端客户把已经用上的 AI 工具整合成完整工作流。先做一个 1.5-2 小时的小范围工作坊，挑 10 位老板，把每家的工作流现场拆解，落地后再对接 1v1 诊断和陪跑。

## 二、7 个表达原则

这 7 条来自一次完整的演讲稿 / PPT 打磨，适用于方案、计划、课程稿和企业分享内容。

### 1. 少讲场面话，直接进案例

先给事实，不先给观点。

不要先写：

> 今天我们将系统探讨 AI 如何进入企业工作流。

更好：

> 这是一家租车公司。它的车会放到多个平台上出租。AI 已经可以做查价前置动作。

### 2. 用“案例事实 → 判断 → 下一步”推进

优先按这个顺序写：

```text
案例里发生了什么
这说明什么
下一步怎么做
```

示例：

```text
AI 已经能查价。
但查价只是流程里的一个点。
下一步是看它能不能接住还车、维修、投诉、结算。
```

### 3. 比喻只在关键处用

比喻要帮助理解，不要抢主题。

可用比喻：

- 台账像行车记录仪，记录过去。
- 流程表像导航，推动下一步。
- 自动化像闹钟，到点响就行。
- AI 写回记录像接力赛，把下一棒交出去。

### 4. 句子短一点，少用抽象词

不要写：

> 实现业务流程自动化闭环，构建企业级 AI 工作台。

更好：

> AI 读表。AI 写回表。飞书自动推送。人处理确认。结果再回到表里。

### 5. 每一页 / 每一节只承担一个推进任务

不要一页里同时讲背景、问题、方法、边界、结论。

更好的台阶是：

```text
AI 已经接了查价
查价只是一个点
AI 接不住散信息
所以要一张表
表要有字段
字段能触发动作
```

### 6. 不替读者太早总结

不要一上来就把大结论压给读者。

先让读者看到事实变化，再让结论自然长出来。

### 7. 保留现场口语感

这里的口语感指自然、易理解的句子，不把正式方案改成聊天或讲者口播。方案仍保持正式文档角色，但不要写成 AI 宣传稿。

更像自然口语的句子：

> 这一步已经跑起来了。但它现在只是流程里的一个点。

不要写：

> 该案例体现了 AI 在业务流程中的初步落地价值。

## 三、6 条写作原则

| 原则 | 含义 | 反例 | 正例 |
|---|---|---|---|
| **具体而非抽象** | 用数字/动作/对象替代形容词 | "小规模、高质量" | "10 位左右，邀约制" |
| **主动而非被动** | 执行者已知时写清谁做什么；执行者未知时保留未知 | "培训由团队交付" | "团队交付培训" |
| **正面而非双重否定** | 普通介绍优先说做什么；真实排除与禁止范围必须保留 | "现场不做完整改造" | "现场范围不包含完整改造" |
| **删除冗词** | 砍"内部对话""作为""与此同时""考虑到" | "考虑到活动的定位，我们认为 3 段方法是比较合适的" | "用 3 段方法" |
| **相关信息紧邻** | 同一段内的"做什么/为什么"靠近，不要打散 | "老板需要做一件事。（中间隔了 5 段其他内容）这件事就是带 SOP 来……" | "老板带 SOP 来；现场拆解" |
| **关键信息放末位** | 普通叙述可将重点放结尾；执行必需的条件、限制与风险必须先于对应动作 | "老板带走的是……怎么改（中间插了 8 行修饰）" | "老板带走 1 件事：怎么改" |

## 四、AI 词反清单（中文）

下列词语与句式只用于提示可能的空泛表达。Agent 必须先判断它是否有项目定义、事实作用、正式引用或作者文体用途；不能按字面禁用或替换。表达强度、条件、否定、数量和确定程度不因润色改变。

**Puffery 形容词**：划时代、里程碑式、标志性、典范性、重中之重、至关重要、不可或缺、举足轻重、卓越、杰出、非凡

**空话短语**：致力于、旨在、力图、不断推动、持续赋能、深入贯彻、全面落实、全方位、立体化、多维度

**营销/AI 高频词**：赋能、助力、引领、打造、构建、矩阵、体系、生态、闭环、链路、赛道、底层逻辑、深耕、颠覆、变革、转型、升级、智能化、智慧化、数字化、定制化、一站式、全链路、端到端、突破性、开创性、无缝、稳健

**AI 高频动词**：深入探讨、深度解析、全面剖析、系统梳理、聚焦、发力

**AI 句式**：
- "在 X 时代背景下..."
- "随着 X 的不断发展..."
- "众所周知..."
- "不难发现..."
- "X 扮演着至关重要的角色"
- "是大势所趋"
- "在这样的背景下..."
- "既是 X，也是 Y"
- "这不仅是 X，更是 Y"
- "我们坚信..."

## 五、写法反清单

| 不要做 | 原因 | 反例 |
|---|---|---|
| **不挂制作来源作开场** | 方案正文独立陈述；必要事实来源与正式引用保留 | "本次方法论基于《XX 课程》第 2、5、8 课" |
| **不写议论稿** | 方案是陈述不是讨论 | "我们认为，本次沙龙的核心价值在于……" |
| **不写未聊透的内容** | 没确认的别写 | "风险控制（5 列表格：风险/触发/预防/兜底/责任方）"——没聊透就不写 |
| **不包太多** | 章节数按规模灵活 | 2 小时活动不写 11 章 |
| **不写 v1/v2 叙事** | 方案不是迭代记录 | "v1 我们考虑过 99 元，v2 改成 199" |
| **不写案例叙事** | 方案不是故事 | "在和某人讨论的过程中，我们意识到……" |
| **不写工具用法清单** | 内容是工作流不是工具科普 | "朋友圈文案生成、客户跟进话术、爆款标题公式……" |
| **不写"对企业的价值"+"对学员的价值"两栏** | 在具体场景里人就是企业本身 | 拆分只在泛指场景下有意义 |
| **不写"联合发起人"** | 角色包装太重 | 直接说"案例合作方 + 社群入口" |
| **不写内部决策过程** | 方案不是工作日志 | "我们讨论后认为…" → 直接写"做 X" |
| **不用空泛辩护句** | 只清理不增加事实的自我辩护；真实否定、例外、约数和不确定性必须保留 | 见下方「肯定句原则」 |

### 肯定句原则（重要）

普通方案叙述优先直接说清对象、动作和结果，不用无信息的辩护导语。否定句本身不表示不自信：禁止动作、非目标、例外和未验证状态必须准确表达。

资料确定时直接陈述；资料只支持推断或未知时保留相应语气。不能为了肯定句把建议改成承诺、把"约"删成精确值，或把未发现改成不存在。

**需要按语境检查的形态：**

| 形态 | 反例 | 正例 |
|---|---|---|
| 否定定义 | "这不是把需求外包成产品" | 概览表已经完整交代同一边界时可删；否则保留排除范围 |
| 辩护导语 | "这是一次低成本的验证尝试…" | 删，直接进事实 |
| 弱化词 | "尝试性方案""不保证完整度" | 只删无信息修饰；"属验证级原型"只有与原边界等义时才能替换 |
| 不确定语气 | "要不要做成…看路演结果再定" | "看到路演结果后，再决定是否做成……" |
| 括号补丁 | "一个懂业务的人（不必是技术）" | 技术背景确非必要且删后不改变人员要求时，才改成"一个懂业务的人" |
| 堆叠否定 | "不出人开发、不组织、不到场" | 上方表格已完整说明同一责任边界时可删；否则逐项保留 |

**边界信息必须保留。** 定义式陈述与原句确实等义时，可以改写"验证级、非成品、深化另谈"等边界；不等义时保留原有否定或限制。不能仅以"属验证级原型"替代"不保证商用完整度"，除非资料明确两者具有同一边界。

**清不干净的信号：** 如果某段话删掉后信息没丢，说明它本来就是辩护；如果删掉后读者会误解边界，就保留该信息；能否改成肯定陈述取决于改写前后是否等义。

## 六、格式克制

| 元素 | 立场 |
|---|---|
| 装饰性 emoji（每段一个小表情） | 不用 |
| 频繁加粗（每句都加粗） | 克制，只在关键判断处加粗 |
| 装饰性 callout 框（"💡注意：…""🔥亮点：…"） | 不用 |
| 表格里 emoji 表头 | 不用 |
| 表格本身（信息密度高时用） | 保留 |
| 章节序号（一、二、三） | 保留 |
| 关键判断处的结构性 callout | 保留（不是装饰性的） |
| 标题中的日期（"｜2026-06-05"） | 仅属装饰或重复元信息时删除；活动日期、截止时限、版本与来源日期不得丢失 |

## 七、工作方式启发

### 动笔前的入口检查

先读 `507-grill` 的累积共识、用户提供的案例/参考文档和项目既有规则。frame 只检查输入是否足够写，不重新开启一轮访谈：

- 工程或资料事实能自行查清就直接查；
- 写法、章节和呈现方式由 agent 专业判断；
- 真正缺少用户意图、边界或风险取舍时，明确缺口并返回 `507-grill`；
- 参考案例用于校准颗粒度和调性，不自动升级为必须照搬的需求。

### 动笔中

- **分块处理**：Agent 可以在内部按 section by section 起草和核对；这不表示要逐节停下来等用户批准，需求充分时仍按下条完成整份方案
- **用 surgical edits**：编辑时只改要改的部分，不要 reprint 整篇
- **按已确认需求完成方案**：需求充分时先完成可通读的方案；用户明确要求逐节共创时再按节反馈。出现会改变意图、边界或风险的缺口时按输入合同返回 `507-grill`，不为普通章节安排额外确认。

### 动笔后（自检）

交付前自己问自己三个问题：

- **"如果读者第一次看到这个文档，他们会问什么？"**——有没有没说清楚的地方
- **"有没有歧义/错误假设/前后矛盾？"**——自己 review 一遍
- **"每个环节所需的规则、数值、条件、责任与产出是否清楚？"**——拿不准时，可比较同类成熟方案的说明范围，不能复制它的事实或补造本方案的数字。资料中的约数、频率和未知必须保留，影响执行的缺项交回相应查证或决策步骤

## 完成与接力

- **完成信号**：方案面向明确读者，目标、边界、动作、责任、时间或验收信息足以推动下一次人类决策/行动；已确认内容与建议内容没有混写。
- **产物**：项目既有方案目录或用户指定位置中的正式方案；若用户只要求讨论载体，则是显式标注状态的同一份草稿。
- **候选出口**：缺少用户取舍时返回 `507-grill`；方案获批并需要具体产品规格时进入 `507-prd`；需要拆追踪任务时进入 `507-issue`；需要现场讲述时进入 `507-stage`；方案本身即交付时直接结束。
- **回退条件**：方案的读者、目标、关键边界、责任归属、资源或时间承诺、验收方式仍依赖未确认的用户取舍，导致方案无法推动下一次真实决策或行动时，保持草稿并返回 `507-grill`；项目事实不足时返回 `507-explore`，外部事实不足时进入 `507-research`。可自行查证的事实不得转成用户问题，也不得把建议写成已确认承诺。
- **边界提醒**：frame 服务“人如何理解、批准和行动”；prd 服务“具体产品应表现为什么行为、如何验收”。
