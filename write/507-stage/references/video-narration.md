# 视频旁白内容包

仅在 `507-stage` 为视频编排旁白、口播或配音稿时读取。这里完成旁白内容与可说性检查，不生成音频或视频。

## 写给耳朵

1. 一句只放一个主要意思，普通叙述尽量将主语和动作前置；听众不能回扫长句。旁白要求观众操作时，必要条件、限制与停止标志必须先于对应动作。
2. 删除“接下来我们看看”“值得注意的是”“总的来说”等开场垫话，直接进入事实。
3. 避免连续三段同长度、强行三点式、口号式反转和“不是 X 而是 Y”的机械句型。
4. 比喻比事实更难解释时，直接讲已有事实；判断需要来源时点名来源或从旁白删除。不能为了改得具体补造事实、人物动作或因果。
5. 每段结尾落在具体事实、动作或问题，不落在“未来可期”“值得期待”。
6. 默读或朗读每句；卡气、回读或失去主语时，拆句再交付。

## 内容边界

- 第一人称只用于真实亲历、实际测试和明确观点，不代替证据。
- 画面没有证明的功能、结果或对比，不写成旁白事实。
- 数字、版本、日期和专有名词单独核查；无法确认就删掉或标注待证。数字对应的对象、单位、范围、约数、时限与否定条件必须一并保留。
- 隐私、账号、路径、客户和会话信息在稿件阶段就标记，不等画面完成后再补救。
- CTA（行动号召）属于已确认的平台/内容决定；没有要求时不自动补“点赞关注”。

## 稳定分段

使用稳定、可读的 section ID，具体语法遵循目标项目；例如：

```text
[SECTION:hook]
旁白正文……

[SECTION:proof]
旁白正文……

[SECTION:close]
旁白正文……
```

每段配套记录：

```text
section: hook
任务: 让观众在 5 秒内知道真实冲突
画面证据: 聊天压力信息 + 游戏标题
预估时长: 5 秒（文字预算，不是最终时间线）
禁说: 不把一次案例概括成模型普遍能力
```

## 发音预检

逐句检查：

- 中文多音字是否因语境可能读错；
- 英文缩写按单词还是逐字母读；
- 版本号、日期、百分比、型号和代码标识怎样自然说；
- 品牌是否有约定中文读法；
- 标点是否提供自然停顿，而不是把标记念出来。

把稳定读法写入项目已有 pronunciation/phoneme（发音）机制；没有机制时在旁白内容包单列说明。不要为了适配某个 TTS 引擎污染观众看到的字幕正文。

## 时长与交接

- 写作阶段只做内容预算；真人配音或 TTS 生成后的实际音频才可能成为时间基准。
- 需要加速时先删冗余，再讨论小幅变速；变速由制作阶段完成并重新测量。
- 旁白修改会使下游音频、字幕、时间线、审片确认和渲染全部失效。

交付给 `507-narrate` 或 `507-video`：旁白正文、section 任务、画面证据需求、发音表、事实/隐私边界、目标时长和声音来源声明。需要本地 TTS 时先由 `507-narrate` 生成分段 WAV 与真实 timing manifest；真人配音、已有声音或无旁白时直接进入 `507-video`。
