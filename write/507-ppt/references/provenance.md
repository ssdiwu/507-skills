# 来源与许可证合同

`507-ppt` 的完成依据是当前仓库、产物和命令输出，不包含历史访问或法律认证结论。

## 当前实现来源

每个新增的运行时代码、第三方依赖、图片、字体或二进制资产，必须在 `../third-party-notices.md` 中有一行记录：

| 字段 | 要求 |
| --- | --- |
| 名称 | 稳定名称或资产 ID |
| 版本 | 精确版本、提交或内容版本 |
| 来源 | 官方 URL 或项目内原创文件路径 |
| 许可证 | 可核验 SPDX 标识或原创声明 |
| 用途 | 解决的具体能力缺口 |
| notice | 交付物中 notice 的相对路径或“不适用” |

项目内原创文件使用相对路径作为来源，并在生成 manifest 中列出 SHA-256。第三方运行依赖仅接受 MIT、Apache-2.0、BSD、ISC、CC0 或等价宽松许可证；不明许可证不能进入产物。

## 范围检查

每次生成前后由 Agent 执行以下来源检查；缺少来源或许可时，不进入产物：

1. 列出 HTML、CSS、JS、Python、PPTX、图片和字体文件；
2. 检查每个非生成文件均有来源/notice 记录；
3. 检查 HTML 不依赖远程 CDN；
4. 计算产物和本地素材 SHA-256；
5. 将检查结果写入产物 manifest。

`python3 scripts/validate_provenance.py --check examples/provenance-report.json` 会把当前扫描结果、notice 哈希、生成器源码哈希与已提交报告逐项比较；新增、删除或哈希变化都会失败。需要更新证据时，显式使用 `--output` 重建，报告同时记录生成时间、Git revision、工作区状态和实际工具版本。工作区为 dirty（有未提交改动）时，源码哈希是可复验身份，Git revision 仅表示所基于的最近提交。

范围检查只能说明当前仓库和产物的记录完整性；它不替代版权、许可证兼容或法律意见。

## 外部研究证据与实现边界

三轴重塑把以下固定版本作为研究证据：

- PPT Master `65bb2eca59a36270819caba377097910c4466c6e`：用于核对 style、mode、image rendering 与 carrier 的分离思路；
- Frontend Slides `9906a34d640d2111f724544cbc50f7f130569ae1`：用于核对真实内容预览、渐进披露和组合选择流程。

它们不是 507-ppt 的运行依赖，也没有模板、代码、字体、版式、验证器、图像、音频或其它资产进入仓库与产物。项目只独立重写不受表达保护的通用机制；实际实现、schema、CSS、PPTX 结构与测试均以本仓库文件为来源。若未来引入任何第三方文件，必须另行进入 notice 台账，不能用“研究参考”替代许可证记录。

旧 skill 只有在本 skill 的 HTML/PPTX 样例、测试、来源记录和恢复命令齐全后才移动到非发现备份目录。
