# 视觉方向收敛（taste）

用于**没有自动判据**的视觉决策。产物不是一张图，是一个被用户确认过的方向，加上一份可复用的收敛记录。

## 为什么不能一步到位

Coding agent 能被放大，是因为它的产出有一个可自动判定的结果：跑通或没跑通。**设计没有这条判据**——判据在用户脑子里，而且用户自己往往说不出来，只能在看见时认出来。

因此"一次生成一张正确的设计"是在赌一次猜中。被 AI 压缩掉的只是**出想法**那一段，**反馈循环**一点没变。

这个 skill 不试图消灭反馈循环，而是把它改造成：**高带宽、低成本、可重复的采样**。每一轮都让用户的判断以最大信息量回流，并把其中能机械判定的部分抽出来交给机器。

## 进入条件

同时满足才使用：

1. 目标是"看起来对"，而不是"功能正确"或"信息准确"；
2. 没有可自动判定的成功条件，最终由人的感受裁定；
3. 用户能参与至少两轮挑选（这个 skill 靠用户的淘汰驱动，不能替他做审美决定）。

只需要一个具体未知的答案 → `507-prototype`。已有明确方向只差实现 → 直接做。

## 不覆盖什么

- 需求、范围与取舍未定 → `507-grill`；
- 单个可观察未知的证据 → `507-prototype`；
- 已定风格下的界面实现与规范落地 → 相应的实现流程或设计体系 skill；
- 内容与文案本身。

## 核心纪律

1. **观点先于像素。** `性格`、`为谁`、`要冻结哪一秒`——这三件是用户独有的信息，模型猜不到，也无法从产品功能推导。没有它就开始画，等于优化一个没有目标函数的问题。观点要落成一句**可反驳的话**（例："抽中不是被罚，是得到"），不是形容词堆砌。

2. **排除法不产生设计。** 只做"这个像盘子、那个像蘑菇"式的淘汰，最终会收敛到"最不像别的东西的那坨东西"。每轮都要有正面陈述：这张图要冻结哪一秒。**功能描述不是画面**——"一副牌正在抽一张"是描述，"运气落到你头上的那一秒"才是画面。

3. **一轮至少收三条信息。** 只问"喜欢哪个"每轮只传 1 bit，而且模型对"哪里不对"的猜测经常是错的。每轮固定收集：**留哪两个、弃哪一个（最讨厌）、可选的一句为什么**。负样本划出边界，信息量通常大于正样本。

4. **粗稿阶段禁止精修。** 开工前明确声明：这一轮不看清晰度、不看小尺寸、不看细节。**在方向未定时抛光是最大的浪费**——精修过的错方向还会因为"看起来完成度高"而误导判断。

5. **变体必须在结构上不同。** 同一张图换颜色、换角度、换装饰不算不同方向。铺开轮要变的是：主体是什么、动作方向、情绪载体、构图关系。收敛轮反过来——**锁死其余一切，只留一个变量**，这样格与格之间的差异才可归因。

6. **能机械判定的交给机器。** 整体没有判据，但**局部有**：小尺寸还原、灰度分离度、明度阶梯、长宽比、剪影完整性、对比度。把这些写成一键脚本，人的时间只花在不可判定的部分上。

7. **方向定了才分层。** 确认方向后拆成独立元素层（背景 / 主体 / 装饰 / 排布……），每层多个变体，并做一个可现场切换的组合台，把"我猜你要什么"换成"你自己点"。**分层过早会把错误结构固化进架构。**

8. **结论要标注适用前提。** 每轮学到的可复用结论写进记录，同时标明它是在哪个观点假设下成立的。观点一变就要重新验证——观点是上游，结论是下游。

## 工作流程

**0 · 取观点与参考**

- 问三件事：这个东西是什么**性格**？做给**谁**？要冻结**哪一秒**？
- 要参考：**5～10 张"对味"的正样本**（不用解释为什么，也不限品类）＋ **2～3 张"做得挺好但不喜欢"的负样本**。一张参考图只够抄表层特征，多张才能提取出共同结构。
- 用户给不出参考时，不要卡住——用性格那一条先跑第 1 步，把参考需求留作后续提升项。

**1 · 铺开**

- 一次产出 **9 个结构差异极大**的粗稿，拼成一张对照表，每格带一句方向说明。
- 表头写清本轮的判断标准和明确不看的东西。
- 有明显失败的格子（几何画错、元素跑出画面）先修再交——失真的格子会浪费用户一次判断。

**2 · 淘汰**

- 请用户圈出最接近的 2 个，并指出最讨厌的 1 个。
- 从**保留项的共同点**和**淘汰项的共同点**两侧提取轴，把提取结果讲给用户确认，不要默默假设。

**3 · 收敛**

- 锁死除一个变量外的一切，再出 9 个。变量通常是上一轮提取出的那条轴。
- 每格声明它在回答哪个具体问题，让对照可归因。
- 必要时重复第 2～3 步，直到用户能指认出单一候选。

**4 · 分层与组合台**

- 把方向拆成独立元素层，每层多个变体，元素各自画在自己的局部坐标里，不假设自己是整张成品。
- 做一个单文件、可离线打开的组合台：每层一个选择器、实时预览、机械验收视图、导出。
- 组合台只负责组合，元素定义留在源文件里，改源文件即更新。

**5 · 机械验收与定稿**

- 跑本领域可自动判定的检查，出对照表。
- 报告结论时区分：机械检查的结果（客观）与个人推荐（主观，要标明）。
- 把可复用结论与未收口项写进记录。

## 每轮反馈的提词

直接用这些句子问，别让用户自由发挥——自由发挥的反馈通常只有 1 bit。

- 铺开轮："圈两个最接近的，再点一个你最讨厌的。不用解释为什么。"
- 提取轴后："我从你的选择里读到的是 `<轴>`，对吗？"
- 收敛轮："这九个只差 `<变量>`，其余完全相同。哪个更好？"
- 卡住时："如果现在必须马上上线一个，你选哪个？"（比"哪个最好"更能逼出真实偏好）
- 反复不对味时：回到第 0 步补参考图，或重新问性格——**不要继续微调**。

## 记录模板

```md
## 观点
- 性格：<一句可反驳的话>
- 为谁：...
- 要冻结哪一秒：...
- 观点确认时间与来源：...

## 轮次
### 第 N 轮 · <铺开 / 收敛>
- 变量：<本轮唯一变化的东西>
- 产出：<对照表文件>
- 用户保留：... / 用户淘汰：...
- 提取到的轴：...（是否已向用户确认）

## 可复用结论
- <结论>（成立前提：<在哪个观点假设下>）

## 机械验收
- <检查项>：<结果>

## 未收口
- ...
```

## 完成与接力

- **完成信号**：用户指认出单一方向；机械验收通过；可复用结论与未收口项已记录。
- **产物**：定稿源文件、元素分层与组合台、收敛记录。
- **候选出口**：需要正式规格 → `507-prd`；需要实现工单 → `507-issue`；需要落进设计体系或界面实现 → 相应实现流程；观点本身被推翻 → 回到第 0 步重开。
- **回退条件**：连续两轮用户仍说"不对味"，停止出图，回到观点与参考——继续微调只会消耗信任。

## 红线

- 不在观点未定时精修；
- 不用同一张图换装饰冒充"不同方向"；
- 不把用户一句"不对"直接翻译成某个参数去调；
- 不在粗稿阶段讨论清晰度与小尺寸；
- 不替用户做审美决定——可以给推荐，但必须标明是推荐；
- 不把机械检查的通过当作"好看"的证明；
- 不隐瞒失败的格子或渲染错误，宁可少交一格。
