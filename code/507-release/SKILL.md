# 对外发布（release）

按用户点名的目标处理推送、标签、版本定版与发布渠道。`507-commit` 负责普通本地提交；本技能选择本次真正需要的发布动作，不把每次推送都变成新一轮发版。

## 安全边界

- 只有用户明确要求相应动作时才执行；不自动扩到其他 remote（远端）、branch（分支）、提交、tag（标签）、包、渠道、dist-tag（分发标签）或身份。
- 创建或变更版本号时，明确版本由用户决定；半模糊的“升一个版本号”可按已核验变更的语义化版本规则补全。仅推送已有引用时不追问新版本；新建标签尚无名称或目标提交时，只补齐这项缺口。
- 用户已点名的推送、标签或发布渠道构成范围授权；范围与目标未变化时持续有效，不拆成逐动作确认。
- 仅泛称“发版”且渠道不明时，先探测项目实际渠道，再一次性确认本次范围。已明确排除的渠道直接跳过。
- 目标变化、引用冲突、验证实质偏差、外部状态不确定、凭据或身份变化、破坏性恢复，需要重新处理相应取舍，不能沿用失效授权。
- 不执行 `git push --force` 到主干，不擅自重置、覆盖或重建已有标签。
- 凭据、令牌与密钥不写入仓库或日志。

## 操作模式与前置检查

先根据请求确定模式；用户已明确时直接采用，不要求选择内部模式名。

所有模式都先确认相关工作已提交、工作区干净、目标提交符合预期、与本次动作相称的必要项目验证已通过或用户已明确知情放行。工作区仍有改动时回到提交或实现流程；不得把“推送”当成提交所有未提交文件的授权。只创建本地标签时不要求远端连接；有远端动作时核对远端、引用和授权范围。

| 模式 | 额外前提 | 本次执行范围 |
| --- | --- | --- |
| 仅推送已有分支或标签 | 精确引用、目标提交、远端状态已核验 | 只推送已授权引用；不要求新版本、Unreleased 条目或创建标签 |
| 仅创建标签 | 精确标签名和目标提交已确定；不存在未解决的同名冲突 | 按项目惯例创建本地标签；只有已授权标签推送时才推远端，不默认改版本或日志 |
| 版本定版与发布 | 新版本已明确；Unreleased 有本次应发布内容；实际渠道与验证前提已核实 | 按范围更新版本与日志、创建定版提交和标签，再推送及发布已授权渠道 |
| 发布已定版版本 | 已有版本、日志、标签和提交相互一致；已核实目标渠道状态 | 发布该版本的指定渠道；不强制制造新的 Unreleased 内容或重复定版 |

版本定版前核对待发布内容与目标版本；定版完成后、推送或发布前，再核对 manifest（存在时）、版本日志、标签和提交一致。不要要求尚未创建的新标签在定版前已经存在，也不能跳过发布前的一致性核验。

## 执行

### 1. 记录已授权的目标与动作

记录模式、仓库、目标提交、相关远端与引用、版本或标签、包和渠道。跨会话继续时复核已有授权与当前状态；只询问尚未确定且会改变范围的内容。

- “只 push，不发包”：只推送已核验分支，跳过定版、建标签和渠道发布。
- “只打本地 tag”：确认名称和目标提交后创建标签，跳过推送。
- “发布已有版本”：使用已有定版证据，不再次创建版本。
- “发版，tag 和 npm 都需要”：缺版本时只补版本，之后在原范围内连续完成；泛化发版默认推送已确认发布分支及其标签，其余渠道按点名或已确认范围执行。

### 2. 定版或建标签（按模式）

需要新版本时，读取最新标签、当前 manifest 和 Unreleased，核对当前起点。按项目版本规则将本次 Unreleased 内容迁入对应版本与日期，保留条目分类，更新实际存在的版本字段。

需要定版时，精确暂存定版改动并创建约定式定版提交，再创建指向该提交的版本标签；名称沿用项目实际惯例，默认新版本标签为 `v<x.y.z>`。仅创建标签时，按已明确的完整标签名与目标提交创建本地标签，不暂存其他改动、不创建定版提交，也不顺带修改版本或日志。

### 3. 核验引用并推送（仅授权远端动作时）

推送前确认提交与引用仍匹配本次范围，按已授权的引用分别执行：

```bash
git push <remote> <branch>
git push <remote> refs/tags/<tag>
```

占位符替换为已核验的精确值；标签名包含项目实际前缀。只授权分支时不执行标签推送；只授权某个标签时不推其他标签或分支。不得用批量推送所有标签的形式扩大范围。

推送后只读回查远端引用，确认它指向期望提交后才记录成功。遇到远端更新、引用冲突或需要改变历史时停止该动作，报告差异；不在原授权下强推或自动重写历史。

### 4. 发布渠道（仅已授权渠道）

按项目实际能力探测；先核实指定版本是否已经发布，已完成则记录结果，不重复创建。

- **npm**：读取真实包 manifest、包名、版本和 registry，核对登录身份；按已授权渠道发布，预发布标签遵循项目约定。凭据缺失或身份不符时停止并报告。
- **GitHub Release**：核对 Git 远端、标签和 CLI 能力；说明取自对应版本 CHANGELOG。多行说明先写入临时文件，再通过 `--notes-file` 提交，核对发布后的标签、版本与说明；预发布状态按已确认版本使用。
- 其他渠道只在用户点名后按实际工具处理；渠道缺失不是自动添加渠道的授权。

每个渠道完成后读取其实际版本、标签或产物状态，再确认发布结果；单次命令退出成功不能替代渠道核验。

## 失败与恢复

先只读核验外部结果，再判断是否重试；不自动回滚已经完成的外部动作。外部状态已经显示完成时记录成功，避免重复发布。

只有以下条件同时成立时，最多自动重试一次：失败已明确属于瞬时网络故障，目标与范围不变，动作可安全重复，且已读取外部状态并排除冲突。远端拒绝、引用冲突、未知外部状态、身份变化、非幂等动作或需要破坏性恢复时停止并报告。

分别报告已经完成、失败、未执行的动作及核验证据；不能把分支已推送等同于标签、包或 Release 已发布。

## 完成与接力

- **完成信号**：所选模式和授权范围内的全部动作已执行并核验；版本、引用、渠道与验证状态准确，未授权动作没有发生。
- **产物**：与本次范围对应的本地标签、定版提交、推送结果或渠道链接；失败时为实际完成状态、失败证据和未完成项。
- **候选出口**：内容缺陷进入 `507-fix`；必要验证或审查未完成时进入相应验证与 `507-review`；只有推送要求时不倒推成未经授权的提交任务；完成后通常直接结束。
- **回退条件**：模式前提不满足、授权失效、引用冲突、身份异常或外部状态无法核实时保留现状，不强行发布。
