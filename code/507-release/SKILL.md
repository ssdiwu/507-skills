# Git 提交与发布（release）

按请求维护本地历史或交付软件版本。原 507-commit 的本地动作由本入口承接，授权范围由用户请求决定。

## 先确定动作

| 请求 | 执行方法 | 结束位置 |
| --- | --- | --- |
| 创建本地 commit | 下文的本地提交流程 | 本地提交与工作区状态；不推送、建标签或改版本 |
| 只起草提交信息或交付建议 | 读取必要差异后交付草稿 | 不创建提交或其他 Git 状态 |
| 推送、标签、定版或发布已有版本 | 按需读[交付方法](references/delivery.md) | 只完成已授权引用与渠道，并读回核验 |
| 明确提交并推送／发版 | 先完成本地流程，再按交付方法连续处理 | 复用仍有效证据和授权，不为同一范围重复询问 |

只推送不是提交未提交文件的授权；本地提交不要求先满足远端交付的“已经提交”前提。交付模式的干净工作区、身份、引用与渠道等前提仍按其方法核对，不能把局部提交变成清理无关改动的理由。

## 本地提交流程

1. 核对分支、最近提交、工作区及暂存差异，把本次、无关和归属未知的改动分清。无关内容保留；不能确认归属的必要内容只暂停对应提交。
2. 按项目规则同步直接相关的导航、说明或 Unreleased 条目；纯内部重构、测试或地图调整不强塞用户日志。本地提交不自动定版、更新 manifest 或制造标签。
3. 核对已有验证是否仍覆盖当前代码、依赖、配置与环境，有效时复用；变化、失败、具体疑点或项目明确要求时补跑相关检查。不跳过提交钩子，不能假装验证成功。
4. 逐路径暂存本次文件，不使用 git add .、git add -A 或其他全量暂存；不纳入临时文件、秘密、私人／客户资料或无关格式化。读回暂存差异，检查主题、遗漏和混入。
5. 按项目规则创建真实本地提交，默认 Conventional Commits（约定式提交），如 type: 中文描述；按变更主题选择 feat、fix、refactor、docs、test、chore、perf、ci 或 build。暂存为空、主题混杂或必要验证失败时不创建半成品提交。
6. 读回提交哈希、提交信息与工作区状态，明确保留项。只有仍在已授权范围内的后续动作才继续；仅本地提交请求到此结束。

本地流程做必要轻量复核，不重复完整 507-review。发现实质问题时由相应实施动作处理并验证后返回。凭据不写仓库或日志，不擅自强推主干、覆盖标签或改变身份。

## 完成与接力

- **完成信号**：本地提交真实生成并核验；交付模式完成相应引用／版本／渠道读回；草稿请求以草稿交付。各自结果不能互相替代。
- **产物**：提交哈希与剩余状态，或已授权的标签／推送／发布结果；失败时给出实际完成、失败与未执行部分。
- **候选出口**：实质缺陷与验证问题由对应动作处理后返回；既有授权覆盖的后续交付连续完成，范围外动作不执行。
- **回退条件**：归属、身份、引用或外部结果不明，必要检查失败或需要破坏性恢复时保留当前状态，先核对事实或实质取舍。
