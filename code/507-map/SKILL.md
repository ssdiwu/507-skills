# 项目地图（map）

本 skill 以实现和已确认文档为依据维护项目地图，让人和 agent 找到目录职责、现行规格、共用规则、实现与验证入口。新项目明确尚未建立的工程入口，已有项目在授权迁移中同步新导航并退出旧维护路径。

## 修改权限

允许在确认范围内创建、移动、重命名或校准：

- 项目根 `README.md`；
- `spec/README.md`、`doc/README.md` 及其他实际承担导航职责的目录 README；
- 含代码目录的分层 `README.md`。

授权迁移时可清理无消费者的旧地图，或按明确消费者与退出条件保留迁移指引；移动或删除非地图正文不属于本 skill。业务代码、测试、配置、脚本、AGENTS、DESIGN、GLOSSARY、功能规格、决策、路线图／实施方案正文与 CHANGELOG 由各自维护动作处理，地图只引用。

## 范围纪律

1. 用户指定路径时，只处理该范围及必须同步的上下级地图。
2. 已授权建立或迁移项目地图时，先扫描并说明必要范围后连续完成；请求只读或目标项目不明确时先报告，只有实际范围取舍才请用户决定。
3. 已有地图过时时只修正失真部分；缺失时只写最小必要说明。
4. 不自动扩到整个项目，不为单个文件机械建立 README。

## 证据顺序

遵循项目阅读顺序，从 AGENTS、根 README 和实际导航进入目标目录及上下级 README，按问题读取 DESIGN、GLOSSARY、spec、doc，再核对代码、测试和配置。迁移前读取旧入口以保全依据，不能仅因新路径已存在就认定权威已切换。

地图中的事实必须能回到当前代码或现行权威文档核对。实现现状以代码和运行证据为准，已确认目标以对应规格为准；冲突时分别标明，不用当前实现覆盖产品要求。新项目可依据已确认文档说明职责与阅读入口，尚不存在的工程入口明确为缺口；不替项目决定新的产品或架构意图。

## 文档地图原则

- 根 README 提供定位与真实入口；spec 导航定位现行功能与验收，doc 导航定位长期依据、说明、规划及历史。设计和术语各有唯一正文，地图只摘要回链；
- 按 [项目启动与迁移标准](../507-setup/references/project-standard.md)组织新入口：功能规格进入 spec，版本交付安排进入 doc。已有项目按授权迁移到同一职责，不以旧布局为永久豁免；只维护地图不授权移动或重写全部正文；
- 文档按职责分类，不因“已经完成”机械移入归档；仍是有效需求或验收基准的规格保留在原职责目录并由目录 README 标明状态，被取代、放弃或只供追溯的材料才进入 `90-归档/`；
- issue 负责本次范围、状态与证据；spec 负责当前行为，实施方案负责一次交付安排，实现说明负责当前事实，CHANGELOG 记录已完成变化；地图不复制正文；
- 小项目可以保持平铺，但要能看出文档职责和权威关系；
- 归档只用于追溯，不写成当前事实；
- 目录职责、入口或上下游变化时同步上下级 README。

## 工作流程

1. **锁定范围**：记录允许修改的地图文档、排除项和必须同步的上下级。
2. **读取现实**：识别入口、公共接口、主要文件、依赖关系和现有边界。
3. **先列出拟写的导航关系**：说明各目录职责、主要文件、入口、上下游和边界。
4. **只写必要的地图内容**：写入证据支持的职责与入口；已确认目标、尚未实现和真实可用分别表达，不将计划或候选写成实现事实。
5. **同步导航**：核对根／上下级 README、spec／doc 导航及受影响引用。迁移时等目标正文完成核验后再切换地图，退出旧现行入口；非地图正文中的旧引用交给对应维护动作同步，未同步的明确报告。
6. **验证**：检查 Markdown（标记语言）链接、相对路径、地图与代码一致性，并确认没有代码文件被修改。

常见 README 骨架按需取舍：

```md
# <目录或项目名称>

## 一句话定位
<目录职责。>

## 主要文件
- `<path>` — <职责>

## 入口与关系
- 入口：...
- 上游：...
- 下游：...

## 边界
- ...
```

## 交付

说明处理与未处理范围、已读依据、每个文档的修改、代码/文档冲突、不确定性和链接验证结果。若发现规范、术语、决策、路线图或变更记录缺口，明确路由，不在本 skill 内代改。

## 红线

- 不改代码；
- 不做全量项目规范巡检；
- 不替项目设计新架构；
- 不把计划或归档写成现状；
- 不凭目录名推断职责；
- 不把个人偏好写成项目规范。

## 完成与接力

- **完成信号**：声明范围内的根／分层 README 与 spec／doc 导航有准确依据，链接和阅读路径已验证；授权迁移的旧地图已退出，范围外待同步项明确，不能将局部地图完成称为全项目迁移完成。
- **产物**：只包含项目地图文档的修改，以及已读范围、冲突和未处理缺口说明。
- **候选出口**：术语或用户决策缺口进入 `507-grill`；规范全量缺口进入 `507-setup`；代码问题进入相应实施；地图修改完成后进入 `507-review`，用户明确要求提交时再进入 `507-commit`。
- **回退条件**：关键职责或入口缺少依据时返回 `507-explore` 或报告证据边界；新项目尚无源码本身不阻止维护已确认的文档导航，不猜测运行入口或实现状态。
