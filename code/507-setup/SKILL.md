# 项目初始化与全局规则校准（setup）

给具体代码项目建立或校准长期协作规范，并按用户明确目标建立或审阅全局 `AGENTS.md`。目标不是让所有仓库长成同一套目录，也不是把项目事实复制进全局规则；而是让下一位 agent 找到真实入口、权威关系、任务与安全边界、验证方式和外部动作授权。

全局规则只保存跨项目稳定的沟通偏好、工作纪律和安全底线。项目级 `AGENTS.md` 只保存当前项目经代码、配置、文档和验证核实的定位、约束、入口和授权边界；项目级规则在该项目内优先。

巡检标准以本技能的 [`references/project-standard.md`](references/project-standard.md) 为权威来源；执行前完整读取该文件。用户明确要求全局候选时，可参考仓库根 [`templates/AGENTS.global.example.md`](../../templates/AGENTS.global.example.md)，但它不是自动覆盖的成品。

## 覆盖什么

- 用户希望建立、审阅或校准全局 `AGENTS.md`；
- 新项目需要建立最小但完整的协作规范；
- 老项目的 `AGENTS.md`、入口地图、文档职责或验证方式可能整体失真；
- 一个或多个已明确选定的项目需要统一比较规范质量；
- 需要识别规范生成文件、历史副本、冻结样本和项目自身维护的分层规则，避免误覆盖。

只维护 README、doc 导航或目录职责时使用 `507-map`；架构摩擦使用 `507-inspect`；业务代码 bug 使用 `507-fix`。

## 项目形态

巡检时先判断项目属于哪种形态，不能先套模板：

- **完整合同**：持续维护的应用、服务、库或多模块项目，存在多个运行边界、外部系统、持久化、安全风险、发布面或耐久文档。
- **精简合同**：单入口扩展、小型包、一次性原型或临时验证目录，职责和验证路径都很短。
- **受保护范围**：框架生成规则、嵌套项目自有规范、测试 fixture、冻结快照、worktree 副本、归档或历史 demo。除非用户明确点名并且维护方式允许，否则只记录，不改写。

选择能完整覆盖当前真实风险的最轻合同。精简不是省略安全、验证或外部动作授权；完整也不是复制全局工程纪律。

## 修改边界

默认只读并输出报告。用户确认落地后：

- `507-setup` 可修改用户明确指定的全局 `AGENTS.md`，或在其明确指定的目标位置创建候选；没有明确目标时只报告，不猜测宿主路径；
- `507-setup` 可修改用户确认的项目级 `AGENTS.md` 及直接属于初始化合同的基础规范；
- README、`doc/README.md`、目录职责和地图结构交给 `507-map`；术语或真实取舍未对齐时交给 `507-grill`；
- 已发现的业务代码安全缺口、bug、测试问题或架构摩擦分别转 `507-fix`、`507-test` 或 `507-inspect`，不得用规范文字伪装成实现已修复。

本 skill 不修改业务代码，不生成宿主专属配置，也不把报告或模板授权扩张为跨项目批量写入。

## 输入范围

用户可分别或同时提供全局规则目标、一个或多个项目根目录、需要保留或排除的文件，以及完成信号。给出 workspace 时：

- 用户已经明确选定项目集合，就按该集合执行，不重复要求选择；
- 范围不明确时先识别仓库、生成/历史/测试边界，再请用户只决定真正需要纳入的集合；
- 全局目标未明确时只输出候选与待确认位置，不推测文件路径或宿主加载机制；
- 不把 workspace 当成单一项目，也不自动修改扫描到的全部仓库。

## 巡检流程

### 0. 读取标准与冻结范围

完整读取 `references/project-standard.md`。确认全局目标是否明确、项目根、Git worktree、当前工作区状态、目标文件、排除项和完成信号。识别生成文件、嵌套规范、历史副本、测试样本、归档与并行 worktree；同一 worktree 只保留一个写入负责人。

### 1. 扫描全局与项目现实

- 全局层只读取用户明确指定的现有规则和宿主文档；没有明确目标时不猜测路径或加载机制。
- 项目层先读根 `README.md` 与 `doc/README.md`（存在时），再读 `AGENTS.md`、manifest、入口、构建/测试配置、目标代码和安全相关配置。
- 通过实现和可运行配置核对项目类型、平台、入口、真实消费者、外部副作用、凭据、持久化、迁移边界、验证命令，以及文档与当前行为的冲突。

### 2. 选择合同形态并核对规范

逐项检查：

- 全局规则是否只保留跨项目稳定内容，并与项目规则、宿主文档保持单一权威；
- 项目 `AGENTS.md` 是否只保留跨任务稳定且项目特有的定位、阅读路由、任务/失败边界、工程/安全约束、验证和外部动作授权；
- 平台、命令、路径和能力是否能由 manifest、源码或运行证据核实；
- 项目已有架构策略与检查时，是否明确唯一权威、实际纳管范围、差异基准、新旧违规区分及例外／基线变更责任；缺少检查时如实记录，不将其写成已具备的保障或自动引入跨项目检查器；
- 是否混入版本号、当前分支、Issue、端口、服务器、临时任务、个人绝对路径、凭据值或一次性进度；
- 是否机械复制全局工程纪律、Skill 路由表、长文档地图或旧初始化模板；
- 现存实现若违反安全目标，是否明确写成“当前缺口 + 阻断 + 修复出口”，而不是笼统声称安全；
- README、CHANGELOG、doc 地图、术语、决策与分层 README 是否按真实消费者和项目形态存在，而不是为形式完整创建。

### 3. 输出巡检报告

```md
# 项目初始化与巡检报告

## 全局规则
- 目标：已指定 / 未指定（只给候选）
- 现状与证据：...
- 候选内容或规范漂移：...
- 不应写入的内容：...
- 待确认的写入位置：...

## 总览
| 项目 | 项目形态 | AGENTS | 入口地图 | 文档职责 | 验证入口 | 受保护范围 | 安全/事实缺口 | 推荐动作 |

## 项目详情
### <project>
- 当前现实与证据：...
- 建议合同形态：完整 / 精简 / 保持受保护
- 规范漂移：...
- 文档与实现冲突：...
- 现存代码风险及阻断：...
- 排除项：...
- 推荐路由：...

## 建议执行顺序
1. ...
```

每项结论给出文件、配置、代码或命令证据。没有真实内容时不建议创建空目录、空术语表、空 ADR 或空经验笔记。

### 4. 经确认后路由落地

- 全局 `AGENTS.md` 候选或合同 → 本 skill 在用户明确指定位置、确认内容后更新；
- 项目级 `AGENTS.md` 合同 → 本 skill 在已授权范围内更新；
- README、doc 导航与目录地图 → `507-map`；
- 术语、产品或风险取舍 → `507-grill`；
- 需求规格或远程工单 → `507-prd` / `507-issue`；
- 代码风险、测试或架构问题 → `507-fix` / `507-test` / `507-inspect`。

一次只处理用户确认的全局目标、项目和文件。发现范围外问题只保留脱敏证据，不自动扩大交付。

## 验证

落地后至少检查：

- Markdown 链接、相对路径、围栏、尾空格和 `git diff --check`；
- 全局候选不含项目事实、个人路径、凭据、动态状态或宿主专属命令；
- 项目规则中的命令、manifest script、平台和入口真实存在，且没有重复全局工程纪律；
- 受保护范围没有意外 diff；
- 文档没有把未运行的构建、测试、联网或人工验收写成通过。

纯文档改动不虚构业务测试结论；若发现的代码风险未获修复授权，验证的是“风险已被准确标注和阻断”，不是“实现已经安全”。

## 红线

- 不未经确认创建、覆盖或迁移全局规则；
- 不猜测全局配置文件位置、宿主加载机制或用户偏好；
- 不把项目事实、个人环境、凭据或一次性状态写入全局文件；
- 不把同一套通用模板复制到所有项目；
- 不覆盖生成文件、嵌套权威、冻结样本、归档或历史 worktree；
- 不修改业务代码，不以规范文字掩盖现存实现风险；
- 不执行未经授权的 commit、push、tag、publish、deploy 或外部系统写入。

## 完成与接力

- **完成信号**：选定的全局或项目范围均已按相应标准检查；事实、缺口、受保护范围和建议合同有证据；授权的规范已落地并验证。
- **产物**：全量巡检报告、全局候选或更新，以及授权范围内的项目合同修改；业务代码风险保持独立、可接力的证据边界。
- **候选出口**：地图进入 `507-map`；代码/测试问题进入 `507-fix` 或 `507-test`；架构问题进入 `507-inspect`；需求或治理项进入 `507-prd` / `507-issue`；落地后进入 `507-review`，明确要求提交时再进入 `507-commit`。
- **回退条件**：项目规则互相冲突、生成所有权不明、全局目标不明确或需要用户选择治理方向时进入 `507-grill`，不自行覆盖当前权威。
