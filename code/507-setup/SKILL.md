# 项目依据与导航维护（setup）

让维护者找到当前要求、共用规则、真实入口和验证依据，并在授权范围内维护这些工作基础。原 `507-map` 的导航维护动作由本入口承接；用户按任务表达目标，不必选择内部模式名。

## 先选择本次维护范围

以请求、已有授权和当前事实选择范围；资料可查时自行核对，只有实质取舍未定时才询问。

| 当前请求 | 必读方法 | 修改边界 |
| --- | --- | --- |
| 补 README、整理目录说明、修正 spec/doc 导航或迁移后的入口 | [导航维护](references/navigation.md) | 仅指定范围及必要上下级的地图文档；不修改规范、规格、设计、术语或进度正文，不跑全项目规范巡检 |
| 新项目初始化、已有项目规范迁移、建立阶段依据或按标准巡检 | [项目标准](references/project-standard.md)与[项目依据维护](references/project-maintenance.md) | 按授权核对并维护工作依据；直接同步相关导航，无需另一次技能交接；具体产品取舍和业务实现仍各自承接 |
| 只校准已明确指定的全局 AGENTS.md | 项目标准中的“AGENTS：工作规则与授权”“规则依据与维护”及对应验证条目 | 只处理指定全局文件；不读取项目实现、建立项目阶段文件或顺带迁移当前仓库 |

只读请求在任一范围都保持只读，交付证据、缺口和建议。发现范围外问题只报告；导航维护中发现缺少规范或进度文件，不自动取得建立这些正文的授权。请求本来同时包含正文迁移和导航同步时，在同一维护任务中完成，不要求用户重复确认。

## 共用边界

- 先核对项目或指定文件、版本、当前工作树、用户改稿、已确认结论及完成证据，保护已有改动。跨会话不因新时间戳重新猜权威。
- 同一工作树只有一个写入者。生成文件通过生成源维护；嵌套项目、第三方原件、冻结样本、历史副本及其他工作树保持各自边界。
- 目标与现行要求、代码实现、实际验证分别判断。地图以实现和现行正文为依据，不能用当前缺陷删除要求，也不能把计划写成已实现。
- 只建立有内容与实际用途的文件。跨会话确需阶段入口时，在已授权的项目依据范围建立 PROGRESS；导航模式仅链接已有入口，不造空文件或无依据的完成状态。
- 准备迁移候选后，先核对含义、来源、消费者和必要验证，再切换正文与引用并退出旧维护路径；剩余消费者或阻塞应明确报告。
- 全局规则只保留跨项目稳定约束，不混入项目状态、私人路径或宿主机制。目标位置不明确时不得猜测或覆盖个人配置。

业务代码、测试与工具建设不属于本技能。产品要求由现行规格维护，需要充分展开时使用 `507-prd`；真实用户取舍由 `507-grill` 处理。外部事实、架构体检或生产故障分别由相应动作处理，不把项目维护变成总控开发流程。

## 执行与交付

读取选定范围需要的方法和现实证据，复用已经核实且未变化的材料；不自动加载其他模式的参考。授权充分时连续完成文件与直接相关导航，常规措辞、目录和验证选择由 agent 判断。

检查内容与来源保全、相对链接／锚点、真实阅读路径及差异范围；相关脚本或工程保障没有实际运行时明确未验证。导航准确、规范迁移完成、实现可用和真实验收分别成立，不以文档检查替代产品验证。

按本次范围报告处理了哪些正文或地图、退出了哪些旧入口、已有改动如何保护，以及未完成项和依赖。简单导航任务可用短说明交付，不强制输出完整巡检表；详细模板按项目依据参考使用。

## 完成与接力

- **完成信号**：导航维护的入口与职责有依据、链接有效且修改不越界；项目依据维护完成授权范围内的正文与引用切换并保全未完成项；只读巡检或单独全局任务分别满足其声明范围。
- **产物**：对应的地图／基础规范修改，或只读发现与建议；附验证证据、未覆盖范围和下一步条件。
- **候选出口**：缺口按事实查证、用户取舍、规格或工程实施承接；已授权的导航与正文维护在本技能内继续；规范或公开行为变化完成后使用 `507-review` 独立收口，提交与发布仅按明确要求进行。
- **回退条件**：权限或维护所有权不清、当前权威冲突、候选未验证或内容无法保全时，保留原可用版本并停止依赖该缺口的写入，继续独立工作；不能把局部维护称为全项目迁移。
