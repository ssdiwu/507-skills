# 审查的公共证据方法

用于 review 的交付审查与 inspect 的架构调查。两者共享取证和判断依据，各自保留任务范围、结论门槛和停止条件。本文随技能包提供，独立使用不需要另一项技能或作者仓库。

## 1. 锚定对象与当前基线

从请求、现行要求、规范和已确认决定确定审查对象。记录相关提交或版本、工作树改动、明确范围及未覆盖部分；未提交内容用工作树状态与必要的快照／指纹定位，不能说成 HEAD 中的源码。沿用用户指定版本，时间更新不自动取得权威。

只读审查不修改被审项目的源码、测试、配置、规则或持久状态。需要补证时读取相关调用、配置和已有检查；只有运行条件与当前授权允许时才执行既有检查，未运行就保留缺口，不以补验证为由新增测试或修实现。

## 2. 从入口追到真实行为

按待回答的问题读取一个相连的代码或文档片段：入口、校验、正式调用、状态写入、副作用、保存与恢复。证据不足时扩到下一相关位置，不因目录名、类名、导出函数或配置项存在就断言运行关系。

分别识别发起请求者、实际执行者、可变事实的写入所有者及最终消费者。某层调用存储接口不等于它直接写盘；后台保存、公开读取与用户实际看到内容是不同事实。异步路径核对生效条件、过期结果、重复、取消、错误与恢复，静态调用不自动证明运行时顺序。

需要组织复杂关系时按问题选择视角，不要求每次画全套图：

| 问题 | 可用视角 |
| --- | --- |
| 谁负责什么、依赖与信任边界在哪 | 模块与边界 |
| 一个用户动作经过哪些处理和分支 | 工作流程 |
| 调用、返回和异步结果怎样先后发生 | 时序 |
| 数据从哪里来、谁转换／写入、谁消费 | 数据流 |
| 对象怎样等待、重试、取消、恢复和结束 | 生命周期 |

图、表和概览用于解释已核实关系，保持来源和未知可追溯；路径有效、结构校验或渲染成功不证明关系语义正确。已有工具足以表达时直接复用，不为审查安装画图平台。

## 3. 分别核对要求、机制与证据

现行要求说明应该怎样，源码／配置说明怎样实现，运行或人工检查说明实际验证到哪里。文档、注释、文件名和绿灯只能支持它们已经观察到的部分。

检查验证是否能拒绝一个有代表性的错误结果：目标未达成时，现有断言是否仍可能通过？元素存在、调用次数、返回类型、无异常或保存成功不能代替用户所需的正确内容与可用结果。按当前风险选择反例，不枚举无价值组合；视觉和语义不足以自动判断时保留实际呈现与独立人工检查的缺口。

引用目标项目已有架构检查时说明实际覆盖、新旧违规、例外和未纳管部分。零源码通过或刷新违规基线不能证明目标成立，未经授权不修改规则和例外来让检查通过。

## 4. 按动作区分结论

| 动作 | 可以交付的结论 | 不能升级成什么 |
| --- | --- | --- |
| review | 与本次范围有关、可定位且有依据的规范偏差、需求遗漏或质量风险；说明影响与严重性 | 仅有另一种更好设计，不能自动成为阻塞交付的缺陷 |
| inspect | 有代码观察支持的维护摩擦与改进候选；说明置信度、公开不变量、预期收益和仍需验证的部分 | 候选不是改造批准，也不证明重构后一定更简单或行为不变 |

严重性与置信度分开。确定的低影响问题与后果可能严重但证据不足的假设，不能使用同一种确定语气。架构偏好必须连接调用者负担、变更局部性、状态协调、复用或验证困难等实际成本，不能只按文件数、行数、层数或命名判好坏。

## 5. 保留可接续的发现与更正

每项发现保留足以复查的观察位置、判断依据、影响、确定程度和下一动作；按任务需要附上调用路径、失败信号或验证缺口，输出格式由调用技能决定。

后续证据支持、反驳或替代旧发现时，更新同一审查记录中的当前结论并说明原因。已被证伪或修复的旧发现不能继续作为当前问题传播；只读阶段不因此修改项目、创建永久总账、自动写记忆或通知外部人员。

当前问题已有相称证据、剩余未知不会改变本轮结论时停止补读；检查通过后只因新变化、失败或具体疑点重复验证。报告事实、推断、未知和未覆盖范围，由相应实施动作处理后续工作。
