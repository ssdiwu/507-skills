# 测试与测试先行开发（test）

围绕公开行为建立可信的反馈环。原 507-tdd 的方法由本入口按明确请求承接，不把每次测试任务自动改成开发任务。

## 选择范围

| 请求 | 方法 | 修改边界 |
| --- | --- | --- |
| 补测、跑测试、修过时测试、分类或缩小失败 | [普通测试维护](references/maintenance.md) | 测试资产与必要测试环境；生产故障只定位并转根因修复，不自行改生产实现 |
| 明确 TDD、test-first 或红绿重构，实现已确认行为 | [测试先行开发](references/test-first.md) | 当前授权行为的测试与最小生产实现，逐个垂直切片验证 |
| 只先写测试、只提出建议，或明确禁止实现 | 对应方法仅执行请求允许的部分 | 不因“先写测试”关键词取得 GREEN 阶段的实现权限；停在实际允许的产物并说明未执行部分 |

材料已经清楚时直接开始。只读运行或诊断请求不变成补测授权；模式间切换沿用当前范围，实质需要新增实现或改变规格时先处理相应取舍。

## 共同要求

- 优先公开 API、CLI、页面或真实用户路径，测试调用者关心的结果，不锁定私有结构或无关调用次数。
- 沿用已有框架和惯例；mock 只放外部系统边界，不模拟自己的内部协作者以掩盖行为。
- 从已确认目标选择输出、状态、错误或副作用；检查目标未达成时断言是否仍会通过。元素存在、无异常、保存成功或返回类型不能代替结果正确。
- 不删断言、放宽预期或伪造内部结果让失败变绿。编译、fixture、依赖和测试错误不是有效 RED，先修反馈环。
- 只选择有意义的主路径、边界和错误场景。需要巨大内部对象时先检查公开接缝，不堆测试专用架构。
- 相关代码、依赖、配置与环境未变时复用有效证据；完成项目必要检查后仅因新变化、失败或具体疑点扩大。

测试先行按 RED → GREEN → REFACTOR，普通维护按失败分类与目标覆盖完成；不把一种模式的固定步骤强加另一种模式。视觉、语义与真实外部能力未覆盖时保留必要验证，不用自动绿灯冒充验收。

## 完成与接力

- **完成信号**：请求范围内的测试维护或已确认行为完成相称验证；测试先行保留有效红绿证据。只写测试或只读任务以该请求的产物结束，不宣称生产实现完成。
- **产物**：测试资产、失败分类、测试先行的最小实现与证据，或只读结果；附未覆盖边界。
- **候选出口**：真实生产故障转 507-fix；规格取舍转相应对齐；完成后独立交付审查，Git 动作只按明确要求进行。
- **回退条件**：反馈环无效、目标未定或环境故障时补证并缩小范围，不用实现修改或放宽断言掩盖未知。
