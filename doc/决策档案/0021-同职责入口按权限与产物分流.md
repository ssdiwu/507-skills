# 同职责入口按权限与产物分流

> 状态：2026-10-07 用户已授权测试与条件整合；18 个隔离场景与两轮静态审查完成，已采用；Git 交付状态以实际提交记录和根 PROGRESS 为准。

> 成文入口的临时 `507-write` 名称由 [0022](0022-保留职责分组与创作命名.md) 校准为 `507-forge`；下文保留本次整合时的名称与权衡，三种方法及权限边界继续有效。

## 决定与依据

setup/map 合并为 `507-setup` 的范围分流；test/tdd、commit/release、forge/frame/stage 分别由 `507-test`、`507-release`、`507-write` 承接。review/inspect 保留双入口，使用同一维护源生成随包证据方法。

[0002](0002-按动作与修改权限划分代码工作流.md) 的修改对象、权限与停止位置继续成立；[0010](0010-commit与release按可逆性边界拆分.md) 的本地与外部动作风险边界继续成立。本决定调整这些边界的承载方式，不依靠“默认不推送”一句话，也不把方法相似当成合并充分条件。

新主入口明确请求、方法、修改权限与结束位置，条件参考提供相应细节。局部导航不加载完整巡检；普通补测不修改生产实现；只先写测试停在有效 RED；本地提交保留无关改动，标签／远端／发布按各自前提核验；文章、方案与口播各用专属方法、声音与审计。

## 收益与代价

同一职责中的连续请求可承接既有材料、状态与授权，减少重复交接和调用名称；共同约束由主入口控制。实际收益须以任务行为与维护方式证明，技能数量或字符数不是成功判据。

入口变宽会提高模式选择与维护一致性的要求，特别是测试的生产修改权与 Git 模式相反的工作区前提。写作包包含三套较长方法；只按当前用途读取，不能为了统一入口混成一种文风。首轮审查发现的“先写测试”触发词冲突说明此类漂移是实际风险，修正后还要复查。

## 保留的替代方案

全部维持独立入口是可用回退点，旧合同与实际改稿已保存在切换前的隔离快照中。也可以把全部工程审查、素材与媒体能力塞入总控入口，但不同的结论门槛、写入权威、账号动作和真实时间基准没有稳定共同执行合同，本轮不采用。

## 验证与消费者

以当前未提交工作树为真实基线，同题比较补测、测试先行、本地提交和局部润色，补充只写测试、诊断、提交信息草稿、只推送、只打标签、标签冲突、方案、课堂准备口播、仅逐页内容和缺事实草稿。记录真实命令、产物和副作用，再做独立合同审查与打包检查；结果见[整合验证](../40-版本实施方案/剩余技能整合验证.json)。

导航、实际包引用、脚本入口和全局规则示例同步迁移。仅切换已识别的使用者，不重启已停用的宿主配置；未知外部安装与宿主自动发现不宣称已验收。提交、推送、公开发布各须另有明确授权。
