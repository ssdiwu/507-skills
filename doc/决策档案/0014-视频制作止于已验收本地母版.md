# 0014 视频制作止于已验收本地母版

## 状态

已采纳（2026-07-22）

## 背景

已有 `507-breakdown` 负责参考视频取证，`507-remix` 负责借手法形成原创创作包，`507-stage` 负责讲述内容，但仓库缺少把成熟内容与真实素材变成视频成品的稳定出口。实际完成的多场景视频还证明，成片不是一次渲染：素材核验、真人配音对时、Studio 审片、联系表检查、反馈重剪和最终技术验收缺一不可。

外部 `video-podcast-maker`（当前为 `CC BY-NC 4.0`）把研究、写稿、TTS、Remotion、发布文案和 Shorts 放进单一多阶段 skill。这能提供端到端便利，但会与本仓库“一 skill 一动作”和已有 research/stage/remix 边界冲突；因此只将其作为机制对照，不复制或改编其受许可约束的文本、代码、schema、模板、组件和资产。

## 决策

新增 `507-video`，只承担：

> 把已确认视频目标、成熟内容/创作包和授权素材，制作为经当前版本 Studio 审片、技术与视觉验收通过的本地母版，并交付可复验回执。

边界如下：

- `507-stage` 负责视频旁白内容包，不生成音频或时间线；
- `507-breakdown` 负责参考片取证，用户自己的成片素材不必先拉片；
- `507-remix` 负责原创创作包，并在进入制作前补齐交接字段；
- `507-video` 负责素材清单、真实时间基准、制作、审片、最小重跑、渲染和验收；
- 研究、选题、主稿、平台文案、登录、上传和发布继续由相邻工作流承担。

当前首选引擎为 Remotion，但不建立多引擎抽象层；已有项目使用其他可验证工具时遵循项目现状。

## 后果

- 视频制作有了与 `507-ppt` 类似的明确视觉交付出口，同时保持上游内容和参考片职责独立。
- Studio 打开、构建通过或渲染成功都不再等同于成片完成；用户当前版本确认和技术/视觉验收是硬门。
- 任何影响观众所见或所听的修改都会使旧审片确认失效。
- 发布不属于视频 skill，避免本地可逆制作和外部不可逆操作混在一个入口。
- 暂不复制外部项目的 TTS 后端、模板、组件、偏好系统或发布脚本；真实重复达到抽象门槛后再评估。
