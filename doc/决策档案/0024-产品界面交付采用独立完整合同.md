# 产品界面交付采用独立完整合同

日期：2026-10-08。状态：采用。

## 背景与决定

用户确认产品 UI 能力应负责设计、授权范围内实现及实际渲染和操作验证。现有 taste 止于方向选择，PRD 负责需求规格，review 独立只读审查；这些职责不能承接完整界面交付。已安装 impeccable 有接近的构建方法，但产品与品牌范围混合，并带有不适用于所有已有项目任务的上下文、样稿和重复确认门槛。

采用 `code/507-ui` 作为本仓库产品界面主入口，吸收可成立的方法后形成自包含合同。Apple 知识及交互细节按场景读取，业务状态与项目视觉体系仍由项目权威承担。普通后端实现、PPT、图文、品牌形象和独立审查不被并入。

## 收益与代价

方向确定后能直接推进实际界面、操作和错误恢复，把完成信号连接到可复验结果；不再依赖使用者机器上的另一个设计技能，避免在 507 体系维护两个相反的 UI 主流程。

代价是精简后入口 28→29，需要维护产品 UI 方法与相邻职责的边界。按风险验证选择、执行和停止位置；不以新增数量或文本更短证明效果。已安装外部技能和各宿主配置不由这项仓库决定自动改写，启用需单独核对实际消费者，不能将文件交付说成已自动加载。

来源比较、未采用默认、读取范围及试点边界见[产品 UI 能力整合](../20-能力参考/product-ui/README.md)。现行行为由[507-ui](../../code/507-ui/SKILL.md)负责，试点与独立审查见[验证记录](../40-版本实施方案/UI能力整合验证.json)。
