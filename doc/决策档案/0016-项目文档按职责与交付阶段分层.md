# 项目文档按职责与交付阶段分层

> 2026-10-03：现行规格默认归属与存量保留策略已由 [0020](0020-现行规格独立维护与存量项目迁移.md) 取代。下文保留原决定，不作为当前默认入口；职责分类、惰性创建和非机械归档原则继续适用。

主动维护型代码项目默认以 `00-产品与原则 / 10-架构与运行 / 20-能力参考 / 30-路线图 / 40-版本实施方案 / 90-归档` 区分文档职责，并保持惰性创建。项目已有清晰历史组织时沿用现状；没有既有规格入口时，已经确认且需要耐久指导交付与验收的 PRD 默认进入 `doc/40-版本实施方案/`，不另建通用 PRD 仓库或把规格继续平铺在 `doc/` 根目录。

这一分层选择“内容负责什么”而不是“文件是否已经完成”作为目录依据：issue 负责状态、调查与执行追踪，PRD / 实施方案负责交付与验收规格，`00` / `10` 负责当前产品与实现事实，`CHANGELOG.md` 记录已经完成的用户可感知变化，`90-归档` 只收被取代、放弃或纯追溯材料。完成但仍是有效验收基准的规格保留在 `40-版本实施方案/` 并由目录索引标明状态，避免机械搬迁造成链接漂移；代价是目录 README 必须持续维护状态与唯一权威关系。
