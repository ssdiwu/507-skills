# 原创多载体 PPT skill 与来源边界

建立 `507-ppt` 作为视觉幻灯片制作 skill：它消费已经收口的逐页内容，依据明确选择或环境能力生成可编辑 `.pptx` 或单文件 HTML。HTML 与 PPTX 都首批支持瑞士风和杂志风。

## 为什么

一个视觉制作 skill 同时依赖另一个同类 skill，会造成发现竞争、能力边界模糊和维护分散。`507-ppt` 因此从风格意图和载体适配出发：瑞士风与杂志风只定义当前可观察的字体、颜色、网格、元数据和图片约束，HTML 与 PPTX 分别以各自原语落实。

本仓库把来源边界落在可检查的当前事实上：项目内文件、依赖和资产需要来源记录；第三方项需有版本、许可证和 notice；输出 HTML 必须离线可运行。该记录支持工程审查，但不作为历史访问或法律结论。

`507-stage` 继续负责现场内容和逐页认知节奏，`507-ppt` 只负责视觉成品与验证。这避免用排版替代内容决定，也避免一个 skill 同时承担内容编排和两个渲染载体。

## 为什么先验证再备份旧 skill

旧 skill 的活动位置只在新 skill 的 HTML/PPTX 样例、测试、来源记录和恢复命令可运行后调整到非发现备份目录。备份目录和恢复命令让技能发现切换可复验，避免切换时丢失可用入口。

## 考虑过的备选

**保留两个同类入口。** 否决：用户需要记住载体和 skill 选择，技能发现也会产生竞争。

**只做 PPTX。** 否决：officecli 缺失时无法交付演示成品，也无法满足独立 HTML 动态演示需求。
