# 现行规格独立维护与存量项目迁移

状态：已采纳，2026-10-03。取代 [0016](0016-项目文档按职责与交付阶段分层.md) 中“现行 PRD 默认进入版本实施目录、已有清楚旧布局继续沿用”的约定；按职责分类、惰性创建与不因完成机械归档的原则继续保留。

持续维护的软件项目使用 README 提供定位与实际入口、AGENTS 规定工作与授权、DESIGN 维护共用设计、GLOSSARY 定义领域词义、spec 持续维护现行功能与验收、doc 保存长期依据、实现说明、规划与历史。版本实施方案说明一次交付的安排，回链 spec；不再维护另一份功能正文。小型或无界面项目按真实用途裁剪，写作和业务工作区按其实际内容职责组织。

新项目直接建立这些依据，已有项目在选定范围内核对有效内容后迁移，同步正文、导航与消费者，退出旧维护路径。选择这一方式，是为了让后续任务直接找到当前要求，避免版本方案、术语和设计中长期保留相互竞争的行为约定；代价是迁移时要逐项保全要求、来源和在途改动，并校准全部受影响引用。

执行与例外以 [项目启动与迁移标准](../../code/507-setup/references/project-standard.md) 为准；规范迁移、工程实现和实际验收分别成立，参考材料与冻结历史继续保持原样。
