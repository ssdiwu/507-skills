# 0025 按用途组织共有资源库

状态：已采纳。日期：2026-11-18。

## 背景

`v0.3.4` 的共有库同时承载判断方法、设计参考、执行脚本、视觉运行包和库务索引。24 个技能的直接依赖既包含执行入口，也包含说明、测试和许可。同一任务的维护者需要先辨认文件用途，才能选择该读的说明和该运行的工具。

## 决定

| 目录 | 职责 |
| --- | --- |
| `lib/methods/` | 按取证与判断、工程与验证、协作与接续、写作、设计与呈现组织方法。设计指引和来源资料随对应方法维护。 |
| `lib/components/visual/` | 同一视觉运行包维护真实控件、页面视图、演示场景和预览环境，共用依赖锁与导出入口。 |
| `lib/components/tools/` | 按检查、数据投影和导出区分可运行工具及其说明。 |
| `lib/catalog/` | 保存共有资源登记、逐技能依赖表及技能名称迁移记录。 |

保留精确文件清单，由每个技能的 `RESOURCES.md` 声明直接依赖，生成的人读视图区分方法、工具、界面组件和库务资料。作用于单个组件的示例、测试、来源和许可随组件维护。

## 取舍与影响

仅调整依赖表的展示可以区分文件用途，源码中的工具定位和引用仍沿旧目录。逐类拆成独立安装包则会增加版本和依赖协调。本次选择迁移物理目录并保留完整集合安装，视觉组件共用一套运行环境。

旧版安装继续使用其版本自带的目录。升级者按新版本说明更新自定义脚本中的直接文件路径。随库交付的调用方、文档、测试和清单同步切换。回退时切回先前完整集合。
