# 保留职责分组与创作命名

2026-10-07 重新通读 28 个活动技能和命名依据后，恢复统一成文入口的 `507-forge` 名称。`507-write` 是上一轮整合时采用的临时名称，没有充分承接 [0007](0007-code与common采用功能直译名称.md) 保留稳定创作命名的要求。本文校准 [0021](0021-同职责入口按权限与产物分流.md) 的成文入口名称；三个产物模式、修改权限、完成条件及总计 28 个活动入口保持不变。

> 后续命名与 taste 归属取舍由 [0023](0023-采用Git与配音名称并调整视觉归属.md) 采纳；本文保留 forge 恢复及当时剩余建议的依据。

## 分组与名称各自表达什么

- `common/` 承载跨交付类型的认知、取证、用户取舍、技能维护与移交；不是必经前置阶段。
- `code/` 承载软件与产品工程，包括工作依据、前置实现证据、规格、任务、修复、测试、结构检查和 Git 交付。
- `write/` 承载知识与内容创作，包括材料、创意、作品、知识入口和媒介成品；目录不按文件扩展名划分。

code/common 继续用易理解的功能名称与已确认的稳定词语。公开入口不必全是动词，prd、issue 等产物名称也能清楚定位职责；不为语法形式统一改名。write 的材料成形主链保留 prospect（探矿）、mine（挖掘）、fuse（融合）、forge（锻造），cast（铸造）从碎片走向知识主题页，与 fuse 并行。视频和媒介制作继续使用其专业动作、载体或主场景名称，不强套冶金词。

公开技能名表达主要职责，中文标题与描述解释动作和边界；模式和参考文件用 prose、proposal、spoken 等产物名称，帮助执行者直接找到方法。恢复 forge 不会把方案写成文章、把讲稿写成正式方案，也不扩大媒体制作或发布授权。

## 实施与恢复

仅保留一个成文 SKILL.md，不恢复独立 frame/stage 或临时 write 的活动别名。同步当前导航、调用、脚本工作目录和已识别的本机旧入口；历史审计保留当时名称，旧路径审计链接固定到相应提交，不伪造过去已使用新名称。

三个核心模式参考、脚本实现、测试和许可证逐字保全；其他审计说明只同步调用名称与工作路径，不改方法与语体。候选在基于 2d415d1 的隔离工作树完成，静态合同独立审查、入口与引用检查通过后再切换；未知外部安装、自动发现和宿主实际调用分别报告。完整审视及剩余命名建议见[复核记录](../40-版本实施方案/命名与目录复核.json)。

其他候选如 taste 的归属、release／ppt／narrate 的更精确名称仍是审视建议，不包含在本次已采用决定中；不得从这份命名决定推导新能力或批量迁移授权。
