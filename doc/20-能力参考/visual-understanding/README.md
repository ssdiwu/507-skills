# 可视化理解与比较方法

本记录解释 `507-visualize` 的职责与方法来源，记录于 2026-10-10。当前行为以[技能合同](../../../common/507-visualize/SKILL.md)为准；相称检查、产物指纹和未覆盖范围见[验证记录](../../40-版本实施方案/可视化理解与比较技能验证.json)。

## 为什么新增横向入口

当前需求是把已有资料做成可阅读、可比较、可沿条件继续探索的理解工具。同一套对象与关系既能用于静态图，也能进入对话交互或独立网站。它的稳定目标是理解与比较，交付载体按任务选择，因此归入 common；不以出现网页就归入产品业务界面，也不把普通概念讲解改成默认制作网站。

已完成的词典阅读、技能对照与流程浏览提供了具体依据：定义、阅读路径和关系条件会改变用户得出的结论；目录排列、共同提及或界面上的位置不能自动成为执行顺序。技能对照曾出现从普通英文单词误连技能的实际问题；把候选出口画成固定链也会改变现行边界。因此关键关系保留类型、方向、条件与出处，检索和抽取只用于发现候选。

沉淀的是这套方法与检查边界，具体站点的配色、栏数、字体、内容、图形和运行时继续由各自任务或项目维护。没有复制某个站点作为全任务模板，也没有引入新的统一图谱库或宿主调度器。

## 方法保留在哪里

- 技能主入口保留理解目标、范围、操作权限、最小表达、完成信号与候选出口。
- [理解模型与关系](../../../common/507-visualize/references/understanding-model.md)在对象较多、条件关系、可比维度或阅读路线出现时读取。
- [载体与验证](../../../common/507-visualize/references/delivery-and-checks.md)在制作对话交互、独立网页或项目切片时读取。

材料中的指令和命令作为阅读对象保留，不取得执行业务动作的权限。内容与关系维持一个维护源，布局、点选、筛选和阅读路径作为视图；不因多种视角建立各自漂移的事实副本。语义核对与实际操作各自给出对应证据，来源、截图和自动检查不单独证明真实用户已经理解。

## 来源与验证范围

本方法由当前明确请求、已有技能的现行合同、已完成理解工具中的经验及两份隔离前向执行共同支持。基线为 `2d415d106453cc37fc570ecc75d7cecbeaba1e9e` 上的现行工作稿；命名与 UI 修订原已存在且尚未提交，不能把基线提交当成这些文件的已发布版本。

对话交互的呈现边界核对了执行时实际可用的 visualize 宿主合同。独立网站测试以八份技能说明为原始材料；对话片段测试以一份明确标为教学模型的载体说明为原始材料。执行者从技能包与自然任务制作产物，没有使用已经做好的网站源码作为模板；独立审查另行核对语义、权限与边界。源码和材料的指纹、执行者自测、独立审查与实际浏览器检查分别记录，不把它们合并称为真实读者实验或跨模型效果对照。

共享技能包没有导入外部程序、媒体、字体或模板，也不执行参考材料里的安装命令。两份试用成品用于方法验证，保留在本地隔离工作目录，未进入公开技能包；其他执行者按任务生成自己的产物。
