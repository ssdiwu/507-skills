# 提示与指令审计：来源与宿主差异

核对日期：2026-10-30。现行方法是 [提示与指令审计](../../../lib/methods/prompt-instruction-audit.md)，由 `507-setup`、`skill-design`、`507-review` 按各自职责采用；本页保存来源和机制差异，不是另一份技能合同，也不自动配置宿主。首版保持20个入口，没有新增审计技能或执行脚本。

## 已有依据与本次提炼

当前上游网址会变化。审计执行时按实际产品与型号重新核对关键主张并记录日期；历史固定版本与当次采用范围继续留在原记录。没有把任何型号写成永久默认目标。

## 宿主机制与实际模型分别核验

下表是官方文档核对结果，供识别应查的机制，不保证使用者安装的任意版本均有相同行为。执行审计仍需实际版本、当前配置和可得运行证据。API 兼容协议与模型别名不足以证明实际厂商或具体型号。

| 维度 | Claude Code | Codex | 审计影响 |
| --- | --- | --- | --- |
| 项目指令 | 核 `CLAUDE.md`、`CLAUDE.local.md`、导入与路径规则；v2.1.277起还需核当前版本和 Project instructions 设置下的 `AGENTS.md` 支持，不读取 `AGENTS.override.md` | 核全局与项目指令链、`AGENTS.override.md`、`AGENTS.md`、备用名称与当前目录；每层选择和合并按当前机制 | 先核加载关系，不能仅凭文件同名或文本不同判冲突；移动文件不自动减少读取成本 |
| 技能发现与正文读取 | 核个人、项目与插件来源、同名解析、调用控制字段和实际读取 | 核技能发现来源、初始目录可见性、元数据与正文的按需读取，以及当前宿主返回内容 | 文件存在、描述可见、正文返回、实际采用各自举证；同名副本不直接按双倍常驻成本计算 |
| 元数据与配置 | `disable-model-invocation` 等是宿主控制能力；字段是否受支持及含义需查当前版本 | 不假定识别或同义执行另一宿主的字段；按当前支持检查 | 不直接照搬调用控制、前置授权或子代理配置 |
| 原生审计入口 | 官方文档记录 `/doctor prompt-audit`，要求 v2.1.283 或以后，并依赖未关闭的内置技能 | 本库通过现有三个技能采用方法，不提供同名命令 | 原生命令报告可以作为待核输入，不能代替自己的范围、当前来源与写入许可核对 |
| 模型行为 | 对实际 Claude 型号查对应官方依据和行为证据 | 对实际 OpenAI 或其他配置型号查对应依据 | 一个宿主可连接不同模型；不能按宿主名称套用另一型号的提示建议 |

机制出处分别为 [Claude Code 工作指令](https://code.claude.com/docs/en/memory)、[Claude Code 技能](https://code.claude.com/docs/en/skills)、[Codex 指令发现](https://learn.chatgpt.com/docs/agent-configuration/agents-md)与 [OpenAI 技能](https://learn.chatgpt.com/docs/build-skills)。这些资料的加载、覆盖与调用语义分别适用，不合成为一条统一宿主规则。

[Claude Code 的 AGENTS.md 说明](https://code.claude.com/docs/en/memory#agentsmd)还明确了直接读取的条件：工作目录及上级的 CLAUDE 文件会影响默认选择，设置和内置能力状态也会改变支持范围。因此同一份 `AGENTS.md` 可被两个宿主采用，却不能共用 Codex 的 override 语义。导入也须区分：文本导入会展开到上下文，普通文字要求“请读某文件”不能直接视为已经加载。

原生命令文档与上游方法可能给出不同默认扫描范围；本库始终沿当前请求与授权范围，不借原生命令的默认行为扩查用户级配置。宿主实际加载机制、个人调度策略和共享方法分别维护，不能将个人绝对路径、凭据或本机配置复制入公开包。
