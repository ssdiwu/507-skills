- **基座**：仓库 `HEAD` 为 `19d00d6368dac418b6ef65bad9ff4d3123c6535c`，审视的是当前工作区，包括已有未提交改动，而非只看该提交。
- **范围**：32 个 SKILL 主入口；根与嵌套规则、安装及工作流说明；相关参考文档与宿主显示元数据；两个实际组装模型请求的函数。

## 结论

发现 7 项有具体位置和相反指令支持的合同问题。其中 3 项可按可追溯的新规则提出局部修订，4 项涉及无法排序的未提交改稿、发布保护条件或审片边界，仅列为 `flag`（待定项）。这是文本层面的结论，尚未证明这些冲突在每次任务中都会导致错误。

最值得先处理的是：grill 的授权落盘规则与旧的立即落盘要求并存；frame 的自主完成职责与逐节审批并存；release 的精确授权范围与批量推送所有 tag 的示例并存。另一个直接影响交付的分歧是 stage 与 ppt 对页面标题的要求不同，两侧均有未提交修改，不能靠文件时间判断谁覆盖谁。

这轮没有把技能数量、字数、禁止句数量或规则重复本身作为缺陷。现有 inspect/simplify、grill/prd、forge/stage/ppt 的职责与停止位置仍有真实区别。

## 发现与依据

### PA-01｜grill 的立即落盘要求未带授权条件

- **位置**：`common/507-grill/SKILL.md:8`、`:185`，对照 `:167`、`:181`、`:229`。
- **原文证据**：旧段落写“一个术语敲定就当场写进 `doc/术语表.md`，不攒着批量补。”；现行归宿段落写“确定归宿不等于获得新的写入授权”，仅授权对齐时先保留会话共识。
- **模式**：第 2 组，同一技能对同一行为存在不一致的条件。
- **影响场景**：用户只要求讨论并确认一个术语，模型可能把“术语确认”理解为“文档写入授权”。这不是已观察到本轮发生了写入，而是两条指令对该输入给出不同动作。
- **历史依据**：立即落盘段来自 `b706261`（2026-06-27）；授权与归宿段来自 `e0697e2e`（2026-08-06）。
- **置信度**：高，条件差异与先后有仓库证据。
- **动作**：`rewrite`。假设沿用较新的授权合同，将开头摘要和术语小节同时改为：需要耐久保存且当前已授权时写入，否则留在会话。保留术语表与 ADR 的准入条件，不删除记录责任。
- **差异**：[proposed.patch](proposed.patch) 中 grill 的两个 hunk（差异块）。

### PA-04｜stage 与 ppt 对同一页面标题的要求不同

- **位置**：`write/507-stage/SKILL.md:259`、`:261`、`:266`，以及 `write/507-ppt/SKILL.md:69`，对照后者 `:28`、`:89`。
- **原文证据**：stage 要求“标题要说出实际问题、判断或动作”；ppt 要求标题默认用“类别：所指”，“只回答这页是什么；观点与金句放正文和 notes”。ppt 同时承诺内容语义不被视觉改写。
- **模式**：第 2 组，上下游交接合同在同一内容字段上分歧。
- **影响场景**：已确认的判断型标题进入视觉制作后，执行者可能保留其判断，也可能为遵守另一条规则改成类别标签。两者对标题承载的信息要求不同，不能只当排版差异。
- **历史依据**：关键的 stage 标题条款和 ppt 文案层条款均为工作区未提交修改，不能用 `git blame` 排出已确认权威的先后。
- **置信度**：高，要求不同可核对；应选择哪一套仍未知。
- **动作**：`flag`，不进入差异。需要确定内容阶段与视觉阶段分别可以修改标题的哪些部分，以及已有明确标题在交接时是否锁定。没有用审计覆盖当前改稿。

| 方法 | 建议承接 | 本次审计增加的要求 |
