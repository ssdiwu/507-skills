## 采用的方法与实际修改

| 对象 | 有依据的问题 | 处理 |
| --- | --- | --- |
| 新增 [507-skill](../../../../common/507-skill/SKILL.md) | 缺少统一维护技能合同的 507 入口，原 write-a-skill 偏重初次创建 | 承接创建、改写、指定范围审视与方法融合；比较职责后决定承接位置，按需读取演进和验证参考 |
| 32 个既有描述 | 执行细节与同义触发枚举混在技能选择信息中，部分宽泛词不能区分相邻动作 | 全部按动作、适用条件与易混淆边界改写；常规执行细节仍在正文，不因压缩描述删除合同 |
| 仓库阅读规则 | “修改前依次阅读”与全部显式引用容易构成无条件读取链 | 首次建立必要背景，后续按变化与相关分支补读；目标技能与适用规则仍须读取 |
| frame 与 grill | 已确认输入容易被误写成必须经过 grill；已明确范围仍可能再确认 | 直接消费用户已确认材料；范围本身有实质取舍或后续扩范围时才确认 |
| stage | PPT 页面与 AI 课程专用细节常驻主文件，检查条目未明确载体条件 | 原文抽到两份条件参考，按实际产物和主题读取；材料真实性、讲者声音、权限与完成要求保留在入口 |
| test 与 commit | “依次扩大”及进入提交阶段重新运行，可能忽略已有有效证据 | 完成目标和项目要求的必要检查；核对内容、依赖、配置和环境后复用有效结果，按新变化、失败或具体疑点补跑 |
| frame 合作写法 | 特定案例的称谓与栏目偏好被推广为通用禁令 | 企业与学员按真实差异区分，角色按已确认职责命名，不自动改掉“联合发起人” |

32 个既有描述合计从 9,038 字符变为 2,410 字符。这是文本规模，既不是宿主实际 token 用量，也不证明正确率、质量或速度改善。27 个技能的正文保持逐字不变；其余 5 个正文的改动类型已逐项记录。stage 移出的两个原文块完整保留。

新技能承接 write-a-skill 的可复用方法，并校准以下条件：不把“多步骤”设为技能准入门槛，不用约 100 行决定拆文件，不把所有问题固定为逐题询问，不把通用化解释成直接删除历史与边界。普通项目任务不自动触发技能编写，单个模型的行为建议不成为共享技能的默认前提。

| 既有视频合同检查 | `python3 write/507-video/scripts/test_contract.py`：5/5 | 该检查直接消费 SKILL.md；没有因此重跑无关媒体、模型或设备测试 |

| frame 修正后的前向执行 | 实际写出正式方案，保留双方“联合发起人”、企业与学员差异、20 人、每人 500 元、半天及日期待公布；没有额外对齐 | 证明该指定请求下的方案产出，不证明真实活动或发布完成 |

系统 skill-creator 的 `quick_validate.py` 对 32 项通过，对既有 breakdown 的 `compatibility` 字段报未知字段；基线同样失败。已核对 [Agent Skills 规范](https://agentskills.io/specification)，该字段是有效的可选元数据，因此保留原字段，另行核对规范约束。没有删字段或修改系统校验器来制造通过。

独立交付审查发现两项 P2：grill 启动清单残留无条件范围确认，以及 frame 的角色／受益方过约束。两项已修正并由原审查者定向复查关闭；未发现剩余阻塞问题。首轮审读与定向复查是语义审查，前向执行与描述选择是另行进行的模型检查。
