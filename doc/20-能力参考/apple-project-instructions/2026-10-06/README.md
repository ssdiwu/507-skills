## 用反例核对决策与动作

以下是移交案例的匿名化推演，描述有范围的历史问题，不宣判任何项目最新状态：

- 阶段进度放入AGENTS、DESIGN或GLOSSARY，内容虽有对应，职责仍可能错放；应保全证据并归回交付／状态载体，不能只数规则覆盖。
- 当普通启用文字已有4.5:1的明确目标，声明组合复算为2.66:1、2.62:1或3.40:1时，仅能判定这些组合不满足该目标；保留失败依据并承接候选替换／复验，不能只标“候选”后永久搁置，也不推断全部控件或禁用文字。
- 720px窗口同时展开264px侧栏与440px检查区，主区剩16px；仅断言两侧存在仍会通过。验收须判断主区阅读与输入目标，适配方案由工程收口，不把明显不满足目标的空间交给用户选择是否接受。
- 助手条目已保存但正式读取未投影正文，条目存在不能证明用户收到。反馈环应沿原操作、正式读取、关闭重开和展示判定结果，不因后台保存或旧绿灯结束。
- 执行接口与产品应用／投影层可能承担不同责任；草稿也可能含需保全的用户输入。应保留高成本关系及其证据，不按目录／类名直接覆盖，或把草稿一概当作可重建缓存。
- 新模型或低风险机制可触发复核，可靠检查确已承接的重复条目可合并；仍适用的数据保护、授权与写入约束不能靠删除后等事故重建。

本轮独立前向检查仅提供单独技能包和七个原始请求，未给预期答案。检查者按各入口判断文档归属、候选差距、版式与正文证据、修复反馈环、TDD阶段、规则退役和公开扣费次数，未发现阻塞这些请求的内部矛盾；同时保留布局机制未知、真实UI未验收与可选外部模板未随包提供的边界。

这是一轮隔离材料上的模型案例推演，不能证明真实产品已修复、全面自动验收或普遍效果改善；链接／格式／入口检查与模型推演分别成立。尚未进行旧稿对照、跨模型或真实读者效果实验。
