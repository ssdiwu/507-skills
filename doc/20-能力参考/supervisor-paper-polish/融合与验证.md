# paper-polish 方法融合与验证

## 采用范围

本次只改造 `507-forge` 的已有稿件表达润色入口，并同步其整稿审计参考、根与写作流说明、文档导航和变更记录。没有新增技能入口，也没有把学术章节惯例、默认英文输出或投稿语体设为通用写作要求。

已有稿件的纯语言修改直接完成；结论强弱、因果、条件、责任主体、论据删减和补入逻辑另列含义风险。用户确认具体变化且所需事实依据成立后才能写入正文。创意卡、材料链和完整成文审计继续用于成文、结构重写和平台改编。

## 原位处理

| 原有位置 | 处理 | 防止的误判 |
| --- | --- | --- |
| forge 的自动入口 | 区分表达润色与成文／结构重写／平台改编 | 仅因已有文字需要改顺，就要求补创意卡和走素材链 |
| forge 的交付门与完成合同 | 保真检查按指定范围执行；整稿审计适用于完整成文 | 局部润色被扩大为重排、压缩、补论据或格式转换 |
| prose-revision 的读取条件 | 明确只服务成文／重写／改编后的整稿审计 | 将删段、材料回补和三分之一压缩试验用于一段既有文字 |
| 作者模型、解释推进与图片证据 | 原文保留 | 采用外部润色方法时丢失既有作者声音和成文职责 |
| stage 与其他创作技能 | 本轮保留 | 把学术稿件润色当作现场讲述或整个写作链的替代 |

## 验证记录

固定来源八个原始文件已与 Git blob SHA-1、SHA-256 和字节数对照，paper-polish 的目录文件集合完整。原件不执行、不作为宿主指令。

候选已通过技能元信息检查和 forge 既有表达检查器的五项回归；本次自有文档的本地导航目标有效。作者模型、解释推进和图片证据段落与基线逐字一致。

两位独立 Agent 在隔离目录分别用基线和候选处理同样的四个请求。评估者只收到指定技能、原始请求及文本和允许写入的临时目录，没有得到预期答案或此前结论。实际八份回复均已读回比较：

| 案例 | 基线观察 | 候选观察 |
| --- | --- | --- |
| 一段既有作者主稿 | 保留核心判断与七段叙述，同时额外建立写作依据与主稿 | 直接润色七段，保留核心判断、反问、口语节奏和两种产品各有需求的边界 |
| 数字、版本与验收条件 | 保住主要信息，但增加写作依据／主稿，并改变段落与缩进格式 | 保留日期、数量、版本、错误预算上限、状态名、因果不确定性及客户验收边界，沿用原格式 |
| 模拟样本不足以支持普遍证明 | 披露后直接在交付正文收窄结论 | 原句保留，另列具体建议、原因与含义风险，候选未写入正文 |
| 不可读公式 | 保留占位并报告未核对部分 | 保留原位置与占位，完成两段可读正文，明确公式未处理 |

基线为四案额外生成八份写作依据／主稿；候选没有额外创作产物。四案的候选行为符合本次确认的轻润色合同。独立 `507-review` 已检查规则、来源、实际输入与两版的八份回复，Standards、Spec 与 Code Quality 均未发现阻塞问题；审查者仅写入自己的报告，没有修改候选或真实仓库。可读与机器记录分别见本页及 [verification.json](verification.json)。

## 证据边界

技能规则、确定性检查、独立 Agent 文本回放和真实作者验收分别成立。回放包含一段既有作者主稿和合成边界样例；私有原稿和回放正文只保留在隔离评估目录，不复制到公开仓库。四个短文本的回放不能证明跨模型效果、长文分块行为、普遍质量提升或作者已经接受某篇改稿。
