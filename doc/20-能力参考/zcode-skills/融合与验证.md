日期：2026-10-03。本文记录提交前已完成的技能合同修改与静态复核，是本次采用范围和验证证据的历史快照；后续提交与发布状态以 Git 历史、版本标签及 Release 为准，当前行为仍以各技能的 SKILL.md 为准。

## 已确认边界

- 融入 ZCode 的功能边界分析与架构治理方法，同时处理 prompt-audit 的全部 7 项合同问题。
- 复用目标项目已有检查，报告真实覆盖与缺口；不新增跨项目检查器、统一工具链或技能入口。活动技能仍为 32 个。
- 页面标题按任务表达问题、判断、动作或资料定位；视觉阶段保留已确定的含义。
- 视频首选 Remotion，已有其他引擎可以使用等价、可核验版本的预览；当前版本的用户确认与适用的独立终检要求继续成立。
- 原件保持冻结；既有无关改动保留。没有操作 D Code 工作目录或修改用户级配置。

## 场景走查

以下是基于实际条款的人工合同对照，用于查权限、入口和停止位置是否一致，不是独立模型的行为回放：

| 场景 | 对照后的合同结果 |
| --- | --- |
| 只有局部文字调整，影响已有证据 | 不强制展开影响矩阵或工程设计表 |
| 多个入口共用组件但提交对象不同 | 分别追踪默认、校验、提交与保存，不推断它们同步改变 |
| 需求充分、准备直接实施 | 正常实施可读工程参考，不先启动用户追问 |
| 只对齐方案时读取工程参考 | 参考不扩大权限，仍不修改代码、契约或配置 |
| 异步结果过期、重复提交或恢复 | 设计交代所有权、顺序和结果生效边界，检查返回真实行为证据 |
| 检查只纳管部分模块 | 报告实际覆盖与缺口，不宣称全仓受控 |
| 新违规可以靠刷新基线消失 | 不能自动刷新；保留失败，按明确范围与审查依据处理 |
| 产品行为仍未定义 | 查事实或返回用户取舍，不将 TODO 藏入完成规格 |
| 只确认一个术语 | 保留会话；不将确认术语等同于授权写入 |
| 已授权维护术语表且满足准入 | 更新现有权威，不再额外设同一动作的确认门 |
| 完整方案需求已充分 | 自主完成可通读版本；显式逐节共创请求仍按节反馈 |
| 判断标题与案例标题进入 PPT | 各按页面任务保留含义，不机械统一句式 |
| 只输出 HTML、明确无备注 | 不制造 PPTX 或备注，仍核对当前内容源与实际生成物 |
| 仅推送已有分支，Unreleased 为空 | 不为推送创建版本或日志；共同安全前提与精确目标检查仍成立 |
| 只建本地标签 | 只对确定提交创建指定标签，不要求远端连接、不产生额外定版提交 |
| 发布已定版版本 | 核对已有版本证据与渠道状态，不强制重复定版 |
| 已有其他视频引擎 | 用等价的整片预览与可核验版本审片；能力不足则报告缺口 |
| 用户说可以渲染但同时提出修改 | 留在修改与审片循环，旧确认不能用于新版本 |
| 产品宣传片只有制作方自检 | 独立终检要求继续成立，不能冒充已独立验收 |

## 验证与审查边界

- 先在隔离候选中生成修改，核对当前工作区哈希后才应用；基于用户已有改稿，没有用 HEAD 覆盖它们。
- 新增 3 个方法参考，26 个技能／导航／变更记录文件完成修改；没有新增活动技能或运行依赖。
- 现有视频条件合同的 5 项检查在改动前、隔离候选和落地后均通过；它们只验证既有条件合同，不等于已渲染或验收非 Remotion 视频。
- 按 507-review 做了单独只读复核，检查规范、已确认选择、各技能权限与出口；补齐了工程参考权限继承、术语惰性创建的授权条件、仅建标签不产生定版提交及远端完成后回查等边界，随后复验。审查来自同一执行 Agent 的独立阶段，没有声称由第二个模型独立复核。
- Markdown 链接、差异格式、文件集合与原件摘要均在交付前复核；机器记录见 [verification.json](verification.json)。
- 此次静态复核未运行全仓媒体生成、真实模型 API、远端发布或跨模型技能效果回放。这些合同在检查范围内一致不等于宿主每次都自动加载，也不等于已经证明实际任务质量或成本改善。

机器记录中的文件摘要与提交状态对应上述提交前快照，不用于判断后续版本的当前状态；上游 26 个冻结原件仍由原有 source-record 与 SHA256SUMS 管理。
