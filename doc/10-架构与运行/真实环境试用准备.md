# 真实环境试用准备

本轮先把同一新版507-skills收成可追溯、可接入、可回退的本地试用副本。下一轮再进入指定项目或工作环境。试用副本不是另一个技能库，也不是正式发布；它冻结当前17入口及其完整随包资源，作者侧共有维护源仍是lib。

## 对照原子不构成待办

507已明确：自动领取ready任务等调度机制不属于当前必补能力。外部方法有某个原子、新版没有明文对应，只是差异；只有当前获授权任务因此失败或受阻，才成立需要修复的能力缺口。原子表不是参考库功能的追齐清单。

固定pstack版本的[Feature](https://github.com/cursor/plugins/blob/d73344bee8cf22e53b9d5f4cf5749d38ba38c174/pstack/skills/poteto-mode/playbooks/feature.md)按实际独立工作流并行，共享写入串行；长期、多PR的[Orchestrate](https://github.com/cursor/plugins/blob/d73344bee8cf22e53b9d5f4cf5749d38ba38c174/pstack/skills/poteto-mode/playbooks/orchestrate.md)才有队列与前沿管理。Matt的[implement-spec](https://github.com/mattpocock/skills/blob/4588b32ecab9ecc9fc8cc6b6c5e7d675b6004b0d/skills/engineering/implement-spec/SKILL.md)采用任务图、集成分支与前沿推进。这些具体方案均不成为本新版的常规强制流程。

coordinate现在按局部协作、任务图推进、持续协调三种情境选择和切换，覆盖写作、研究与一般工作。它组织真正独立的结果，维护必要依赖，核交回证据并回到原目标；不新增自动ready队列、常驻调度器或强制固定集成分支。详细边界见随库[task-coordination方法](../../lib/methods/task-coordination.md)。

## 进入前确认

1. 固定技能构建身份、目标项目当前版本和原始请求。先按项目已有依据承接任务；不把历史试跑的期待答案交给执行者。
2. 在目标宿主实际技能列表中核对名字、说明和来源路径。先发现，再选择，再读取，再执行，分别保存证据。目录里存在SKILL.md只证明文件可用。
3. 检查同名旧入口与插件来源。明确本次选中的源文件；同名不能当作版本覆盖或合并。先使用项目范围，是否替换用户范围另行确定。
4. 核对目标环境已存在的工具、模型和数据权限。技能带有确定性脚本不等于有图片/PPTX/视频工具、业务账号或付费权限；缺条件时说明依赖，继续独立工作。

官方Codex文档说明：仓库范围读取`.agents/skills`，也读取用户、管理员和系统位置；同名技能不会自动合并。可以显式选择，也可以按description自动匹配；自动匹配依赖技能元数据。新增文件被宿主发现、实际选择正确入口和完成任务仍须分别验证。[OpenAI官方技能文档](https://learn.chatgpt.com/docs/build-skills)

首次建议由维护者把试用副本中需要的完整技能目录复制到指定项目的技能发现位置，保留源指纹与原配置备份，并按宿主当前行为核对列表。不要只复制SKILL.md。此说明没有安装程序，也不修改个人技能目录或宿主设置。

## 真实任务怎样开始

用户保持原来的任务表达，不需要报一串内部技能名。主要技能处理其独有判断；目标明确则直接进入具体能力。不要用“必须先what、再why、再how”替代真实需求。

| 实际任务 | 第一轮观察 | 相邻反例 |
| --- | --- | --- |
| 工作更新 | 对照权威事项和新消息，保留未撤销的日期、状态、条件与责任；完成后继续获授权工作 | 仅需知情、来源歧义不应建立个人责任或冻结独立明确指令 |
| 创作与改稿 | 材料充分时直接成文/适配；方向未定才讨论作者主线，保留原话与主张支持范围 | 讨论PPT顺序不等于修改文件；历史套餐前提不等于当前价格核实 |
| 工程实施与修复 | 成熟规格直接实施，明确故障先复现；范围达成后由独立审查收口 | 读代码解释不等于改代码；本地测试通过不等于真实服务或业务验收 |
| 策略与规格 | 必要介入点、取舍、验收与第一个可执行工作项 | 不把how变成每个fix/implement任务必经的前置规划 |
| 技能演进 | 有真实失败或复用需求时再修改入口、共有方法或组件 | 普通业务任务不启动技能编写，不为覆盖数量新增空包 |

先运行自然请求；若没有被正确发现或选择，再用相同任务显式点名一次以区分宿主/元数据问题与执行问题。显式补救不能回写成自然调用成功，也不能用指定路线的第二轮掩盖首轮失败。

## 记录放在哪里

继续使用目标项目已经有的过程文档；本试用不另设必须维护的工作日志。每次保留原请求、技能/项目版本、实际采用与读取、动作与产物、未完成、验证与返回位置。具体金额/日期/状态/对象保留原始来源，不要求每个任务填同一张大表。

多Agent协作沿原过程文档登记写入者、工作位置、依赖、候选身份与交回点。同一工作树一名写入者；并行写入需要独立位置。子任务完成后回到原目标，不能以“PR草稿完成”或“方法结束”关闭还未完成的用户任务。

需要共同查看任务关系和进展时，使用随库[task_view组件](../../lib/components/task-view.md)从已有记录生成临时网页。已支持明确JSON任务数组或Markdown唯一标题下的表格；映射只描述显示方式，业务内容仍在原记录。记录更新后再次运行同一组件；手改生成HTML会被拒绝。缺格式、字段或交互时修订组件及相关验证，不为每项工作重新写网页。

给维护者的可选记录骨架见[试用记录](../40-版本实施方案/真实环境试用记录模板.json)。它用于整理证据，不作为业务Agent的额外总控指令；字段未获得证据时写未知，不能预填通过。

## 出现卡点怎样改

| 实际症状 | 先检查 | 修改归属 |
| --- | --- | --- |
| 没有发现入口、出现同名来源 | 宿主范围、插件、列表与实际路径 | 接入；不先改技能内容 |
| 选了相邻入口或过度路由 | 原始请求、元数据、必要判断是否充分 | 对应入口的触发与跳过边界 |
| 多个消费者犯同类判断错 | 实际读到的共有方法及消费者条件 | 原位共有方法，核受影响消费者 |
| 明确机械动作重复失败 | 输入、依赖、错误回执及当前输出 | 已有组件；确认确定性需求后才新增 |
| 项目业务逻辑错 | 原动作、实际源码与真实调用方 | 目标项目产物，按项目规范修复 |
| 缺领域或载体能力 | 目标是否真的需要该能力、现有工具能否承接 | 新任务证据成立后再组织次要技能或组件 |

## 回退与退出

试用前保全原技能目录/配置及项目可用基线。回退只撤销本次已登记的接入和候选改动，按备份恢复；不删其他技能，不清理业务数据，也不覆盖其他Agent在途工作。核对实际启用路径和项目原路径后再恢复使用。

本轮准备达标：17入口普通文件资源完整、源和副本一致、已有测试证据可追溯、原子映射可查、试用副本可独立读回、网站状态一致。下一轮真实环境中取得宿主发现/自然选择/执行/返回与业务验收的证据后，再决定扩大使用或替换旧入口；未验证的媒体、真实平台与领域能力继续保留缺口。
