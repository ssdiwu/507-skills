# 旧工作流与当前设计的条件接力

旧侧绑定已推送5f3b0f8的README原图；当前侧为5主要/32方法/48组件设计导航，不是技能迁移或运行证据。图只说明条件和返回，用户不必按what→why→how或三级顺序触发。规划请求止于规划，实施沿既有授权继续，子结果不结束未完成父目标。

旧README八图保留原文及固定行号；原边空条件不解除相邻正文的权限、基线或退出约束。当前内容平台发布仅为外部出口，不能冒充48接口内已实现发布能力。

## 当前工程路线

```mermaid
flowchart TD
 task["工程目标、版本与修改权限"] -->|"目标有实质缺口"| what["what"]
 task -->|"机制未知"| why["why"]
 task -->|"跨约束策略未成"| how["how"]
 task -->|"已有方案/故障/任务图"| work{"直接选择完整工作"}
 what --> work
 why --> work
 how --> work
 work -->|"只建立/维护PRD或规格"| spec["spec：PRD/行为与验收规格"]
 work -->|"只做执行计划"| plan["plan"]
 work -->|"记录/追踪问题"| issue["issue"]
 work -->|"新增/改变行为"| implement["implement"]
 work -->|"明确故障"| fix["fix"]
 work -->|"只读改进机会"| inspect["inspect"]
 inspect -->|"收益、行为基线及授权充分"| simplify["simplify"]
 work -->|"测试资产/获授权TDD"| verify["verify"]
 implement -->|"仅必要行为依据"| spec
 spec -. "父任务已授权实施，规格结果回交" .-> implement
 spec -->|"仅规格请求完成"| result
 implement -->|"复杂接力拆解"| plan
 plan -. "父任务已授权实施，计划结果回交" .-> implement
 plan -->|"仅计划请求完成"| result
 issue -->|"仅记录/追踪范围完成"| result
 issue -. "执行态就绪且原目标已授权实施" .-> implement
 implement -->|"独立写入值得协调"| coordinate["coordinate"]
 coordinate -. "集成与整体复验回交" .-> implement
 implement -->|"产品操作路径"| interaction["interaction"]
 interaction -. "行为与操作证据回交" .-> implement
 implement --> checked["原目标完整路径与必要检查"]
 fix --> checked
 simplify --> checked
 verify --> checked
 checked --> review["review：独立只读"]
 review -. "发现回原实施者" .-> work
 review -->|"范围达成；未请求交付"| result["范围结果与未覆盖"]
 review -->|"已授权具体终点"| deliver["deliver：Git/PR/版本终点"]
 deliver --> result
 result -->|"明确复盘/重复摩擦"| retro["retro：改进候选"]
```

`spec` 承接旧 `507-prd` 的完整需求规格职责，在界面中显示为“spec · PRD／行为与验收规格”。只写PRD、只做执行计划或只记录问题都可直接进入对应方法，并止于该范围结果；只有父任务已经授权实施，规格或计划的结果才回到实施。这里保留的是完整方法身份，模板与机械写入可交共有组件；未新增已实现技能包。

## 直达与结束

明确故障直达fix，已有方案直达implement，现成任务图直达coordinate；成熟稿修订直达draft，清楚资料整理直达organize。只有当前缺口才采用主要思考或配套方法。

独立review的范围、提交/推送/合并/发布的授权与回执分别成立。模型、任务图、demo、网页点选、源代码存在不证明正式运行。真实中断采用resume；retro只在明确复盘或有重复摩擦时给改进候选，不自动改规则、工具或技能。
