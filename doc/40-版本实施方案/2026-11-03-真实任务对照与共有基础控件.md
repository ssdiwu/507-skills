# 真实任务对照与共有基础控件

本轮保持21个技能和单份共有 React 库。验证采用成熟双语内容适配、真实历史打包故障、两份原稿只读比较、按既有要求制作隔离界面四类任务；每组输入、初始可用工具及派发目标一致，由新执行者自行选择方法和组件。原稿和原始回执留在获授权的任务证据位置，不进入技能库。

## 对照能说明什么

先做指定规则正文的消融对照，不把两组称为完整历史版本。每次共有实现变化后重新冻结两组相同工具，保留首轮失败；后来收窄两组相同的隔离说明，明确“禁止宿主507技能副本”不禁止已提供的工具使用指南。这些不同轮次不能混算纯规则收益。

18次独立执行构成9组任务对照。首次多数执行者没有读取被改动的方法正文，不能据结果归因。后续仍出现错误工具判断、另起浏览器和自行实现通用控件；有一次另装浏览器依赖破坏了严格工具控制，该结果只作失败证据。最后一组两侧都主动引用共有控件与导出器，使用指定浏览器页面；当前组也实际读取了新增入口对应的方法。该结果证明这些限定路径可以自然采用，不能证明新规则整体优于旧规则、全部21技能稳定采用或长期质量提升。

## 实际发现与修正

| 发现 | 本轮处理 |
| --- | --- |
| 质量方法没有进入成熟内容的真实呈现路径 | artifact-rendering明确读取视觉方向并实际核阅读关系；不新增固定采访或多稿要求 |
| 将集合缺少同名目录当成宿主工具不可用 | 运行合同区分工具与507技能集合，保留指定浏览器/页面范围；对照隔离说明也消除范围歧义 |
| 新建界面只读交互方法，未进入“查组件”的可选分支 | do主文把新页面和隔离样稿纳入组件复用条件，React依赖与构建适用、项目缺少对应组件时读取共有ui；保留既有项目设计系统、其他技术栈和无界面/文案微改边界 |
| 自行拼装场景出口，遗漏完整许可与统一产物保护 | 同一导出器增加browser-only的--scene入口，处理挂载、CSS、完整许可、来源图和排他输出；输入场景不在Node服务端执行 |
| 选中按钮悬停变浅底白字、减少动效下骨架仍闪动 | 修共有样式选择器并实际复验，增加浏览器回归 |
| 自持组合错误暴露asChild，可能破坏结构或键盘行为 | 限制DialogContent、Switch、DropdownCheckboxItem、AccordionTrigger的类型和运行透传；支持边界在接入合同明确 |
| 固定正文先于列表，拆散说明、案例与依据 | 阅读页增加有序sections分组，与旧字段互斥，旧模型兼容；双语分组、图解身份及参数严格对应 |

## 共有组件与来源

[ui接入合同](../../lib/components/visual-runtime/ui/README.md)包含17类基础能力：按钮、输入框、文本域、原生选择、字段关联、复选框、开关、状态标签、提示反馈、空状态、骨架、进度、对话框、页签、菜单、工具提示、折叠说明。Artifact、TaskView、ProductMap直接采用同一Button/Input/Select；界面场景直接引用ui，技能不拥有运行库或控件副本。

继续使用React 18.3.1、原生CSS与lucide；复杂交互采用锁定的Radix UI，shadcn/ui的MIT组合适配到同一运行库。书签来源中，AI Elements已提示迁往shadcn/ui，未安装其旧注册表；Motion Primitives和Bencho只作交互参考，没有引入动效引擎、付费块或网站资产。Bencho免费块的MIT许可与Pro的禁止组件库再分发条件分别保留，不能笼统判断整个站点。固定来源、原文件哈希、许可和补件精度见[SOURCES](../../lib/components/visual-runtime/ui/SOURCES.json)。

`kit`继续负责光标、窗口和时间线编排，其播放状态不代表真实业务交互；真实界面采用ui。两者均由同一共有运行库维护，业务场景只保留自己的内容和状态。没有新增主技能、私有demo运行库或第二种前端技术栈。

## 验证边界

本机执行类型检查、预览构建、11项呈现/导出行为、3项实际浏览器交互、4项检查器行为、3项布局检查、47项仓库回归、85项共有数据组件回归及集合检查。实际Ego操作覆盖共有目录与限定业务样稿，包括校验、焦点、菜单/页签、错误恢复、窄屏与减少动效。首次失败和误标截图保留，修复后用相应动作重新取得证据，不用退出0代表审美通过。

这些检查、独立审查和具体任务重放分别成立；未覆盖全部宿主自动发现、长期滚动更新、所有浏览器及设备、真实业务权限/负载、读者接受和版本发布。以上记录的是当时未发布源码增量；本轮已纳入0.3.3本地定版，不追改当时的验证范围。


## 0.3.3质量方法的后续优化与隔离验证

本轮以`09c055c`为基线。单技能质量改进现在直接读取已有能力设计，沿方法是否需要、是否读到、动作及反馈定位缺口；共有验收在后续工作依赖质量判断时先取相称反馈，保留原授权和只读职责；验证方法区分首次结果、同条件效果比较及未用于修订的迁移案例。21个入口和资源布局不变，没有新增技能、工具或独立过程文档。

本轮另用独立子代理执行以下7个合成隔离情境。它们不与前文真实来源任务的18次对照合算，也没有构成本轮方法的基线／候选效果对照。方法读取由执行者报告；产物差异、计算、文件核对和独立复验分别作为相应结果的证据，不把自报读取当作完整调用回执。

| 情境 | 可核对结果与范围 |
| --- | --- |
| 单技能质量改进 | decision-brief从沿用摘要解释、检查段落齐全，改为核原始材料、证据及决定依据，保留简短说明、只做说明和不默认监控边界；这是技能编辑与静态情景检查，不是业务效果对照 |

| 资料整理 | 从虚构摘要、原记录和后续确认中区分排队已定口径、尚未实现、普通账号隔离未验证、7天替代14天及估算候选；只在回复交付，未新增或修改资料文件 |

本机重新运行集合检查（21技能、315检查文件、0共有副本）、资源关系表检查、47项仓库回归和85项共有组件回归，均通过；本轮未改React实现，不用这轮Python回归重述此前浏览器和呈现检查为新结果。独立审查还核对16个validation直接消费者及现行文档，发现并修正规格中的旧20项数量、历史覆盖页时点和共有反馈的只读边界；受影响修订与最终差异已由同一独立审查者复核，限定范围内未发现剩余阻塞问题。

呈现检查的首次直接Chrome尝试超时并遗留进程；删除命令因采用`rm -rf`被自动审查拒绝，未重试同一命令。核实为本轮独立配置后停止对应进程，后续改用Ego官方能力完成桌面独立核验；这项失败不记为390像素通过。

本轮测试输入、产物、截图、浏览器配置及遗留进程已在独立核验后清理，未进入正式集合；既有依赖、历史交付和回退材料保留。当前记录保存可复查的场景条件、结果及边界，原始执行回执留在会话。不据这7个样例宣称全部21技能稳定、跨模型改善、真实用户接受或生产效果。
