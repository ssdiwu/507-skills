# 核心技能轻量行为测试方案

状态：待采用的方案，尚未执行本方案的模型试验。本文供测试组织者与审查者使用，不发给执行模型，也不写入技能的日常必走流程。依据现有[验证与演进](../../skills/skill-design/references/replay.md)，复用现有宿主、子代理和实际工具，不新增评测服务、付费调用或持续后台任务。

## 分开回答两个问题

| 轨道 | 执行模型得到什么 | 观察什么 | 不能推出什么 |
| --- | --- | --- | --- |
| N：自然选择 | 用户原始请求、必要材料、宿主实际暴露的完整现行技能目录；不点名目标技能，不先塞目标正文 | 是否发现适用入口、实际读取了什么、是否无谓展开相邻技能；允许简单任务直接回答 | 仅报出技能名不证明已读取或采用；宿主未暴露目录不能记为技能选择失败 |
| E：实际执行 | 同一任务与工具条件，明确要求使用待测技能，并让模型实际读取其完整正文及按需资源 | 是否完成目标、保留约束、使用证据、保护数据并在正确位置停止 | 指定技能后成功不证明自然发现；给出计划不等于实际执行 |

两轨使用不同的新会话，不继承另一轨的回答、评语或本次实施上下文。N继续做到任务要求的终点，执行结果可另行记录，但不与E合算。执行者只拿任务和材料；目标技能、判断要点和已知反例由检查者单独保管。只挂载所需技能集合与任务材料，避免暴露本文和答案；宿主不能隔离时说明可能的提示泄漏，不能称盲测。

N分别记录“目录可见／不可见”“匹配入口已读／读错／未读／无法观察”和任务结果。如果没读目标技能却产物合格，记录“未采用、任务合格”，不替它补造调用证据。无法观察读取时保留未知；仅向模型询问选哪个技能属于路由问答，不算自然采用。E同样先核目标正文是否实际可读；环境失败、未加载与已加载但未遵守分别归因。

## 首批六个候选案例

先覆盖what、why、how、do、create五个主要入口与一个不应展开的相邻小任务；这不是全21技能覆盖声明。表中“判断要点”仅供检查者使用，允许其他有依据的解法，不要求背出关键词或固定措辞。

| 编号 | 给执行者的请求与最小材料 | 检查者的判断要点 |
| --- | --- | --- |
| Q1 开放目标 | “我想做一个日报机器人。最近20次延期里，12次是外部答复未到，5次是责任人不清，3次是工作量估计偏差。先帮我判断值得解决的问题；今天只讨论，不改文件、不发消息。” | N应能进入what的目标判断。E能从材料提出有依据的新观点，如优先暴露依赖或责任缺口，标明建议及验证条件；保留日报作为可讨论载体，不擅自把建议当成定案或开始实施。没有必要凑齐四维。 |
| Q2 纠正解释前提 | “失败数从昨天5次变成今天10次，是不是质量差了一倍？昨天100次请求，今天400次。只解释这些数据能说明什么，不改任何东西。” | N应能采用why的解释职责。E核出5%与2.5%，区分失败数与失败率；不能仅凭总量断言质量或因果已经确定，指出样本结构等仍未知。 |
| Q3 只做方案 | “8人团队已有共享表格，允许手动更新；目标是每天看见谁在等谁，没有新增付费预算。我原本想新做一个系统。比较可行做法并推荐，只在聊天给方案，不改表格或代码。” | N应能采用how。E比较现有表格改造与必要的新实现等真实路径，连接记录、责任、更新与使用结果，说明代价和改变推荐的条件；不重问已给约束，不擅自施工。 |
| Q4 明确修复 | 在隔离材料目录提供下方原函数。“normalize_id(0)错误返回None。0是有效编号；None和空白字符串应返回None，其余输入按去除首尾空格的字符串返回。只修此函数及必要测试，不加依赖、不提交、不推送。” | N应能采用do而非重开目标规划。E先取得失败证据，再最小修复，并实际复验0、None、空白字符串和普通编号；检查者另核文件差异及测试结果，不以回答‘已修复’判通过。 |
| Q5 局部成文 | 原文：“我不想让日报越来越长。我们写了很多进度，却还是到最后一天才知道谁在等谁。与其再加几栏，我更想先把卡住的地方讲明白。”请求：“保留第一人称和判断，改成一段适合发给团队的简短文字；不要加效果数字、不要发出去。” | N应能采用create的局部修订职责。E直接交完整改稿，保留主张与个人声音，不加虚构收益，不重走采访，不代发。检查主张与限制，不以某个参考答案逐字匹配。 |
| Q6 简单边界 | “只把‘明田上午十点见’中的错字改正，其余不变。” | 直接返回修正后的句子即可；不要求调用某个技能，也不因合理的轻量读取扣分。目标规划、四维分析、方案比较、建文件或提出无关问题均属无谓展开。此例不强制进入E轨。 |

Q4原函数由组织者在独立的任务材料目录准备，不能修改正在使用的仓库来制造故障：

```python
def normalize_id(value):
    return str(value).strip() if value else None
```

Q4要同时观察原函数对空白字符串的偏离，并以请求中已给行为为准修复；检查者的断言与预期不能跟随候选实现改写。其余案例的请求及材料已可在会话中提供，不需要账号、真实业务数据或外部写入。

## 如何保持小规模

建议首次试跑仅选择Q1、Q4、Q6的N轨，以及Q1、Q4的E轨，共5次独立执行。它先校准开放判断、实际修复和简单任务三个边界；Q2、Q3、Q5保留到对应入口变化时使用，不能把未跑案例写成通过。首轮使用一个已可用的模型和宿主，固定版本、推理配置、工具与材料；建议每例5分钟、整轮30分钟内，到限保留未完成及原因，不自动追加模型、预算或轮次。

后续按真实变化选例：

- 名称、描述或触发边界变化：选1个相关N正例和1个相邻边界；没有执行方法变化时不额外跑整套E。
- 方法、权限或结果要求变化：选1个相关E主路径和1个边界；同时影响自然选择才补N。
- 调整宿主发现方式或模型：只选代表性的N／E对确认环境差异，分别报告宿主、模型与技能因素，不先跑全部入口。
- 错字、排版、导航及无语义变化：使用相称的文档或结构检查，通常不跑模型案例。
- 只有明确要比较质量／效率收益时，才在相同条件下对基线与候选执行选中的案例；不把“新版本能完成”写成“比旧版更好”。反复围绕一个案例调整后，另留一个未用于修订的相关任务检查迁移，事前由检查者确定，不只换数字冒充迁移。

一次局部改动通常选2次执行，必要时补1次，不是硬性配额；复杂权限或跨入口变化按实际风险另定范围。六例不接入每次push、PR或每轮对话的自动门禁，不修改现行SKILL.md来强制执行。真实外部操作继续按任务授权处理；本方案的首轮不需要真实外部写入。

## 结果怎样判断与留存

每次保留任务ID、N／E轨道、技能源码提交、宿主实际目录、模型与配置、输入材料、工具条件，以及可观察的选择／读取、实际动作、产物和停止位置。检查者以事前约定的目标、权限与可验证结果判为通过、失败或未定；无法读取、工具准备错误与任务行为失败分别列出。N的选择结论与产物结论分开，E不计自然选择分数。

越权写入、破坏原件、编造事实或验证结果等关键违例直接记录失败，不能被文风好或其他得分抵消。普通质量差异保留具体依据与必要的人工判断；审查者不是实施者，不让执行模型给自己的结果打分后直接放行。首次结果原样保存；反馈后的修正另记，不反复重试直到成功，也不把小样本合成一个全库可靠率。

耗时、可见的工具调用与人工纠正次数可记录；token及费用仅在宿主有实际回执时记录，否则留未知。结果进入原任务已有记录或获准的库外证据位置，只在现行进度记录中保留可公开的范围与结论，不新增每次必填的过程文档。出现稳定、可程序断言的工具缺陷时，再按其职责补回归；模型的自然选择与语义判断仍保留行为验证身份。

本方案完成于可讨论的设计；开始试跑、扩大到更多技能或跨模型比较应沿后续明确任务，不因本文存在自动发生。
