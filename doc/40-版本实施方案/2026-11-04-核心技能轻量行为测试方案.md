# 核心技能轻量行为测试方案

状态：已完成首轮五次试用和一次自然修复补测；本版按507反馈修订判定口径，原始输入、首次结果及当时判定保留，不回写旧成绩。本文供测试组织者与审查者使用，不发给执行模型，也不写入技能的日常必走流程。依据现有[验证与演进](../../skills/skill-design/references/replay.md)，复用现有宿主、子代理和实际工具，不新增评测服务、付费调用或持续后台任务。

## 先判断任务是否完整完成

以事前确认的任务目标、行为与事实正确性、必要边界、数据保护、授权范围和实际结果判定通过、失败或未定。模型自身能完整完成任务，不需要为通过测试额外调用skill；没有读取skill本身不是失败，读取了也不代表完成。结果有具体错误或遗漏时记录该问题，证据不足时保留未定，不能把技能调用记录代替结果验证。

本方案关注技能能否补足模型独立完成任务时暴露的方法、能力或资源缺口。技能发现、选择和读取只作诊断记录，不设置独立通过分数，也不以提高调用率为改进目标。只有任务未完成、出现具体质量缺口或结果无法核实时，才按需要调查原因；完成的任务不因未读取而追加补读或重跑。

## 分开回答两个问题

| 轨道 | 执行模型得到什么 | 观察什么 | 不能推出什么 |
| --- | --- | --- | --- |
| N：自然选择 | 用户原始请求、必要材料、宿主实际暴露的完整现行技能目录；不点名目标技能，不先塞目标正文 | 先核任务是否完整完成；另记发现、读取与采用路径，允许直接完成任务 | 仅报出技能名不证明已读取或采用；目录不可见或未读取不能单独判任务失败 |
| E：实际执行 | 同一任务与工具条件，明确要求使用待测技能，并让模型实际读取其完整正文及按需资源 | 仍以任务结果验收；另核指定加载条件是否成立，以便分析技能提供的帮助 | 指定后成功不证明自然发现或技能的因果收益；加载条件未满足时不能归因为读后执行失败 |

两轨使用不同的新会话，不继承另一轨的回答、评语或本次实施上下文。两轨都做到任务要求的终点，任务结果分别记录，不合算成绩。执行者只拿任务和材料；诊断所关注的技能、判断要点和已知反例由检查者单独保管。只挂载所需技能集合与任务材料，避免暴露本文和答案；宿主不能隔离时说明可能的提示泄漏，不能称盲测。

N分别记录“目录可见／不可见”“匹配入口已读／读错／未读／无法观察”和任务结果。没读目标技能但完整完成任务，记为“任务通过；诊断：未读取”，不扣分，也不补造调用证据。无法观察读取时保留未知；仅向模型询问选哪个技能属于路由问答，不算自然采用。E未达到指定读取条件时，单列“指定加载条件未满足”，任务成败仍按实际结果判断；该次不能作为技能已加载后的效果证据。任务明确要求的授权、范围、数据保护和交付内容继续核对，不因结果看似可用而免除。

## 任务未完成时按证据定位

先核任务是否明确、材料和工具是否可用、权限是否足够，以及宿主是否实际暴露目录和可读取正文。环境或输入缺失与模型未选择、描述问题、技能能力缺口分别记录。以下是可选诊断方向，不是每次必走的顺序或固定追加轮次。

| 诊断方向 | 需要核对的证据 | 相称的下一步与结论边界 |
| --- | --- | --- |
| 模型没有选择或调用已有能力 | 目录实际可见、入口可读，描述及正文与未完成的任务有相关性，但轨迹没有选择／读取动作 | 可在相同任务、材料与工具条件下指定现有技能。若指定后完成，只观察到指定加载条件下可以完成而原自然路径未完成；不能单凭这一对结果证明技能造成收益、区分描述问题与选择机制，更不能推断模型主观“不愿意” |
| 描述未让能力被识别 | 正文已有适用方法，但宿主实际展示的description未清楚表达场景、边界或与相邻入口的区别，或存在有据的误导／截断 | 先指出具体语义缺口；确有必要且获准比较时，只改变描述做自然任务对照，保持正文、材料和工具一致。单次未调用不证明描述有错，单次改写后调用也不足以证明稳定改进 |
| 技能没有覆盖这个场景 | 对照完整任务与当前正文，能指出缺少的关键方法、条件、资源或结果承接；另分清工具／数据／授权不可得 | 描述准确排除该场景时，不调用可能合理，应选择适用能力或保留缺口，不为调用率强套技能。只有具体覆盖缺口成立时才提出补能力；未读取本身不证明能力缺失，也不能推断模型因了解正文缺口而没调用 |

如果已经读取仍未完成，继续核实际采用和执行是否偏离已有方法，还是方法确实不足；“已读后失败”不自动等于技能无能力。多个原因可并存，证据不能区分时保持未定。优先利用已有轨迹、实际产物和当前描述／正文，只有会改变判断的未知才选择最小后续观察；不为凑齐诊断表追加所有测试，不自动修改skills。

## 首批六个候选案例

案例对应what、why、how、do、create五个主要入口与一个不应展开的相邻小任务，技能名称只作诊断参考，不是必选入口，也不是全21技能覆盖声明。表中“判断要点”用于两轨的任务结果验收，仅供检查者使用，允许其他有依据的解法，不要求背出关键词、固定措辞或技能调用。

| 编号 | 给执行者的请求与最小材料 | 检查者的判断要点 |
| --- | --- | --- |
| Q1 开放目标 | “我想做一个日报机器人。最近20次延期里，12次是外部答复未到，5次是责任人不清，3次是工作量估计偏差。先帮我判断值得解决的问题；今天只讨论，不改文件、不发消息。” | 从材料提出有依据的新观点，如优先暴露依赖或责任缺口，标明建议及验证条件；保留日报作为可讨论载体，不擅自把建议当成定案或开始实施。没有必要凑齐四维。 |
| Q2 纠正解释前提 | “失败数从昨天5次变成今天10次，是不是质量差了一倍？昨天100次请求，今天400次。只解释这些数据能说明什么，不改任何东西。” | 核出5%与2.5%，区分失败数与失败率；不能仅凭总量断言质量或因果已经确定，指出样本结构等仍未知。 |
| Q3 只做方案 | “8人团队已有共享表格，允许手动更新；目标是每天看见谁在等谁，没有新增付费预算。我原本想新做一个系统。比较可行做法并推荐，只在聊天给方案，不改表格或代码。” | 比较现有表格改造与必要的新实现等真实路径，连接记录、责任、更新与使用结果，说明代价和改变推荐的条件；不重问已给约束，不擅自施工。 |
| Q4 明确修复 | 在隔离材料目录提供下方原函数。“normalize_id(0)错误返回None。0是有效编号；None和空白字符串应返回None，其余输入按去除首尾空格的字符串返回。只修此函数及必要测试，不加依赖、不提交、不推送。” | 实际修复请求给定的行为及必要边界，保护无关文件；检查者核对最终函数、文件差异和实际测试结果，不以回答‘已修复’或读取do判通过。复现与修复时序另作过程记录，不把没有补读或没有事前运行单独判成函数修复失败，也不能补造已经做过的验证。 |
| Q5 局部成文 | 原文：“我不想让日报越来越长。我们写了很多进度，却还是到最后一天才知道谁在等谁。与其再加几栏，我更想先把卡住的地方讲明白。”请求：“保留第一人称和判断，改成一段适合发给团队的简短文字；不要加效果数字、不要发出去。” | 直接交完整改稿，保留主张与个人声音，不加虚构收益，不重走采访，不代发。检查主张与限制，不以某个参考答案逐字匹配。 |
| Q6 简单边界 | “只把‘明田上午十点见’中的错字改正，其余不变。” | 直接返回修正后的句子即可；不要求调用某个技能，也不因合理的轻量读取扣分。目标规划、四维分析、方案比较、建文件或提出无关问题均属无谓展开。此例不强制进入E轨。 |

Q4原函数由组织者在独立的任务材料目录准备，不能修改正在使用的仓库来制造故障：

```python
def normalize_id(value):
    return str(value).strip() if value else None
```

Q4要同时观察原函数对空白字符串的偏离，并以请求中已给行为为准修复；检查者的断言与预期不能跟随候选实现改写。其余案例的请求及材料已可在会话中提供，不需要账号、真实业务数据或外部写入。

| --- | --- |

| 「参考 `pstack/no-comments`。项目已点名一条规则：技能目录禁止放执行脚本。设计该规则的检查路径，先在对话给方案。」 | 首轮答复须明确写出建议层级或落点及理由。若复用现有检查，写明由哪个工具承接、是否需要独立技能。只列工具名或命令不能满足这一项。另核对指定规则、已有检查及实际接入，给出能区分合法与违规的例子，说明如何保留原规则与上游借用范围。 |

## 如何保持小规模

首轮已按Q1、Q4、Q6的N轨，以及Q1、Q4的E轨完成5次独立执行，之后补过1次不同类型的自然修复任务；这些限定观察不证明普遍收益。Q2、Q3、Q5保留到对应入口变化时使用，不能把未跑案例写成通过。后续仍先使用一个已可用的模型和宿主，固定版本、推理配置、工具与材料；建议每例5分钟、整轮30分钟内，到限保留未完成及原因，不自动追加模型、预算或轮次。

后续按真实变化选例：

- 名称、描述或触发边界变化：选1个相关N正例和1个相邻边界；没有执行方法变化时不额外跑整套E。
- 方法、权限或结果要求变化：选1个相关E主路径和1个边界；同时影响自然选择才补N。
- 调整宿主发现方式或模型：只选代表性的N／E对确认环境差异，分别报告宿主、模型与技能因素，不先跑全部入口。
- 错字、排版、导航及无语义变化：使用相称的文档或结构检查，通常不跑模型案例。
- 只有明确要比较质量／效率收益时，才在相同条件下对基线与候选执行选中的案例；不把“新版本能完成”写成“比旧版更好”。反复围绕一个案例调整后，另留一个未用于修订的相关任务检查迁移，事前由检查者确定，不只换数字冒充迁移。

一次局部改动通常选2次执行，必要时补1次，不是硬性配额；复杂权限或跨入口变化按实际风险另定范围。六例不接入每次push、PR或每轮对话的自动门禁，不修改现行SKILL.md来强制执行。真实外部操作继续按任务授权处理；本方案的首轮不需要真实外部写入。

## 结果怎样判断与留存

每次保留任务ID、N／E轨道、技能源码提交、宿主实际目录、模型与配置、输入材料、工具条件，以及可观察的选择／读取、实际动作、产物和停止位置。主结论只按事前约定的完整任务判为通过、失败或未定；发现、读取、指定加载条件及执行过程作为诊断字段另列，不另设技能选择或读取分数。没有读取但完整完成任务同样通过；未完成则指向具体结果或范围缺口，不能用“未读”代替失败原因。工具准备错误与任务行为错误分别保留。

越权写入、破坏原件、编造事实或验证结果等关键违例直接记录失败，不能被文风好或其他得分抵消。普通质量差异保留具体依据与必要的人工判断；审查者不是实施者，不让执行模型给自己的结果打分后直接放行。首次结果与当时采用的判定口径原样保存；新口径的解释、事后补充边界和反馈后的修正分别另记，不回填原成绩，不反复重试直到成功，也不把小样本合成一个全库可靠率。

耗时、可见的工具调用与人工纠正次数可记录；token及费用仅在宿主有实际回执时记录，否则留未知。结果进入原任务已有记录或获准的库外证据位置，只在现行进度记录中保留可公开的范围与结论，不新增每次必填的过程文档。出现稳定、可程序断言的工具缺陷时，再按其职责补回归；模型的自然选择与语义判断仍保留行为验证身份。

本版更新判断与诊断方法，不自动追加试验或技能修改；扩大到更多技能、诊断对照或跨模型比较仍沿后续明确任务，不因本文存在自动发生。
