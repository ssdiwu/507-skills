# 507-rednote 产品需求

状态：已实现并完成本地验证，作为当前产品与验收基准。

本需求落实[小红书图文区分连续文章与视觉摘要](../决策档案/0015-小红书图文区分连续文章与视觉摘要.md)。当前公开行为以 `write/507-rednote/SKILL.md` 及其机器规格为准，本文作为产品与验收基准。

## Problem Statement

“原文全部进入图片”不等于“文章模式成立”。如果渲染规格仍要求每个物理页面拥有独立观点、标题、布局、页码和品牌元素，Agent 即使逐字覆盖全文，也会把文章改造成轮播课件：文字被迫缩小，原有标题位置被改变，证据图退化成卡片素材，作者的阅读节奏被逐页闭合打断。

另一方面，真正的视觉摘要确实需要选择观点、压缩原文和设计单页焦点。两种目标不能共用同一个逐页观点合同，也不能让用户只说“小红书图文”时默认承担内容删改。

## Solution

`507-rednote` 提供两个显式模式：

1. `article`：默认模式。把成熟主稿作为一篇连续文章排版，再按阅读高度切成图片。文章是内容单位，物理页面只是载体。
2. `summary`：用户明确要求“视觉摘要 / 一页一个观点 / 提炼”时使用。每页承担一个观点，允许在忠实与可追溯的前提下选择内容。

封面与文章正文采用不同职责：封面建立标题、阅读承诺和作者识别；文章正文让设计退场，优先保证手机上的连续阅读。动态图片槽与公众号封面对继续作为可选载体，不扩大到长视频剪辑、公众号正文或平台发布。

## User Stories

1. 作为内容作者，我只说“做成小红书图文”时，希望完整文章实际出现在图片中，并保持原来的措辞、顺序、标题和论证节奏。
2. 作为手机读者，我希望正文无需放大即可持续阅读，而不是面对一组字号很小、每页重复标题和装饰的课件。
3. 作为内容作者，我希望图表、截图和产品证据出现在原文论证位置，而不是被另做成装饰海报或缩略图。
4. 作为明确需要传播提炼的作者，我希望可以主动选择视觉摘要，并知道哪些内容入选、哪些内容被排除以及去向。
5. 作为交付接收者，我希望机器规格、图片、HTML、联系表和清单来自同一版本；当系统报告“已经改成 N 页”时，实际文件就是 N 页，而不是仍保留旧页面的分页候选。

## Product Requirements

### 1. 模式选择

- `rednote-project.json` 必须显式写 `mode: article | summary`。
- 用户只说“小红书图文 / 图卡 / 编辑小红书”时，Agent 自行选择 `article`，不把模式选择重新抛给用户。
- 只有用户明确要求“视觉摘要 / 一页一个观点 / 提炼 / 精华版”时才选择 `summary`。
- 同时要求两种成品时，使用两个规格和输出目录；不能用其中一种冒充另一种。

### 2. 文章模式内容合同

- 标题、小节、正文、列表、图片和图注全部进入图片，顺序与主稿一致；`excludedContent` 必须为空。
- Agent 先建立连续文章流，再按画布高度切成物理页面；不得先为每页分配观点后反向改写原文。
- 重新分页前必须打平旧 `pages` 分组和小节分页边界，以真实浏览器中的可用高度重新流排；旧页数、字符数估算和旧页面占用率不能作为分页结果。
- 页面不要求语义闭合，可以在段落、句子或转折中间续页；切页不得导致删字、重排、概括或补写过渡。
- 正文页只记录 `sourceMap` 和按原文顺序排列的 `blocks`，不接受逐页 `point`、`layout` 或页级自动标题。
- 原文小节标题使用 `heading` 内容块，因此可以出现在页面中段；没有原文标题时不得生成分类标签、页标题或总结。
- 文章模式正文不渲染页眉、页码、逐页观点标题、重复头像、金句框、网格或装饰卡片。
- 封面默认 1500×2000；正文默认 1440×2400。正文使用大字号、宽行距、稳定页边距和高对比文字。
- 初次分页后必须通过联系表复核整组密度；相邻页仍有大面积空间时继续跨旧边界重排，只有不可拆图片、截图、列表或标题防孤行确实阻断内容流时，才接受明显留白。
- 尾页内容较少时允许自然留白；不得为了填满画布新增结论、行动号召或装饰信息。
- 单篇图片数量超出平台容量时拆为连续系列，明确每篇覆盖范围，不缩小到不可读。

### 3. 文章模式媒体合同

- 图片、截图和图注按原文位置进入正文，默认近全宽显示。
- 横向图表、并排产品状态或多图证据应先组成一个可读证据单元，再嵌入文章流；不能缩成卡片内部的小图。
- 应用界面、网页、终端和代码截图以完整可读为优先；设备壳、浏览器壳和边框只在证据本身需要时使用。
- 动态图片槽仍只接受用户已经选定的短视频，每个物理页最多一个。

### 4. 视觉摘要合同

- 摘要模式必须先确定一句中心判断，再选择共同支撑它的观点。
- 每张正文图卡只承担一个观点；例证、对比、步骤或数据只能服务该观点。
- 每个入选观点和关键证据必须映射回来源；未进入图卡的重要内容必须记录去向。
- 不设固定页数目标，不通过缩小字号维持页数，也不为了填满画面编造观点、标签或数据。
- 摘要图卡保持 1500×2000，并继续使用显式 `point`、`sourceMap` 和 `layout`。

### 5. 视觉与封面

- 封面只负责主题、阅读承诺与必要作者识别，不同时展开多个正文观点。
- 编辑杂志与瑞士国际主义继续作为封面、摘要图卡和全局配色语言。
- 文章正文采用稳定的连续阅读基线，不把摘要模式的页面布局或封面装饰复制到每一页。
- 样式选择同时检查封面、最密正文页、证据页和手机缩略图；封面好看不能替代正文可读。

### 6. 输出与新鲜度

- 交付包括独立图片、单文件 HTML、整组联系表和 `render-manifest.json`。
- 联系表必须完整包含 3:4 封面和 3:5 正文，不得为统一缩略图比例裁掉正文顶部或底部。
- 清单记录 `mode`、规格与素材哈希、页数、每页来源范围和实际尺寸。
- 任何内容、素材、模式、主题或页数变化后，受影响产物必须重新生成；规格与清单不一致时不得报告完成。
- 页数变化必须全量渲染并清除旧页。只有规格中的 `pages` 数量、清单 `pageCount`、实际 JPG 数量和联系表页数一致，清单 `renderedPages` 是 1 到末页的完整序列，且文件名连续时，才可报告“已经改成 N 页”。局部重渲染不得改变页数，`renderedPages` 只记录本次页面。

### 7. 动态图片槽与公众号封面对

- 动态图片槽只替换既有媒体位置，沿用该位置的裁切、安全区和视觉层级；不承担长视频选段或叙事剪辑。
- 在 Live Photo 打包前先生成与最终构图一致的静态首帧，并通过普通页面检查。
- 公众号 21:9 主封面和 1:1 分享封面分别构图，保持同一中心判断与识别资产；不生成公众号正文。

## Implementation Decisions

- 顶层 `mode` 决定正文页面合同；封面合同保持独立。
- `summary` 沿用现有观点页结构；`article` 正文页只允许 paragraph、heading、list、note、quote、image、screenshot 和 motion 内容块。
- 渲染器为文章正文使用独立 720×1200 CSS 画布，经 2× 输出为 1440×2400；封面与摘要页继续输出 1500×2000。
- 文章正文 HTML 不生成 topbar、页码、逐页标题或头像，并使用独立的 `article-flow` 样式。
- 文章页尾由画布底部 padding（内边距）统一提供留白，最后一个内容块的 margin（外边距）归零，避免两者重复计入溢出并制造假分页。
- 联系表和样式预览使用 contain 而不是 crop，以兼容同组不同纵横比。
- 页数变化走全量渲染；渲染器在输出新页前清除既有页面文件，再按当前规格重建联系表和清单。
- 全文覆盖由 Copy Spec 与逐段核对承担；脚本负责规格结构、尺寸、溢出、素材和清单新鲜度。

## Testing Decisions

### Unit

- `mode` 必填且只有 `article` / `summary`。
- 文章模式拒绝非空 `excludedContent`、逐页 `point` / `layout` 与 cards / flow / timeline 摘要结构。
- 摘要模式继续要求每页 `point`、`sourceMap` 和 `layout`。
- heading、list、图片、截图和 motion 的字段与本地素材边界得到验证。
- 清单记录模式和每页实际尺寸。
- 文章页尾最后一个内容块不保留会与画布底部留白重复计算的 margin（外边距）。

### Integration

- 摘要 fixture 能继续生成 1500×2000 图卡、HTML、联系表、清单和公众号封面对。
- 文章 fixture 能生成 1500×2000 封面、1440×2400 正文、无裁切联系表和清单。
- 文章 HTML 的正文页不存在 topbar、页码、逐页标题或重复头像。
- 两种模式都通过浏览器溢出与字号检查。
- 页数变化后，规格、清单、实际图片和联系表页数一致，旧页面文件不残留。

## Acceptance Criteria

1. 默认文章模式完整覆盖原文并保持顺序；正文看起来是一篇连续文章，而不是逐页观点课件。
2. 原文小节标题可以出现在页中，证据图在论证位置清晰可读，尾页可以自然留白。
3. 文章正文没有自动页眉、页码、逐页标题、重复头像、分类标签或装饰卡片。
4. 摘要模式仍能生成一页一个观点、来源可追溯的 3:4 图卡。
5. 两种模式的 HTML、图片、联系表与清单来自当前规格并通过自动与视觉检查；页数变化后四者页数一致、文件连续且没有旧页残留。
6. “已经改成 N 页”只用于实际交付已经成为 N 页的状态，不用于测算、临时 HTML 或尚未写回机器规格的分页候选。
7. 长视频剪辑、公众号正文、账号登录和平台发布不会被误认为本功能已支持。

## Out of Scope

- 在 `507-rednote` 内重新写长文、选择中心判断或修复尚未成立的主稿。
- 从长视频自动选段、变速、剪辑或生成叙事序列。
- 公众号正文排版、账号登录、上传、发布和运营。
- 在渲染阶段自动搜索或下载网络图片。
- 复制外部参考项目的代码、模板、文档正文或视觉资产。

## Further Notes

本需求用“文章模式默认、视觉摘要显式选择”取代 0013 的“视觉摘要默认”决策。视觉摘要、动态图片槽和公众号封面对仍保留；变化只涉及默认内容合同与文章模式的真实实现。
