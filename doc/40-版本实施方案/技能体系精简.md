## 从候选到本轮范围

最初比较四组工程入口全部合并到 29 项，以及三类成文入口进一步合并到 27 项；第一轮先试点 setup/map，保留其他候选。后续按实际合同与任务验证评估：减少名字不能单独证明收益；应减少无关读取、重复交接和维护分歧，并保留权限与结论门槛。

| 组合 | 本轮决定 | 依据 |
| --- | --- | --- |
| setup／map | 试点合并为 `507-setup` 的项目依据与导航维护范围；验证后退出旧 map 入口 | 完整规范迁移本来包含导航同步，二者共用文档职责与当前事实；局部维护须能跳过完整巡检 |
| review／inspect | 保留双入口，统一证据方法 | review 判断交付偏差与风险，inspect 提供结构改进候选，不能互相套用结论门槛 |
| test／tdd | 已合并为 `507-test` 的普通测试与测试先行模式 | 共用测试反馈环；实现权须在主入口明确区分，“先写测试”本身不能升级到 GREEN |
| commit／release | 已合并为 `507-release` 的本地提交与交付模式 | 共用 Git 状态与引用核验；本地只提交、远端只执行点名动作，前提与完成证据分别成立 |
| forge／frame／stage | 已合并为 `507-write` 的书面、方案与现场内容模式 | 共用素材、事实与作者声音保护；三种产物只读对应方法，保留专用审计与制作出口 |

其他材料、视频、解释与交接入口也不因本轮试点自动合并。新独立入口只有确有职责与消费者时才建立，不能把共享方法再包装成所有任务必经的总控技能。

## setup 的承接方式

主入口先根据请求选择范围，不要求用户选择内部模式名：

| 请求 | 方法与结果 | 范围保护 |
| --- | --- | --- |
| 只修 README、文档导航或目录说明 | 只读取包内导航维护参考，核对事实并修改地图 | 不加载完整巡检，不改规范、规格、设计、术语、进度或源码 |
| 初始化、规范迁移、建立阶段依据或按标准巡检 | 读取项目标准与项目依据维护参考，在同一任务中同步相关导航 | 只读巡检仍只读；正文维护、业务实现和远程动作分别遵守授权 |
| 单独维护明确指定的全局规则 | 只读标准的全局约束与目标文件 | 不因为当前目录存在项目就巡检、建立 PROGRESS 或修改项目文档 |

原 `507-map` 的有效方法进入 setup 包内 `references/navigation.md`，不保留第二个活动合同。既有调用者、README、词义与当前导航改到相应范围；历史记录保留当时名称，确需点击旧正文的审计链接固定到历史提交。已识别的本机旧入口在整合后退出；未知外部安装不宣称已迁移。

## review／inspect 的共同基础

公共方法的唯一维护源是 [review-evidence.md](../../common/references/review-evidence.md)。它处理版本与范围、真实调用和状态写入、要求／机制／证据、结论确定程度及后续更正。

review 继续输出与变更相关的缺陷、规范偏差或可证实风险；inspect 继续输出含公开不变量、收益与验证缺口的候选。另一种可能更好的设计不自动成为交付阻塞问题，候选也不等于批准改造。

两个技能各带一份完整的 `references/evidence.md`，独立安装时直接读取，不能依赖另一个技能或作者仓库。维护者只编辑唯一源，通过 `python3 scripts/sync_review_evidence.py --write` 生成随包副本；默认或 `--check` 只读检查一致性。检查已接入 `scripts/test_all.py`，避免手工维护两个漂移版本。

## 验证与切换

合并在隔离工作树内基于实际未提交改稿准备；合回前核对目标文件的当前指纹，保护已有工作。根 PROGRESS 记录当前授权与进展，候选验证后才替换可用基线。

- 同题比较旧 map 与新 setup 的局部导航维护，记录实际读取、修改范围与交付结果；不从字符数推算延迟或成本。
- 验证只读巡检、项目依据建立和指定全局规则三个边界，特别检查源码／规格保护、是否创建无用途文件，以及是否越过明确目标。
- 检查元数据、活动路由、历史链接与独立包引用；验证生成副本缺失、漂移、只读检查、恢复与重复生成的行为。
- 独立审查共同方法与两个入口的结论门槛，修正有证据的问题后定向复核。ZCode 仅在实际模型访问可用时计为参与，命令存在不等于已完成审查。

完成状态、实际验证、限制与旧入口处理分别记录；提交、推送和发布不包含在本轮默认动作中。

setup/map 第一轮隔离检查和前向执行已完成，详见[验证记录](技能体系精简验证.json)。五个场景的修改均在授权范围；旧 map 与新 setup 的导航产物逐字一致，两者都没有读取完整项目标准，新入口多读一份导航参考，因此本轮不宣称节省耗时或上下文成本。32 个入口元数据、相关方法引用和随包检查通过，独立审查的两项文档同步问题已修正并复查关闭。当时 ZCode CLI 实际调用因模型访问未配置而退出，未发送模型请求；独立审查与前向执行由当前可用子代理完成。
