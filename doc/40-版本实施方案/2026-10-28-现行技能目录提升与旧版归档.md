# 现行技能目录提升与旧版归档

## 目标与范围

新版内容已进入 main，但 next 的目录命名和旧分组在根目录并列的摆放仍暗示新版待接入。本次将实际维护入口与当前身份对齐，不重建技能体系、不改变20个现行技能的职责与合同。

| 原位置 | 唯一现行或归档位置 |
| --- | --- |
| next/skills/ | 根目录 skills/ |
| next/README.md | skills/README.md |
| next/packages.json | 根目录 packages.json |
| next/scripts/package_skills.py | scripts/package_skills.py |
| next/tests/ | tests/ |
| next/dist/ | 本地忽略的 dist/ |
| 根目录 common/、code/、write/ | archive/legacy/ 下同名分组 |

lib、spec、doc 仍分别维护共有资源、现行规格与长期依据。旧入口来源登记指向真实归档位置；历史正文中的原版本、命令和路径继续表示当时记录。历史资料只更新实际链接，不批量改写结论；归档合同、样例和二进制素材保留。

## 维护与验证入口

现行清单、生成索引、随包副本、独立包构建、回归测试与CI统一使用新位置。目录提升不保留 next 的软链接或双份现行包。打包工具仍拒绝未声明技能或文件、越界、软链接、副本漂移及覆盖已有不可变构建；skills/README.md 是目录说明，不进入任何技能包。归档目录受构建输出重叠保护。

旧版专项回归仍通过根目录 scripts/test_all.py 执行，不因归档而删除或跳过。PPTX、图片和原始验证资产未重生成；两份旧版生成证据副本只更新维护源位置标记。来源与处置索引由实际源重新生成，包内普通副本继续由唯一共有源派生。

其他会话的维护钩子候选保持未提交身份，不进入本次迁移提交；恢复现场时仅适配受本次布局影响的路径和测试准备，不改变其未启用状态、行为范围或历史验证结论。临时组合副本验证这些适配后再恢复，原件和差异另存库外。

## 验证边界

迁移核对实际入口、构建、独立包闭包、名称查询、负例保护、来源身份和原始内容、文档链接、CI路径及专项回归。新增布局回归检查现行/归档位置唯一、所有旧版回归工作目录与脚本仍可达，以及CI使用真实维护入口。

首轮旧版PPT回归遇到本地officecli缺少XML运行组件；原位置同用例对照与迁移位置67项PPT回归随后通过，未修改实现或断言来消除该失败。首轮结果单独保留，不回填首次通过。

验证回执与最终独立审查保存在库外。新路径存在、包检查、自动测试、独立审查、本地main整合及远端CI分别判定；本次不推送、不发布，也不自动更新安装目录。既有自然采用、跨宿主和读者理解的未验证项不因目录迁移消失。
