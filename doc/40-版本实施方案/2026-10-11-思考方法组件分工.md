# 思考、方法、组件的分工设计

状态：507初步确认what、why、how、create、skill-design五个主要技能；可继续增减与重组。次要方法与组件的具体合同仍为设计候选，未应用到技能实现。

## 承接与三种责任

主要技能保留任务特有思考、方法选择和整体目标责任；次要技能具有独立输入、判断、可消费结果与返回；共有组件承担明确动作。共有资料提供按需思考依据，工具适配承担平台及版本差异。prompt、脚本、CLI是实现形式，不决定责任层级。

图片、卡片、PPT、网站、视频保持载体位置。用户表达目标，Agent按真实缺口采用能力，已有方案、成熟稿、明确故障或入库动作可直接处理，不设what→why→how固定门。

主要技能的特有判断详文见[思考参考](../10-架构与运行/主要技能特有思考参考.md)，旧/新路线见[工作流对照](../10-架构与运行/工作流对照与条件接力.md)；本表只摘要职责。共有UI／UX资料见[design](../../lib/design/README.md)，没有新增Skill或改变32/48候选接口数量。

## 初步确认的五个主要技能

| 名字 | 特有判断 | 结果与结束 |
| --- | --- | --- |
| what | 真正要解决什么；哪种缺口改变下一动作；决定属于用户还是Agent | 足以推进的目标、范围、关键决定和真实未决项。下一步所需决定足够便返回；仅澄清时结束。 |
| why | 什么解释更成立；证据支持到哪里；哪些关系或竞争解释需要看清 | 有证据和限制的解释、关系模型或理解结果。核心解释与未知足以被当前目标消费；载体关键观察动作另行检查。 |
| how | 哪些关键环节值得改变，哪些必须保持；改变如何跨状态、数据、权限与消费者耦合；复用、替换、并存和迁移哪种更可行；怎样用试验、实施顺序、退出与目标验收形成策略 | 有依据的变更策略：介入点、关键改变、不变量、耦合与依赖、试验、迁移/退出和目标验收；按任务需要交付，不固定方案模板。策略足以被当前目标消费时回交；只规划止于策略，需要实施时承接原授权继续，不将策略完成当整体目标完成 |
| create | 让受众理解或感受到什么；主张与材料负载是否相称；作者声音、结构与事实责任怎样保留 | 有明确含义与表达责任的作品内容，以及所需载体上的可用结果。约定作品的含义、表达及载体可用；制作成功不替代作者接受或发布。 |
| skill-design | 什么值得成为独立能力；思考、方法、做法如何归属；复用是否减少负担与协调；旧身份是否应退出 | 分工设计或获授权的技能包，含消费者、采用条件、退出与验证范围。规划请求停在设计；编写请求完成文件与验证；返回仍未完成的原目标。 |

why保留接近understand的理解、解释与追因范围。how负责变更策略，并在实施请求中继续获授权工作；已有策略可直接implement。create保留作者、受众和表达责任；skill-design是技能设计能力，区别于技能库和单个技能，实际507-skill包未改名。knowledge继续下沉organize。

## 完整方法候选

当前设计有32个方法候选：原22项加10项。它们不是必经层或待一次性实现的配额；每项都需真实消费者与后续实施验证。

| 工作名 | 完整结果 | 采用／直接跳过 |
| --- | --- | --- |
| research | 证据、来源身份、覆盖、冲突与未知 | 有事实、机制、历史或来源缺口；已有有效证据直接复用，不重新调查 |
| compare | 对照模型、共同原子、差异、缺项与不可比处 | 存在多套方法/方案的实质差异；已有完整比较模型可直接采用，不制造候选 |
| model | 可判断和验收的关系/行为模型 | 对象关系、业务行为或职责接缝需要建模；关系已充分成立或只改样式时跳过完整建模 |
| interview | 一手材料、观点归属与未确认缺口 | 需要作者/参与者尚未表达的一手材料；成熟材料或仅润色时跳过 |
| compose | 可制作的内容/叙事结构与表达依据 | 需要组织论证、场景或认知台阶；已有成熟结构可直接制作；轻润色不重建选题链 |
| visualize | 表达模型、阅读路径、观察动作与语义检查 | 关系/条件/多来源需要表达或探索；简单表格足够便直接用；不强制网页 |
| design | 可评审的设计方向/视觉计划及采用边界 | 主观方向不明或体验表达需判断；已有方向可直接实现，不重新采样 |
| probe | 支持/反驳/证据不足的观察结论、适用边界和原型清理状态。 | 未知可证伪、观察会改变决定，且试验比正式实现更便宜。；直接证据足够时跳过；不能代替真实偏好决定 |
| verify | 有效测试资产、观察与覆盖结果；明确授权测试先行时交付逐切片实现及回归 | 测试资产、失败分类、行为验收需要独立方法，或用户明确要求测试先行实现；运行已成立检查可直接调用组件 |
| review | 可证实发现、结论和未覆盖范围 | 明确交付范围需要独立判断；纯机械校验可由组件执行，独立结论不能由实施者冒充 |
| coordinate | 独立工作结果、集成状态、整体复验与剩余项 | 依赖与独立写入足够复杂，协调本身值得委派；少量独立只读工作可直接并行；已有任务图不重跑what/how |
| retro | 有证据的改进候选及最小验证设计 | 明确要求复盘，或具体重复摩擦需要分析；无实际信号不制造每次结束仪式 |
| setup | 指定范围内的项目依据、导航和已验证迁移结果 | 初始化、检查或迁移项目工作依据，或维护指定导航与引用；局部更新不扩成全项目迁移 |
| adapt | 适合呈现的内容结构、保留映射与实际缺口 | 换载体改变阅读/叙事关系或容量有实质限制；纯格式转换可直接组件；不因缺内部模板重写内容 |
| organize | 独立材料、主题索引或来源关联的组织结果，含更新与失效边界 | 用户要求整理、归并、建立主题或维护知识关系；明确保存几项内容可直接组件，不重建知识系统 |
| issue | 状态明确的草稿或同一持续演进工单，含当前正文、证据历史、元数据和实际读回 | 明确要求记录、追踪或维护问题；需跨会话或协作者接力；一次局部修复无需工单可直接fix；发现问题不自动创建远程对象 |
| fix | 根因依据、最小修复、原动作与相关回归结果、未覆盖范围 | 已明确存在的软件故障、报错、崩溃、回归或合并冲突；只要调查时停在证据；规格变化交spec/what，测试资产或环境问题交verify |
| inspect | 只读机会报告：观察、消费者、候选、收益、不变量、置信度与验证缺口 | 需要主动调查架构、可维护性或复用机会；只审指定交付用review；明确故障用fix，不泛扫全库 |
| simplify | 行为不变改造及回归，或有证据的关闭/退出结论 | 用户授权内部简化或承接可检查的架构候选；没有可用基线先补观测；要求行为变化交spec/what，不伪装简化 |
| spec | 唯一现行行为和验收基准，含来源、直接引用及未决边界 | 需要建立、修订或迁移可持续消费的行为依据；小改直接更新现行规格；恢复既定行为或格式微调不机械新建PRD/issue |
| interaction | 范围内可用交互界面，及实际动作、反馈、恢复与未覆盖证据 | 任务需要设计或实现真实产品使用路径；静态内容展示可直接呈现；已有方向不重新采样，未知行为先model |
| deliver | 达到授权终点的版本或平台交付状态，含身份、范围、回执与剩余项 | 已明确请求版本提交、推送、PR或其他交付，且状态判断值得独立委托；一次明确工具动作可直接组件；只写PR正文直接pr.describe，不启动发布链 |
| implement | 获授权实现、接入结果、整体目标路径验收、清理与未覆盖范围 | 普通新增或改变行为的实施请求，已有方案充分；故障直接fix；行为不变改造用simplify；仅要求策略时停在how |
| resume | 脱敏且足以继续的会话摘要，区分完成/未完成/未知/阻塞与下一有效动作 | 真实中断、转交、压缩或明确续办请求；普通完成不产额外收尾记录；活跃分工用coordinate，持久知识用organize |
| measure | 测量合同、真实样本、误差/混杂、产物证据、结论与限制 | 性能、效果或投入数字会改变采用判断；只需行为是否成立用verify；已有有效测量直接复用 |
| evaluate | 可复验试验设计、真实逐任务结果、评分分歧、误触发/无效路由与采用建议 | 技能、工具或解法候选需要真实效果证据；名称、目录数或合同审读足够回答时不声称效果；纯对象比较用compare |
| material | 去重材料单元、支持位置、来源/发言身份、可用引语与未确认缺口 | 作品或知识需消费材料，独立性与证据身份尚未成立；成熟材料直接消费；清楚保存动作不重建材料链 |
| draft | 完整主稿或指定范围修订、含义风险、受影响载体同步及未覆盖项 | 需要写成作品或修改成熟稿；清楚机械写入用text.write；主张未成先回create/compose，成熟稿不重建采访链 |
| media-study | 语义观察、实际本地证据、时间基准、置信/降级限制及分析完成状态 | 参考片手法研究或具体视听主张核验；普通录像入制作不强制拉片；查媒体技术信息可直达media.probe |
| media-production | 可恢复项目、当前预览、审片状态、技术/视觉验收与本地母版回执 | 视听作品制作或续改；仅音频生成直达audio.generate；仅分析参考用media-study |
| plan | 含任务/依赖/文件锚点/检查/回退/完成信号的可接力计划 | 方案已定但复杂实施或委托还缺可执行拆解；简单任务或已有有效任务图直接实施/协调 |
| user-study | 可追溯主题、原话/反证、分群/场景差异、偏差与下一证据动作 | 需要用户/客户事实来校准目标、产品或传播；已有可靠用户研究直接复用；作者采访用interview；市场规模另设测量范围 |

## 共有组件与资料

48个接口是原40项加8项候选动作。新增session.snapshot、trace.capture、measure.collect、eval.run、artifact.preview、capability.inspect、media.package、chart.render。工具可用时直接适配，不要求先新建CLI。生成、操作、检查只回报实际结果与失败，不能替代语义、授权、作者接受或设备验收。

共有库除动作接口外还需版本化领域资料：框架/语言、UI保全与设备差异、统计/归因、演示/连续图文/视听制作、声音平台、表达与关系语义、项目依据、证据与恢复。资料绑定适用条件、来源版本、消费者、验证范围及失效/退出；原则不各自成为Skill，也不全库预读。
