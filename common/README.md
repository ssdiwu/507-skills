# common/ 横向认知与协作层

`common/` 放不依赖具体交付类型、可同时服务代码与写作的能力。它不是“先 common、再 code/write”的固定前置阶段，而是任意工作流在遇到项目未知、概念障碍、外部证据、用户决策或会话转交时调用的横向层。

任务已经清楚时可以直接进入 `code/` 或 `write/`；横向问题解决后，应返回原任务或进入边界最清楚的下一动作。

## 横向关系

```mermaid
flowchart LR
    task["任意代码 / 写作任务"] --> need{"当前缺口"}
    need -->|"项目内事实与未知"| explore["507-explore"]
    need -->|"用户不理解概念"| explain["507-explain"]
    need -->|"外部事实与机制"| research["507-research"]
    need -->|"用户意图与取舍"| grill["507-grill"]

    explore --> task
    explain --> task
    research --> task
    grill --> task
    handoff["507-handoff"] -. "任一阶段中断 / 转交" .-> task

    explore -->|"低成本可观察假设"| prototype["507-prototype<br/>code/ 前置证据层"]
    research --> prototype
    prototype --> task
```

## 五个动作

### `507-explore` 项目探索

从项目实际阅读入口读取本轮相关规格、设计、词义与实现，承接既有共识，区分已确认要求、当前实现和验证证据；迁移中先核对新旧权威是否已切换。在临时会话内维护目标、已知、未知、当前可推进边界与证据范围，多条路径仍无法选择时，分别说明候选的依据、适用条件和最小验证动作。具体行为影响按需使用[代码影响调查](507-explore/references/code-impact.md)；整体启动或规范迁移缺口交 setup，局部导航失真交 map，探索自身保持只读，不建立持久地图。

### `507-explain` 概念解释

解释用户不理解的一个内部或外部概念。最短定义的名词必须指向用户能辨认的对象；用户无法想象时先给场景，再提炼定义。引入未解释术语时，必须现在解释、说明暂不展开的黑盒作用，或删掉并重写。解释未成立时按构造、表达、载体三层依次排查：先修定义落地与术语归宿，再改图设计或换真实运行证据，只有量级、连续变化或需亲手调整才有直觉的感知型障碍才在临时位置生成视觉件。示意使用表格或受支持的 Mermaid，无法渲染时退回结构化文字或表格，不生成 ASCII 图。默认不落盘，不替代项目探索和外部查证。

### `507-research` 外部调研

核实外部项目、文章、标准、竞品或时效事实；多角度问题按可独立查证的子问题展开，关键主张逐条对齐原文，取证失败时保留待核实状态。区分事实、来源观点、本项目推断与未知，默认在对话中产出可追溯的 evidence handoff（证据交接）。学习传播或增长内容时，还须交接标题点击理由、正文兑现及效果证据边界，创作与标题改编归 forge。只有结论需要长期复用时才落项目既有参考目录。

### `507-grill` 决策对齐

在提问前查清可核实事实，只询问用户拥有的产品意图、权责、体验、成本和风险取舍。复杂对齐按需显示受支持的 Mermaid 决策控制台，简单问题使用文字或表格。确认新结论前先核对与既有决定的冲突；需要保存且获授权时，更新唯一现行正文：代码项目的共用设计进入 DESIGN，词义进入 GLOSSARY，功能与验收进入 spec，依据、实现说明及交付安排进入 doc；读取时核对实际入口，旧内容按授权迁移，写作项目遵循自己的组织规则。耐久写入与远程工单仍受授权约束，不建立第二决策库。代码需求的[工程设计](507-grill/references/code-change-design.md)由 Agent 收口，明确需求可直接使用该参考；写作中缺少作者尚未表达的材料时进入 [`507-prospect`](../write/507-prospect/SKILL.md)。

### `507-handoff` 会话移交

中断、换会话、压缩上下文或转交时，在对话中输出脱敏临时摘要。它引用正式产物，不建立第二事实源。

## 边界速查

| 当前真正缺什么 | 使用 | 典型返回 |
| --- | --- | --- |
| 项目里知道什么、还不知道什么、现在先查什么或验证哪个候选 | `507-explore` | 原任务、research、prototype、grill 或交付 |
| 一个概念是什么意思、怎样建立正确心智模型 | `507-explain` | 原任务 |
| 外部事实或机制能确认什么、证据在哪里 | `507-research` | explain、explore、mine、grill、规格或交付 |
| 作者如何叙述自己的亲历与判断，但尚未充分表达 | [`507-prospect`](../write/507-prospect/SKILL.md) | mine、返回调用它的创作动作或直接结束 |
| 已知前提下的用户取舍最终选什么 | `507-grill` | frame、prd、issue、prototype、写作或实施 |
| 把尚未沉淀的运行状态交给下一会话 | `507-handoff` | 下一会话对应动作 |

## 出口纪律

- 每个 skill 可有多个候选出口，也可直接结束或返回调用它的原工作流。
- Agent 根据当前目标、证据和各 skill 的出口合同选择下一步，并简短说明理由。
- 用户只回答其真正拥有的意图与取舍，不负责记忆或选择 skill 名称。
- 长期事实仍进入项目既有术语表、决策档案、经验笔记、规格、工单或写作资产；横向层不新建总控状态库。
