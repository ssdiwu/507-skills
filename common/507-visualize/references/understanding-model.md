# 理解模型与关系

对象较多、关系带条件、比较需要对齐维度或需要阅读路径时使用。模型决定用户能得出什么结论，界面只是它的呈现。

## 从困惑选择结构

| 用户需要理解什么 | 应组织的内容 | 合适的表达方向 |
| --- | --- | --- |
| 一个对象是什么，与相近对象有何不同 | 可指认的定义、实际场景、易混淆边界 | 对象说明、对照表；无需先画全局图 |
| 一个过程怎样发生或接向哪里 | 真实入口、动作、条件、停止与返回 | 带条件流程、逐步探索；并行和回环单独表达 |
| 多个对象怎样关联 | 稳定身份、关系类型、方向、范围与出处 | 分组、局部关系、按对象探索；布局位置不承担未成立的含义 |
| 方案之间如何取舍 | 相同问题、可比条件、差异、成本及未确定项 | 并排比较或按维度查看；无需制造统一分数 |
| 某个条件改变后会怎样 | 明示输入、机制或假设、结果与限制 | 最小推演或模拟；测量值、预测与假设分开 |
| 一组资料怎样连续阅读 | 从具体困惑到必要概念或动作的依赖 | 问题路线与可返回的关联阅读；目录次序不自动成为学习顺序 |

同一批材料可以有不同阅读入口，只添加当前目标需要的视角。关系网不适合表达长篇论证时，让正文承担解释；目录很小且易找时，不为形式加入搜索。

## 对象与证据身份

复用材料已有编号和组织方式；有重复名称或版本时补足稳定身份和别名，避免选错对象。必要时记录对象的显示名、类型、主要作用、适用条件、输入／结果、当前状态和来源。字段由实际用途决定，不为短图建立完整数据库。

分清原文事实、来源观点、当前实现、已经确认的要求、假设、推断与建议。原文中的标题、图示、接口或绿灯只证明其对应范围。使用者指定或修订的版本优先；当前工作稿不得冒充已提交或发布的版本。

词典式解释先指认对象，再用真实或标为假设的场景展开；技术术语和简化模型保留必要边界。把原文译成中文或拆成卡片，不取得补写动机、因果或作者立场的权限。

## 关系必须先有含义

每条关键关系至少能回答：谁与谁有关、什么关系、是否有方向、在什么条件下成立，以及依据在哪里。用材料中可定位的段落、行、场景或记录支撑；未知关系保持未知，单纯提到同一个词不能证明调用或依赖。

| 关系 | 需要保留的区别 |
| --- | --- |
| 引用或提及 | 只表示资料中谈到了另一对象，不承诺执行或先后 |
| 依赖 | 指明哪项前提阻止哪个动作；共同出现不证明依赖 |
| 调用或数据流 | 指明发起方、实际处理方或消费者，不把普通说明词识别为入口 |
| 时间顺序或阶段 | 写清是实际顺序、建议阅读顺序还是一个路径示例；并行不画成严格串行 |
| 条件接力、返回与结束 | 保留进入条件、当前停止位置和返回原因；“可进入”不改成“必须进入” |
| 同类、互补或比较对应 | 表达职责关系，不画成真实执行；部分相似不声称完全等价 |
| 建议、候选或未来合同 | 保留未采用或尚待执行的身份，与当前事实分开 |

机器检索、关键词、同名符号和自动抽取用于发现候选；正式图谱的关系语义需要核证。普通英语单词、文件夹名称、被否定的旧方法和示例路径都可能产生误连。关键出处相互矛盾时展示具体差异及适用范围，不静默裁成一条顺滑流程。

不要用一个没有语义说明的“相关”箭头混合所有关系。适合方向的关系才用箭头；图例与可读条件共同表达含义，颜色不承担唯一解释。图中只显示局部时，说明省略范围，并保证关键停止、分歧和未知仍可发现。

## 比较与探索

从用户当前问题选择比较维度，核对对象是否针对同一目标、版本和条件。某对象没有对应能力时说明范围差异；证据不足与确认缺失分别标记，不猜价格、性能、成熟度或优劣分数。

展示主张如何连接到证据、条件和结果。用户能先识别一个对象，再沿必要关系继续理解；已有完整材料可以直接进入正文或比较，不强制逐个概念解锁。

筛选、展开、点选和参数变化各自应有一个可观察的理解收益。操作只是改变呈现时，源数据和关系不变；推演改变假设输入时，结果注明模型范围。没有已核实机制的曲线或动画不能作为科学、产品或性能结论。
