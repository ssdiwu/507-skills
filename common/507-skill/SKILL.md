# 技能编写与演进（skill）

把可复用的工作方法整理为未来 agent 能准确选择、执行和完成的技能。支持新建、局部修改、来源融合与指定范围的技能审视；这些是同一份技能合同的维护方式，不是每次都要依次完成的阶段。

## 范围与输入

先确定用户要维护的能力、目标技能或仓库、当前版本和交付范围。已有请求、文件与已确认结论足够时直接推进；只读审视只交付发现，创建或修改请求持续完成范围内的文件、关联导航与验证。

优先复用现有技能。比较它们实际承担的动作、输入、产物、权限和停止位置；能在既有职责内融入的方法原位维护，有独立动作与边界时才新建入口。普通实现不因包含多步就必须包装成技能，短小但有稳定专用知识的工作也不因步骤少被排除。

| 当前任务 | 按需读取或处理 |
| --- | --- |
| 新建一个职责已清楚的技能 | 按下文建立最小合同；需要验证方法时读[验证与回放](references/validation.md) |
| 修改既有技能、融合外部方法、检查一组技能 | 读[审视与方法融合](references/evolution.md)，核对基线、来源和受影响消费者 |
| 职责变化、批量入口调整或流程较复杂 | 读[验证与回放](references/validation.md)，检查选择、执行与结束行为 |

项目当前需求与规则仍由项目自己的规格、AGENTS 和导航负责；本技能不接管产品实现、插件开发、宿主安装配置或对外发布。来源事实不清时可使用 `507-research` 查证；真正的用户取舍缺口可使用 `507-grill`。这些技能不是必经前置步骤，目标环境没有它们时使用等价查证或对齐方式。

## 确定信息归属

| 信息 | 归属 |
| --- | --- |
| 只服务当前请求的指令 | 当前任务或一次性提示 |
| 项目内持续成立的规则、入口、设计或需求 | 对应项目权威；个人偏好留在个人配置 |
| 特定任务才需要、会改变 agent 判断或行动的方法 | 技能合同 |
| 某种模式才需要的详细步骤、格式、领域资料与例子 | 技能内按条件读取的参考 |
| 值得复用或需可靠执行的确定性操作 | 现有工具或必要脚本；先核实已有能力 |
| 一次失败的过程、外部原件与改写依据 | 项目已有证据或参考位置，不作为默认执行指令 |

不把对话原句、私人称呼、机器路径或单个案例的偶然条件直接写成通用规则。提炼规则时保留真实权限、否定、例外、失败边界和作者意图；历史材料按用途保全，不能把“通用化”变成无依据删除。

## 编写最小可用合同

目录沿用目标项目或已指定宿主的约定，名称与文件夹一致；新技能使用小写字母、数字和连字符。`SKILL.md` 至少包含有效的 `name` 与 `description` 元数据，以及能指导执行的正文。

描述写清**什么动作、什么时候使用、容易混淆的边界**。以用户意图选择技能，不用宽泛领域词、穷举同义词或“任何相关任务必须加载”吸引不相干请求。执行步骤、输出模板和工具参数不塞进描述；简短不能牺牲关键区分。

正文围绕当前工作保留：

- 所需输入、允许的修改和外部动作边界；
- 会改变判断的依据、必要顺序及失败处理；
- 产物、完成信号与未满足前提时的处理；
- 需要继续时的候选出口，以及何时直接结束或返回原任务。

按真实需要组织章节，不用统一行数、章节数量或固定流程套所有技能。指令详细程度与风险相称：授权、不可逆动作、数据保护和脆弱工具合同保留具体约束；一般实现、措辞、文件组织和可查事实由 agent 判断，不转交用户审批。

把模式专用内容放在参考文件时，在入口写明**何时读取、读取后做什么**。共享权限和完成要求仍应在主文件可见；不把所有内容移到一份默认全读的大参考，也不为短技能制造路由层。独立安装技能所必需的合同留在技能包内，不能依赖作者仓库才有的规则。

## 完成改动与验证

在授权内同步技能入口、实际消费者和直接相关导航；目录移动后检查相对链接、脚本命令与安装边界。需要退出旧入口时先核对消费者和恢复方式，在候选验证后切换。创建仓库文件不等于宿主已发现或实际使用，安装和启用分别报告。

检查元数据、命名、引用和实际脚本；再按风险验证技能是否选对任务、保留用户意图、完成目标且没有额外暂停或越权。行为改变或复杂流程按验证参考做独立检查；已有检查仍对应当前输入与环境时复用，出现新变化或具体疑点才扩大。

用户只要求建议时交付有证据的发现与候选；已授权创建或修改时，措辞和结构等常规选择直接完成。遇到必须暂停的边界，说明具体缺口及其来源，只暂停依赖该缺口的部分；完成一个内部技能步骤不等于整个用户任务结束。

## 完成与接力

- **完成信号**：目标范围内的技能或审视结论已交付；触发、输入、权限、输出和停止条件一致；关联入口有效，已完成验证与未覆盖范围可区分。
- **产物**：可独立读取的技能包或对既有技能的精确改动；只读请求产出范围、证据、建议及不建议修改项。来源与迁移证据按项目需要保留，不强制另建文档体系。
- **候选出口**：查证、用户取舍或脚本问题分别进入相应动作后返回；交付审查可使用 `507-review` 或目标项目的等价流程；提交、发布和宿主启用仅在各自获授权范围内继续。
- **回退条件**：来源无法核实、职责仍冲突、不能保留关键约束或验证失败时，保留当前可用版本及失败证据，不把候选说成已验证效果。
