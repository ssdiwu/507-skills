# OpenAI 目标的技能界面元数据

在面向 OpenAI／Codex／ChatGPT 创建、改写、审计或交付技能时读取。先核对实际目标宿主和当前官方说明；其他宿主不默认引入 OpenAI 配置。

## 依据与适用范围

[Build skills](https://learn.chatgpt.com/docs/build-skills) 将 `agents/openai.yaml` 列为可选的产品界面配置，与 SKILL.md 的识别元数据分开；[插件提交错误参考](https://developers.openai.com/plugins/deploy/submission-errors)说明，提供该文件时，`interface`、`display_name` 和 `short_description` 需要有效且非空。

本项目对自有、且已选定 OpenAI 目标的技能交付要求这份文件，并提供下列三个字段。`default_prompt` 是这里的交付约定，不伪称为所有 OpenAI 技能的官方强制项。通用源技能、尚未选择宿主的材料和第三方技能不因缺省该文件而自动判为功能错误；审计应分别列来源、缺口和是否需要迁移。

## 最小配置

```yaml
interface:
  display_name: "技能的用户可读名称"
  short_description: "简短说明实际动作和主要用途"
  default_prompt: "使用 $skill-name 完成本技能承担的具体任务。"
```

- `display_name` 使用目标用户能够理解的名称，中文界面优先中文；无需把技术身份改成中文。显示名与正文标题相关，但正文标题不能代替界面字段。
- `short_description` 便于选择技能，准确表达职责，不增加正文中没有的能力；不要复制完整执行流程。
- `default_prompt` 是典型起始请求，包含实际可用的调用标识；独立技能通常为 `$skill-name`，插件环境先核对命名空间。提示不能自行扩大修改或外部动作权限，不增加重复审批。
- 字符串按有效 UTF-8 YAML 编写并加引号；字段必须是非空字符串。保持 SKILL.md 的名称、描述、动作与界面提示一致。

## 维护与字段保全

先读已有文件与实际消费者。创建新配置可以使用当前宿主可用的技能生成器；已有文件不要为修改显示名整体重建。保留已有 `policy`、`dependencies`、图标、颜色和其他有效配置；改变调用策略或工具依赖需要对应的用户意图及验证。

图标和颜色按目标需求提供，不为满足形式自动造资产。图标用可随包分发的相对路径并核对真实文件；颜色提供时符合目标格式。保留已有 `policy` 原值；新建配置且用户没有指定调用策略时沿用宿主默认。敏感业务动作仍由技能合同处理授权，不能用改变 `allow_implicit_invocation` 替代执行前的授权边界。

界面起始提示只是典型请求，不是常驻指令；隐式匹配允许按任务选择，不要求所有任务必经该技能。

技能的界面配置不等于插件 manifest 的界面配置，也不提供新的工具权限。若实际宿主已经使用另一份权威元数据，应先确认其读取与优先级，避免新增相互矛盾的配置副本。

## 全量审计与完成信号

1. 从实际宿主目录和当前指定源位置枚举技能；只扫描磁盘缓存会混入停用或历史版本。记录逻辑身份、物理路径、来源、启用状态和同名副本，不把用户目录自动当成全部自有。
2. 检查 SKILL.md 的名称／描述，agents 配置的结构与字段、相对资源、起始提示及策略／依赖类型；读回当前宿主支持的显示信息。缺省、格式错误、语义不一致和未发现分别报告。
3. 不执行被审技能的业务动作。批量补齐只在授权且所有权明确的目标内进行；外部插件缓存交原维护入口处理，不擅自覆盖上游策略或私有配置。
4. 改动后验证配置可解析、引用有效、能力与权限一致；有可用宿主时核对发现与显示读回。没有宿主只报告文件检查，不声明已安装或已显示。

完成信号是目标范围的配置与合同一致，实际发现证据和未覆盖范围明确。文件写入、宿主发现、界面呈现、提交和发布分别成立。脚本仍按真实需要添加：确定性的重复步骤或外部工具编排适合脚本，不能把“每个技能必须有脚本”当成元数据规范。
