# 审视与方法融合

用于修改、整合或检查已有技能。局部请求只检查受影响合同；用户指定全套时枚举全部活动入口，并分别报告主文件、参考、脚本和宿主配置的实际检查范围。历史副本和外部原件不是待自动执行的活动技能。

## 基线与来源

核对指定版本、用户改稿、现行决定、未提交变化及实际消费者。多人协作时确定写入责任；在隔离候选中改动，合回前核验基线仍相同。新时间戳不自动覆盖用户指定版本。

外部文章、图示或代码只作为待判断材料。记录能复查的链接、版本或内容指纹及读取范围；重要规则来自配图、附件或脚本时实际读取它们。需要保留原件时按项目参考目录及来源许可处理，原件不进入技能自动发现范围，不运行尚未审查的来源脚本。

把来源中的事实、作者建议、模型或宿主专属行为、可迁移的方法与未知分开。模型升级是重新检查的理由，不是通用权限或流程可以被删除的证据。

## 逐项比较

| 检查对象 | 要回答的问题 |
| --- | --- |
| 任务选择 | 描述是否用实际动作定位任务？是否把同领域但不需要该方法的请求吸引进来？相邻技能是否能区分？ |
| 当前合同 | 输入充分、用户已授权时能否直接完成？“已确认”是否被误写成必须经过某个技能？是否存在相反的权限或停止条件？ |
| 加载路径 | 主文件和参考是否说明读取条件？简单任务是否被要求通读全部分支？关键约束是否仍能被执行者读到？ |
| 判断自由度 | 固定步骤、数量或工具是否保护真实风险？示例有没有被推广成所有任务的前提？ |
| 完成与验证 | 是否检查用户关心的结果？已有效验证是否会被无条件重复？是否过早交还未完成任务？ |
| 独立使用与迁移 | 是否暗中依赖作者的私有路径、宿主或另一份未安装技能？改名、移动或退役后有哪些真实消费者需要更新？ |

每个改动连接到可定位的现状、影响场景与预期行为。篇幅、重复、禁止句或“看起来复杂”只能提示继续检查，不能独立证明缺陷。分别保留“应修改”“证据不足，待验证”“保持不变”的结论。

## 选择承接位置

先比较动作、输入、产物、权限和停止位置，再决定融入、替换、按需参考或新建。表面上都使用问答或文档，不能证明职责相同；来自两篇文章也不等于需要两个新技能。

把有用方法写进现行合同，不并排保留相互矛盾的新旧指令。不复制外部模型的整套提示、个人配置或工具实现；只迁移已成立的方法及其适用条件。保留真实安全、数据、来源、作者声音和交付约束；规则退役应有可靠承接、删除风险和恢复办法。

批量改动记录每个入口的处理方式与理由。说明字段变化、条件迁移、参考抽取或保留原样，不把抽样或字符串扫描称为全量行为验证。需要安装层去重时先核对实际加载与消费者；磁盘上有两份文件不等于某个宿主必然加载两次。

候选完成后进入[验证与回放](validation.md)。获授权的旧入口退出应与消费者切换一起完成；未授权的宿主或发布渠道保留为清晰的后续范围。
