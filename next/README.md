# 当前技能入口

当前清单包含 **20 个入口：10 个主要技能、10 个次要工作能力**。`next` 是现行源码目录名，不表示这些技能仍待接入。当前版本、能力范围、已知限制与待办见[公开进度](../PROGRESS.md)，历史方案与验证见[历史导航](../doc/历史导航.md)。

主要／次要沿[术语表](../GLOSSARY.md#分层与共有资源)定义：用户主要触发主要技能，Agent 按需采用主次技能。清楚任务由 Agent 直接采用所需能力，不固定串行调用；这不表示运行环境权限或宿主已经隐藏次要入口。

| [507-clean](skills/507-clean/SKILL.md) | 指定模块的代码与规则清理；先列清单、核行为规格，超过800行先出拆分方案 |

## 次要工作能力

| 实际入口 | 独立结果 |
| --- | --- |
| [507-plan](skills/507-plan/SKILL.md) | 已有方向的步骤、依赖、验证、恢复与接续安排；不自动派工或实施 |
| [507-visualize](skills/507-visualize/SKILL.md) | 有依据的状态图、时序图、关系图、比较表与配套说明；不代替产品证据地图或业务验证 |
| [507-spec](skills/507-spec/SKILL.md) | PRD、行为与验收规格 |
| [507-product-map](skills/507-product-map/SKILL.md) | 指定功能的交互点及关系，同对象设计／实现／运行证据与可探索地图 |
| [507-review](skills/507-review/SKILL.md) | 独立只读审查 |
| [507-issue](skills/507-issue/SKILL.md) | 可独立接手的调查／执行工单；只起草也整理依据、下一动作与推进条件 |
| [507-coordinate](skills/507-coordinate/SKILL.md) | 依赖、并行隔离与集成 |
| [507-deliver](skills/507-deliver/SKILL.md) | PR表达与授权版本交付 |
| [507-retro](skills/507-retro/SKILL.md) | 复盘与工具化建议 |
| [507-material](skills/507-material/SKILL.md) | 整理指定资料的来源、身份、重复与支持范围，或按请求组织已有知识入口 |

明确故障、成熟稿、充分规格和已有任务图可直接进入相应能力；不因技能存在重跑what/why/how/plan或全链。三组分工见[术语表](../GLOSSARY.md#会话分层与验收职责)：技能身份不决定会话角色，B 复用任务能力，C 用 review 独立核验。技能缺失可按同一合同直接工作，独立审查仍须另一执行者。

工单只起草时直接采用507-issue主文的正文组织方法，调查态保留关键未知并给证据动作和推进条件；行为、范围、依赖与验收充分后才作为ready交接。平台参考只在对应动作已获授权时读取，不把正文组织挂在平台许可之后。

## 常见任务的直接入口

| 任务 | 采用方式 |
| --- | --- |
| 实现功能、修 bug、局部修改或只跑测试 | do 沿已有需求和方案直接处理；修复保留复现、根因和原动作复验；只跑测试不自动改代码 |
| 大扫除、去死代码／重复逻辑或清理旧规则 | clean 限定读取与修改范围，先交清单；重构前沿用或补齐现行行为规格，spec补齐依据后回到原清理项；只读请求不改文件，超过800行先交拆分方案 |
| 了解可定位的陌生项目 | why 自主建立必要全貌并核对代表路径；交互地图只在确有需要时使用 |
| 初始化仓库或维护文档导航 | setup 按范围建立或维护项目依据；spec维护现行行为与验收，issue维护软件工单和跟进；局部导航直接处理，不串成固定流程 |
| 整理材料、成文或换载体 | 材料确需独立核身份时用 material；成文、主张或论证重写、普通局部润色用 create；成熟内容换受众或载体用 adapt，表达改写不重开作者主线 |
| 找产品界面组件 | do 按需读取[包内组件方法](skills/507-do/references/component-reuse.md)；只查不改，已知可用直接采用，没有适用组件且有多个确定使用位置才抽取并迁移，单处留在原地 |
| 把复杂关系表达清楚 | visualize 按理解动作选择图、表和说明，复用已有材料；简单事实不建图，图解不增加业务操作或资料库写权 |
| 梳理功能与实际操作证据 | product-map 对齐交互点、关系及设计／实现／运行证据；普通实现不强制建图 |
| 推进已有工作或安排协作 | work 持有本次事项与推进结果；需要协作时按需采用 coordinate，工程、创作和研究也可直接采用它 |

产品界面组件库与本技能库的共有资源库是不同对象。前者由 do 的包内组件方法处理，后者由 `skill-design` 处理。旧 `507-component` 已退出活动入口，原包与验证保留在历史导航。方法和工具可以直接采用，不必为读取一段参考再启动一个技能。

## 资源维护与构建

[共有资源库](../lib/README.md)分开说明方法、执行脚本、工具说明、设计参考与名称索引。当前登记 28 份共有方法、10 个执行脚本；50 个共有源形成 223 份随包副本。加上各技能的 64 份自有文件，精确包清单共 287 个文件。事实以[packages.json](packages.json)与[catalog.json](../lib/catalog.json)为准。

共有源修改后生成对应副本，不手改随包副本。入口合同或旧名处置改变时，按[名称索引说明](../lib/components/library-view.md)先生成并核对索引，再同步包。名称查询只返回声明，不执行技能或证明宿主已启用。

在仓库根按变更范围运行：

```sh
python3 next/scripts/package_skills.py sync
python3 next/scripts/package_skills.py check
python3 next/scripts/package_skills.py build
python3 -m unittest discover -s next/tests -v
python3 -m unittest discover -s lib/components/tests -v
```

sync 验证候选后切换并保留失败恢复；check 核身份、精确文件、资源闭包、软链接、副本漂移和索引新鲜度；build 生成按内容指纹定位的不可变快照。构建工具不承担宿主安装或自动调度。只改导航说明时核链接、范围和内容保全，不为文档整理重跑业务。

GitHub Actions 配置为在 Python 3.10、3.12 上执行 `check`、`next/tests` 和 `lib/components/tests` 三项检查，再继续运行原有专项回归。CI 通过只证明这些检查覆盖的包一致性与脚本行为，不证明宿主发现、自然采用或业务效果。

## 能力与验证边界

入口和资源已实现，不等于每个自然任务都已稳定采用。离线 HTML 与 PNG、PPTX、音频或视频分别核验；源码检查、实际操作、独立审查、安装发现与人的接受保留各自证据。

公开能力范围、已知限制与待办在[PROGRESS](../PROGRESS.md)维护；可公开的历史结论见[历史导航](../doc/历史导航.md)，本机安装、试验过程与临时交接留在库外。历史测试命令和已发布专项能力仍保留在原版本记录中，不作为本清单的默认执行流程。
