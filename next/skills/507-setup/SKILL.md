# 项目依据与导航维护

让维护者找到当前目标、现行要求、共同规则、真实入口与验证依据，并判断下一步具体工作是否具备前提。它有独立的文档维护结果；不持有产品开发、故障修复或架构改造的全部责任。

## 输入、权限与停止位置

承接指定项目或文件、有效版本、用户修订、已确认决定与当前授权。先核对实际入口、工作树和已有改动，明确唯一写入者、允许正文与必要消费者。只读请求只交证据、缺口和建议。

| 请求 | 当前可处理范围 |
| --- | --- |
| README、目录说明、spec/doc 导航或局部地图维护 | 仅指定地图和必要上下级引用；不改规则、设计、词义、进度、规格或业务实现正文 |
| 项目初始化、依据建立或已授权规范迁移 | 规则、已确认词义／共用设计的整理归位、相关当前快照及直接导航；具体行为正文沿现行规格职责维护，不改产品意图或源码 |
| 按标准只读巡检 | 读取范围内依据、实际入口与验证信息；不补文件、测试或工具，不将巡检完成当迁移完成 |
| 明确指定的全局 AGENTS.md 校准 | 仅指定文件及必要来源；不猜宿主路径，不顺带迁移当前项目 |

导航任务读[项目导航](references/shared/project-navigation.md)即可。建立、巡检或迁移工作依据时读[项目依据](references/shared/project-foundation.md)，按实际风险选择完整或精简职责，不创建没有内容与消费者的文件。全局文件只采用其中全局规则与规则维护条目，跳过项目步骤。

## 建立或切换依据

分别核对应该怎样、现在怎样实现、实际验证到哪里。现有缺陷不删减已确认要求；旧计划、未勾选项和历史候选不自动成为现行目标。规则变化说明具体防错对象、适用条件与依据，已有机制能够承接时才退役；篇幅、固定清空周期和模型升级不能单独证明安全。

迁移先按内容建立来源、唯一目标与受影响消费者映射，保全有效条件、排除项及未完成。隔离候选通过含义、来源、覆盖与链接核对后，在同一受控变更切换正文和引用；清理无消费者的重复正文，历史保留后继入口。必要迁移指引记录真实消费者和退出条件，不继续维护第二套现行正文。受保护原件、生成文件、嵌套项目、冻结样本和其它工作树沿其所有权处理。

PROGRESS 只承载确有接续用途的当前阶段、必要完成证据、未完成／依赖与下一动作。阶段切换先保全历史和未完成，再更新当前快照；已有细任务状态回链原工单。一次局部导航维护不能新建进度系统。

授权充分时连续完成正文与直接引用，不为本任务内部动作重复索取同一许可。必要工程保障未建立或未运行时，给具体建设动作和受阻路径，由工程实施承接；规范文字不冒充工具保障。

## 验证、完成与返回

检查含义与来源保全、链接／锚点、实际阅读路径及变更范围。从现行要求走到共用规则、实现入口与验证依据；新项目没有实现时明确缺口，不造运行能力。巡检、文档迁移、工程可用、业务接受和发布分别报告。

完成时，本次范围的当前正文与入口唯一，授权旧维护路径已退出，未同步消费者、未完成与依赖可查。交付相应文件或只读结论、来源与验证、下一步开工条件；不能用新目录存在或地图准确称全项目迁移完成。

规则、权限或正式需求变化由另一执行者独立 review。只要求维护时结束；原目标仍有授权工作则携当前依据返回继续，提交和发布按具体授权另立结果。权威冲突、所有权不清或候选未通过时保全可用基线，只暂停依赖部分。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。
