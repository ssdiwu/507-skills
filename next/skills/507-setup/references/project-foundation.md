# 项目工作依据与内容归属

在建立、巡检或迁移项目依据，或核对规格／规则／进度的归属时采用。它说明共同判断，消费者自身仍持有读取、修改范围和停止位置；不能由此取得全项目迁移或工程实现权限。

## 从下一步结果选择依据

先确认项目与当前阶段、下一条完整用户或调用者路径及允许范围。持续维护的应用、服务、库按其运行边界、数据、外部系统与协作风险建立足够依据；职责单一的小工具可以在 README 的明确章节承载短合同。风险与实际用途决定详略，不按行数、文件数或旧布局判断。

| 内容 | 唯一职责与最低依据 |
| --- | --- |
| README | 定位、范围、前提与真实入口；命令回到配置／脚本，目录说明不复制当前规格或进度 |
| AGENTS | 跨任务稳定的项目规则、阅读入口、授权与验证责任；命令和地图回链原正文 |
| GLOSSARY | 稳定领域对象与易混词义；操作变化进规格，选择理由进长期依据 |
| DESIGN | 跨功能的体验与视觉约束；局部操作、状态和验收进规格；参考、候选、定案和实测分别表达 |
| spec | 唯一现行功能行为、条件、排除、失败恢复与可观察验收；已确认未实现要求仍保留 |
| doc | 研究来源、架构与运行说明、决定理由、长期规划、版本实施安排和历史；不维护第二份功能要求 |
| PROGRESS | 确需接续时的当前目标、必要完成证据、未完成／阻塞与依赖、下一动作；细项回链现有工单，历史归 doc |
| 工单与实施方案 | 状态／责任／证据历史与一次交付安排；摘要回链唯一规格，不按完成与否机械归档仍有效材料 |
| CHANGELOG | 项目要求的已完成变化与实际版本；不复制 Git 流水、未来承诺或倒填历史 |
| 工程与检查 | 实际配置、命令、纳管范围与回执；缺少机制不由规范文字补成“已保障” |

没有真实内容与消费者不造空 DESIGN、GLOSSARY、doc 或 PROGRESS。按实际内容建立 doc 导航或编号分段，具体项目已确认的结构优先。

## 规则与阶段快照

新规则或退役需说明具体误判、适用条件、实际失败／难以廉价重建事实／已确认边界／高代价风险中的依据。优先校准已有条目；退役前核对有效性、重复、可靠承接及恢复方式。授权、数据保护与单一写入约束不能先删后等事故验证。

全局规则仅在目标明确时处理，保留跨项目稳定沟通、工作与安全边界；项目状态、私有路径、动态版本、宿主机制与命令不进入全局。项目规则保持自己的权威，用户已确认要求优先。

PROGRESS 随实质状态变化维护，不能每次工具调用追加流水。阶段切换先保全结果、关键变化与验证边界到已有 doc 位置，再将历史移出快照；未完成与阻塞显式接续，不能归档成完成。不存在当下工作时按用途移除或保留必要入口并同步导航，不从旧计划自动恢复现状。

## 迁移的受控切换

核对原版、用户指定或最新确认的要求、实现及验收；生成、第三方原件、嵌套权威、fixture、冻结样本、归档和其它工作树保持所有权。逐项将有效要求、共用设计、词义、理由、交付安排和历史映射到唯一目标，保留来源、排除及未完成。

隔离候选通过含义、覆盖与链接核对后再切换正文和直接消费者。旧现行正文无消费者时清理；只供追溯的材料注明后继；必要迁移指引列消费者与退出条件。未获远程写入授权的引用明确待同步，不声称远端完成。只有范围内旧现行消费者全部处置，才称该范围迁移完成。

## 开工条件与验证

分别报告文档已建立、迁移已完成、相关实现可用及人的接受。工程前提按真实下一步风险选择，复用既有框架和检查；纳管范围、差异基准、新旧违规、例外与未覆盖可查，零源码绿灯不证明功能或架构成立。不刷新基线掩盖新增违规。

走查“找到现行要求 → 读取共用规则 → 找到实现入口 → 找到验证依据”的真实阅读路径。缺失项说明阻止哪一步、最小建设动作与可继续工作，不以一个缺口阻断全部独立目标。
