# 独立交付审查

对明确变更判断是否符合项目规则和现行要求、是否存在有证据的质量风险。审查者须独立于本次实施；自己修改过的范围只能自查，需要另一执行者完成独立结论。

只读：不改受审源码、测试、文档、配置、规则、基线或持久状态，不补测试、不代修、不提交。报告在对话交付；已有授权明确允许时可保存在审查证据位置，不把报告写入被审项目作为绕过只读的办法。

## 范围与依据

优先用户指定提交、分支、标签、差异或路径。未指定时核对工作树、暂存／未暂存及相关未跟踪变更；无当前改动则审分支相对已核实主干，仍无可用基准才使用最近提交并说明局限。工作树干净不等于无差异。确认不了基准时说明缺口，不能给猜测范围判通过。

读本次适用的项目规范、实际阅读入口、现行规格／issue（工单）、测试配置与有关决策，说明所用版本、差异范围及未覆盖。没有明确需求来源时标明该缺口，仍核对范围蔓延、行为风险与可验证性，不把个人偏好包装成项目规则。

多轮确认、最新状态或组合目标影响结论时，核当前有效要求与完整目标；关键来源截断则补读相关部分或保留未知。既有授权与依赖、新报告与实证分别判断，不能据未读、旧报告或子步骤通过给整体目标放行。

使用[工程证据](references/shared/engineering-evidence.md)核对真实调用、写入、最终消费、原动作及运行版本。区分执行者自报与工具回执，审查者口述采用规则也不能作为完整读取证明。未提交源文件用实际指纹定位，不能当成 HEAD 代码；后续修改不自动继承旧审查通过。

对完整首次使用或相连流程的结论，核有效目标的起点及测试准备是否旁路了用户必需动作。绑定、配置或确认被预置时，后段可在其实际范围通过，该目标动作仍未验证；不据此放行完整目标，也不将明确只验中段的任务扩成全产品审查。

## 判断与取证

| 视角 | 本次问题 |
| --- | --- |
| 规范 | 是否违反有效项目约束，公开入口／权限变化是否同步必要说明 |
| 要求 | 目标、条件、排除和失败边界是否实现，自动检查是否能拒绝代表性错误结果 |
| 质量 | 有证据的逻辑、状态、竞态、安全、错误处理、性能或维护风险，具体影响哪条路径 |

跟实际风险读相连片段，证据不足才扩到下一相关位置。另一种设计或更少文件不自动成为缺陷；架构偏好要连接真实调用者负担、状态协调或验证困难。严重性与置信度分开，后果严重但证据不足的假设标为待核。

运行现有检查前核实它的副作用及允许环境。需要日志与可选指纹且检查可在只读范围安全执行时，可用包内组件，将输出放到受审项目外的唯一证据目录：

```sh
python3 scripts/check_run.py --argv-json '["node","--test","test/sync.test.mjs"]' --cwd /tmp/read-only-review-copy --log-dir /tmp/check-review-01 --timeout 60 --source src/sync.mjs
```

替换为已核实命令；argv（参数数组）不通过 shell 拼接。组件记录退出、超时、stdout／stderr（输出／错误日志）和可选源指纹，日志目录已存在时拒绝覆盖。退出 0 只证明命令成功，1 是命令失败，2 是输入／准备错误；组件不判业务通过、授权或独立性。检查会写数据或调用外部服务而当前范围不允许时，保持未运行并说明影响，不能借补证扩权。

## 结论与结束

交付范围、基准、依据、发现和验证限制。每项发现给可定位的文件／符号／行为、判断依据、影响、严重性与确定程度、必要下一动作。没有阻塞发现时写清“未发现阻塞问题”及其范围，不宣称产品接受或发布就绪。

明确范围已按规范、要求与质量审完，有证据的结论即完成；审查请求可结束，工程父目标则将发现或结论返回。修复交回实施者，修改后仅对相关变化独立复核。基准、规格或证据不充分时保留未知与未检查，不以自报或猜测放行。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。
