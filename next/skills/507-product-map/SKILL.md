# 交互点功能梳理

交付用户在指定产品范围内可以做什么、从哪里进入、怎样操作及返回的功能地图。页面、Tab、按钮、表单、字段、菜单、开关与抽屉等各自是交互点；按钮不降为页面的附属动作字段。

## 输入、权限与范围

承接用户目标、产品版本、角色与功能边界、已有设计和运行资料。先核项目现行要求与源码，再按可用环境观察必要动作。默认只读产品；允许写本次地图、证据整理和由组件生成的网页，不因发现缺口获得产品修复、需求修改或远程发布权限。运行会改变业务数据时先核原授权与隔离条件，条件不足保留未观察并继续可读部分。

直接功能梳理可进入本职责；父任务需要这一结果时按给定范围完成后返回。只要目录导航、组件复用、故障修复或明确实施时直接做相应工作，不把地图改成每个界面任务的必经步骤。

## 建立同一份地图

读[交互点、关系与证据](references/shared/interaction-map.md)，确定稳定身份、功能边界和采证范围。维护项目已有同类记录；没有时在本次交付位置建立一份地图 JSON，网页与表格均为派生视图。

1. 按用户可进入、操作、提交或切换的单元辨认节点。相同名称、共用组件不证明身份相同；两个位置的按钮分别保留，共用抽屉保留同一目标身份。静态分组和内部函数不当交互点，成功提示可记为结果。
2. 分开记录包含与进入／打开／切换／返回／触发关系及条件。树是包含关系的投影，允许多父级；操作循环与返回保留在关系中。不能为了画树复制共用对象或删掉关系。
3. 每个节点和重要关系分别保存设计、实现和运行记录。每条依据写来源、支持范围及条件；源码声明、单元测试或旧截图不自动成为当前完整路径跑通。缺证据保留未知；相反观察并列，不由生成器选胜者。
4. 从实际入口走到范围目标、失败恢复和返回，记录本次覆盖及未覆盖。只观察中段时说明前置；不把预置或摘要升级为完整路径成功。节点有正向证据也不自动意味着整条路径通过。

需要点击节点、过滤状态或看关联时，按[地图组件合同](references/shared/product-map.md)运行包内组件：

```sh
python3 scripts/product_map.py --record map.json --out-dir map-view-r1
```

更新同一源记录后生成新的输出目录，保留旧网页。需要新字段、关系或布局时改组件再生成，不能手改生成 HTML。组件只验证模型并展示原证据，不判断自然语言真实、权限、功能完整性或产品接受。

## 交付、完成与返回

交付同一份节点／关系记录、可探索网页、源版本与采证范围，以及设计缺口、接线缺口、实际失败和未知分别列出的差距。已确认要求与候选建议分清；不以未见记录判缺失，不把地图数量或结构校验当功能验收。

完成于约定范围的交互点与关系已梳理、证据能定位且未知可见，网页的筛选、详情、关联导航与必要阅读已核对。完整性声明由梳理者依据实际范围负责，不能由脚本替代。父目标未完成时带地图和未覆盖返回；需变更需求、实施或修复时回原负责人，不自动修改产品。来源或环境不足则交付可核部分与最小补证动作，保全旧记录及网页。

设计基线、版本与来源冲突时采用[事实与证据](references/shared/evidence.md)；验收层级与负例采用[可观察验收](references/shared/validation.md)；新旧记录归宿及父任务返回采用[权威与返回](references/shared/authority-and-return.md)。这些方法按实际缺口读取。
