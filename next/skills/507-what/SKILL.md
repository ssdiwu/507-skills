# What · 明确目标与关键取舍

把仍会改变行动的意图或取舍弄清楚，形成足以继续工作的结论。信息充分时直接返回原任务；不要求每个任务先过本技能。

## 输入与边界

承接原请求、已有材料、当前决定、用户修订和有效授权。先自行核实可查事实；实现、措辞和常规可逆技术选择由 Agent 处理。只向用户询问其拥有且尚未确定的目标、优先级、体验、责任、成本或风险取舍。

默认产物是会话中的目标、范围、关键决定、未决项及下一动作。只要求澄清时，交付后直接结束；原任务已经授权实施时返回并继续实施，不再追加“共同理解确认”关口。

本技能不自行实施产品、创建整套规格、发布或发送消息。需要持久化且已有对应写入授权时，只更新结论实际约束的当前权威。决定归宿本身不增加写入权限。

## 只处理当前必要缺口

先判断信息是否已经足够。存在必要缺口时读[澄清与追问](references/conversation.md)：意图未成形用中性问题显化，真实取舍才给候选与推荐；不把两者混成固定问卷。

| 当前缺口 | 按需方法及用途 |
| --- | --- |
| 事实、版本或来源有疑点 | [事实与证据](references/shared/evidence.md)：自行核实，只冻结依赖未知事实的决定 |
| 分不清谁应该决定 | [决定归属](references/shared/decision-ownership.md)：复用授权，收回应由 Agent 完成的设计 |
| 多个问题相互依赖 | [问题依赖](references/shared/question-frontier.md)：先前提、后分支，独立问题可批量收集 |
| 有真实策略或优先级取舍 | [候选与反证](references/shared/alternatives.md)：给成立条件、代价与推荐，不凑选项 |
| “完成”“更好”等目标不可观察 | [可观察验收](references/shared/validation.md)：澄清可识别结果，区分偏好与事实 |
| 新决定冲突或需要返回、沉淀 | [权威与返回](references/shared/authority-and-return.md)：核对取代关系与当前正文归宿 |
| 关系复杂、表达妨碍判断 | [清晰表达](references/shared/clear-expression.md)：只展示当前需要理解的关系 |

`why` 用来按需澄清目的、价值和优先级；其余5W2H角度同样按缺口采用，不轮流问完。方法只解决相应问题，不自行启动新技能或执行所讨论的业务动作。

## 完成与返回

- **完成**：下一步所需的用户决定已足够；已确认内容、事实与假设可分辨；仍未确定的事项只保留真实影响。不要求走完预先列出的所有分支或完成工程设计。
- **产物**：与规模相称的对齐结论。简单问题一两句即可；复杂时包含目标、范围、决定、未决依赖与下一动作，不强制图或新文件。
- **返回**：继续原任务已有授权的工作。仅请求澄清时结束；进入技能规划或编写须原请求确有该目标，不能因为澄清产生方法就自动调用 `skill-design`。
- **恢复**：遇到事实缺口、矛盾或用户尚未回答，只暂停依赖部分；可推进的工作继续。用户新答复使旧问题失去必要性时删除该问题。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。
