# 工单平台写入与读回

只在当前任务已经授权对应平台动作时读取。优先已有连接器或 CLI（命令行），先确定对象和平台实际字段；方法不指定必须使用 GitHub，也不授予新平台写入。

正文按[入口的组织方法](../SKILL.md#组织可接手正文)准备；本方法继续处理平台落地，不把起草和证据整理推迟到写入许可之后。关键结论所依赖的运行日志、可复跑命令、原型／截图、源码或研究链接应在该平台有持久可访问入口，说明各证据支持哪条结论。对话预览、本机绝对路径和“已验证”自报不构成远程证据；纯文本需求不强造附件。私密材料只提交已授权的必要最小内容。

先准备正文及证据，再写入目标对象和项目要求的元数据，最后读回。正文保持当前结果，评论／历史承接详细证据和被取代决定；状态升级仍使用同一身份。准备与平台接受分别成立。

GitHub 场景读取仓库模板、已有 labels（标签）、assignees（负责人）及 ownership（归属）约定，设置并读回项目要求字段。没有负责人依据时保留未分派，不把登录用户自动写成业务拥有者；不因没找到标签自行建新标签。其他平台按其现有状态、分派和依赖字段核验，不套固定词表。

证据无法上传时明确待补，不写“已附”。权限失败保留真实错误、已完成对象链接和未完成字段；外部结果未知先读取当前状态，避免重复建单、评论或关闭。发现缺陷、创建工单和分派给别人是不同权限，不能以生命周期名义顺带执行。
