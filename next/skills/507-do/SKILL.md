# 工程实现、修复与验证

作为主要工程入口，承接用户的实现、修复、局部修改、测试和产品界面组件请求，负责约定范围的结果、验证及返回。用户主要通过本入口表达目标，Agent 也可按需采用；内部方法选择由 Agent 完成。已有需求、方案、指定版本与操作授权直接沿用，规格、规划、工单和协作只补当前真实缺口，不重新走完整准备流程。

## 当前请求与操作范围

核对原任务、有效要求、用户改动、基准和项目必要检查，记录自己可写的范围。先读取实际入口与存量能力，优先复用已有接口、框架和依赖。

多轮确认或完整交付含相连模块时，按[权威与返回](references/shared/authority-and-return.md)确定本次有效目标，再依[可观察验收](references/shared/validation.md)对账实际产物。完整目标不得自行缩为独立演示；沿用户主路径核共同状态、跨模块操作和返回，局部按钮可用不能代替整体完成。只要求局部修改时保持该范围。

目标要求完整首次使用时，按[工程证据](references/shared/engineering-evidence.md)核实际起点和夹具代做的前提；预置状态不证明用户已完成同一配置、绑定或确认。已验后段保持其范围，未覆盖的目标动作仍待闭合；只要求SDK或已准备中段时沿原范围执行，不强制增加首次使用全流程。

| 请求范围 | 可修改与停止位置 |
| --- | --- |
| 新增功能或改变已确认行为 | 直接实现已有需求与方案，修改范围内代码、必要行为测试及直接相关说明，完成约定用户路径 |
| 恢复既定行为、修 bug 或合并冲突 | 进入下节修复模式；保留失败信号、根因、最小修复及原动作复验，不借修复改变目标 |
| 指定位置的局部修改 | 沿指定版本直接处理，修改范围保持局部；属于故障仍走完整修复步骤，属于新行为或行为不变调整分别采用对应做法 |
| 明确保持公开行为的内部简化 | 范围内代码与必要行为基线；逐项修改并验证、有据关闭或转回需求变化 |
| 补测、修测试或维护测试环境 | 仅相应测试资产及必要测试环境；生产故障只定位并返回修复需求 |
| 只跑测试或只读诊断 | 运行约定检查并分类报告；不修改生产代码、测试断言或持久配置，失败不自动转为修复；必要运行产物沿原测试约定处理 |
| 只查产品界面组件 | 只交真实库、组件位置、适用性和未知；不修改组件、调用处、依赖或库配置，不自动转为接入或抽取 |
| 明确 TDD（测试驱动开发）并实施行为 | 测试及最小生产实现，逐个完整行为保留红绿证据 |
| 只先写测试，禁止实现 | 完成有效失败测试后停止，不进入生产实现 |

已有规格足够时直接实施；项目要求规格先行且行为变化时，先在同一授权内补受影响的现行条目，不机械新建 PRD。只有用户目标、成本或风险发生实质改变时才返回该取舍。局部范围内的故障也须保留修复步骤；必要检查可以覆盖相邻路径，修改范围仍保持原约定。只跑测试发现的故障只报告，不因本入口兼具实现能力取得修改权。

## 修复模式：复现、根因与原动作复验

当前目标是恢复既定行为或处理合并冲突时，修改前读[修复方法](references/debugging.md)，保留原输入、版本、准备条件和观察位置。主文的四项要求始终适用于修复，详细方法只在该模式采用：

1. 先取得可信失败信号。复用已有失败测试、请求、命令或原操作证据；没有确定信号时补观测并缩小范围。原故障版本不可得时说明限制，不破坏当前可用版来制造失败。
2. 定位最早偏离的输入、状态、转换或时序，分清生产故障、规格变化、过时测试及依赖／环境问题。环境或测试准备失败不冒充目标行为失败。
3. 按有证据的根因做最小修复，保护无关行为与存量数据；不删断言、放宽预期、伪造返回或静默失败来求通过。
4. 修复后用同一输入、关键准备条件、原动作和观察复验，再检查实际受影响路径。涉及共享状态或生命周期时，核已有及之后新建消费者；保留首次失败与后续修复的区别。

新增功能不需要先制造旧故障，普通实施不强制测试先行。只要求诊断时止于证据和原因；发现实质需求变化或额外操作需求时处理具体取舍，仍有效的原目标与授权继续承接。

## 完成原目标路径

以调用者可观察的垂直切片推进，选择已有公开 API（接口）、CLI（命令行）或页面验证入口。明确写入所有者、接口和失败恢复，只在状态／异步变化影响结果时展开相连路径；不增加第二条权威写入路径或临时双轨来凑结果。

测试资产、测试先行或失败分类需要展开时，读[测试方法](references/testing.md)。不默认将普通实施改成 TDD；不写仅镜像内部实现的无效测试。验证覆盖原目标的实际输入、操作、输出及必要边界；自动测试不足的视觉、语义或真实外部能力保持未覆盖状态。

按项目要求运行必要检查，通过后只有新变化、失败或具体疑点才扩大。有关架构检查区分新增问题、已有违规、例外与未覆盖，不刷新基线制造通过。同步本次实际影响的规格、入口与日志，保护无关改动。

需要可复验的命令日志或前后源码指纹时，使用包内组件，例如：

```sh
python3 scripts/check_run.py --argv-json '["node","--test","test/sync.test.mjs"]' --cwd /tmp/project-candidate --log-dir /tmp/check-implementation-01 --timeout 60 --source src/sync.mjs
```

例子的测试入口应换成已核实的真实命令，argv（参数数组）不通过 shell 拼接。日志目录须本次唯一且尚不存在。退出 0 只表示该命令成功，1 表示命令失败，2 表示输入或运行准备错误；业务判定仍依据断言与日志。组件不自动运行全套检查，超时与未运行如实保留。

## 按需采用

| 条件 | 读取与用途 |
| --- | --- |
| 指定版本、未提交改动或旧报告影响基准 | [事实与来源](references/shared/evidence.md)：确认实际原版与执行覆盖 |
| 需要区分例行工程选择与实质目标取舍 | [决定归属](references/shared/decision-ownership.md)：在现有授权内收口 |
| 关键断言、原动作或运行状态证据 | [工程证据](references/shared/engineering-evidence.md)：核验红绿、最终消费者和源码指纹 |
| 验证计划、代表性错误或扩大测试范围 | [可观察验收](references/shared/validation.md)：选择相称检查并保留边界 |
| 规格修订、内部工作已完成或父目标仍未完成 | [权威与返回](references/shared/authority-and-return.md)：保全条件并继续原目标 |
| 用户点名呈现参考，或视觉／交互方向有会改变做法的缺口 | [视觉方向与真实反馈](references/shared/visual-direction.md)：按需查已授权来源、优先复用并把选择落实到产品；已有设计与普通局部修改直接继续 |

存在可独立结果且并行收益成立时才采用 coordinate；串行可直接完成。行为、数据、权限或公开契约变化完成后由另一执行者独立 review；实施者自查不替代独立审查。提交、推送、PR（拉取请求）写入与发布按具体授权另立结果。

需要查目标产品的组件库、核对适用性或抽取并迁移重复界面块时，先读[组件查找、复用与抽取](references/component-reuse.md)，在原任务授权内处理。只查找时只交位置、适用性和未知，不改组件、调用处、依赖或库配置。库内没有且同一块有多个已存在或已确认即将实现的使用位置时才抽取，并迁移范围内已写调用；单处留在原地，不能编造未来消费者。已知可用组件直接采用，不为普通界面工作重走查找或完整流程。产品操作、状态、反馈及完整路径仍按本职责采用 interaction 方法并验证。

结果包含多个状态或异步交叠、读者难以看清故障位置时，可采用 `507-visualize` 把已取得的事件顺序、异常与应有行为图解后返回本任务。图只表达证据，不代替原动作复验或授权新修复；简短结果直接说明。

## 完成与返回

范围内行为已实现并回到原目标完整路径，必要检查与独立审查状态准确，直接相关说明已同步，交付实际文件、证据、未覆盖和剩余项。只查组件时以可定位的发现、适用性和未知完成；只要求测试时以该范围完成，均不宣称生产实现或用户接受。

检查失败时保留原信号和可用基线，定位失败类型后按本次范围处理：已授权实现或修复时继续修相关部分；仅测试维护时只处理已授权的测试资产和测试环境；只跑测试或只读诊断时报告结果，不自动转为修改。不删断言、放宽预期、静默失败或替换基线来伪造通过。需要新增操作授权或实质产品取舍的部分停在具体缺口，独立部分继续。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。

本次出现执行已授权行为不变修改，逐项建立基线、修改或有据关闭时，读[行为不变修改证据门](references/shared/behavior-preserving-change.md)并在本职责原权限与完成边界内采用。

本次出现实现产品操作、异步状态与失败恢复时，读[操作、状态与实际呈现](references/shared/interaction.md)并在本职责原权限与完成边界内采用。
