# 复现、根因与修复

围绕现有行为恢复正确结果。承接故障输入、原动作、环境、预期结果、指定版本与可写范围；可查资料自行核对。完整读错误和首个真实失败，再沿调用与数据流寻找最早偏离，区分生产故障、规格变化和环境／测试问题。

## 先建立反馈环

修改生产实现前，将最小复现固化为明确通过／失败信号，可以是已有失败测试、公开请求、CLI（命令行）重放或实际用户操作。没有确定信号时补观测并缩小范围，不能凭症状猜改代码。已有绿灯但故障仍可复现时，先纠正验证入口；断言须能拒绝原错误结果。

读[工程证据](shared/engineering-evidence.md)绑定故障版本、原动作和最终消费者。RED（红灯）必须是所需行为失败，环境、fixture 或编译错误不算。故障版本不可得时保留原证据与限制，不破坏当前修复来制造失败，也不声称已完整复现。

每次有价值的尝试保留假设、动作、实际结果和新增信息。同类连续两次尝试既无新信息也未缩小范围时，暂停该路径，核验版本、入口、依赖与环境等前提，并改用不同诊断假设；错误在变化且范围缩小时可继续。

## 修根因并回到原动作

确定哪个输入、转换、状态、时序或边界首先违背既定契约，报错点是否仅为症状，现有检查为何漏过。根据证据选择最小修改，优先既有写入所有者和复用路径；保持无关公开行为与存量数据，不增加第二条接受写入的路径。

拆分共享状态、对象快照或客户端前，先查其更新入口与创建入口，定位已有和后续新建消费者应共同承接的值。修复后的必要回归包括这些受影响路径；不能因原两项故障已绿就跳过本次改变的生命周期。

不得删断言、放宽预期、静默失败、伪造内部返回或改规则／违规基线掩盖问题。测试中的故意错类型不进入生产代码。临时插桩使用可搜索标记，完成前清理新增调试内容和敏感输出。

修复后重放同一输入、准备条件、原动作与观察，再完成相关回归和项目必要检查。改变共享配置、对象快照或客户端生命周期时，验证更新后的已有消费者与之后新建消费者实际采用的身份和值，按[工程证据](shared/engineering-evidence.md)选择受影响分支；原故障绿灯不代替这项相邻回归。必要命令与源码指纹可用包内组件捕获：

```sh
python3 scripts/check_run.py --argv-json '["node","--test","test/sync.test.mjs"]' --cwd /tmp/project-candidate --log-dir /tmp/check-fix-green-01 --timeout 60 --source src/sync.mjs
```

命令与文件替换为当前已核实入口；每个红／绿记录使用独立、尚不存在的日志目录。参数是 argv（数组），不通过 shell 拼接。组件保存命令退出、超时、原始日志及可选前后指纹；退出 0、1、2 分别是命令成功、命令失败、输入／准备错误，不代表业务验收或许可。读日志确认通过来自预期修复。

## 特殊情况与按需依据

合并冲突时核对全部冲突文件和双方意图，保留合理改动并整体复验；产品行为存在真实分歧时暂停相应选择，不能机械选择一边。恢复既定行为不机械新增规格；改变公开行为的修复同步项目现行要求与必要变更记录。

| 条件 | 读取与用途 |
| --- | --- |
| 当前故障版本、用户改动或证据归属不明 | [事实与来源](shared/evidence.md)：定位基准 |
| 准备故障复验、回归或真实环境检查 | [可观察验收](shared/validation.md)：覆盖原结果及风险 |
| 证据表明规格或风险承受需要改变 | [决定归属](shared/decision-ownership.md)：交回真正取舍 |
| 修订要求、保存结论或本能力完成 | [权威与返回](shared/authority-and-return.md)：返回原目标与未完成项 |

## 完成与返回

原故障有可复查信号，根因和最小修复有证据，同一原动作通过必要回归，临时内容已清理；交付修改、根因、红绿证据及未覆盖。行为、数据、权限或公开契约变化由另一执行者独立 review，发现返回原实施者；提交和发布只按具体授权继续。

证据显示属于规格变化或环境问题时停止猜改生产实现，返回相应任务。受阻时报告已验证事实、已排除可能、当前故障边界和最小下一动作，保留可用基线并继续不受阻部分。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](shared/continuation.md)并在本职责原权限与完成边界内采用。
