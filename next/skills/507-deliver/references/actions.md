# Git、PR 与渠道动作的独立证据

对应动作已获授权才采用。先核对仓库、分支、当前差异／暂存、提交、精确引用、实际 remote（远端）与身份，分清本次、无关和归属未知改动。不以交付清理或覆盖用户改动。

## 本地提交

按项目要求同步直接相关说明或 Unreleased（未发布）条目；内部测试／文档不硬塞产品日志。复用仍有效验证，必要检查失败不造提交。逐路径暂存本次文件，读回暂存差异；不全量暂存、不混临时文件、秘密、私密原料或无关格式变化，不跳过钩子。按项目约定创建提交并读回哈希、正文和保留状态。本地提交不顺带改版本或标签。

## PR 平台写入

先核对源／目标分支、实际最终差异和已有 PR，准备标题、正文及模板必需字段。平台动作所需的推送若未获授权或目标不存在，停在具体缺口与可审草稿，不能为建 PR 自行提交或推送其他改动。更新复用同一对象，创建后读回 URL、分支、标题和正文；有合并请求才核对独立审查、检查状态和目标后执行合并。调用宿主支持的附件方式将真实创建／续办的 PR 关联到当前任务，平台回执与附件成功分开记录。

## 引用与版本

仅推送已有分支／标签先确认精确引用及其目标提交，读远端状态；按已授权引用推送，禁止批量推所有标签或强推主干。仅建本地标签只核对名称、目标和冲突，不顺带提交、推送或改版本。引用操作不因存在其他未提交改动就取得处理它们的权限；这些改动不影响精确引用证据时保留并说明，项目有更严格前提则服从。

新定版核对最新标签、当前版本、项目版本规则及实际应发布内容，按授权更新版本／日志及实际 manifest（清单），精确提交，再创建指向目标提交的标签。发布前再核对日志、版本、标签、提交与渠道；既有版本发布复用定版证据，不制造新版本或重复日志。

真实远端／包渠道操作核对登录身份、registry（分发源）、目标包／版本、预发布标识及已存在状态。已完成版本不重复发布；项目没有该渠道或用户排除的渠道直接跳过。GitHub Release 说明来自对应版本记录，多行正文用文件提交以保留实际换行，不把 shell 拼接当文本传输。

## 读回与恢复

命令退出成功后分别读回 PR 内容、远端引用所指提交、包实际版本或 Release 对象，才记录该结果。分支已推送不证明标签、包或 Release 已送达。

失败先核验外部状态；仅明确瞬时故障、目标不变、安全可重复且已排除冲突时最多重试一次。未知结果、身份变化、冲突或需要破坏性恢复时停止对应动作，保留真实失败及已完成项；不自动撤回已经完成的外部动作，不改凭据或重写历史来凑成功。
