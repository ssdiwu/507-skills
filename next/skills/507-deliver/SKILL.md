# PR 表达与版本交付

让接收者理解具体问题、最终变化、验证和边界，并按当前授权到达指定终点。承接目标范围、实际差异／提交、独立审查、项目交付规则、目标仓库与渠道；工程尚未达标时返回相关实施，不把漂亮说明当完成。

## 本次动作与终点

| 已授权请求 | 本次结果 |
| --- | --- |
| 写 PR（拉取请求）描述、提交信息或交付说明 | 可直接使用的草稿，不改 Git 或平台状态 |
| 创建／更新指定 PR | 实际 PR 对象与读回核验；不自动合并或发布 |
| 本地提交 | 精确范围的真实提交与工作树状态；不自动推送、定版或创建标签 |
| 推送已有引用／仅创建标签 | 对应引用与实际核验；不倒推为提交未提交改动的权限 |
| 指定版本／渠道交付 | 仅该版本、引用与渠道的实际状态；准备、发布及接受分开 |

已有授权在范围和目标不变时持续有效，不拆成逐动作再次确认。泛称“交付”先核实项目真实终点；只在具体动作仍不明确且会改变范围时处理该缺口，不猜发布渠道。安装、发消息或发布到额外渠道不随交付名称附送。

请求或项目约定仍点名旧507-git等入口时，按[旧引用与当前职责](references/shared/skill-entry-resolution.md)查询包内声明并核本次动作。旧名称不扩原许可，索引不证明宿主存在；明确保留的提交／引用／渠道条件继续有效，实质冲突交回具体取舍。只要草稿仍止于草稿，不为迁移技能名修改未授权项目规则。

## 写清最终变化

先完整读最终差异和项目模板。说明面向未看过对话的接收者：具体问题及触发条件、结果行为、必要设计取舍、相关验证与限制。范围改变时重写标题与正文，去掉废弃方案和聊天过程；复杂差异才展开结构，不复述整段代码。

验证明确实际命令、版本及结果，区分构建、测试、原路径、独立审查、人的验收和远端状态。已有证据仍覆盖当前代码／依赖／环境时复用；新差异或具体疑点才补验。未完成及风险写成具体缺口，不声称已接受。

## 执行已授权动作

需要 Git、PR 平台写入或版本／渠道操作时，读[动作与读回](references/actions.md)。先完成全部可审的文件、正文、证据和版本核对；实际操作前核对对应许可、身份、引用和渠道，不让前一个成功结果自动授权下一个。

## 按需方法

| 条件 | 读取与用途 |
| --- | --- |
| 差异版本、独立审查或远端结果来源不清 | [事实与来源](references/shared/evidence.md)：确认可交付基准与实际回执 |
| 目标渠道、动作许可或成本有实质歧义 | [决定归属](references/shared/decision-ownership.md)：只处理缺少的取舍 |
| 验证是否足以支持目标终点 | [可观察验收](references/shared/validation.md)：限制通过与就绪结论 |
| 部分交付、失败恢复或父目标尚未完成 | [权威与返回](references/shared/authority-and-return.md)：携带真实状态继续 |
| 说明关系或差异难以理解 | [清晰表达](references/shared/clear-expression.md)：以最小表格或必要图表达 |

## 完成与返回

草稿请求以可用说明结束；状态变更请求以对应提交、PR、引用、版本或渠道的真实结果及读回完成，交付链接／哈希、已完成、失败和未执行部分。没有完成的渠道不得写成发布成功。

身份、归属、引用冲突、必要验证或外部状态不明时保留现状，先核对事实；不强推、覆盖标签或自动回滚已完成外部动作。继续已有授权的独立部分，父目标未完时返回实际依赖。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。
