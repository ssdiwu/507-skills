# 复盘与工具化建议

解释这次任务哪里有效、哪里失败、还不能判断什么，再提出有证据的改进。承接明确范围、实际工作版本、操作／日志、完成产物及用户反馈；不用后见结论改写失败记录，也不把计划或自报当发生过的结果。

## 从真实过程提炼

按当前问题选择有价值的事件：当时假设与条件、采取的动作、实际结果、新信息、后续改变。区分实现缺陷、需求变化、环境问题、无效反馈环和评估输入错误；同类重复尝试没有新信息时标为摩擦，不能计成多份成功经验。

对照目标、原动作与最终结果，找具体漏项和收益，不按文件数、规则数、短代码或单次绿灯推算更好。已有成功短路径保留；某次失败的特殊环境和个人偏好不直接成为所有任务的永久规定。

## 改进与重复任务的去向

| 观察 | 建议产物 |
| --- | --- |
| 一次性的实现或数据错误 | 对应修复及必要回归，不提升为通用方法 |
| 多个真实消费者有同一判断困难 | 方法候选：采用条件、共同输入／输出、责任和验证样本 |
| 确定性的重复操作且已有工具不足 | 工具建议：输入参数、依赖、输出、副作用、错误及替代方案 |
| 缺少可信版本、回执或验收 | 证据捕获／验证改进，保留本轮结论限制 |
| 有效项目约束缺少承接 | 在其真实归宿提出修订，不另建竞争状态总账 |

工具化前核对已有脚本、平台能力、标准库与成熟依赖，比较复用、维持原动作或新增工具的总复杂度。只有确定性步骤才建议封装；目标、语义、权限和取舍仍由消费者判断，不造通用路由或自动审批器。用真实重复成本、失败风险和可复验证据说明价值，未同条件实测的收益保持假设。

每个建议说明适用条件、实际来源、预期改进、代价、反证及最小验证。无需凑固定数量，也不将每次任务追加一条永久规则。

## 权限与方法

默认交付复盘和建议，不改代码、技能、规则、共享方法、个人记忆或平台状态，不自动通知他人。明确批准具体方法／工具写入后才按原范围继续建设，准备隔离候选、直接消费者和有区分力的验证，再由独立审查收口；批准复盘本身不构成批准这些写入。

| 条件 | 读取与用途 |
| --- | --- |
| 过程、来源版本或完成自报需核实 | [事实与来源](references/shared/evidence.md)：绑定实际材料与覆盖 |
| 多个改进有真实收益／代价差异 | [候选与反证](references/shared/alternatives.md)：避免为偏好凑方案 |
| 提议验证、对照收益或验收方法改变 | [可观察验收](references/shared/validation.md)：建立能拒绝错误的观察 |
| 将建议写成行为、权限或工具建设前 | [决定归属](references/shared/decision-ownership.md)：核对具体批准范围 |
| 纠正旧结论、保存改进或完成复盘 | [权威与返回](references/shared/authority-and-return.md)：保持当前归宿与父目标 |

## 完成与返回

完成时能区分事实、推断、未知和建议，重复摩擦及候选有来源与边界，交付可决策的改进和最小验证。只要求复盘时结束；原工程目标未完则将具体结果返回，不用复盘替代修复或交付。

关键日志／原版不可得或结果尚未成立时说明限制，仍完成可证部分，不补造过程。没有证据的推广候选不进入正式方法；真实批准之后按候选验证结果决定是否替换可用基线。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。
