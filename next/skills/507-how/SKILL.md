# How · 方案构造与变更路径

判断改变哪里才能达成目标、哪些行为和数据必须保持，选择总复杂度低且能恢复的变更路径。策略收益来自调用者少知道细节、少维护重复规则与状态，或完整目标更容易成立；拆文件、搬代码、减行数不单独证明收益。

## 输入、权限与任务责任

承接已确认目标、当前版本、用户修改、允许范围、现有方案与验证条件。只缺可查现状时先查；目的、责任或实质成本风险仍未定时补必要取舍，不要求完整上游格式或重新确认已有授权。

只要求分析或方案时，不实施产品、不改代码、测试、配置或业务数据；持续方案工作主动在当前工作位置维护必要方案依据，遵守明确只读、不写文件和临时讨论限制。按[工作记录](references/shared/work-records.md)保存方案、假设、取舍与验证路径，不改无关项目文档。原请求已要求实施时，策略是内部工作，成立后持续完成授权范围的实现、直接消费者与验证。新增外部动作、提交、推送、合并和发布各按具体授权，策略不增加权限。

明确故障直接修复，成熟方案、执行工单或可用任务图直接实施；只有新的跨约束介入缺口才采用本技能。作品的表达策略归创作目标，技能封装归能力设计；不因请求包含“怎样”而接管所有行动。

## 形成可消费的策略

新产品、重设计或没有旧实现时，先读[方案构造](references/solution-design.md)，从一条真实任务构造方案；已有系统变更采用下列路径。用户拥有体验目标和实质取舍，不意味着每个设计细节都要用户先给答案。

1. 核对目标原动作、当前现象与不变量。沿实际调用者找公开入口、内部接缝、读写所有者、数据与存量消费者；区分要求、实现与验证，先复用既有能力。
2. 定位介入点，说明它怎样影响目标。比较复用、替换、迁移、局部调整或暂不改等真实路径；常规可逆技术选择自行收口，有实质用户取舍时给依据、推荐与影响。
3. 从调用者用法检查接口：初始化、刷新、清理、顺序、错误与恢复由谁处理；共享之后不能要求调用者维护更多内部状态。存在跨状态、迁移或新旧并存时，读[跨约束策略](references/change-strategy.md)，补齐所有权、切换、退出和失败保全。
4. 为策略选择能推翻它的观察和实施切片，每片有可验结果与回退点，最终回到目标完整路径。已有充分策略不重复画计划；只做策略的请求止于可消费方案，实施请求继续行动。

| 当前缺口 | 按需方法及读后动作 |
| --- | --- |
| 当前版本、调用、消费者或运行状态不明 | [事实与证据](references/shared/evidence.md)：核对实际入口、所有者、数据与观察范围 |
| 范围、权限或取舍归属不清 | [决定归属](references/shared/decision-ownership.md)：保留实施授权，分清技术责任与用户取舍 |
| 策略依赖尚未成立的信息 | [问题依赖](references/shared/question-frontier.md)：查清或只问阻止当前介入的问题 |
| 存在真实替代路径 | [候选与反证](references/shared/alternatives.md)：比较总负担与使推荐失效的条件 |
| 需要定义切片和最终检查 | [可观察验收](references/shared/validation.md)：绑定原动作、实际分支与可拒绝错误的结果 |
| 新决定冲突、权威回写或内部策略完成 | [权威与返回](references/shared/authority-and-return.md)：对账当前消费者，持续推进原目标 |
| 接口、状态或迁移关系复杂 | [清晰表达](references/shared/clear-expression.md)：用必要表格或图显示读写、依赖、切换与恢复 |

## 按独立结果采用工作能力

需要把已成立方向组织为有依赖、验证点和接续位置的执行步骤时采用 `507-plan`；不以计划代替设计或实际派工。需要长期行为依据可采用 `507-spec`；范围已成立的实现与明确故障按需采用 `507-do`，由其分别承接实现或修复模式，问题记录用 `507-issue`。独立写入和集成确有收益时用 `507-coordinate`，行为、数据、权限、公开接口或正式需求变化用 `507-review` 独立审读；已授权的具体版本终点用 `507-deliver`，明确复盘请求用 `507-retro`。

方案的状态变化、责任交接或同条件比较难以看清时，可采用 `507-visualize` 交付图表与必要说明；不以画图替代方案取舍或要求每个方案建图。

这些是按需工作角色，不是流水线或安装前提。委托给出目标、当前版本、范围、权限、不变量与可消费结果，返回后核对产物并继续集成和整体验证。相邻技能不可用时按同一合同直接完成；独立审读须由另一执行者承担，不能把实施者自查标为独立审查。

## 完成、返回与恢复

- **完成信号**：新方案的目标路径、关键关系及必要失败/修改/停止/恢复已连贯，或已有系统的介入点、变化与不变量、调用者用法、状态与数据所有权、必要迁移/退出、反证与验收已足以执行。只需方案时完成于此；实施请求完成于范围内目标路径及必要检查，内部方案或单片通过不结束整体任务。
- **产物**：现有交付位置中的可消费策略；获授权实施时附实际改动、消费者切换、验证和独立审读结果。规划、构建、实测、人工接受与发布分别报告。
- **候选出口**：信息与策略足够则直接实施或返回原负责人；仅分析请求结束。发现用户实质取舍才回交决定，事实缺口先查；内部简化若需要改变公开行为，按获授权需求实施处理，不能冒称行为不变。
- **回退条件**：基线不足、迁移条件不成立、范围冲突或验证失败时，保全上一可用版本与数据，停止受阻切片并记录失败信号、已验证范围与最小下一动作，继续独立部分。不放宽断言、不刷新基线掩盖失败、不把未见消费者当作可删除证据。

本次出现外部依赖、方案或参考机制尚未核实时，读[外部取证与证据交接](references/shared/external-research.md)并在本职责原权限与完成边界内采用。

本次出现成立策略需要同条件对照或可操作关系表达时，读[对象关系、比较与观察](references/shared/visual-understanding.md)并在本职责原权限与完成边界内采用。

本次出现真实中断、上下文压缩或转交时核实际版本、写权、有效尝试与未完成；普通结束跳过时，读[真实中断、交接与续办](references/shared/continuation.md)并在本职责原权限与完成边界内采用。

本次出现一个可观察未知会改变策略且收益大于制作与清理成本时，读[可丢弃原型证据](references/shared/probe-lifecycle.md)并在本职责原权限与完成边界内采用。

本次出现需要可定位的改进机会及完整候选处置时，读[架构摩擦与候选证据](references/shared/architecture-candidates.md)并在本职责原权限与完成边界内采用。

本次出现构造保持公开行为的内部简化策略时，读[行为不变修改证据门](references/shared/behavior-preserving-change.md)并在本职责原权限与完成边界内采用。

本次目标需要对齐产品功能、入口与用户操作的设计／实现／运行差距时，读[交互点与证据](references/shared/interaction-map.md)。需要独立的可探索地图结果可按原权限委托 `507-product-map`；普通策略、规格或审查不强制建图，结果回到当前职责。
