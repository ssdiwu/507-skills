# 从目标构造方案

目标与约束足够、方案尚未成形时采用；已有成熟方案直接沿用。无需旧实现，不借调查读取用户明确排除的材料。

1. 从真实任务写清谁怎样开始、系统怎样响应、最后得到什么。先形成一条连贯路径，不先列组件清单。
2. 沿路径确定必要对象、操作、状态、数据与权限、职责及结果关系。优先复用已有能力；常规可逆选择由 Agent 提议并落实，标明依据。
3. 检查本次有关的失败、修改、停止和回来继续：保留什么、何时失效、由谁恢复。用户实质体验或成本风险取舍才交回，其余设计继续。
4. 对会改变方案的未知查证、比较真实替代方案或安排隔离验证。参考产品的做法不自动成为本产品决定，不为图完整而猜功能。
5. 在现有正文形成当前完整方案，区分用户要求、已采用设计、候选与待验证假设；同步被新决定影响的关系和验收。目标定义有缺口只补受阻部分，规格、计划各按独立需要采用。

完成于方案足以实施或验证；原则列表、调查报告或待讨论问题只是中间结果。方案请求止于方案，原目标已含实施则继续其授权范围。没有阻塞时不以等待用户逐条批准设计细节结束。
