# 编写与独立交付

用于获授权的新建、改写或资源结构变化。沿目标项目与宿主的实际规范；业务权限由原任务授予。

SKILL.md 的 name 与目录一致；主要技能采用简短动作词或短语，展示名称保持简洁，详细职责和模式写在 description 与正文。description 用动作和使用条件区分相邻任务。主文保留输入、权限、必要判断、产物、完成、失败与返回；章节和长度按实际职责选择。

按需参考在主文写明“何时读取、读后做什么”。共有源记录消费者，交付时生成普通随包副本或声明真实独立工具依赖；单项包不能暗中依赖作者仓库、兄弟技能、软链接或机器缓存。复制不改变维护权威：只编辑共有源，再生成并检查副本。

面向OpenAI且项目要求界面元数据时，使用agents/openai.yaml维护用户可读的display_name、short_description和包含实际调用标识的default_prompt。核对目标宿主当前规范；已有policy、依赖和资产字段保留。文件检查、宿主发现和界面显示分别验证，未实际发现不能宣称已启用。

新增工具优先复用现有能力。若确需脚本，明确输入与输出路径、依赖、失败退出、副作用和覆盖行为；先在隔离位置验证候选，再替换有效结果。不要生成通用业务执行器、默认安装器或自动发布步骤。

同步直接消费者、导航、示例和退出旧入口的范围。旧原件可以作为证据或回退材料保全，但不能与新合同同时冒充当前权威；不要自动安装第三方源或修改宿主配置。
